# 混淆文件备份

日期：2026-09-19

本轮供人工查看的结果已移出仓库，保存在本机 `d:\mcaddon\归档\反编译测试归档-1.0-beta1-61168863\`
（103.9 MB：完整反编译结果、CFR 抽样、解压字节码、对应发布包和测试日志，中文目录说明见其中的 `阅读说明.md`）。
移出原因：它是本轮一次性人工归档，占了大半个目录体积，跟着仓库走没有意义；`buildRelease` 不会自动运行反编译器或更新这些结果。

运行 ` .\gradlew buildRelease --console=plain `，混淆产物通过检查后自动备份到：

```text
05-混淆文件备份/<版本>/02-字符串与控制流加强版-<版本线>-<SHA-256前8位>/
    mapping.txt          类、方法和字段名称映射
    proguard-rules.pro   本次保留及混淆规则
    hardening-stats.json 字符串和控制流覆盖统计
    protection-audit.txt 最终发布包加密常量与字节码审计
    产物信息.txt          JAR 名称、版本、校验值和验证状态
```

发布包在 `build/release/`；本目录独立于 `build/`，`gradlew clean` 不会删除它。
相同产物的备份可重复使用，已有不同内容时构建报错，不覆盖历史。
目录采用中文标签 + 版本线 + 摘要前 8 位（如 `02-字符串与控制流加强版-26.2-1bcf30d9`），
完整 SHA-256 保存在各目录的产物信息中；加线标之前建的归档沿用旧名，看不出属于哪条线时看
`产物信息.txt` 的「产物」行或查对应报告。
`01-基础混淆版-21413309` 是历史基线；`02-字符串与控制流加强版-61168863` 是本轮加强版。
按出问题的 JAR 的 SHA-256 选择对应映射，不能使用其他构建的映射还原堆栈。

**保留规则**：每份归档约 1.3 MB（大头就是 1.34 MB 的 `mapping.txt`，纯文本，git 压得很好），
所以正常发布的映射**一律保留**，不按版本删。要清只清**作废归档** —— 产物被同名覆盖（同版本重出）
或从未对外挂过的那些，映射已经没有对照对象，当场删掉；体积大的反编译/反汇编资料一律放仓外，
不进本目录。删除与否只看「还有没有对应的产物」，不看发布了几版。

本目录是内部资料，不得上传到公开发布仓库 `origin`、Release 附件或发送给普通用户。
映射会暴露原始类名、方法名与字段名。源码提交与推送仍需用户明确授权。

当前方案使用免费的 ASM 9.9.1 自研变换与 ProGuard 7.9.1：
AES-256-GCM 字符串加密、ConstantDynamic 延迟解密、基本块随机重排、加密整数驱动的跳转分派、名称混淆与调试信息清理。
保留 Fabric 入口、Mixin 契约、枚举配置、Gson 字段与原始资源；第三方嵌套依赖不做二次加固。
构造器、异常处理、同步方法等不适合安全重排的代码跳过控制流变换，公开常量与资源仍可能包含明文。
解密材料必须随客户端分发，因此不能保证无法反编译、阻止 AI 还原或达到“免费最高级别”。

`buildRelease` 自动执行行为对照、最终常量审计、类加载和资源检查；
可单独运行 `testHardening` 或 `auditProtectedConstants` 排查问题。
普通 `build` 或 `buildPersonal` 生成 `build/libs/yiyiaddon-<版本>-personal+<MC 版本>.jar`。
`buildRelease` 生成 `build/release/yiyiaddon-<版本>-<MC 版本>.jar` 与同名 `.zip`（如 `yiyiaddon-1.0-beta1-26.1.2.jar`），公开版不带混淆后缀；ZIP 内只有该发布 JAR。两条版本线的版本号相同，个人版与发布版都靠 MC 版本后缀区分，不带就分不清谁能装；发布包名同时是游戏内更新提示的判据，个人版不会被当成可安装包。
任务内部名称仍保留 obfuscated，便于维护，不影响对外文件名。历史归档名称保留原状。
每次真正重新加固使用新随机材料，应按实际 JAR 摘要保存对应备份，不能跨构建混用。
JAR 内附有 `META-INF/反编译声明.txt`，声明不能代替技术保护。
