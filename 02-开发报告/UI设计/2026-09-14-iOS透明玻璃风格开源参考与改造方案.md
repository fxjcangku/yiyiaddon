# iOS 透明玻璃风格开源参考与改造方案

**日期：2026-09-14**
**用途：模块中心与整体界面风格的 iOS / macOS 化改造依据**

---

## 一、结论摘要

现在这套界面不像 iOS，原因不在配色，而在三处结构性问题：

1. **玻璃用错层**。iOS 26 的官方原则是「Liquid Glass 只用于导航层，绝不用于内容」。
   当前实现把所有卡片都做成了半透明玻璃，结果是「到处都是玻璃」，反而失去层次。
2. **没有 rim 高光与阴影**。macOS 的毛玻璃卡片靠「1px 白色高光内描边 + 外阴影」立起来，
   当前只用了一圈主题色描边，看起来是一块半透明色块，不是玻璃。
3. **只有单一字重**。iOS 的层级主要靠字重（Regular / Semibold）建立，字号只是辅助。
   当前字体资源只有一个字重，层级只能靠字号和颜色凑，所以「就是不像」。

## 三、从参考中提取的苹果设计参数

以下数值来自 iOS / macOS 公开的设计规范与上述实现，作为 yiyiaddon 改造的对照表。

### 3.1 暗色系统色（Minecraft 场景以暗色为主）

| 语义 | 值 |
| --- | --- |
| 背景 基础 / 次级 / 三级 | `#000000` / `#1C1C1E` / `#2C2C2E` |
| 填充 三级 / 四级 | `rgba(118,118,128,0.24)` / `rgba(118,118,128,0.18)` |
| 分隔线 | `rgba(84,84,88,0.65)` |
| 主强调色 systemBlue | `#0A84FF` |
| 系统灰 2 / 3 / 4 / 5 / 6 | `#636366` / `#48484A` / `#3A3A3C` / `#2C2C2E` / `#1C1C1E` |
| 语义色 绿 / 橙 / 红 / 黄 | `#30D158` / `#FF9F0A` / `#FF453A` / `#FFD60A` |

### 3.2 文字分级

| 层级 | 暗色值 |
| --- | --- |
| label | `#FFFFFF` |
| secondaryLabel | `rgba(235,235,245,0.60)` |
| tertiaryLabel | `rgba(235,235,245,0.30)` |
| quaternaryLabel | `rgba(235,235,245,0.18)` |

### 3.3 字阶

| 语义 | 字号 |
| --- | --- |
| caption2 / caption1 | 11 / 12 |
| footnote / subheadline | 13 / 15 |
| body / headline | 17 / 17（headline 用 Semibold） |
| title3 / title2 | 20 / 22 |

规则：≥20pt 用 Display 字族，<20pt 用 Text 字族；层级优先靠字重，其次靠颜色与字号。

### 3.4 玻璃材质参数

| 参数 | 取值依据 |
| --- | --- |
| 玻璃底色 | 暗色场景取近黑 + 约 45% 不透明度（对应 NSVisualEffectView 的 dark 效果） |
| rim 内描边 | 白色，不透明度约 0.25，宽度 1px |
| 圆角 | 容器 20、卡片 16、控件 10、胶囊半高 |
| 阴影 | 黑色低不透明度、大模糊半径、向下偏移 |
| 模糊半径 | 中等，配合降采样 |

### 3.5 交互规则

- 玻璃元素可点时必须给按压反馈（缩放约 0.97 + 变暗）。
- 动效使用弹簧（临界阻尼），不用线性插值。
- 多个玻璃元素相邻时归入同一容器，由容器统一控制间距与融合。
- tint 只用于表达语义（主操作、选中），不做装饰性着色。

## 四、当前 yiyiaddon UI 的差距诊断

对照第三、四节，逐条列出实际问题：

| 序号 | 现状 | 苹果做法 | 影响 |
| --- | --- | --- | --- |
| 1 | 所有卡片都是半透明玻璃 | 玻璃只用于导航层（窗口底板、侧栏） | 层次全糊在一起，是「不像」的首要原因 |
| 2 | 描边取主题色、不透明度 0.55 | 1px 白色 rim，不透明度约 0.25 | 缺少玻璃的高光边，观感是色块不是玻璃 |
| 3 | 无阴影 | macOS 卡片靠外阴影建立悬浮层次 | 卡片贴死在背景上，没有纵深 |
| 4 | 圆角统一 14 | 容器 20 / 卡片 16 / 控件 10，成组区分 | 圆角不成组，观感偏「网页卡片」 |
| 5 | 字阶 15 / 10 / 9 | 11 / 12 / 13 / 15 / 17 语义字阶 | 字阶不成体系，且偏小 |
| 6 | 层级靠字号 + 颜色 | 层级靠字重（Semibold 标题） | **字体资源只有单字重，是结构性短板** |
| 7 | 文字色取主题色板派生 | label 四级固定语义色 | 对比度与层次不稳定 |
| 8 | 强调色为主题 accent | 主强调色对应 systemBlue | 缺少苹果系统的识别度 |
| 9 | 动效为线性插值 | 弹簧（临界阻尼） | 交互偏生硬 |
| 10 | 点击无按压反馈 | 缩放 + 变暗 | 缺少「可交互」的触觉暗示 |
| 11 | 状态用胶囊徽章 | 小圆点或直接文字色区分 | 偏 Web 后台风格 |
| 12 | 侧栏选中为浅色块 + accent 文字 | 侧栏选中为强调色填充 + 反色文字 | 选中态不够「macOS 设置」 |

## 五、改造方案

### 5.1 分层归位（优先级最高）

```
窗口底板        玻璃（模糊 + 近黑半透明 + rim + 阴影）
左侧导航        玻璃（同一块底板内，不额外加材质）
内容区          不透明白底（systemBackground 层级色）
卡片            surface 色 + 1px 分隔线描边 + 极轻阴影（不用玻璃）
卡片悬停/选中   填充色提亮一档 + rim 微亮
```

这与当前实现是相反的：现在卡片最花、底板最素；苹果做法是底板玻璃、内容实心。

### 5.2 令牌层重写

在既有主题体系内新增一层 iOS 语义令牌（不新建并行主题系统）：

- 背景：`bgBase` / `bgSecondary` / `bgTertiary`
- 填充：`fillTertiary` / `fillQuaternary`
- 文字：`label` / `labelSecondary` / `labelTertiary` / `labelQuaternary`
- 分隔：`separator`
- 强调：`accent`（systemBlue）+ `accentOn`（反色文字）
- 圆角：`radiusContainer` / `radiusCard` / `radiusControl`

现有 `ClickGuiThemeColors` 的色槽由这层令牌派生，旧主题仍可用「预设」形式保留。

### 5.3 几何调整

| 对象 | 现值 | 目标 |
| --- | --- | --- |
| 窗口圆角 | 现有值 | 20 |
| 导航项圆角 | 8 | 10 |
| 卡片圆角 | 14 | 16 |
| 分类卡片高度 | 94 | 88 或 96（按实测观感） |
| 卡片内边距 | 16 | 16（左右）/ 20（上下） |
| 卡片间距 | 12 | 12 |

### 5.4 字重问题

当前字体资源为单字重（HarmonyOS Sans），无法直接表达 Semibold。三条路：

1. 引入一份 Bold 字重字体文件，按 `FontRenderer` 的注册机制加一族（推荐）；
2. 用 Skija 描边做伪粗体（零新增资源，但小字号会糊）；
3. 暂不解决，仅用颜色与字号分层（不推荐，这就是当前问题的根源）。

需要单独确认后再动手。

### 5.5 动效

- 悬停/选中：临界阻尼弹簧或先快后慢的缓动，替换当前线性 `lerp`；
- 按压：缩放 0.97 + 亮度下降；
- 但保持「只做状态过渡」的克制原则，不加常驻动画。

### 5.6 影响范围

| 文件 | 改动 |
| --- | --- |
| `ui/theme/ClickGuiThemeColors` / `ClickGuiPalette` | 新增 iOS 语义令牌并派生既有色槽 |
| `ui/component/GlassPanel` | 增加 rim 高光描边、阴影、模糊强度参数 |
| `ui/component/CategoryCard` / `ModuleCard` | 改为实心表面 + 分隔线，去掉玻璃 |
| `ui/component/StatusBadge` | 改为圆点 + 文字 |
| `ui/component/CardLayout` | 圆角与内边距常量 |
| `ui/screen/ClickGuiScreen` | 底板玻璃参数、导航选中态、按下反馈 |
| `ui/render/SkiaBlurRenderer` | 可能需支持按区域模糊（卡片区不再模糊，仅底板） |

`module` 包与页面结构**不需要改动**，本次是纯表现层改造。

## 六、边界与风险

- 本文档**未复制任何开源项目源码**；借鉴的是公开设计参数、组件职责与交互规则。
- Modern UI 为 LGPL-3.0，仅参考其能力清单，不引入依赖、不复制实现。
- 第 3.1 / 3.2 节系统色为苹果公开值，落地后需在实际画面上确认对比度。
- 玻璃融合（多个玻璃元素互相影响）在 Skija 直绘管线中无法完整复现，
  只能做「同一块底板上分区」的近似，需接受这一限制。
- 折射、色散一律不做。
