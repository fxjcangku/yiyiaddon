## 一、机制总览

- **只有一处框架实现**：`core/YiyiaddonModule.reportSelfCheck(List<String>)`。
- **触发时机唯一**：模块开启时（`onActivate()` 内前置拦截），不是每 tick、不是指令触发。
- **未通过时行为是双重的**：先「禁止继续启动」（`return false`，调用方 `return`），再「延后一帧自动关闭模块」。

```java
// core/YiyiaddonModule.java:147-161
protected boolean reportSelfCheck(java.util.List<String> missing) {
    if (missing.isEmpty()) return true;

    chatFeedback = false;
    mc.execute(() -> {
        if (isActive()) toggle();
        chatFeedback = true;
    });

    notifyError("还差 " + missing.size() + " 项没配好，配完再开：");
    for (int i = 0; i < missing.size(); i++) {
        notify("§6  " + (i + 1) + ". §f" + missing.get(i));
    }
    return false;
}
```

两条注释是设计意图原文：

- `:141-143`：`Module.toggle() 是先 addActive 再调 onActivate，在 onActivate 里直接 toggle() 会造成状态机重入`（故走 `mc.execute` 延后一帧）
- `:138-139`：`一次列出所有缺失项，用户配好一项下次启动就少一条，不用挤牙膏式反复试。`
- `:145`：`@return true 表示自检通过可以继续启动，false 表示已中止`

调用方固定写法：`if (!reportSelfCheck(selfCheck())) return;`

## 二、自检项的三种构造写法

### 写法 A：模块内私有 `selfCheck()` 返回 `List<String>`（主流）

```java
// librarian/AutoLibrarianModule.java:183-209
private List<String> selfCheck() {
    List<String> missing = new ArrayList<>();
    if (moduleSettings.targetEnchantments.get().isEmpty()) {
        missing.add("§d目标附魔§f·未勾选");
    }
    if (!baritoneAvailable()) {
        missing.add("§bBaritone§f·未安装或未启用");
    }
    int lectern = 0, book = 0, emerald = 0;
    for (int slot = 0; slot < 36; slot++) {
        ItemStack stack = mc.player.getInventory().getItem(slot);
        if (stack.is(Items.LECTERN)) lectern += stack.getCount();
        if (stack.is(Items.BOOK)) book += stack.getCount();
        if (stack.is(Items.EMERALD)) emerald += stack.getCount();
    }
    if (lectern == 0) missing.add("§a讲台§f·背包没有");
    if (book == 0) missing.add("§a书§f·背包没有");
    if (emerald == 0) missing.add("§a绿宝石§f·背包没有");
    return missing;
}
```

调用点：`librarian/AutoLibrarianModule.java:130`

### 写法 B：独立自检类，构造时注入实例


### 写法 C：枚举驱动 + 外部数据源，按模式只查所需点位

```java
// enchant/AutoEnchantBook.java:1759-1771
private List<String> selfCheck() {
    List<String> missing = new ArrayList<>();
    TargetMode mode = 目标模式.get();
    for (PointType type : requiredPoints(mode)) {
        if (type == PointType.AFK && 当前运行模式() == RunMode.DRAIN) {
            continue;
        }
        if (getPointPos(type) == null) {
            missing.add("§6" + type.title() + "§f·未绑定");
        }
    }
    return missing;
}
```

点位清单来自 `requiredPoints(TargetMode)`（`enchant/AutoEnchantBook.java:758-770`），由 `enchant/point/PointType.java:12-31` 统一。

### 写法 D：不走基类，改由状态播报器贴版（星露谷专用）

`stardew/StardewFarmModule.java:592-634` 的 `collectStartupProblems()` 返回 `List<String>`，失败时交 `statusReporter.startupCheckFailed(missing)`（`:581`），由 `StardewStatusReporter.startupCheckFailed`(`:94-110`) 渲染成纵向字段卡片，末行 `status(Level.FAILURE, "禁止启动")`(`:106`)。**这是有意为之的例外，不是漏改**。

两者**不是同一层**，且都**不参与模块 enable 自检**。

### 5.1 `core/BuildSelfTest.java` —— 构建期 / 真机验收自检

```java
public static void runIfRequested() {
```
