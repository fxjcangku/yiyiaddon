## 二、为什么是「新增」而不是「迁移」

- 旧项目全树没有独立的重连模块：重连是旧 `autologin` 的一个子处理器（旧 `autologin/service/ReconnectHandler`），
  设置挂在自动登入的「自动重连」组里，随自动登入模块一起开关。
- 用户要求「单独拆一个、做全点、加测试键」。按 [01-总纲](01-总纲-迁移口径与复刻原则.md) 同类先例
  （「透视」模块：用户点名新增，登记为**新增非迁移**，见 [30 号](30-移植总览-已移植与未移植全清单.md) §2.8），
  本模块同样登记为新增。
- **自动登入模块一字未改**：它自己的断线重连（旧行为 1:1）原样保留，包括设置项、两个概览页按钮与全部播报；
  103 号报告描述的自动登入行为仍然成立。

## 三、逻辑收口（第 169 条：同源逻辑不留两份）

拆出独立模块后，重连会出现两份实现，因此先把两处实体逻辑上提为共用件：

| 共用件 | 原实现 | 收口方式 |
|---|---|---|
| `ReconnectEngine` | 旧 `autologin/service/ReconnectHandler` 的倒计时 / 服务器记录 / 失败计数 / `ConnectScreen` 发起 | 引擎只认 `Policy`（enabled / delay / max / unlimited 四个读口）与一个 `onStart` 回调；自动登入与本模块各持一个实例、各读自己的设置 |
| `ConnectionCloser` | `AdminDisconnect` 里的 `handleDisconnect(new ClientboundDisconnectPacket(...))` | 管理员检测的「§c立即断线」与本模块的「测试重连」都调它 |

自动登入侧改造后逐条对账（应完全等价）：

| 旧行为 | 现状 |
|---|---|
| `startReconnect()` 读 `reconnectDelay` / `maxReconnectAttempts` | 引擎 `startReconnect()` 读 `Policy` 的同两个字段 |
| `startReconnect(delay, max)` 覆盖等待与上限（自用路线异常恢复用） | 引擎同名重载，逐条保留 |
| `if (!settings.autoReconnect) return false;` | `Policy.enabled()` |
| `if (!settings.alwaysReconnect && attempts >= max) return false;` | `!unlimited() && attempts >= max` |
| 服务器信息为空时合成 `ServerData(Type.OTHER)` | `recordServer` 原样搬入引擎 |
| `reset()` 清服务器记录、`cancelScheduled()` 只清倒计时 | 两个方法原样保留，语义未变 |
| `getLastAddress()` / `getLastServerData()` | **不搬**：本项目全树无调用点（界面只读倒计时与调度状态），属死代码 |

## 四、设置项（6 项，一组）

| 设置名（= 落盘键） | 类型 | 默认 | 取值域 | 说明 |
|---|---|---|---|---|
| 自动重连 | 布尔 | 开 | — | 总开关；关闭后本模块只显示状态，不发起任何连接 |
| 重连等待（tick） | 整数 | 100 | ≥20 | 断线后等多久再连（20 tick = 1 秒），沿用自动登入同名字段的措辞与默认值 |
| 无限重连 | 布尔 | 关 | — | 忽略「最大重连次数」 |
| 最大重连次数 | 整数 | 5 | ≥1 | 连续失败到该次数停止并播报 |
| 连接稳定判定（tick） | 整数 | 200 | ≥20 | **本模块特有**：把自动登入里写死的稳定阈值（旧 `RECONNECT_STABLE_TICKS = 200`）变成可调项 |
| 回主菜单时取消重连 | 布尔 | 开 | — | **本模块特有**：把自动登入里固定打开的行为变成可关开关 |

行级显隐照自动登入的同一套条件：总开关关闭 → 只留总开关 + 一句灰字；「重连等待」「无限重连」仅总开关开启时出现；
「最大重连次数」仅总开关开启且未开无限重连时出现（改开关会整页重建，行立刻增删）。

改动立即 `ModuleManager.saveSettings`（第 172-175 条）；`settingsScope()` 保持 `null`（重连设置与具体服务器无关）。

## 五、测试键（用户点名的验证入口）

**位置**：控制台 → 概览 → 「重连控制」块 → `§e测试重连`（与「立即重连」「停止重连」同一排）。

**动作链**：点按钮 → 二次确认窗（`ConfirmPanelScreen.inPlace`，三条后果说明）→ 确认后
`AutoReconnectModule.testReconnect()` → 等 **10 tick** → `ConnectionCloser.disconnect(原因文本)` →
原版断线界面出现 → 本模块 `SCREEN_OPEN` 捕获 `DisconnectedScreen` → 按「重连等待」倒计时 →
`ConnectScreen.startConnecting` 连回 → 进服播报「已重新连接成功」→ 「连接稳定判定」窗口内失败计数归零。

**为什么等 10 tick 再断开**：二次确认窗是 `PanelScreen`，关闭有弹簧动画，动画结束时会 `setScreen(上级窗口)`；
若断开与关窗抢同一次 `setScreen`，玩家会看到断线界面被旧窗口盖回去。10 tick（0.5 秒）足够动画走完。

**按钮置灰判据（第 214 条：判据与动作读同一份数据）**：
`立即重连` / `停止重连` → `!engine.isScheduled()`；`测试重连` → `!ConnectionCloser.hasConnection()`，
且各自悬停提示会说明为什么不可点。

**用户验证步骤**：进服 → 关掉自动登入模块（避免让它接管）→ 本模块开启 → 控制台概览 → 测试重连 →
确认断开 → 看聊天栏「服务器断开，N 秒后重新连接。」→「正在重新连接... (第 1 次)」→「已重新连接成功。」

## 六、共存与边界

| 场景 | 行为 | 判据 / 说明 |
|---|---|---|
| 自动登入模块已开且它的「自动重连」开着 | **让路**：断线后本模块不调度，概览页「谁在接管」显示「§e自动登入接管」 | `autoLoginTakesOver()` 读自动登入的只读接口与其设置字段，不改对方状态 |
| 管理员检测点「§c立即断线」 | 断线后**不重连**，播报「本次断开是主动断线（管理员检测），自动重连不介入。」 | `AdminDisconnect` 断线前开 `ReconnectSuppression` 5 秒窗口（旧项目对应物是「断线前关第三方 AutoReconnect」，本项目零第三方依赖，改为抑制自家重连） |
| 玩家自己点「断开连接」退回主菜单 | **不重连** | 原版走 `TitleScreen`，不出现 `DisconnectedScreen`；本模块只以断线界面为调度入口 |
| 等待倒计时期间手动进主菜单 / 服务器列表 | 取消本次重连并播报 | 「回主菜单时取消重连」开关为开时（默认开）；取消只清倒计时、**保留**服务器记录 |
| 从未进过服务器 / 中途开启模块 | 中途开启会立刻补记录；确实无记录时断线播报「没有可重连的服务器记录」 | `recordCurrentServer()` 取 `getCurrentServer()`，为空则回落到 `getConnection().getServerData()` |
| 连接失败（连不上服务器） | 客户端会出现「连接失败」断线界面 → 再次调度，计数 +1 | 上限内自动重试，达到上限播报「已达到最大重连次数，自动重连停止。」 |

**不订阅 `DISCONNECT` 的理由**：该事件在「玩家主动退出服务器」时同样派发，用它触发重连会把主动退出也连回去；
断线界面只在真的掉线时出现，与旧项目自动登入的判据一致。

## 八、有意差异与登记项

1. **`autologin/service/ReconnectHandler` 删除两个只读方法**（`getLastAddress` / `getLastServerData`）：
   本项目全树零调用点，按「死代码可删」不搬；引擎内部仍持有这两项数据。见第三节末行。
2. **`AdminDisconnect` 的旧「断线前关第三方重连」改为抑制窗口**：旧那一步关的是第三方框架的
   `AutoReconnect`（本项目没有该对象）；改为 `ReconnectSuppression` 让「立即断线」仍然断得掉。
   行为目的相同，实现随本项目形态改变（该文件注释已同步改写）。
3. **自动登入的行为未受抑制窗口影响**：管理员检测的主动断线仍会让自动登入按它自己的逻辑重连
   （与旧项目一致 —— 旧实现只关第三方重连，不动自动登入）。如需把自动登入也纳入抑制，请明确裁示。
4. **本模块文案为自造**：旧项目没有这个模块，设置名 / 状态串 / 播报句式沿用自动登入同名字段的中文措辞，
   使用说明五章按其余模块的说明格式新写。登记为「新增功能的原创文案」，不是旧资产。
5. **不再保留「每步等待（tick）」之类的重名键问题**：本模块 6 个键各自唯一（自动登入那对重名键按 103 号
   登记维持原样，两者互不影响 —— 键名前缀/模块分区不同）。
