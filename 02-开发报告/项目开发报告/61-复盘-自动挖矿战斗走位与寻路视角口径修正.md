## 2. 视角：删除模块侧视角跟随（`MiningViewFollow` 整类删除）

### 2.1 根因（取证：Baritone 26.1.2 源码，非推测）

旧实现（上一批次落地的 `MiningViewFollow`，未提交）每客户端刻写一次 `setYRot / setXRot`，
它假设「Baritone 寻路时不写可见视角、所以模块必须自己写」。取证结论是这个假设只在走路场景成立：

| 场景 | Baritone 实际行为 | 源码依据 |
| --- | --- | --- |
| 挖掘 / 破坏 / 放置（`blockInteract=true`） | `freeLook=true` + `blockFreeLook=false` → 解析为 **CLIENT 模式**，**每刻把可见视角对准正在挖的方块**（含俯仰） | `LookBehavior.Target.Mode#resolve`、`MineProcess:127-131` |
| 平面走路（`blockInteract=false`） | `antiCheatCompatibility=true` → **SERVER 模式**：PRE 写朝向、POST 还原，本地视角不动（静默） | 同上 + `LookBehavior#onPlayerUpdate` |
| 破坏方块瞬态 | 死亡 / 存档 / 世界切换时清目标 | `LookBehavior#onWorldEvent` |

即：**挖矿时本来就存在两个写入者**（Baritone 的 CLIENT 写 + 模块的写），两边每刻互相覆盖，
这才是用户看到的「剧烈抖动」；走路时模块是唯一写入者，抖动另有来源（目标角度本身在跳）。
用户实测证据：`run/baritone/settings.txt` 里没有任何 `freeLook / blockFreeLook / antiCheatCompatibility`
覆盖项 → 走的就是上表默认值。

### 2.2 改动

- 删除 `feature/mining/fsm/MiningViewFollow.java`（整类）。
- `AutoMinerModule`：删 `import`、删 `viewFollow` 字段、删 `onTick` 末尾的 `viewFollow.tick(...)` 调用；
  类注释里补写本轮口径与上述源码依据；状态机规模说明由「11 态」改回「10 态」。
- 保留的写角度处（均为旧项目逐字移植或战斗需要，不在「挖矿 / 寻路视角」范围内）：
  - `MiningStateMachine#smoothRotateTo`（挂机修复点对准工作台，旧 `:1730-1748` 逐字）；
  - `MiningStateMachine#faceBlock`（卸货 / 补给开箱前面向箱子，旧 `:1750-1761` 逐字）；
  - `MiningCombat#turnTowards`（战斗时盯住怪；战斗期间 Baritone 移动朝向是 SERVER 静默，仍是唯一可见写入者）。

### 2.3 用户可见行为（待实机确认）

- 挖掘时：视角跟随镐子作业的方块，**上下（俯仰）也跟**——由 Baritone 自己完成，不再经本模块。
- 走路时：不再被模块强行转头（Baritone 默认行为），也就没有模块侧的抖动源。
- 战斗时：视角盯住怪物（本模块），与走路共用同一套「单一可见写入者」。

## 3. 苦力怕：删除 `EVADE` 撤离态，改「打了就退」走位

### 3.1 删除项

| 删除内容 | 原位置 |
| --- | --- |
| `MinerState.EVADE`（「撤离威胁」） | `MinerState.java` |
| `tickEvade()` 与 `case EVADE` 分派 | `MiningStateMachine.java` |
| `onStateEnter(EVADE)` 分支、`resumeInPlace` 里的 EVADE、播报 `COMBAT, EVADE` 合并分支 | `MiningStateMachine.java` |
| `preferEvade()`、`EvadeOutcome`、`tickEvade(...)`、`beginEvade()` | `MiningCombat.java` |
| 逃跑点搜索 `findEscapeSpot()` / `isSafeStanding()`、逃跑视角 `followEscapeView()`、
  相关常量（`CREEPER_EVADE_MAX_ROUNDS`、`CREEPER_SAFE_DISTANCE`、`EVADE_MAX_TICKS`、
  `ESCAPE_REPATH_INTERVAL`、`ESCAPE_THREAT_MOVE_SQR`、`FALLBACK_ESCAPE_DISTANCE`、`pathTo`） | `MiningCombat.java` |
| 死代码：`threatDetected()` 无参重载、`target()`（全项目零调用） | `MiningCombat.java` |

状态流转回到：`GO_WILD/MINING → COMBAT → MINING`。

### 3.2 苦力怕打法（`MiningCombat#tickCreeper`，按优先级）

| 序 | 条件 | 动作 | 依据 |
| --- | --- | --- | --- |
| 1 | `creeper.getSwellDir() > 0`（引信点燃） | 撤到 8 格（闪电苦力怕 12 格） | 原版 `SwellGoal:41-53`：距目标 > 7 格或失去视线即 `swellDir = -1`；`Creeper:126-148`：`swellDir < 0` 时每刻减 1 直至熄灭，满 30 刻才炸。且点燃期间 `SwellGoal#start` 调 `getNavigation().stop()`，它自己不动，后撤窗口安全 |
| 2 | 攻击冷却未满 | 拉回到 5 格等冷却 | 原版 `SwellGoal#canUse`：`distanceToSqr(target) < 9.0` 才点燃引信——3 格内贴着等冷却等于白给 |
| 3 | 冷却满但距离 > 3.2 | 按它的速度预判落点后贴近（`GoalNear` 2 格内即停） | 沿用原「动态预判」修正（不复走它当前位置） |
| 4 | 冷却满且在 3.2 格内 | 出手（原版 `gameMode.attack + swing`），并当刻挂上后撤目标 | 「打了就退」 |

其他怪物（`tickMelee`）行为不变：贴上去按攻击冷却砍，不躲、不撤（用户裁定血量不是理由）。

### 3.3 新增常量与节流

- `CREEPER_KITE_DISTANCE = 5`（出手后保持距离）、`CREEPER_DEFUSE_DISTANCE = 8`、
  `CHARGED_CREEPER_DEFUSE_DISTANCE = 12`、`RETREAT_MARGIN = 1`、`RETREAT_STOP_DISTANCE = 1`。
- 战斗寻路新增 `PathKind`（`APPROACH` / `KITE` / `FLEE`）+ `issuePath(...)`：
  同类型按 `REPATH_INTERVAL`(20 刻) 节流，**类型切换当刻立即下发**——
  引信点燃那一瞬要立刻从「贴近」切成「后撤」，等节流窗口人就站在爆炸范围里。
  后撤目标点按当刻实时坐标算（不再有「记住 20 刻前坐标」的问题）。
- 播报新增一条：`§e⚠ 苦力怕引信点燃 §8▸ 后撤熄灭`（键为「引信 + 怪物名」，与「发现」播报各自的冷却互不吞并）。
