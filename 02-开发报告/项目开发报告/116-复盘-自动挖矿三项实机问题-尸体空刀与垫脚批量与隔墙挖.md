# 116-复盘-自动挖矿三项实机问题（尸体空刀、岩浆垫脚逐块、隔墙挖）

日期：2026-09-19
项目：yiyiaddon（新项目，Fabric 26.1.2 客户端模组）
旧项目对应物：`D:/mcaddon/26.1.2` 自动挖矿状态机（耐久 / 战斗 / 垫脚 / 漏捡各分支；本项目在此之上有 2026-09-17 起的自建能力：战斗拦截、连锁挖矿、近矿清扫、垫脚铺设）

## 一、用户报的问题（原话）

1. 怪物已经死亡了还攻击怪物的尸体，空刀，要求修流畅度、加强判定逻辑；
2. 填岩浆时一块一块放，要求「一次性铺满，跟投影打印机那种」；
3. 有时候隔着墙就开始挖我选的矿石，怀疑是连锁挖矿导致掉落物留在墙后、又来回跑去捡，要求修成隔墙不挖。

三问确认（用户 2026-09-19 答复）：第 1 项按 bug 修；第 3 项口径取「禁止隔墙挖」（用户答复原文「静止隔墙挖就好了」，按「禁止隔墙挖」理解并已在对话中标注）；第 2 项取「一次铺一片（走绕行通道）」。

## 二、逐项取证与定性

### 2.1 空刀打尸体（本项目 bug，在挖矿战斗拦截）

- 先排除独立杀戮光环：`combat/target/TargetScanner.java:102` 已排除 `isDeadOrDying()` / 非存活实体，那边不会空刀。
- 真凶 `MiningCombat#findThreatForResolve`（原 `:285-289`）：候选谓词只有「未移除 + 非无敌 + 非坚守者 + 有视线」，**刻意不查活性**（原注释口径：只按实体存在性判）。客户端实体在血量归零后还留着约 20 刻死亡动画，这段窗口里 `isAlive()` 已是 false、`isRemoved()` 仍是 false → 被判定成「附近还有活怪」→ 重新锁回这具尸体 → `tickMelee` 继续 `swing` 空刀，且状态机被压在 `COMBAT` 态不回挖矿。

### 2.2 岩浆垫脚逐块（能力增强，非缺陷）

- `MiningStateMachine#tickLavaBridging`（原 `:1813-1830`）：`BRIDGE_PLACE_INTERVAL_TICKS = 3`，**3 刻一块**；一轮 16 块要站 2.4 秒。
- `BlockPlacer#placeAt` 走原版 `mc.gameMode.useItemOn`，其 `USE_ITEM_ON` 包要过「发包防踢」的放置限速（`AntiKickBypassModule#decideThrottle`，默认每秒 8 个，`AntiKickBypassSettings:113-115`）→ 单纯缩短间隔并不会真的变快。
- 项目既有口径（`ClientPacketSender` 类注释「谁能额外绕行」）：`platform/network/BlockPacketSender` 代表模块按任务节奏主动批量发起的交互，走绕行直发、不进限速判据。

### 2.3 隔墙挖（本项目 bug，在两处自建能力上）

- `MiningVeinMiner#sweepNearbyOres`（原 `:378-382`）与 `#scanVein`（原 `:490-501`）**只判距离**（`isWithinBlockInteractionRange`），墙后 3 格内的目标矿会被秒破；
- 秒破留下的掉落物落在墙后，`MiningStateMachine#findNearbyOreDrop`（原 `:1986-2014`）同样不判视线 → 被认领 → 停 mine 寻路去捡 → 来回路程，正是用户描述的「来来回回比较浪费时间」；
- Baritone 自身的 mine 会挖开路径去够矿（含穿墙挖通道），这部分属正常挖矿行为，不动。

## 四、影响面

- 只动自动挖矿模块与其依赖的平台层放置通道；无新增设置项、无新增指令、无落盘结构变更。
- `BlockPlacer` 是垫脚铺路与连锁封堵的唯一放置入口（第 169 条同源一份），两处都改走绕行直发；放置包不再受「发包防踢」的每秒 8 个放置限速约束（用户 2026-09-19 明确选择该口径）。
