## 6 有意差异（每条带理由）

| # | 差异 | 理由 |
| --- | --- | --- |
| 1 | 接管点由主线程事件改为网络线程规则；「可破坏性判定 + 入队」顺延到主线程下一刻 | 规则在网络线程，不能碰世界状态 → 0~1 刻延迟 |
| 2 | **AIM 模式的本地破坏预测未拦**（见 §7 待拍板 1） | 本次授权只允许改 3 个文件，无 mixin 改动空间 |
| 3 | 转发视图不含命中面 | 旧事件带 `direction`；本项目按「玩家→方块最近方向」求面（原版对破坏包不校验朝向） |
| 4 | 「目标方块」名单存方块 ID 字符串 | 对齐本项目既有 ESP 类模块做法（判定处用 `BuiltInRegistries.BLOCK` 还原） |
| 5 | 颜色落盘用 `EspColor` 四键，键名以旧设置名起头 | 本项目统一样式 |
| 6 | `EspStyle` 三选项文案保留旧模块自己的「仅线条 / 仅面 / 线+面」 | 逐字资产优先于 `ShapeMode.labels()` 的通用文案 |
| 7 | 渲染字号 `10f` / 线宽 `1.5f` | 旧框架默认值在本项目无对应物，取 `AdminThreatRenderer` / `VisionBlockRenderer` 同款 |
| 8 | 冲突运行时停机直接 `setEnabledSilently` | 旧实现经 `mc.execute` 重入 `toggle()`；语义等价、少一次重入 |
| 9 | **登记不修（3 条旧 bug 原样保留）** | ① `startAcknowledged` 只写不读；② `restoreSlotIfNeeded` 实为空操作（工具不会切回）；③ `sendStartNow` 的 `destroyDelta >= 1.0F` 近路只发 START 不发 STOP |

## 8 实机验证项

1. 瞄准模式挖软/硬方块各一块 → 能破坏、进度框与百分比正确。
2. 范围自动 + 白名单 → 只挖白名单、串行单槽、队列上限 64。
3. 自动换工具：最快工具在主背包时换到手上；挖完是否切回（**预期不切回，旧 bug**）。
4. 转向发包开/关 → 视角对准目标方块。
5. 与自动挖矿秒破同开 → 拒启（普通路径）+ 运行时巡检自动停机（两条文案）。
6. 单人世界开启 → 自动关闭并播报 `§c单人世界无需发包秒破`。
7. **ESP 总闸**：关「各模块 ESP → 发包秒破」→ 框与标签全部消失，重开恢复。
8. 设置落盘：改枚举 / 数值 / 开关 / 颜色 / 名单 / 标签内容各 1 项 → 重启仍生效。
9. `runClient` 启动无崩溃、日志含 `yiyiaddon initialised`；模块页、控制台、方块选择器、调色板可打开。
10. 服务器卡顿或拉回冷却期间不发包（受「服务器卡顿自停」控制）。
11. 弱网下 STOP 未 ACK → 最多重发 2 次后放弃并播报。
12. 离服/换服 → 队列、关注坐标、反馈全部清空。
