# yiyiaddon 第六阶段开发报告

日期：2026-09-14
阶段：第 06 阶段
主题：模块运行时、指令系统与第一个真实模块接入

---

## 一、本阶段目标

把已存在但内容为空的模块中心从展示状态升级为可运行的模块系统，建立所有后续模块共用的底层运行框架，并接入第一个真实模块验证整套框架。

本阶段交付的能力：

1. 模块运行时（注册、查找、开关、每刻派发、异常隔离）
2. 模块生命周期（初始化 / 启用 / 关闭 / 每刻 / 自检，含关闭清理）
3. 模块状态持久化（独立配置文件，不污染界面配置）
4. 统一事件入口（七个事件类型，模块声明式订阅）
5. 客户端指令系统（注册、中文提示、参数补全、错误提示）
6. 第一个真实模块：ID 识别与配置管理

本阶段不迁移任何业务模块，不做界面美化，不改第五阶段已迁移代码的结构。

1. `ModuleRegistry.register` 除示例条目外没有真实模块注册，模块中心无实际内容。

## 五、模块系统设计

### 5.1 分层

```
界面（模块中心 / 模块列表 / 模块页面）
        ↓ 只读 ModuleEntry
module/ModuleRegistry（注册表，1 个事实来源）
        ↑ 注册
core/module/ModuleEntries（模块 → 条目的唯一转换点）
        ↑
core/module/ModuleManager（运行时：注册 / 开关 / 持久化 / 派发 / 隔离）
        ↑ 继承
feature/<模块>（业务模块，只实现自己的功能）
```

模块中心、模块列表、模块卡片、快捷键、指令都不认识具体模块类：新增模块只改 `AddonModules.createModules()` 一处。

### 5.2 模块基类能力边界

| 类别 | 模块负责 | 运行时负责 |
| --- | --- | --- |
| 元数据 | 声明 ID、名称、分类、图标、权重、版本 | 转换为模块中心条目并注册 |
| 生命周期 | 实现 `onInitialize` / `onEnable` / `onDisable` / `onTick` / `selfCheck` | 调用时机、异常捕获、状态写回 |
| 事件 | 用 `subscribedEvents()` 声明类型，在 `onEvent` 处理 | 订阅、退订、去重、异常归属 |
| 设置 | 在 `loadSettings` / `saveSettings` 里做字段编解码 | 读写文件、原子写、失败回滚 |
| 界面 | 提供 `page()` | 页面路由与压栈 |
| 指令 | 提供 `commands()` | 注册与派发、异常兜底、补全 |

模块禁止自行注册 Fabric 事件、自行读写文件、自行吞异常。

### 5.3 异常隔离

| 环节 | 出错后的处理 |
| --- | --- |
| 初始化 | 记录日志，标记永久不可用，模块不再出现在模块中心（不发布条目），启动继续 |
| 自检 | 按缺项处理，不启用 |
| 启用 | 捕获异常 → 中文播报 → 自动关闭 → 状态写回未启用 |
| 每刻 | 捕获异常 → 中文播报「运行异常，已自动关闭」→ 强制关闭 |
| 事件回调 | 由事件总线按所有者归属到具体模块 → 中文播报 → 强制关闭 |
| 关闭 | 异常仅记录，不影响状态写回 |

初始化失败与启用失败的模块 ID 分别记入不可用集合与等待队列，不会每次启动重复报错。

### 5.4 状态持久化

新增 `config/module-state.json`，与界面配置 `yiyiaddon.json` 完全分离：

```json
{
  "模块": {
    "identity": {
      "启用": true,
      "快捷键": -1000,
      "设置": { "识别模式": "CHAT_AUTO", "详细输出": true }
    }
  }
}
```

- 写入走 `repository/JsonFileStore.writeAtomic`（临时文件 + 原子替换），复用第五阶段的存储规范。
- 字段缺失按默认值、类型不符按默认值、文件损坏按默认值，且不删除原文件，不阻断启动。
- 快捷键与界面快捷键分家：界面配置重置不会清掉模块开关与模块快捷键。

## 六、生命周期设计

### 6.1 调用时序

```
客户端初始化
  AddonModules.bootstrap()
    ├─ 注册分类
    ├─ EventDispatcher.init()          注册七个事件来源（唯一注册点）
    ├─ ModuleManager.bootstrap(模块列表)
    │    ├─ 载入 module-state.json
    │    ├─ 逐个 onInitialize()        失败 → 永久不可用
    │    ├─ 发布 ModuleEntry 到模块中心
    │    ├─ 注册模块自带指令
    │    ├─ 订阅运行时事件（每刻 / 进服 / 断线）
    │    ├─ 装配模块快捷键存储与触发回调
    │    └─ 恢复启用状态
    └─ CommandManager.bootstrap()      注册内置指令 + 接管聊天输入
```

### 6.2 状态恢复与等待队列

本阶段实测发现：进服事件早于玩家实体完全就绪，若只在进服那一刻尝试启用，自检会持续失败。因此启用恢复定义为一台三态机：

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| 成功 | 条件满足 | 启用并写回 `启用 = true` |
| 条件未满足 | 自检返回缺项 | 进入等待队列，**不写回状态**；进服事件与每 20 刻各重试一次 |
| 失败 | 初始化失败或启用过程抛异常 | 写回 `启用 = false` |

这样「上次开着、下次启动时还在主菜单」不会把玩家的开启状态抹掉；条件满足后自动开启并中文播报。

### 6.3 关闭清理

关闭时按所有者一次性退订全部事件、调用 `onDisable` 清理运行态、写回 `启用 = false`。模块的 `onDisable` 必须可重复调用。

## 七、事件系统设计

### 7.1 七个事件与来源

| 事件 | 来源 | 线程 |
| --- | --- | --- |
| 每刻 | `ClientTickEvents.END_CLIENT_TICK` | 主线程 |
| 进服 | `ClientPlayConnectionEvents.JOIN` | 主线程 |
| 断线 | `ClientPlayConnectionEvents.DISCONNECT` | 主线程 |
| 打开界面 | `ScreenEvents.AFTER_INIT` | 主线程 |
| 关闭界面 | `ScreenEvents.remove(screen)`（按界面实例注册一次） | 主线程 |
| 收到数据包 | Mixin `Connection#channelRead0` → 队列 | 网络线程入队，主线程派发 |
| 发出数据包 | Mixin `Connection#send(Packet, ChannelFutureListener, boolean)` → 队列 | 同上 |

### 7.2 三条设计约束

1. **唯一注册点**：Fabric 事件只在 `EventDispatcher` 注册；模块通过 `subscribedEvents()` 声明，运行时负责订阅与退订。
2. **按所有者去重**：订阅表按 `module.<模块ID>` 归类，重复启用直接覆盖，关闭时整批退订，结构上排除重复监听。
3. **收发包不跨线程回调模块**：网络线程只把「方向 + 包类名」入队（队列上限 4096，溢出计数丢弃），主线程每刻最多出队 512 条后派发。包对象不进入事件载荷，模块拿不到也不持有游戏内部对象。

派发顺序固定：先出队数据包（按实际发生顺序），再派发每刻事件。

### 7.3 异常归属

事件监听抛异常时，总线按所有者回调失败处理器，运行时据此定位模块并执行「中文播报 + 自动关闭」，同时写日志。单个监听异常不影响同事件的其他监听。

## 八、指令系统设计

### 8.1 形态

自研客户端指令系统，不依赖原版命令树、不需要服务端支持：整条指令在客户端拦截并本地执行，不产生网络流量。前缀沿用 `.`（满足后续 `.id`、`.fumo` 等接入）。

拦截方式是 Fabric 的聊天发送事件 `ClientSendMessageEvents.ALLOW_CHAT`，不注入原版界面。以 `.` 开头的消息（含未知指令名）一律拦下并给出中文提示，避免误发到服务器。

### 8.2 已实现指令

| 指令 | 别名 | 子命令 |
| --- | --- | --- |
| `.help` | `h`、`帮助` | 无参数列出全部指令；带参数显示别名与用法 |
| `.module` | `m`、`模块` | `list [分类]`、`on <模块>`、`off <模块>`、`toggle <模块>`、`status <模块>` |
| `.id` | `identify`、`识别`、`身份` | 无参数按识别模式识别、`item`、`block`、`entity`、`stat`、`mode [模式]` |

模块可用模块 ID、英文名或中文名指定；中文名支持包含匹配，找不到时列出全部可用 ID。

### 8.3 补全

`CommandManager.applyTabCompletion` 实现两级补全：第一级补全指令名（含中文别名），第二级把候选交给指令自己声明的 `complete(context)`。

- 唯一候选：直接补全并追加空格。
- 多候选：补到公共前缀；无法推进时在聊天栏列出候选（最多 30 项）。
- 聊天框内按 Tab 生效，由 `ChatScreenCompletionMixin` 在文本以 `.` 开头时接管；原版补全只响应 `/` 开头输入，正常聊天与服务器指令的 Tab 行为不受影响。

### 8.4 错误处理

参数缺失给用法提示、未知子命令给子命令提示、未找到模块给可用 ID 列表、执行抛异常由 `CommandManager` 兜底并打印异常类型与消息。全部中文。

| 输出统计 / 清理失效目标 | 聊天栏输出统计；清理选中项中已不存在的身份引用 |

### 9.3 与第五阶段代码的关系

第五阶段代码零改动、只调用：识别走 `ItemIdentifier` / `BlockIdentifier` / `EntityIdentifier`，存储走 `IdentityService`，目标选择走 `IdentityTargetConfig`，路径走 `GamePaths`，存储规范走 `JsonFileStore`。模块自身只做编排、展示与中文回显。

### 9.4 事件订阅

订阅 `JOIN_SERVER`：进服后重新读盘并清理失效目标。理由是身份库以磁盘为唯一事实来源，长时间不重载会残留上一台服务器的失效项；这是对第四阶段扫描发现的「跨服状态残留」问题的正面处理。

## 十一、发现的问题

### 11.1 本阶段发现并已修复

1. **进服事件早于玩家就绪**：只在 `JOIN_SERVER` 时刻恢复启用状态会漏开模块。修复：改为三态恢复 + 等待队列 + 每 20 刻重试（第六节 6.2）。
2. **等待队列不得写回状态**：条件未满足时若按旧逻辑写回 `启用 = false`，玩家在主菜单启动一次就会丢失开启状态。修复：只有真正的失败才写回关闭。

### 11.2 本阶段发现、未修复（不在本阶段范围）

1. **`ItemIdentity.isCustom()` 把 `item_name` 组件当作自定义证据**：26.1.2 中原版物品也带该组件，实测 `minecraft:grass_block` 被判为「自定义 / 原版物品」标签错误（见 10.5 落盘 JSON）。属第五阶段模型语义问题，按本阶段禁止修改第五阶段代码的要求未动，建议后续阶段评估。
2. **`ModuleEntry` 与 `Module` 的元数据双份**：`ModuleEntry` 由 `Module` 转换而来，字段是副本而非引用；目前只读且转换点唯一，暂无风险，但未来若允许运行时改元数据会出现不一致。

### 11.3 观察到的环境问题

1. 并行编辑导致的两个文件一度编译失败（见 2.4、10.1）。多人同时改同一目录时，编译失败的责任归属需要靠分析错误文件位置判断，建议重要阶段验证期间冻结编辑。

## 十二、下一阶段开发规划

### 一、目标

完成指令系统与事件系统的运行期验证，并把资源链路从「有框架无实现」推进到「可真实解析」：实现资源内容探针，使服务器资源包检测与方块语义识别在真实多人服务器上产生可用结果。

### 二、原因

1. 本阶段新增的指令系统（`.help` / `.module` / `.id`）与聊天框 Tab 补全、快捷键按键触发均未在运行中验证，只有代码路径与绑定持久化被验证。这些是后续所有模块的文本入口，必须先证明可用，否则会在每个模块接入时重复排查同一问题。

3. 方块语义识别（`BlockStateModelResolver`）已接入 `BlockIdentifier`，但「已确认 / 未知」两类结果的比例从未在真实服务器上统计过；资源探针实现后才能评估其可用性，这是后续星露谷与农场类模块的前提。
