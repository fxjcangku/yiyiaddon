## 2 三处框架适配（对应 96 号 C1/C2/C3）

### 2.1 发包拦截：同步判据，不是事件（C2）

旧框架把待发包对象交给模块，模块当场 cancel / 改包。新架构明令禁止模块持有包对象，且事件在主线程派发（届时包已发出）。因此落地为：

```
Connection.send(HEAD, 网络线程)
  → SendInterceptor.intercept
      → 绕过？(核心直发)               → 放行
      → 无规则？                        → 入队观测 + 放行（保持原行为）
      → 构造 SendView → SendGate.evaluate(规则链)
          PASS          → 入队观测 + 放行
          CANCEL        → 丢弃；聊天消息把原文入队交接（CLIENT_CHAT）
          REPLACE_INPUT → 丢弃原包 + 直发改写后的输入包
          DELAY         → 丢弃原包 + 入延迟队列（到期主线程直发）
```

* **架构边界保持**：模块只拿到 `SendView`（不可变只读视图），只能回 `SendDecision`；包对象始终留在核心。
* **线程契约写进 `SendRule` 的 javadoc**：禁阻塞、禁派发事件、禁保存视图；规则抛异常一律吞掉并放行。
* **死锁免疫**：核心直发与延迟重发走 `PacketSendBypass`（ThreadLocal 计数），不会被自己刚注册的规则二次拦截。
* 覆盖三件套全部用例：Brand 伪装 / 频道拦截 / 假潜行 / 假疾跑（改写输入）/ 聊天排队 / 挖掘限速 / 放置限速 / 网络延迟 / 移动包豁免。

### 2.2 收包快照：按关注坐标筛选（C1/C2）

* `SERVER_POSITION` 扩字段 `playerDistance`：拉回判定要用的距离在**收包同刻**（网络线程）算好，避免主线程晚一刻导致基准漂移（旧实现在网络线程读玩家位置）。
* `SERVER_BLOCK`：`BlockWatchService` 登记关注坐标后，只对命中的方块更新派发快照；区块批量包不会逐条展开（否则一个包上千条事件会淹掉主线程）。序列号 ACK 与坐标无关，无条件派发。
* `SERVER_CHANNEL`：自定义负载频道 id，原版 `brand` / `register` / `unregister` 在核心侧剔除（与旧实现一致）。
* 指令树**不派发**：服务器检测直接读 `connection.getCommands()`（96 号 D-18-03）。

### 2.3 常驻订阅（C3）

`TacticalCoordinator.init()` 以固定所有者 `core.tactical` 订阅 `TICK` / `JOIN_SERVER` / `DISCONNECT` / `SERVER_POSITION`。`ClientEventBus` 是全局广播、与模块开关无关，因此常驻语义与旧静态自挂完全一致，且**不新增任何 Fabric 注册点**（核心事件注册仍只在 `EventDispatcher`）。

会话重置：旧 `SessionResetEvent` 由协调器发布、模块订阅；新架构下模块直接订阅 `JOIN_SERVER` / `DISCONNECT`（各清各的，顺序无关），协调器自清由同一对事件触发——语义等价，且不扩充核心枚举。

模块侧通知改为 `TacticalCoordinator.Listener` 回调（`onRubberBand` / `onAntiCheat`），模块启用时注册、关闭时注销。

## 3 与旧项目的**有意差异**（登记，非缺陷）

| # | 差异 | 理由 |
| --- | --- | --- |
| 1 | 被闸门取消的包**不再派发** `PACKET_SEND` 观测事件 | 新架构里「没发出去」就不该通知；旧实现在 cancel 前已派发过一次。为不丢信息，被拦下的聊天消息改用 `CLIENT_CHAT` 交接原文（模块据此排队重发） |
| 2 | 新增 `CLIENT_CHAT` / `SERVER_BLOCK` / `SERVER_CHANNEL` 三个事件类型 | 旧框架用「模块直接读包体」和「模块自定义总线事件」实现；新架构的等价物是核心只读快照 + 核心枚举 |
| 3 | 模块通知从总线事件改为 `TacticalCoordinator.Listener` 回调 | 不为业务事件扩充核心枚举（第 89/92 条：核心只保留通用事件类型） |
| 4 | 延迟队列的漂移精度 | 仍为 5ms 轮询（逐字照旧），未退化为主线程 1 刻粒度 |
