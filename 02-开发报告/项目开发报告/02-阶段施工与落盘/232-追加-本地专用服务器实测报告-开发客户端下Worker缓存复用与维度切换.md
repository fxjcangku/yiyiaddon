### 3.2 远端区块（区块 -400,380 = 37）与缓存累积

玩家用 OP 命令传送到 `(-6399.5, 100, 6080.5)` → 区块 **(-400, 380)**，该区域是**服务器此前从未生成过的新区域**（小地图显示「积雪针叶林」，画面正在逐块加载）。

```
[14:55:26] (yiyiaddon/seed) 种子挖矿：提交预测 种子 20260922 区块 (-400,380)
[14:55:27] (yiyiaddon/seed) 种子挖矿：预测成功 种子 20260922 区块 (-400,380) → 37 个（调度敏感 0 / 未解析 37 / 确定性 0），
                                      耗时 1140 ms，缓存区块 1058，宿主 ChunkMap 查询 0（必须为 0）
[14:55:27] (yiyiaddon/seed) 计算器诊断 状态=已就绪；PID=12780；会话=s1-135283a；启动次数=2；预测次数=3
```

关键点：

- **Worker 没有重启**（仍是 PID 12780、启动次数仍 2、会话仍 `s1-135283a`）→ 同一会话跨区块复用；
- **离线缓存累积**：529 → **1058**（新增目标所需的邻居区块被并入同一缓存）；
- **耗时只有首次的一半**（1140 ms vs 2203 ms）→ 先前缓存被真正复用；
- **宿主 ChunkMap 查询 0** → 没有借「玩家已在远地」偷看宿主真实区块。

> ⚠️ 数字口径提醒：这里是 **seed 20260922** 下的 `(-400,380) = 37`。
> 它与冻结回归里 **seed 2** 的 `(-400,380) = 23 / 1 / 22 / 0` **不是同一个用例**，两者不可互相对照。

### 3.5 退出世界 / 客户端退出：Worker 回收，零残留

**（a）退出世界**（测试中我为启用 OP 重启了服务器，导致客户端掉线）：

```
[14:48:54] (yiyiaddon/seed) 种子挖矿：停止本地世界生成计算器（原因：退出世界）
[14:48:54] (yiyiaddon/seed) 种子挖矿：已离开世界，计算结果已清除、计算器已停止（配置保留）
[14:48:54] (yiyiaddon/seed) 种子挖矿｜Worker：已发送停机指令（PID 10024）
[14:48:54] (yiyiaddon/seed) 种子挖矿｜Worker：本地世界生成计算器已停止（PID 10024，退出码 0）
```

进程核对：PID 10024 消失。随后客户端自带「自动重连」模块 5 秒后自动回服（`已重新连接成功`），回到世界后一切正常。

**（b）客户端退出**（本次用 Gradle 任务强制停止客户端进程，相当于「强杀」而不是点退出按钮）：

- 客户端进程消失后，**Worker 进程（javaw PID 12780）同样消失**；
- 最终残留扫描：`无 CLIENT / SERVER / WORKER 进程残留`（服务器随后也单独停止）。

说明 Worker 的父进程看护（watchParent）在**非优雅退出**路径下也能收口，不留孤儿 Java 进程。

逐条对应 232 口径：

1. **只接本机**：`客户端已连接（来自 /127.0.0.1）`；
2. **宿主不开公网/不接客**：`宿主监听 已停用（不接受任何外部连接）`；
3. **Worker 侧与客户端侧数字完全一致**（45/37/45，缓存 529/1058/1058）→ IPC 无信息损耗；
4. **空闲不空转**：`Server empty for 60 seconds, pausing` → 宿主在无请求时自我暂停，说明没有无关 tick / 玩家模拟在烧 CPU；
5. **往返开销极小**：Worker 侧往返与本地耗时几乎相同（2223 vs 2203、5 vs 5），IPC 不是瓶颈。

## 六、测试中遇到的（与本模组无关的）环境问题

为让后续复现者少踩坑，如实记录：

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 首次 quickPlay 连服被拒，界面显示「无法连接至服务器 / **客户端不兼容！请使用 26.1.2**」，服务器端**连握手都没收到** | 客户端 `ViaFabricPlus` 的 `config/viafabricplus/settings.json` 里 `"selected-protocol-version": "1.21.11"`（此前为玩其它服选的），导致客户端以 1.21.11 协议号连接 26.1.2 服务器 | 备份为 `settings.json.232test-bak` 后移除该字段（回到原生 26.1.2）。**与 yiyiaddon / Worker 完全无关**（这条链路上线都没建立） |
| 2 | 按 `T` 打不开聊天栏，屏幕底部出现「骑视：已禁用」 | 该客户端内其它 Mod 占用了 `T` 键 | 改用 `/` 键打开聊天栏（Minecraft 原生快捷键） |
| 3 | UI 自动化无法用 `type_text` 往种子输入框打字 | 该输入方式走 UI Automation，Minecraft 只吃键盘/字符回调 | 改用「剪贴板 + `Ctrl+V`」——yiyiaddon 的 `SettingTextBox` 原生支持粘贴 |
| 4 | 想进下界必须传送，但默认无 OP | 测试服务器 `ops.json` 原为 `[]` | 写入 `yiyijia`（level 4）并重启服务器；**属测试环境改动，可在复现后还原** |
| 5 | 服务器重启导致客户端掉线 | 环境操作 | 客户端自带「自动重连」模块 5 秒后自动回服（顺带验证了「退出世界 → 计算器回收」） |

> 前置提醒：种子输入框的**可点击区域是控件本身（220 设计像素宽）**，不是整行玻璃背景；点击行左侧空白不会进入编辑态。对正常玩家鼠标点击无影响（框内点即可），但自动化脚本需要点控件区域内。

**结论：在开发者的真实日常客户端（100+ Mods）里，人工点击路径下，数字与冻结口径逐项一致，没有出现「开发装置能过、真实客户端不成立」的情况。**

## 九、结论

1. 在**日常开发客户端 + 本机专用服务器**的真实环境下，种子挖矿的多 Worker 闭环**完全成立**：
   进服即可用、点按钮就出结果、数字与冻结口径逐项一致；
2. **缓存复用确实是设计的效果**：先 529 → 1058 累积，再对同一目标复预测**不增长且 5 ms 命中**，
   Worker 进程 / 启动次数 / 会话编号全程不变；
3. **维度切换收口正确**：下界不支持 → 不启动 Worker、清空结果、禁用按钮；回主世界自动恢复、种子保留；
4. **无孤儿进程**：优雅退出（退世界）与强杀退出（客户端被强杀）两条路径都收干净；
5. **网络与隔离面继续保持**：Worker 只接受来自 `127.0.0.1` 的连接，宿主就绪后监听停用，
   宿主空闲 60 秒自动 pause，Host ChunkMap 查询恒 0；
6. 本次唯一「失败」来自客户端自身的 ViaFabricPlus 协议版本设置，与本模组链路无关（连握手都未建立）。

**判定：本轮本地服务器实机验收通过**，可作为 233 阶段的性能与行为基线（相邻目标复用 ≈ ms 级、新目标 ≈ 1.1 s、冷启动 ≈ 4.2 s、常驻约 476 MB）。
