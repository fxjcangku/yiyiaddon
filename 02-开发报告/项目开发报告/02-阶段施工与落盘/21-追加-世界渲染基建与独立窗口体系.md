## 二、交付清单

### 2.1 世界渲染基建（`ui/render/world/`，11 个类）

| 类 | 职责 |
| --- | --- |
| `ShapeMode` | 绘制模式：`线框` / `面` / `两者`（标签逐字取自旧项目 `stardew/render/EspShapeMode`） |
| `Dir` | 六个面方向的位掩码与「棱归属两面」的剔除判定 |
| `ColorPresets` | 九色预设（红 / 绿 / 蓝 / 青 / 黄 / 紫 / 白 / 橙 / 黑）与默认填充透明度 |
| `EspColor` | 唯一颜色载体：预设色 / 自定义色 / 彩虹 / 彩虹速度 / 相位偏移 |
| `Rainbow` | 彩虹色相计算（绘制瞬间按单调时钟取样） |
| `RenderCamera` | 单帧相机快照：位置 + 视图×投影矩阵 + 屏幕尺寸 |
| `ScreenPoint` | 投影结果（GUI 缩放坐标 + 可见性 + 齐次深度） |
| `WorldProjector` | 世界坐标 → 屏幕坐标，含手写近平面线性裁剪 |
| `EspRenderer` | 绘制入口：框 / 面 / 线 / 双色渐变线 / 射线 / 世界坐标文字 / 遮挡开关 |
| `Visibility` | 「被方块挡住」的体素射线近似判定 |
| `WorldOverlay` | 层注册中心与每帧渲染入口 |

### 3.2 本轮修复的缺陷

1. **世界叠加层完全不出图**。`WorldOverlay` 使用无参 `SkiaGlBackend.begin()`，即画到 Framebuffer 0；而此刻真正呈现的是主 RenderTarget，其内容在帧末被 `blitToScreen` 整体覆盖，表现为「层注册数正常、画面什么都没有」。已改为显式传入 `SkiaGlBackend.mainFramebufferId()`，并写入铁律第 144 条。
2. **`PanelScreen` 滚动从未生效**。此前只做裁剪、未平移内容，滚动偏移量从未被使用，超出视口的内容永远看不到（使用说明窗四章下半部分不可见）。已改为「宿主并入 y」口径，与既有页面统一，并写入铁律第 155 条。
3. **拖动未锁定按下元素**。`CompactStack.onDrag` 按当前鼠标位置重新查找元素，导致拖色相条会改到饱和度面板。已改为按下时锁定元素，并写入铁律第 157 条。
4. **单层异常被静默吞掉**。`WorldOverlay` 原先空 catch 所有 `Throwable`，任何层出错都无痕迹。已改为同一层只上报一次的错误日志。

### 3.3 未关闭的问题

1. **ID 三件套缺 `选择目标物品` 选择器 UI**。数据层 `config/identity/IdentityTargetConfig` 已完整（选择持久化、`pruneInvalid`、计数文案与旧项目一致），但**没有打开选择窗的入口**；旧项目 `itemid/ItemTargetSelectScreen`（99 行，双栏多选）在新项目没有对应物。铁律第 136 条把 `选择目标物品` 列为必须逐字对齐的按钮文案，该按钮当前尚不存在。**2026-09-14 补充定性（更正）**：ID 三件套**包含自动箱子的目标选择链**，二者是设计上的正向联动而非耦合缺陷——旧项目 `IdIdentifyModule.java:35-36`「产出的 ID 供「ID 配置管理」与「自动箱子」消费」、`AutoChestModule.java:50-51`「目标物品统一来自「ID 配置管理」（ItemIdManager），本模块只消费」、`AutoChestSettings.java:191-195` 直接以 `ItemTargetSetting` 承载「目标物品」配置项。因此该按钮**不是可选装饰，而是「ID → 自动箱子」消费链的断点**（契约见《基准-05》§0.8）。
2. **星露谷作物语义按口径排除**。旧项目 `itemid/IdCommand`、`IdIdentifyModule`、`IdResultScreen`、`worldblock/BlockResultScreen` 四处引用 `stardew/recognition/CropRuntimeStateResolver`，用于展示「所属作物 + cropKey + 类型 + 生长中 / 成熟」。这是**下层反向依赖上层**的结构倒挂：身份识别是通用底座，星露谷只是消费方。本轮按既定口径未迁移该块，结果窗与指令中相应分区缺失，待以 `IdentitySemanticProvider` 插口在第 09 阶段接入。

4. **验证口径冲突未定案**。第 07 阶段报告称「第六阶段列为未验证的指令、Tab 补全、快捷键触发三类已转为实际功能验证通过」；《用户交互资产迁移规范报告》则称「指令系统、模块快捷键、资源检测、指令前缀四项仅做过编译与静态核对，端到端实机验证尚未完成」。两份报告结论相反，且均无可追溯的实测证据。本轮以「未完成端到端实机验证」为准，待第 08 阶段实测后定案。
