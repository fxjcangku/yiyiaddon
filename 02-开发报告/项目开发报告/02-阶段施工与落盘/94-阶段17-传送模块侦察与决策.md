### 3.2 三模式算法要点（施工逐行搬，常量逐字）

**GROUND（`SurfaceScanner.scan`，98 行）**
1. 起点取当前格 `fx=floor(x)` / `fz=floor(z)` / `startY=floor(y)`；`CollisionSafety.areaLoaded` 不通过 → `脚下区块数据未加载`。
2. 当前格 `canSeeSky(BlockPos) && subject.checkStand(...) == null` → `rise=0`（决策层据此 `skipExecute`）。
3. **优先向下**：`startY-1 → level.getMinY()`，首个通过者即落点（`rise` 为负）。
4. **再向上逐阶段**：`top = min(startY + maxRise, level.getMaxY() - 1)`；`findStageAbove` 先跳过当前空腔（`subject.hasSpace`）到天花板，再找首个 `checkStand == null` 的格；**阶段目标不看 `canSeeSky`**（矿洞/空腔也算阶段），只有第 2 步的「已在真正地表」判据用 `canSeeSky`。
5. 全败 → `上方未找到可站立阶段空间（可增大地表扫描上限）`。

**WALL（`WallRayScanner.findLanding`，155 行；常量 `STEP=0.5` / `START=2.0` / `DEVIATION_WEIGHT=100.0`）**
- 输入是**触发瞬间锁定的视线快照**（`rayOrigin` = `player.getEyePosition(1.0F)`、`rayDir` = `player.getViewVector(1.0F)`、`eyeHeight`）；缺失 → `视线快照缺失，请重试`。
- 第一阶段：从 `START` 起按 `STEP` 采样，定位第一道障碍的**出口**并统计穿透层数（`layers` / `anyObstacle` / `obstacleRuns` / `exhaustedInsideSolid` / `reachedUnloaded`）。
- 第二阶段：出口后采样，评分 `deviation * 100.0 + max(0.0, ahead)` 取最小者（方向一致优先、沿射线近者优先），含 `maxFall` 内竖直下落。
- 主路无候选时按原因回执：`前方世界数据未加载，扩大搜索前请先走近` / `障碍太厚，超出最大穿墙距离`；否则用 `SafePositionFinder` 在 `maxDeviation` 半径内做局部修正（约束 `minAhead = WallRayScanner.START` + 准星偏离上限 + 必须沿射线前进），失败 → `准星方向的落点修正范围内没有可站立位置`。

**COORD（`TeleportCoordinator:258-276`）**
- 目标点 = `new Vec3(x + 0.5, y, z + 0.5)`（键位与指令同一算法）。
- `subject.checkStand` 通过 → 直接落点（`standPos` = 所在格，`deviation = 0`）。
- 不通过 → `SafePositionFinder`（半径 `回退搜索半径`，`0` = 不回退），失败 → `目标坐标不安全，邻近搜索无可用落点`；成功则播报附加 `已修正至邻近安全点`。

**执行前二次校验 `recheck`（`:297-312`）**：维度 / 存活 / 目标非空 / **重新取 `TeleportSubject.of(player)` 再 `checkStand`**（不用搜索阶段缓存的碰撞箱），任一失效 → `传送前世界已变化，已取消执行` / `传送前玩家状态异常，已取消执行` / `目标缺失，已取消执行` / `目标区域已变化（<原因>），已取消执行`。

**执行 `PositionExecutor.execute`（71 行）**
- 本体：`absSnapTo(x, y, z, yRot, xRot)` + `ServerboundMovePlayerPacket.Pos(x, y, z, true, false)`（**onGround 恒 true**，安全判据已保证脚下有真实支撑；horizontalCollision 恒 false）。
- 摔落无伤（本体）：`resetFallDistance()` → 发 `(x, y, z, false, false)` → 再发 `(x, y+0.001, z, false, false)` → 本地 `absSnapTo(y+0.001)`，`ctx.expectedPos = (x, y+0.001, z)`。
- 载具：`getRootVehicle()` 必须 `isLocalInstanceAuthoritative()`（否则 `当前乘坐的载具无法由客户端传送`）；保持乘客相对偏移不变整体平移，`absSnapTo` + `ServerboundMoveVehiclePacket.fromEntity`，`expectedPos = 载具目标坐标`。
- 载具 + 摔落无伤 → 直接拒绝：`乘坐载具时服务端没有安全的下落累计重置路径，请先下车再使用摔落无伤传送`。

**验证（`TeleportCoordinator.tick` + `RubberbandVerifier`）**
- 执行后 `verifyEndTick = level.getGameTime() + verifyWindow`；tick 中维度变化 / 死亡 / 载具关系变化 → 中止（`传送期间世界变化，已中止` / `传送期间玩家死亡，已中止` / `传送期间载具关系变化，已中止`）。
- 权威包分类：`ClientboundPlayerPositionPacket` → `PositionMoveRotation.calculateAbsolute(PositionMoveRotation.of(player), p.change(), p.relatives()).position()`；`ClientboundMoveVehiclePacket` → `v.position()`；距离 ≤ `verifyThreshold` → `CONFIRM`，否则 `RUBBERBAND`（记录 `rubberbandPos` / `rubberbandDist`）。
- 窗口超时无包 → `success()`（视为服务端接受）。
- 忙时重复触发（节流 20 tick）：`执行中 ▸ 上一次传送尚未结束，请稍候`；死亡：`传送失败 ▸ 死亡状态下不可传送`。

### 3.3 状态机与生命周期

- 状态：`IDLE → OBSERVE → DECIDE → EXECUTE → VERIFY → SUCCESS / FAILED`（`TeleportState` 七态）。
- 触发入口（三键 + `.tp`）→ `build(req)` 打包 15 项参数 → `coordinator.request(player, level, req)`。
- 结束：`finish()` 把 `active` 移交 `last`（调试渲染复用），`active = null`。
- 模块关闭（`onDeactivate:271-275`）：`coordinator.cancel("模块已关闭，传送中止")` + `coordinator.clear()`（清 `active` / `last` / 状态）。
- 已在地表无需移动（`completeNoMove`）：`§a✓ 已在真正地表 ▸ 无需传送`。

| 联动范围（关键） | **不是传送一个模块的能力**：战术绕过三件套（`FlightBypass` / `AntiKickBypass` / `PacketInstantBreak`，含 `ServerDetector`）在旧项目里由 `TacticalCoordinator` 消费**同一个包、逐字相同的换算**（证据见 §1.4 第 1/2 行），故本事件按**四模块共用底座**设计 |
| 拟做法 | 新增 `SERVER_POSITION` 事件 + 新 mixin 注入 `handleMovePlayer` / `handleMoveVehicle` 的 HEAD，在**平台层完成唯一一次**绝对坐标换算（`PositionMoveRotation.calculateAbsolute`）后入队，派发只读坐标；阈值裁决（传送 `verifyThreshold` 1.5 / 战术 10 格）各自持有，模块仍拿不到包对象（与既有 `SERVER_TEXT` 同一手法） |
| 影响面 | 核心 3 文件改动 + 1 新 mixin + 1 行 mixins.json；不改任何既有模块行为。阶段「战术」迁移时直接复用该派发，**不得另写换算**（第 169 条） |

**D-17-02 常驻功能键通道（模块关闭时也要能提醒）**

| 项 | 内容 |
| --- | --- |
| 旧项目对应物 | `KeybindSetting` ×3（`action` 在**松开**时触发）+ [KeyRemindListener.java](file:///d:/mcaddon/26.1.2/src/main/java/com/example/addon/teleport/remind/KeyRemindListener.java)：进构造器即挂常驻总线，监听 `KeyAction.Release`（键盘 + 鼠标，`EventPriority.LOW`），**节流为全局单一时间戳 3 秒**（`:77-82`，任一键提醒后三键都不再提醒），是否提醒由回调方 `isActive()` 裁决 |

| 两路语义（禁混） | **模块开启** → 功能键触发传送（模块自身 tick 边沿检测，等价旧 `action`）；**模块关闭** → 功能键只播报提醒（`KeyRemindListener` 等价物）。旧实现里提醒监听器只读绑定值、**不触发 action** |
| 拟做法 | 新增 `ui/keybind/FunctionKeybinds`：模块注册 `Supplier<AddonKeybind>` + 回调，核心每刻轮询**松开边沿**；节流口径**照旧项目 = 全局单一 3 秒窗口**（不是按键各自节流）；由既有 tick 调用点驱动，**不新增 Fabric 注册点** |
| 规则依据 | 第 215 条（缺壳件优先自研，可在 javadoc 写明参考来源）、第 214 条（键位必须可取消）、第 89 条（模块不自管事件） |
