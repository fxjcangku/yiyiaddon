### 7.2 新项目当前缺少 / 差异的界面能力

1. **`CommandMessageFormatter` API 不全**：新项目仅有 `of / field / status / render / send / line / sendLine`（`core/CommandMessageFormatter.java:74,79,85,92,104,109,114`）；旧指令用到的 `world()`、`dimension()`、`key()`、`highlight()`、`coord()`、`raw()`、`lineOf()`（`core/CommandMessageFormatter.java:91-135,181-185`）**均缺失**。→ `AutoChestCommand` 的 `坐标` 字段需手工拼接，环境字段需另行获取。
2. **无 `GuiRenderer.RESET` 等框架常量**：新项目按钮文案需显式写字面量。
3. **无 Meteor 设置组 / 自定义设置类型机制**：设置项、可见性、计数标签刷新都要在页面类内自管（新项目 `ModulePage` 由页面自己 emit 元素，`ui/page/ModulePage.java:14-17`）。
4. **无「计数标签」统一刷新通道**：旧项目用 `countLabels` + `refreshCount()`（`autochest/config/ContainerTypeSetting.java:29,57-60`），新项目需用 `TextLine(Supplier<String>)`（`ui/component/TextLine.java:35`）或在数据变更时重建页面。
5. **无「✓/✗ 单选切换列表」控件**（对应 `ContainerTypeSelectScreen`）：`SelectorScreen` 是双栏增删模型，语义不同（`ui/screen/SelectorScreen.java:24-33`）。→ 需确认用 `ListRow` + `Button.selected` 组合还是新增控件。
6. **确认按钮默认文案不同**：旧 `§c§l确认`（`autochest/ui/ConfirmScreen.java:21`）vs 新 `确认`（`ui/screen/ConfirmPanelScreen.java:33`），复刻时须显式传参。

8. **`core/CommandMessageFormatter` 的颜色/对齐逻辑与旧版不同**：新项目 `field()` 直接 `fields.add(line(label, value))`（`:79-82`），不做旧版 `field` 里的 `维度/状态` 特判与 `§f` 自动上色（`core/CommandMessageFormatter.java:91-96`），也不做 `alignedComponent` 的 `§8▸`→`§8▶` 与自定义像素补白（`:195-215`）。逐字复刻回执需注意。
