## 二、逐字保真点（搬运时一个不动）

### 2.1 落盘路径与 JSON 键（老档可读）

| 数据 | 路径 | 元素键 |
|---|---|---|
| 标点 | `<configDir>/yiyiaddon/autochest/points/{fileSafeServer}.json` | `x` `y` `z` `dim` `type`（**不落 server**，由当前会话回填） |
| 处理记录 | `<configDir>/yiyiaddon/autochest/{fileSafeServer}.json` | `x` `y` `z` `dim` `type` `t` `ver` |

- 服务器键口径沿用 `WorldIdentity`：多人 `host:port` 小写、单人 `singleplayer:<存档目录名>`；文件名前缀 `server_` / `singleplayer_`。
- 旧文件迁移 `migrateLegacyFile`：**只复制不移动**。

### 2.2 常量与状态机

- 状态 18 个，中文名逐字（`空闲` / `扫描` / `选择目标` / `锁定目标` / `等待距离` / `计算站位` / `寻路中` / `已到达` / `打开容器` / `读取槽位` / `匹配物品` / `取物中` / `校验结果` / `关闭容器` / `已完成` / `失败` / `冷却` / `已停止`）
- 常量：`MAX_OPEN_ATTEMPTS=5`、`OPEN_REACH=4.5`、`OPEN_TIMEOUT_TICKS=60`、`MOVE_TIMEOUT_TICKS=200`、`NEXT_COOLDOWN=5`、`FAIL_WAIT_TICKS=10`、`IDLE_SCAN_WAIT=5`、`ALIGN_WAIT_TICKS=20`
- 扫描器：`BUDGET_PER_TICK=512`、`RECENTER_SQR=4`、游标推进顺序（x→z→y）与完成判定
- 视角同步常量：`VIEW_TURN_STEP=15.0f`、`VIEW_SYNC_RANGE=6.0`、`VIEW_ALIGN_TOLERANCE=25.0f`

### 2.3 取物核心语义

- 三态结果 `WITHDREW / FINISHED / INVENTORY_FULL`、`TAKABLE / DONE / INVENTORY_FULL`
- 差额算法 `目标数量 − countPlayerHas(含副手)`；`canFit` **不用** `Inventory#getSlotWithRemainingSpace`
- 槽位归属判据 `slot.container != inventory` + `Inventory.isHotbarSlot`
- 开箱：唯一走 `BlockPacketSender.interactBlock(MAIN_HAND, pos, Direction.UP)`；容器同步要求 `stateId` 连续稳定 3 tick
- 多人保护命中**不写**已处理；有限重试 + 临时冷却键 `dim:x,y,z`，冷却 `cooldownTicks*50L`

### 2.4 界面文字（全部来自 `基准-03` / 附录 B）

- 模块名 `自动箱子`；描述 `扫描并自动处理附近容器，取走ID配置中的目标物品。详细参考下面使用说明。`
- 8 个分组名、21 个设置项名称与描述、全部可见性条件（与旧项目一一对应）
- 头部按钮：`设置箱子点位（对准容器）`、`清空全部点位`、`清除当前维度处理记录`、`清除全部处理记录`、`§c删除`
- 点位卡片：`§b■ §f{类型名}` + `§7X§f.. §7Y§f.. §7Z§f..` + `§7维度 §f{维度}` + `§c已处理`|`§a未处理`；空态 `§8当前维度暂无箱子点位`；未知类型 `未知容器（类型 ID：{id}）`
- 三个确认窗：标题 `清空点位`/`清除记录`×2 与三句正文逐字；确认按钮显式传 `§c§l确认`，取消 `§7取消`
- 三个入口按钮：`选择容器类型`、`选择目标物品`、`配置每种物品数量`
- 计数标签：`已选 N / M 类`、`未选择目标（共 N 项）`/`已选 X / N 项`、`已配置 X / Y 项`
- 独立窗口标题：`容器类型`、`目标物品`、`每种物品数量`；三句顶部说明逐字
- 使用说明 4 章节（`§l自动箱子 · 使用说明` / `§e§l▌ 使用方法` / `§a§l▌ 三种模式` / `§d§l▌ 保护机制` / `§c§l▌ 注意`）逐字
- 启动自检 4 条缺项逐字；自检播报 `还差 N 项没配好，配完再开：` + 逐项 `§6  1. §f…`
- 全部播报逐字（添加/删除/清空点位、清除记录、ID 失效、停止自动化、状态机五条）

### 2.5 指令

`.autochest`（无别名、无 TAB 补全）：根无参执行状态查询；子命令 `添加` `移除` `清空` `状态` 全部无参；标题/字段/状态行格式逐字（见附录 B 第 4 节）。坐标与环境字段按旧格式手工拼接。

### 2.6 ID 三件套联动（本次打通的链）

- 数据源唯一：`IdentityService`（= 旧 `ItemIdManager`）+ `IdentityTargetConfig`（= 旧 `ItemTargetSetting` 的选中键）
- `选择目标物品` → 本项目 `SelectorScreen`（窗口标题 `目标物品`、左栏分组 `§a§l▌ 原版物品` / `§d§l▌ 自定义物品`、空态 `  §8无`、无确定按钮即时生效）
- ID 删除后反向回调：`pruneInvalid` → 计数刷新 → `有 N 个目标 ID 已失效，已从选择器移除`
- 自动箱子**不建**第二套物品库

### 2.7 寻路

`PathingService` 已按旧项目逐行移植，直接用 `baritone.api.*`（`build.gradle` 中 Baritone 为 `compileOnly`，运行期由嵌套 jar 提供）。三种运行模式全部具备。

## 三、与原项目的差异及处置

| # | 差异 | 性质 | 处置 |
|---|---|---|---|
| 1 | 设置持久化：旧为 Meteor NBT，新为模块 JSON | 框架替换（必然） | 沿用新项目 `Module.loadSettings/saveSettings` + `AutoChestSettings.save/load`。**旧 NBT 设置无法自动迁移**，玩家需重设设置项（点位/记录不受影响，仍读旧 JSON） |
| 2 | 「重置」按钮：旧为纯图标（`GuiRenderer.RESET` 是 `GuiTexture`，无文字，见 `26.1.2/01-开发参考库/Meteor原始源码/.../GuiRenderer.java:42`），新为 `IconButton`（码点 `\uE5D5`） | 壳按本项目 | 已确认旧项目**没有文字**可复刻。该码点未实机核对字形，首次进游戏需确认 |
| 3 | `CommandMessageFormatter` 缺旧版 `world()/dimension()/coord()/key()` | 底座能力缺口 | 已在指令层手工拼接等价格式，逐字对齐；**未改动底座**（避免波及既有指令） |
| 4 | 自定义维度显示名：旧 `自定义维度` + 追加 `维度 ID` 行；新回退原始标识 | 底座口径差异 | **未改**，待你拍板是否调整 `WorldIdentity.dimensionDisplayName` |
| 5 | `stopAutomation` 后多一条 `§c§l已关闭` 播报 | 运行时行为 | 旧项目用 `chatFeedback=false` 抑制；新项目运行时无静默关闭入口。**待你拍板**：是否给运行时加静默关闭参数 |
| 6 | ESP 彩虹态不落盘 | 设置载体 | 设置项存 ARGB 整数，彩虹仅影响取色预览；不影响 ESP 功能 |
| 7 | 布局：重置按钮与计数标签同排、点位卡片用 `ListRow`、清理按钮位置 | 壳按本项目（第 128 条允许） | 文字与交互未变 |
| 8 | 每种物品数量输入框步进取 1（旧 `noSlider` 实际也只步进 1，`64` 是未启用的 slider 上限） | 等价 | 默认值与值域语义已复刻（未配置 → 64，1~2304） |
| 9 | `SelectorScreen` 右栏为空时也显示 `  §8无`（旧项目右栏无空态） | 共享控件 | 未改共享控件；如需严格一致可单独调 |
