### 1.4 与既有模块的联动（实测定稿）

1. **`TacticalCoordinator` 是四模块唯一决策/状态中枢**，被 `FlightBypass`（`evaluateFlight` + `SessionResetEvent`）、`AntiKickBypass`（`hasAdvancedAntiCheat/isServerLagging/isRubberBandCooldown` + `RubberBandDetectedEvent/AntiCheatDetectedEvent/SessionResetEvent`）、`PacketInstantBreak`（`hasAdvancedAntiCheat/isServerLagging/isRubberBandCooldown` + `AntiCheatDetectedEvent`）、`ServerDetector`（`reportDetection/currentSession/getRubberBandTotal`）四方调用。**协调器必须先落地**。
2. **拉回判定与传送同源**（94 号已定）：`SERVER_POSITION`（只读绝对坐标）已在传送阶段落地，战术的拉回判定/飞行冷却/限速收紧**直接复用同一事件**，不再做第二份 `PositionMoveRotation.calculateAbsolute`（第 169 条）。
3. **秒破与挖矿联动**：旧 `PacketInstantBreak` 冲突检测第 1 条即本项目自动挖矿（`AutoMinerModule.getFastBreak()`）——新项目对应 [AutoMinerModule.getFastBreak():1417](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/mining/AutoMinerModule.java#L1417) + [MiningSettings.fastBreak](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/mining/config/MiningSettings.java#L170)（默认 `true`）。**这条冲突检测在新项目必须保留且语义完全一致**。
4. **发包侧互不干扰（硬约束）**：旧 `AntiKickBypass.shouldDelay` 排除 `KeepAlive` / `AcceptTeleportation` / **`MovePlayerPacket`** / `PlayerAction`（旧 `795-801`），注释明写「移动包不进延迟队列，避免与飞行模块的移动注入互相抖动」。新项目 `MiningFastBreakController` 依赖 `PlayerAction` 的真实 tick 间隔 → **该豁免必须逐字保留**。
5. **资源包能力同源**：旧 `ServerDetector` 的下载/缓存走 `ResourcePackDownloader`（注释：星露谷复用同一套）。新项目已有 [service/resourcepack/](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/service/resourcepack)（`ResourcePackCache` / `ResourceExtractionService`）—— **同源点，需核对能力覆盖**（是否有断点续传 / 重试 / 超时 / 通知回调）。

## 4 核心缺口（本阶段必须补，均属第 163 条例外的「必要」）

### G1 发包拦截与改写通道（**最关键**）

战术三件套的全部核心动作都发生在发包路径上：

| 动作 | 用例 |
| --- | --- |
| 取消 | Brand 伪装原包、非原版频道包、聊天排队、超限挖掘/放置、需延迟的包 |
| **改写包体** | `ServerboundPlayerInputPacket` 改写 `shift`/`sprint` 标志（假潜行/假疾跑） |
| 直发绕过 | Brand 伪装重发 `vanilla`、延迟队列到期重发（三参直发，防递归） |

现状：`PACKET_SEND` 只给类名，**不可取消、不可改写、不可直发**。`ClientEvent` 已有 `CancelToken` 先例（第 38-40 行），可扩展；但"改写包体"与"直发"必须按新架构的边界设计——**模块不得持有包对象**。

### G2 收包只读快照通道（多类型）

| 需要的数据 | 用例 |
| --- | --- |
| 方块破坏 ACK 序列号 | 秒破的 `stopAcknowledged`（旧 `PacketMiningFeedback`） |
| 权威方块更新（单方块 + 区块批量） | 秒破的破坏确认与"拒绝/回弹"判定 |
| 自定义负载频道 ID | 服务器检测的插件频道指纹 |
| 指令树 | 服务器检测的命名空间指纹（**注意**：也可由 `connection.getCommands()` 直接读，无需包） |

### G3 原版破坏入口接管

AIM 模式靠 `StartBreakingBlockEvent` 拦下原版开始破坏并改走发包。新项目挖矿已有 `MultiPlayerGameModeFastBreakMixin` 接管 `startDestroyBlock/continueDestroyBlock/stopDestroyBlock`。战术接入需**同一 mixin 按模块分派**，否则两个模块抢同一个入口。

### G4 常驻订阅（已核实可行，无需新增机制）

`ClientEventBus` 是全局广播，与模块开关无关；核心以固定 `ownerId`（如 `core.tactical`）订阅 `SERVER_POSITION`/`TICK`/`JOIN_SERVER`/`DISCONNECT` 即可复刻旧静态常驻语义，且不需要新的 Fabric 注册点（第 89/92 条）。

### G5 TPS / 卡顿

旧用 `TickRate.INSTANCE.getTickRate()`，`TPS_SAMPLE_INTERVAL = 20` 采一次、`LAGGING_TPS_THRESHOLD = 18.0`。新项目无对应物 → 需自研（按刻计时估算 TPS）。

### G6 工具层

`findFastestTool`（最快工具）、`swap/swapBack/move().toArmor`（换槽）、`Rotations.rotate(..., 50, callback)`（转向 + 回调）、世界空间文本标签绘制 → 逐项核对既有 `platform/` 与 `ui/render/world/` 是否覆盖，缺则自研。

### G7 控件缺口：`BlockList`

`目标方块` 是方块集合设置，新项目 16 个控件里没有对应物 → 需新增（或退化为文本输入，**不允许擅自退化**，需拍板）。
