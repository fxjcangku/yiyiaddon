# 01 · 总纲：迁移口径与复刻原则

日期：2026-09-14
性质：**口径正本**。凡其它报告中与本文件冲突的表述，一律以本文件为准。
适用范围：本项目全部后续开发（含所有阶段的模块迁移、界面重写、指令实现）。

---

## 一、一句话口径

> **旧项目的功能、模块、互相关联，全部复刻过来，一样不少；唯一变化是 UI 外壳。**
> 旧项目的文字与交互 + 本项目现有主题与按钮 = **文字照搬、交互对齐、壳换掉**。
> 新项目**自研**，彻底脱离 Meteor 及一切第三方客户端框架。

---

## 二、复刻范围（必须 1:1 搬过来的东西）

| 类别 | 具体内容 | 逐字依据 |
| --- | --- | --- |
| 模块与分类 | 全部功能模块、模块分组、模块名与说明 | 《基准-04》第 2 章、`core/AddonTemplate.java` 分类常量 |
| 模块间关联 | 谁调用谁、谁通知谁、共享底座、事件回调链 | 《基准-04》第 2~5 章、《基准-05》逐模块依赖 |
| 用户交互文本 | 播报、卡片字段、按钮文字、窗口标题、提示与错误 | 《基准-01》全量、《基准-03》按钮表 |
| 指令 | 指令名、别名、子命令、参数、帮助、错误提示、成功提示 | 《基准-06》全量 |
| 自检 | 每个模块的缺项判定条件与缺项文案逐字 | 《基准-02》逐模块清单 |
| 数据与结构 | 身份库（物品/实体/方块）、点位、快照、记录、资源索引、报告落盘 | 《基准-04》第 6 章、《基准-05》各模块「数据文件与持久化」 |
| 行为 | 状态机流程、触发时机、坐标归一化、跨服/跨维度隔离语义 | 《基准-04》第 5 章、《基准-05》各模块 |
| 配置项 | 设置名、分组名、可见性条件、默认值 | 《基准-03》与各模块配置页按钮表 |

**「互相关联检查出来的东西都不变」** = 《基准-04》《基准-05》中登记的依赖边、监听器、回调、共享静态状态、数据同源关系，迁移后必须仍然成立（可用新架构表达，但语义与效果不得改变）。

## 三、唯一变化：UI 外壳

| 维度 | 旧项目 | 新项目 |
| --- | --- | --- |
| 渲染 | Meteor GUI | 本项目自研 Skija 体系（`ui/render`、`ui/theme`、`ui/anim`） |
| 页面骨架 | Meteor Screen / WindowScreen | `PanelScreen`（独立窗口统一骨架）、`CardPage`、`CompactModulePage`、`ClickGuiScreen` |
| 控件 | Meteor `WButton` / `WTable` / `WIntEdit` 等 | 本项目 `ui/component`、`ui/widget` 自研控件 |
| 主题 | Meteor 主题 | 本项目主题（iOS 透明玻璃风格，见 23~25 号参考） |
| 按钮文字与作用 | — | **逐字照旧，一个字不改、作用不差**（开发习惯 96 / 100 / 105 条） |

即：**壳可以重画，字和动作不能改。**

## 四、唯一例外清单（允许不复刻）

来自 `开发习惯.md` 第 43 条，且仅限以下各项：

1. 明文密码外发与隐私上报类（`YiyiaddonPasswordInterceptorService` 等）
2. 水印（`YiyiaddonWatermark`）
3. 指令名上报 Mixin（`ClientCommandSourceMixin`）
4. 示例 HUD（`hud/HudExample`）
5. 主题模块（`theme/ThemeModule`）
6. 全部 recognition / adapter 死代码层（24 个文件）
7. `stardew/profile/StardewProfileStore`

另有两类不属于「功能」的排除：

- **第三方框架层**：Meteor 模块外壳、Setting 系统、Event 总线、GUI 组件、指令注册、汉化 Mixin、accessor 接口 —— 按本项目架构重写（开发习惯 32 / 34 条）。
- **运行态与构建产物**：旧项目 `run/`、`build/` 不迁移（`16-阶段04` 第 47 行）。

除上述外，**不存在「建议不迁移」「暂不迁移」「按口径排除」的模块**。此前报告里对星露谷 / 自动箱子 / 自动附魔 / 自动农场 / 战术等模块的「不迁移」表述，均为定稿前的待决项，**自 2026-09-14 起一律作废**。

## 五、框架边界（脱离 Meteor 的准确含义）

允许：

- 使用 Fabric API 与 Mojang 官方映射下的原版 API
- 内置 Baritone 作为寻路依赖（旧项目同样内置，属功能依赖非框架依赖）
- 参考第三方实现的做法，但按本项目架构重写

禁止：

- 任何 `meteordevelopment.*`（Meteor）的 import 或调用
- 其它第三方客户端框架的 API（如第三方模块的 `toggle()`、第三方 Setting 体系、第三方 GUI 组件）
- 产物中出现旧框架名称（代码、注释、界面文案、对外文本一律不得出现）

## 六、复刻流程（每个模块固定四步）

1. **查基准**：读《基准-01》对应章节（说什么）、《基准-02》（缺什么不能启动）、《基准-03》（界面上有什么）、《基准-05》对应模块（要搬哪些依赖）、《基准-06》（若有指令）。禁止凭印象或报告转述动手。
2. **搬逻辑**：`model` → `platform` / `repository` → `service` → `feature/<模块>`，按本项目包结构分类（开发习惯 47~49 条）。
3. **换外壳**：界面用本项目 `PanelScreen` 体系与主题重写，文字逐字照搬。
4. **验收**：用户交互文本逐字比对（开发习惯 105 条）+ 实机验证；缺一不算完成。

## 七、验收标准

| 项 | 通过条件 |
| --- | --- |
| 文案 | 与《基准-01》《基准-03》《基准-06》逐字一致（含 `§` 颜色码与全角空格） |
| 按钮 | 文本、作用、出现条件与《基准-03》一致；无多余、无缺失 |
| 自检 | 缺项条件与文案与《基准-02》一致；缺项时不得启用 |
| 关联 | 《基准-04》《基准-05》登记的依赖与回调在新架构下仍然成立 |
| 指令 | 名、别名、子命令、参数、补全、回执与《基准-06》一致 |
| 框架 | `src` 下 `meteordevelopment` 命中 0；产物无旧框架名 |
| 实机 | 该模块主流程实际跑通（编译通过不算） |
