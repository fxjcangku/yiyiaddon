## 八、已知差异与限制（如实清单）

1. **master 是并发开发线**：本轮期间另一条开发线（235 AutoMiner 接线）正在 `D:\mcaddon\yiyiaddon` 工作区编辑（`git diff --shortstat` 从 35 文件变为 40 文件）。本移植固定在 21:12 的 master 快照（`b926bba`），**不是**「master 永远如此」。后续若主线上的 Seed Mining 有业务改动，仍需按第 231 条搬运。
2. **满覆盖口径的总条数不可跨运行直接比**：49 个目标区块以玩家所在区块为中心，观察窗口随玩家位置与观察批次变化（26.2 本轮 1133，234.1 那次 1061，光影场景 1061）。可比的是**同窗口的重叠区块**（(0,0) / (-3,-3) / (1,2) / (0,2) 逐项一致）。
3. **矿石放置链路等价，地形管线有真实差异**：`NoiseBasedChunkGenerator#buildSurface`（生物群系来源）、`Blender.empty()`、`spaghetti2D` 重组在源码层确有改动。本轮实测显示它们**没有**改变这批目标区块的候选集合；但这属于「实测余量」而不是数学证明——换种子、换坐标仍应重跑 oracle。
4. **`OreFeature` 的等价结论建立在调用顺序逐条核对上**：`random.nextDouble()/nextFloat()` 的调用次数与顺序两版一致，这是「同种子同结果」的直接依据；未做字节码级逐指令比对。
5. **26.2 的 `Feature` 注册表删了旧 id**（`pointed_dripstone` / `dripstone_cluster`）并把 `simple_random_selector` 换成 `CompositeFeatureConfiguration`。任何引用旧 id 的数据包会在 26.2 直接加载失败，从而让整条 biome 特征表失真（预测器会整体失准）——属**环境前提**，不是本模组缺陷。
6. **production Validation smoke 的调参口径（工具，不是产品）**：`gradle/production-smoke.ps1` 的 `-VersionId` 默认是 `LunarFox`（26.1.2 实例），在 26.2 上必须显式传 `-VersionId 26.2`，否则会取到 26.1.2 的 `fabric-api` 并以「没有观察到任何 Worker 进程」判不通过。本轮实测踩到并已按此口径跑通。
7. **冒烟脚本的数组参数不可跨进程传递（工具，不是产品）**：把 `-SeedPocJvmArgs '-Da=1','-Db=1','-Dc=1'` 写在同一个 `powershell -File` 命令行里，会被外层 PowerShell 合成**一个**逗号连接的参数（实测命令行为 `-Dyiyiaddon.seedpoc.enabled=1,-D…=1,-D…=1`），三个开关全部失效、装置根本不挂载。本轮改用「同一会话内直接调用」的包装脚本（`.dev-runs\26.2\seed\_logs\smoke-*.ps1`，不进版本库）解决。**26.1.2 线的同一条命令存在同样的坑**，建议主线后续一并收口。
8. **光影场景未取到画面截图**（屏幕捕获被编辑器窗口遮挡）；该场景结论依赖装置日志与「无崩溃报告」。
9. **未做**：Nether / 末地；其它矿物（仍 Diamond only）；AutoMiner 接线；Radius6 压力烟测（本轮未排入任务书，且 234.1 已在 26.1.2 侧取得完整实测）；MISSING 三世界顺序实验（234.1 已定案，本轮不重复）。
10. **`b926bba` 的提交信息**由 `git stash create` 自动生成，形如 `On master: port-26.2 baseline snapshot`，只作锚点，不含业务语义。
