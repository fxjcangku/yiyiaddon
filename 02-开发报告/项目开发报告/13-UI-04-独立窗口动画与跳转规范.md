## 一、本规范要解决的问题

旧项目的交互形态是「**配置面板上的某些按钮，点下去会弹出一个独立的窗口**」，而不是在同屏展开、也不是往聊天栏丢结果。
新项目必须做到同一件事，且**动画细节要完整**——窗口不能硬切出现、不能硬切消失，内容不能一次性砸出来。

本规范固定两件事：

1. **独立窗口的动画规格**（开合、内容入场、控件反馈）——参数写死，全项目统一，子类不得自行发挥；
2. **独立窗口的跳转规格**（谁开谁、谁返回谁）——只在导航类定义一处。

## 二、独立窗口统一骨架：`PanelScreen`

**位置**：`ui/screen/PanelScreen.java`

本项目全部独立小窗口都继承它，**没有一个例外**。它负责：

| 职责 | 实现 |
| --- | --- |
| 面板几何 | 复用 `PanelFrame`，与主界面同尺寸（`CARD_W 740` × `CARD_H 500`）、同圆角基准（`CARD_RADIUS 16`），因此窗口与主界面视觉完全一致 |
| 面板材质 | `GlassPanel.shadow` → `GlassPanel.frost` → `GlassPanel.rim`，圆角裁剪 |
| 标题栏 | 返回按钮（`BackButton`，左上 `18,16`）+ 加粗标题（`19f`），标题横坐标 `18 + 28 + 12 = 58` |
| 内容区 | `CONTENT_TOP = 70`、左右 `CONTENT_PAD = 18`、页内缩进 `PAGE_INSET_X = 10`、滚动条预留 `PAGE_RESERVED_W = 40` |
| 滚动 | `ScrollViewport`，滚动条与内容区同步淡入 |
| 输入分发 | 返回按钮命中 → 内容命中 → 滚动条命中 → 空白清焦点 |
| 关闭 | `requestClose()` 播放反向动画后再真正切屏 |

**子类只允许做一件事**：在构造末尾调用内容助手填内容。

```java
addSectionTitle("§b§l▌ 分区标题");   // 分区标题
addField("标签", "值");               // §7标签 §8▸ §f值
addButton("按钮文字", this::action);  // 满宽按钮
addButtons(b1, b2);                   // 一行等宽按钮
addGap();                             // 空行
addDivider();                         // 分隔线
```

**子类禁止**：自己画面板、自己算坐标、自己处理 `canvas.save/restore`、自己写 `setScreen` 做跳转。

## 三、开合动画规格

### 3.1 打开（三件事同时发生，0.16s）

| 通道 | 起点 | 终点 | 曲线 |
| --- | --- | --- | --- |
| 缩放 | `0.88` | `1.00` | `Easing.easeOutCubic` |
| 上浮 | 面板下移 `16`（设计单位） | 归位 | 与缩放同一进度 |
| 透明度 | `0.0` | `1.0` | 与缩放同一进度 |

- 时长：`PanelFrame.OPEN_DURATION = 0.16s`（`PanelFrame`）
- 缩放起点：`PanelFrame.OPEN_MIN_SCALE = 0.88`
- 上浮距离：`PanelScreen.ENTER_RISE = 16f`
- 圆角补偿：`cardRadius = CARD_RADIUS / animationScale`，保证缩放期间圆角视觉不跟着变粗

**上浮必须只作用于绘制**，命中几何仍用 `PanelFrame` 给出的 `scale()`，与既有的缩放动画同一口径；
上浮幅度小、时长 0.16s，用户无法在动画窗口内完成一次准确点击。

### 3.2 关闭（严格反向播放）

- 触发：`requestClose()`（返回按钮、`ESC`、确认后的自动关闭都走它）
- 行为：`PanelFrame.beginClose()` → 进度反向推进 → 归零后调用 `SkiaScreen.closing()` → `minecraft.setScreen(parent)`
- 一次性：`requestClose()` 有 `closingRequested` 卫语句，重复调用不会重复播放
- 关闭期间：`mouseClicked` 直接返回 `false`，不接受新输入
- **返回按钮不瞬间消失**：`backVisible = alpha > 0.01f`，跟随整体淡出

**禁止**：在任何窗口里写 `client.setScreen(xxx)` 直接切屏来「返回」。唯一例外是「打开另一个窗口」（见第七章）。

### 3.3 同步淡出项

面板的 `animationAlpha()` 会同步作用到：玻璃面板、边框、标题、返回按钮、内容、滚动条。
即关闭时**整块一起淡出**，不允许出现「面板淡出但某个元素还亮着」。

## 四、内容入场动画规格（`CompactStack`）

**位置**：`ui/component/CompactStack.java`

### 4.1 参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 单项时长 | `ENTER_DURATION = 0.18s` | 单个元素从 0 到 1 的时间 |
| 错峰间隔 | `ENTER_STAGGER = 0.018s` | 相邻元素的起始间隔 |
| 错峰上限 | `MAX_STAGGER_INDEX = 10` | 第 10 项之后不再继续推迟，避免长列表尾部迟迟不出现 |
| 曲线 | `Easing.easeOutCubic` | 先快后慢 |
| 作用通道 | **仅透明度** | `alpha * progress` |

### 4.2 关键设计

1. **默认关闭**。`enterAnimation(false)` 是缺省状态，模块页等常驻界面保持即时呈现，避免每次切页整体闪一下。独立窗口在字段初始化时显式 `enterAnimation(true)`。
2. **只改透明度，不改几何**。高度、绘制坐标、命中坐标全部不受动画影响，杜绝「看得到点不到」。
3. **零风险兜底**。若宿主从未调用 `update(dt)`，`enterStarted` 保持 `false`，`enterProgress()` 直接返回 `1`，内容正常显示——不可能出现整屏不可见。
4. **进度已满则跳过绘制**。`progress <= 0.006f` 的元素本帧不绘制，减少首帧开销。

### 4.3 宿主义务

宿主（`PanelScreen.drawPanel`）每帧必须按顺序执行：

```
scroll.layout(...)  →  scroll.update(dt)  →  content.update(dt)  →  content.draw(...)
```

`update` 必须先于 `draw`，否则本帧拿到的还是上一帧的进度。

## 五、控件级动画（既有资产，禁止重写）

| 控件 | 动画 | 参数 |
| --- | --- | --- |
| `Button` | 悬停底色过渡 | 时间常数 `HOVER_SMOOTHING = 14f`（≈0.14s）；`HOVER_TINT = 0.10`；次级按钮混入 `SECONDARY_HOVER_TINT = 0.14` |
| `Button` / `IconButton` / `BackButton` | 按压缩放回弹 | `PressState`：按下 `0.09s` 到 `0.97`，松开 `0.26s` 用 `easeOutBack` 回弹到 `1.0`；一次性按钮用 `pulse()` |
| `BackButton` | 悬停过渡 | `12f` 时间常数 |
| `ScrollViewport` | 滚动缓动 | `ScrollTracker` 时间常数 `0.085s`，指数逼近、帧率无关；差距 `< 0.05` 直接吸附；拖动滚动条走 `jumpTo` 跳过缓动 |
| 滚动条 | 淡入淡出 | 跟随面板 `alpha`，内容不足一屏时 `hasScrollbar()` 为 false 直接不画 |
| `SettingTextBox` | 焦点态 | 由控件自身维护，窗口关闭时 `SettingTextBox.clearFocus()` |

**禁止**：为某个窗口单独写一份悬停、按压或滚动动画；发现需要新的动画语义时，改公共控件。

## 六、窗口跳转规格

**位置**：`feature/identity/ui/IdScreens.java`（本模块）；后续每个模块照此结构建自己的 `XxxScreens`。

**唯一职责**：集中定义「哪个窗口打开哪个窗口」「哪个窗口返回哪个窗口」。

```java
public static void openManagement(Screen parent, IdConfigModule module)
public static void openDataClean (Screen parent, IdConfigModule module)
public static void openAdd       (Screen parent)
public static void openHelp      (Screen parent)
public static void openItemResult  (ItemIdentity  identity, Screen parent)
public static void openBlockResult (BlockIdentity identity, Screen parent)
public static void openEntityResult(EntityIdentity identity, Screen parent)
```

**规则**：

1. 业务模块、页面、指令**只调这些静态方法**，禁止 `new XxxScreen(...)` 直接建窗口。
2. 关闭语义二选一，不得混用：

   | 语义 | 实现 | 适用窗口 |
   | --- | --- | --- |
   | **回游戏**（连同 GUI 一起关掉） | 构造里调用 `exitToGame()`，关闭动画结束后 `setScreen(null)` | 使用说明、添加物品、二次确认、识别结果 ×3、ID 更多管理 |
   | **返回上级窗口** | 默认行为，`closing()` 里 `setScreen(parent)` | 仅 `ID 数据清理` 一处 |

3. **这个不对称来自旧项目源码，必须照抄**：

   ```java
   // 旧项目 IdConfigModule.java:424-431 —— 更多管理的「§7返回」是回游戏
   mc.setScreen(new IdManagementScreen(theme,
       this::openAddScreen, ..., this::openDataCleanScreen,
       () -> mc.setScreen(null)));          // ← 回游戏

   // 旧项目 IdConfigModule.java:436-443 —— 数据清理的「§7返回」是回更多管理
   mc.setScreen(new IdDataCleanScreen(theme,
       ..., this::openManagementScreen));    // ← 回更多管理
   ```

4. 存在唯一一处父子层级，用「自引用持有」把父窗口传给子窗口：

   ```java
   IdManagementScreen[] self = new IdManagementScreen[1];
   IdManagementScreen management = new IdManagementScreen(parent,
           () -> openAdd(parent),
           ...,
           () -> openDataClean(self[0], module));   // 数据清理：返回 → 更多管理
   self[0] = management;
   client.setScreen(management);
   ```

5. 跳转关系固定为（与旧项目逐条一致）：

   ```
   主界面（ClickGuiScreen）
     ├─ 更多管理 ──┬─ 添加物品 ──取消/成功──→ 回游戏
     │             ├─ 打开 4 类目录
     │             └─ 数据清理 ──┬─「§7返回」──→ 更多管理
     │                           └─ 清空按钮 ──→ 二次确认窗 ──确认/取消──→ 回游戏
     │             └─「§7返回」────────────→ 回游戏
     ├─ 使用说明 ──「关闭」──→ 回游戏
     └─ 识别结果 / 实体识别结果 / 方块识别结果 ──关闭──→ 回游戏
   ```

### 7.3 二次确认窗规格（`ConfirmScreen` 原文）

旧项目 `autochest/ui/ConfirmScreen.java`：

- 正文：按 `\n` 拆行，逐行一个标签（因此支持多行结构化提示）
- 确认按钮：默认 `§c§l确认`；清空类操作传 `§c§l确认清空` / `§c§l确认全部清空`
- 取消按钮：`§7取消`
- 两个按钮均 `minWidth(120)` 等宽
- **确认动作先执行回调再 `setScreen(null)`；取消直接 `setScreen(null)`** —— 即两者都回游戏

### 7.4 使用说明窗规格（`HelpScreen` 原文）

旧项目 `ui/HelpScreen.java`（**全部模块共用一个基类**）：

- 窗口标题：`module.title + " - 使用说明"`（如 `ID配置管理 - 使用说明`）
- 正文：`String[]`，逐行一个标签；**空字符串行渲染为一条水平分隔线**
- 标题框三行（`buildHelpContent` 生成）：

  ```
  §8┏ + ━ × 51 + ┓
  §8┃ §3§l> §b§l使用说明 + 空格 × 38 + §8┃
  §8┗ + ━ × 51 + ┛
  ```

- 每个章节：1 个空行 + `§3[§b#§3] §f<章节标题>` + 若干正文行
- 底部：一条水平分隔线 + 满宽 `关闭` 按钮（点击 `setScreen(null)` 回游戏）

ID 模块的四个章节为 `使用方法` / `数据链` / `清空说明` / `注意事项`，正文逐字见 `IdConfigModule.buildHelpContent()`。

## 八、验收清单

打开任一独立窗口，逐条确认：

- [ ] 窗口不是硬切出现：有缩放 + 上浮 + 淡入，0.16s
- [ ] 内容不是一次性砸出：逐项淡入，首项最先、末项最晚
- [ ] 标题与返回按钮与面板一起淡入
- [ ] 返回按钮 / `ESC` 关闭时是**反向播放**动画，不是瞬间消失
- [ ] 关闭过程中返回按钮跟随淡出，不会先消失
- [ ] 按钮悬停有底色过渡，按下有回弹
- [ ] 内容超一屏时滚动条可见，滚轮滚动是缓动的，拖动滚动条是跟手的
- [ ] 子窗口的关闭目标与旧项目一致：`ID 数据清理` 的「返回」回到「更多管理」，其余窗口的关闭 / 取消 / 返回 / 确认都直接回游戏
- [ ] 再次打开同一窗口，动画重新播放（实例是新建的）
