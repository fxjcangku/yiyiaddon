## 1. 结论先说

**能，而且和抖动没有关系。** 但**不能靠男中音自带的渲染**——那一项本来就是开的，实机看不到不是设置问题。

## 2. 取证：为什么「调 Baritone 设置」这条路是死的

| 事实 | 证据 |
| --- | --- |
| 路径渲染默认就是开的 | `baritone/api/Settings.java:697 public final Setting<Boolean> renderPath = new Setting<>(true);`（`renderGoal` 707 同为 true、`renderPathAsLine` 702 默认 false） |
| 你的本地设置里没有任何覆盖 | `run/baritone/settings.txt` 全文只有两行：`acceptableThrowawayItems …`、`blocksToAvoid tripwire` |
| 它确实在画（代码路径完整） | `PathingBehavior#onRenderPass:580-581` → `PathRenderer.render(event, this)` |
| 渲染挂点 | `baritone/launch/mixins/MixinWorldRenderer.java:45-56`：注入 `LevelRenderer.renderLevel` 的 **RETURN**，逐 baritone 触发 `onRenderPass` |
| 你的环境 | 客户端日志模组表：`iris 1.11.4+mc26.1.2`、`sodium 0.9.2+mc26.1.2`、`sodium-extra 0.9.3`（共 287 个模组） |

即：`renderPath = true` + 代码路径完整 + 你实机看不到 ⇒ 它的渲染在 Iris / Sodium 的管线里被丢掉，
**在设置层面没有出口**（把它关了再开、换成线模式，结果一样）。

## 3. 改法：改由项目自己的世界渲染层自绘

新增 [`MiningPathRenderer`](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/mining/render/MiningPathRenderer.java)，
作为自动挖矿模块的**第三条**世界渲染层注册（与点位层 `mining`、挖掘进度层 `mining:break` 并列）：

```
WorldOverlay.register(PATH_LAYER_ID, pathRenderer::render);   // 启用时
WorldOverlay.unregister(PATH_LAYER_ID);                       // 关闭时
```

- **通路**：`WorldOverlay` → `EspRenderer` → 原版 `Gizmos.line`。这条通路你实机已经验证可见
  （点位框、岩浆透视、挖掘进度框都走它），不经过 Baritone 的 `renderLevel` 注入点。
- **数据源**：`IBaritone#getPathingBehavior()` 的 `getCurrent()`（当前段）与 `getNext()`（预先算好的规划段），
  逐节点取 `IPath#positions()`，**方块中心**（`+0.5`）之间连线。
- **段起点**：从 `getPosition() - 3` 起（与 Baritone 的 `PathRenderer` 同口径）——不留这一截，
  线会从脚底下开始、走过的地方瞬间消失，看起来像在追一根断线。
- **上限**：单帧最多 200 个节点，避免长路径把「ESP 全局设置」的单帧图元预算吃光、挤掉其它层。
- **配色**：当前段不透明（自己在走的），规划段半透明 110/255（算好还没走的）——两段同色会看成一条，
  而自动挖矿时目标常切换，分不清会以为路径在乱跳。

## 4. 为什么这条线不可能引起抖动

上一轮「剧烈抖动」的根因已查清：**模块的 `MiningViewFollow` 与 Baritone 同时写可见视角**（双写入者），
该类已整类删除。本轮的线只向渲染层提交线段顶点：

- 不写 `player.setYRot / setXRot`，不碰 `LookBehavior`，不读改 `Target`。
- Baritone 那侧的可见视角只由 `LookBehavior.Target.Mode#resolve`（`LookBehavior.java:336-356`）决定：
  - 走路（`blockInteract=false`）→ `antiCheat ? SERVER : NONE`：**不写可见视角**（SERVER 会在 POST 还原）；
  - 挖矿（`blockInteract=true` + `blockFreeLook=false`）→ **CLIENT**：对准正在挖的方块，这是你要的「跟随视角挖掘」。

自绘路径线不在这条链路上 ⇒ 构造上就不可能产生抖动。

## 5. 设置项（按「挖掘进度 ESP」的规格，落在控制台「点位」页 ▸ 显示与颜色）

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 寻路路径线 | 开 | 纯显示开关，关掉不影响寻路与挖矿行为 |
| 寻路路径线颜色 | `(0,224,255)` 青 | 存 RGB；透明度由渲染层固定（当前段不透明 / 规划段半透明） |

持久化接的是模块既有机制（`MiningSettings` 的 `save/load` + `module.persistSettings()`），无第二套配置。

## 6. 待实机验证项

1. 自动挖矿运行中能看见一条沿路径节点连成的线（青色），走到哪、线延伸到哪。
2. 视角与上一轮一致——**不抖**（线只画几何，不写角度）。
3. 规划段（暗一档的线）确实存在，且在目标切换时不会看成「路径乱跳」。
4. 关掉「寻路路径线」后线立刻消失、其它 ESP 不受影响。
5. 长距离寻路（回补给点 / 卸货）时同样可见，且不出现明显掉帧。
