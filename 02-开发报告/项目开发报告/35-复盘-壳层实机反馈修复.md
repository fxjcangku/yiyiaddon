## 二、逐条判定

### 图一 · 目标物品：右栏不分组、添加无提示

| 项 | 结论 |
| --- | --- |
| 旧项目行为 | `ItemTargetSelectScreen` 右栏只画 `§a + 显示名` ＋ 减号，`setSelected` 里只有 `setting.set(values)` 与 `setting.refreshCount()`，**既无分组也无任何播报** |
| 判定 | **不是移植偏差**（旧项目就是这个行为） |
| 用户决定 | **增强**：右栏也按原版 / 自定义分组；添加 / 移除后给聊天回执 |

### 图二 · `已选 2 / 2 项 ⟳` 位置飘在行中间

| 项 | 结论 |
| --- | --- |
| 根因 | 该行由 `ButtonRow(SettingText, IconButton)` 构成。`SettingText.draw` 用的是 `x + width - textWidth`（**右对齐到自身 240 宽区域的右边界**），于是计数文字被推到行中部、图标紧跟其后；而它上下所有行都是「左标签 ＋ 右控件」 |
| 判定 | **壳层缺陷**（`SettingText` 的右对齐是为「设置行右侧状态值」设计的，被误用在整行状态行上） |
| 用户决定 | **不该居中，应两端对齐** |

### 图三 / 图四 · 颜色预览是绿白棋盘格马赛克

| 项 | 结论 |
| --- | --- |
| 根因 | `ColorPreview.draw` 与 `SettingColorPicker.draw` **各自逐格画了 8×8 / 6×6 的棋盘格底**，再用真实 alpha 叠色。类注释即写明「底下铺棋盘格表示透明度」 |
| 判定 | **新项目自造**；旧项目 Meteor 的 `WColorSetting` 预览是**纯色** |
| 用户决定 | **改纯色** |

### 图五 · 搜索框打不进字 / 有些输入框完全无响应

| 项 | 结论 |
| --- | --- |
| 根因 | `PanelScreen` 是「独立小窗口」的统一骨架，但**没有转发 `keyPressed` / `charTyped` / `preeditUpdated`**；`ModuleScreen`、`ClickGuiScreen` 各自都写了一份。因此走 `PanelScreen` 的窗口（双栏选择器、调色盘、更多管理页）输入框一律收不到按键 |
| 排除项 | 中文不是被过滤：`SettingTextBox.isAllowed(codepoint)` 是 `codepoint >= 32 && != 127 && != \n\r\t`，中文字符可过；`focus()` 也已调 `ImeBridge.setTextInputActive(true)` |
| 判定 | **壳层缺陷** |
| 用户决定 | 直接修 |

## 五、遗留

1. **回执文案是本轮新写的**（旧项目该窗口没有任何提示）：`§7已添加 §a名称` / `§7已移除 §c名称`，前缀用窗口标题（如「目标物品」）。文案如需调整，改 `SelectorScreen.notifyAction` 一处即可。
2. **`SettingText` 的默认右对齐保持不变**：只给整行状态行按需加 `alignLeft()`，设置行右侧的状态值仍是右对齐。
3. **`ButtonRow.split` 只覆盖「两端各一个控件」**：多元素时中间元素紧跟左侧元素排布，本轮回执、计数三类行都只用两个控件。
4. 前序报告未结项：`IdentityService.itemSnapshotCount()` 新增孤儿；`IdentityModulePage` 的「识别模式」说明仍是分段单句而非旧项目整句原文；`IdConfigModule.pruneTargets()` 的界面入口是否属旧项目资产待核查（见 34 号第六节）。
