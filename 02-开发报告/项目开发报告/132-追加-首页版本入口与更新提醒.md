# 首页版本入口与更新提醒

## 范围与依据

本次为用户明确要求的新能力：首页右上角版本信息、仓库入口、自动更新提示、稍后更新、跳过版本、手动检查和反馈问题。它属于独立新项目的客户端服务，不是旧项目业务迁移；未修改旧项目。

取证位置：`ClickGuiScreen.drawPageHeader` 为首页页头，既有 `ClientIdentity.version()` 从模组元数据提供版本；`EventDispatcher.onClientTick` 为客户端事件入口；`PanelScreen` 提供独立窗口动画与返回语义；`Button` 提供现有按钮样式。跳过版本的写盘复用 `JsonFileStore.writeAtomic`。

公开发布列表接口参考 [GitHub 官方文档](https://docs.github.com/en/rest/releases/releases#list-releases)，系统浏览器入口已在参考库 `net/minecraft/util/Util.java` 查证。真实接口回读确认仓库 Issues 已启用，当前公开版本为 `v1.0-beta1`，类型为测试版。

## 实现

- `ui/component/VersionHeader`：紧凑版本徽标、检测状态、项目仓库、检查更新、反馈问题；主题颜色与按钮沿用公共控件，绘制和命中使用同一设计坐标。
- `ui/screen/ClickGuiScreen`：仅首页增加右上角版本区，为副标题保留独立宽度。
- `service/update/ReleaseVersion`、`ReleaseCatalog`：规范化版本比较，包含 Beta；忽略草稿、坏条目、未完成上传和个人包。固定本仓库链接，不执行或渲染远程发布正文。
- `service/update/UpdateService`：后台检查，启动后及每 15 分钟读取一次最近 100 条公开发布记录；有限超时，失败在页头反馈。手动检查间隔至少 10 秒，并复用已有请求。
- `service/update/UpdateSession`：自动提示每个客户端进程最多一次。稍后更新、Esc 或返回均不会导致同一进程重复弹窗。
- `service/update/UpdatePreferences`：跳过所选版本写入 `config/yiyiaddon/update.json`；只在保存成功后修改内存状态。更高版本继续提示，手动检查可查看已跳过版本。
- `ui/screen/UpdatePanelScreen`：紧凑公共玻璃面板，显示当前与目标版本，提供立即更新、稍后更新、跳过此版本；保存失败留在弹窗并显示错误。
- `PanelScreen` 仅增加受保护的尺寸设置助手；`EventDispatcher` 仅接入更新服务 tick。保留这些文件中原有的其他工作区改动。

立即更新打开具体版本的发布页，玩家手动下载替换并重启；不热替换 JAR。反馈问题打开 GitHub 新建 Issue 表单，预填当前版本与复现模板，玩家补充并提交。没有自动发送 Issue，没有读取或上传日志、账户及服务器资料。
