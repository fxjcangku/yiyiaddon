## 一、文档定位与使用铁律

### 1.1 这份文档解决什么问题

旧项目的全部界面都建立在 **旧框架 GUI 组件体系**之上（`WindowScreen` / `WTable` / `WButton` / `WMinus` / `WPlus` / `theme.item` / `GuiRenderer.RESET`）。新项目已确立「**不保留任何旧框架产物，UI 全部自研**」，因此旧项目界面代码**一个字节都不能复用**。

但界面上的**用户交互资产**（按钮文字、区块标题、字段标签、配色语义、排列顺序、确认文案）属于用户体验契约，**必须逐字继承**。

于是本模板把两者切开：

| 维度 | 处理方式 |
|---|---|
| 界面**外观与文案** | 逐字继承旧项目原文（本文档即为唯一基准） |
| 界面**实现代码** | 100% 自研重写，零旧框架依赖 |
| 界面**布局结构** | 继承信息架构（谁在上、谁在下、几栏、几列），实现方式自定 |
| 界面**视觉风格** | 新项目自定（Skija 玻璃拟态体系） |

### 1.2 三条铁律

1. **文案不得改写**：本文档给出的原文含 `§` 颜色码，迁移时必须字字一致（颜色码也属于资产）。禁止"优化措辞""统一风格""简化表达"。
2. **零旧框架复用**：本文档只记录**外观与文案**。任何 `meteordevelopment.*` 的类、方法、图标常量都不得出现在新项目。
3. **本文档未记载者不得凭印象补写**：旧项目不存在的新界面，按 `开发习惯.md` 第十七章规范新写，而不是"猜一个旧项目风格"。

## 三、全局界面语法（旧项目统一排版规范）

旧项目全部界面共用同一套文本语法。**这一节是模板的核心**——复刻任意界面时，按此语法还原即可得到一致的观感。

### 3.1 区块标题语法

```
§<色>§l▌ <标题>
```

| 用途 | 示例原文 |
|---|---|
| 识别结果区 | `§b§l▌ 识别结果` |
| 方块结果区 | `§b§l▌ 方块识别结果` |
| 作物状态区 | `§b§l▌ 作物真实状态` |
| ID 清单头 | `§b§l▌ 当前ID清单 §8▸ §e共 " + total + " 条（筛选：" + filterText + "）§8▸ 第 " + (page+1) + "/" + totalPages + " 页` |
| 选择器左栏 | `§a§l▌ 可添加<类别名>` / `§a§l▌ 原版物品` / `§d§l▌ 自定义物品` |
| 选择器右栏 | `§b§l▌ 已选择` |
| 说明章节 | `§e§l▌ 使用方法` / `§a§l▌ 三种模式` / `§d§l▌ 保护机制` / `§c§l▌ 注意` |
| 统计区块 | `§6§l▌ 实时概览` / `§b§l▌ 在线与最近活跃` / `§d§l▌ 当前使用该扩展的玩家` |

**颜色分工**：`§b`(青) 主数据区 · `§a`(绿) 可用/正向区 · `§d`(紫) 自定义/特殊区 · `§e`(黄) 说明入口 · `§c`(红) 风险区 · `§6`(金) 统计区。

**折叠区块**：`§b§l<名称> §8· §7独立配置  §8(点标题可收起)`

### 3.2 字段行语法

```
§7<标签> §8▸ §f<值>
```

- 分隔符统一 ` §8▸ `（右三角，暗灰）
- 标签统一 `§7`（灰）
- 值统一 `§f`（白）
- 强调值用色码：`§a`(绿，成功/已确认) · `§e`(黄，警示) · `§c`(红，失败) · `§b`(青，技术值) · `§d`(紫，自定义)

**多字段同行**：` §8▸ ` 串联，或 `§8│` 作分组分隔（`§7作物 §8▸ … §8│ §7锄地 §8▸ (开/关) §8│ §7收割 §8▸ (批量/单个)`）。

**汇总行**：`§7物品 §f<N> §8▸ §7实体 §f<N> §8▸ §7方块 §f<N> §8▸ §7快照 §f<N>`

**卡片坐标行**：`§7X§f%d §7Y§f%d §7Z§f%d`，维度行 `§7维度 §f<dim>`

### 3.3 状态标记语法

| 语义 | 前缀 | 示例原文 |
|---|---|---|
| 成功 | `§a§l✓ ` | `§a§l✓ 已识别物品 §8▸ <名>` |
| 失败 | `§c§l✗ ` | `§c§l✗ 已删除 ID §8▸ <名>` |
| 警告 | `§e` | `§e该物品已在 ID 配置中` |
| 危险按钮 | `§c` | `§c清空全部物品 ID` |
| 最高危险 | `§c§l【…】` | `§c§l【最高危险】清空全部 ID 数据` |
| 选中态 | `§a✓ ` | `§a✓ 全部` |
| 未选中态 | `§c✗ ` | `§c✗ 箱子` |
| 启用/停用 | `§a` / `§8` | `§a设置` / `§8设置` |
| 已绑定/未绑定 | `§7已绑定 §f<N> §7个` / `§8暂未绑定` | — |
| 空占位 | `§8-` | — |
| 空态提示 | `§8` | `§8无匹配记录，请调整搜索或筛选条件` |
| 空态（列表内） | `§8` | `  §8无` / `§8无（资源包未发现或已全部选中）` |

**禁止**：状态标记与正文之间不加空格以外的修饰；不复用 `✓` 表示失败，不复用 `✗` 表示成功。

### 3.4 按钮语法

- 按钮宽度统一：`expandX().minWidth(200)`（基类 `addUniformButton`，常量 `BUTTON_MIN_WIDTH = 200`）
- 危险操作按钮前插入 `theme.horizontalSeparator()` 分隔线
- 说明入口按钮：`§e查看使用说明` / `§e使用说明`
- 返回按钮：`§7返回` / `§7关闭`
- 确认按钮：`§c§l确认`（可定制，如 `§c§l确认清空` / `§c§l确认全清空`）
- 取消按钮：固定 `§7取消`
- 重置按钮：`GuiRenderer.RESET`（旧框架内置图标 → **新项目必须自研图标替代**）

### 3.5 空值兜底

显示层绝不出现 `null` / 空串。统一兜底字：

- 通用：`无`
- 数值缺省：`§8-`
- 未绑定：`§8暂未绑定`
- 未就绪：`未就绪`
- 无法判定：`无法可靠确定（未猜测）`（方块作物态专用）

### 3.6 tooltip 语法

```
§<色>标题\n§7<说明行>
```

| 示例原文 |
|---|
| `§c缺失图标\n§7<诊断链>` |
| `§f<中文名>\n§7技术ID §8▸ §f<cropKey>\n§a成熟产物 §8▸ §f<produce>\n§7识别状态 §8▸ §7<evidence>` |
| `§7种子 §8▸ §f<seedDisplayName>\n§7技术ID §8▸ §f<seedModel>` |
| `点击打开「<类别名>」选择器` |
| `显示 / 隐藏「<对象名>」` |
| `删除当前服务器已绑定的全部点位（不可恢复，会二次确认）` |
| `只清这里的历史记录，不影响状态与聊天栏` |
| `概览页每秒自动刷新；其余页手动刷新（避免打断输入与阅读）` |

**tooltip 只承载"技术 ID / 诊断 / 完整值"**；主列表承载"看得懂的名字"。

### 3.7 输入框语法

- 搜索框：`theme.textBox("")`，`minWidth(400)`（星露谷选择器固定 420），**初始聚焦 `setFocused(true)`**，无占位文字
- 搜索框上方标签：`§7搜索（中文名 / 技术ID / 坐标）`
- 占位文字仅用于表单输入（如 `minecraft:diamond`）
- 表单输入框上方说明：`§7<说明>（如 §f§e<示例>§7）`

| `StardewCropLogisticsSetting` | `每种作物的后勤参数` | `对每种已选作物分别设置补货 / 卸货阈值。成品卸货触发 = 允许卸货的最低数量：达到后才会卸，实际时机在所有农田任务之后；背包空格不足时提前插队。取消选择不会丢失已保存的参数` | 可折叠区块 + 下拉 + 整数输入 + 恢复默认 |

**统一构成模式（4 种）**

1. **选择型**：`[按钮「选择/配置/点击选择」] [计数标签] [重置按钮]` —— 共 5 个控件用这套
2. **展示型**：纯标签（`InfoTextSetting`）
3. **图标型**：`[物品图标] [按钮] [摘要/计数] [重置]` —— 共 3 个控件用这套
4. **内嵌列表型**：图标 + 内联增删列表（`CustomEnchantSetting`）

**注册方式（旧项目）**：`SettingsWidgetFactory.registerCustomFactory(XxxSetting.class, theme -> (table, setting) -> ...)`

## 七、物品图标渲染清单

全部旧项目 UI 中，**仅 5 处**渲染原版物品图标：

| # | 位置 | 图标来源 | 实现方式 |
|---|---|---|---|
| 1 | `stardew/selector/StardewTargetSelectScreen` | 作物成熟产物 / 种子 / 工具 | `StardewPreview.of(itemModelId)` → `theme.item(stack)`；不可渲染 → `§8[?]` + 诊断 tooltip |
| 2 | `enchant/gear/GearEnchantScreen` | 当前装备 | `BuiltInRegistries.ITEM.getValue(id).getDefaultInstance()` → `theme.item(...)`；空/异常 → `ItemStack.EMPTY` |
| 3 | `EnchantmentSelectSetting` | 附魔书 | `Items.ENCHANTED_BOOK.getDefaultInstance()` |
| 4 | `CustomEnchantSetting` | 附魔书 | 同上 |
| 5 | `GearEnchantSetting` | 当前装备 | `currentIconStack()`（按 gearId 查注册表） |

**旧项目图标构造要点（`StardewPreview`）**

- 优先取注册物品默认实例
- 无 `ITEM_MODEL` 时补设 `DataComponents.ITEM_MODEL`
- 资源包缺 `assets/<ns>/items/<path>.json` 时判定不可渲染，**绝不渲染黑紫**
- `diagnose(itemModelId)` 输出完整诊断链供 tooltip 展示

**新项目现状**

新项目为 Skija 自绘，**当前全项目零物品图标渲染能力**（无 `ItemRenderer` / `renderItem` / `theme.item` 等价物）。

**建议实现路径**（待实机验证）

复用已有 GL 基础（参考 `ui/render/SkiaBlurRenderer.java` 的 `ensureCaptureTarget`）：

```
离屏 FBO（GL 纹理 + framebuffer）
  → 原版管线渲染物品（16 / 32 / 64 三档）
  → Image.adoptGLTextureFrom(context, textureId, GL_TEXTURE_2D, w, h, GL_RGBA8, BOTTOM_LEFT, RGB_888X)
  → 得到 Skija Image
  → 按 (物品ID, 尺寸) 缓存
  → canvas.drawImageRect 贴到面板
```

关键不确定点：26.1.2 的 GUI 为 extract 阶段新架构（`GuiGraphicsExtractor`），离屏渲染物品的具体 API 入口需实机验证。**此项为 ID 三件套及全部带图标选择器的前置阻塞项。**
