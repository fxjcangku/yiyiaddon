# 109 - 复盘：自动挖矿首次启动「传送被取消」被误判为传送成功，导致就地找矿挖

- 日期：2026-09-19
- 触发：用户实机复现 —— 自动挖矿首次启动时服务器 RTP 先进入「請勿移動」等待，玩家故意移动使服务器
  取消传送，结果模块判定「传送已生效」→ 进 MINING，人在原地由 Baritone 就地找矿挖
- 涉及文件：`feature/mining/fsm/MiningStateMachine.java`（单文件）
- 验证：`./gradlew build --console=plain -q` → **EXIT=0**；**未实机**

---

## 1. 根因（旧项目同款判据）

`tickGoWild` 判定「传送是否生效」用的是位置距起点：

| 位置 | 旧判据 | 后果 |
| --- | --- | --- |
| `tickGoWild` 阶段 3 | `Math.sqrt(distSqr(teleportStartPos)) > 2` → 传送生效，进 MINING | 玩家在「請勿移動」等待期自己走 2 格以上 → 判成传送成功，人还在原地就开始挖矿 |
| `tickGoWild` RTP 冷却分支 | 同上（冷却期内「传送才落地也算成功」） | 同一个坑：走动也能让冷却被提前结束 |

这段是逐字移植旧项目 `tickGoWild:272-320`。RTP 插件是两段式（先「請勿移動」、几秒后才「你已被隨機傳送」），
等待期玩家一移动，服务端就取消这次传送 —— 位置确实变了，但那是走路，不是传送。

## 2. 用户决策（2026-09-19）

- 范围：**只改 GO_WILD 两处**；卸货 / 补给 / 修补三处「超过等待时长还在起点 2 格内 = 指令无效」的
  指定点传送判据**本轮不动**（改动面更大，且它们的后果是「走 Baritone 去箱子」而非「就地乱挖」）。
- 阈值：**8 格**。玩家正常单刻位移最大约 1.5 格（鞘翅），8 格远高于它；服务器传送一瞬间完成，
  哪怕只挪几十格也必然超过 —— 能接住「传得近」的 RTP，不会因传得近而误判失败。

## 3. 实现

| 改动 | 说明 |
| --- | --- |
| 新增常量 `TELEPORT_JUMP_DISTANCE_SQR = 8×8` | 与 `MANUAL_TELEPORT_DISTANCE_SQR`（32 格，抓「玩家自己敲指令传送」）同族但更灵敏，注释写明两者为何阈值不同 |
| 新增状态位 `teleportJumpThisTick` | **由已有的 `manualTeleportDetected()` 每刻刷新**：复用它对 `lastWatchPos` 的单刻位移计算（第 169 条：同源判据不留两套），只在 `distSqr > 8×8` 时置位 |
| `tickGoWild` 阶段 3 | `distance > 2` → `teleportJumpThisTick`：只有服务器真把人挪走才算生效 |
| `tickGoWild` RTP 冷却分支 | 同样改看瞬移，冷却期内「走动」不再能提前结束冷却 |
| 顺带清理 | GO_WILD 阶段 1 里 `teleportStartPos` 的赋值已无读者（该状态不再用它），一并删除，注释同步；`reset()` 里清零新状态位 |
| 类注释 | 「本项目相对旧项目的有意差异」新增一条，写明两处判据改动 + 三处指定点传送未改 |

## 4. 行为变化

- **移动不再等于传送成功**：在「請勿移動」等待期自己走动，模块会判「传送未生效」→ 走原有超时逻辑
  （默认等 `传送等待时长` 8 秒 → 报「⚠ 传送未生效 ▸ 等待 60 秒冷却后重试 N/3」→ 冷却后重发指令）。
- 服务器真传送（含只挪几十格的 RTP、重生式传送）照旧立刻判成功并进 MINING。
- 玩家手动 /home 一类传送：仍由 `manualTeleportDetected()` 先抓住并停机（本轮未动）。

## 5. 验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew build --console=plain -q` | **EXIT=0** |
| 实机 | **未实机** |

复测清单：

1. 进服后启动自动挖矿 → 在服务器「請勿移動」等待期间**故意移动** → 应播报「⚠ 传送未生效」并进入
   冷却重试，**不会**就地开始挖矿；
2. 正常不干扰 → 传送照旧一次成功进 MINING（不应出现「传送明明成功却报未生效」）；
3. 顺带确认原有「挖矿途中敲 /home 会停机」仍正常（手动传送检测未动）。

## 6. 遗留

- 三个指定点传送状态（`UNLOADING` / `SUPPLY` / `REPAIR`）仍是「超过等待时长还在起点 2 格内 =
  指令无效」的原判据：玩家在那些等待期移动同样会被误判成「指令生效」，随后走 Baritone 去箱子/补给点。
  本轮按用户口径未改，若要一并收，需加一个「本次传送是否见过瞬移」的状态位把这 5 处统一。
- 重试体验：默认「传送等待 8 秒 + RTP 冷却 60 秒」决定了被取消后的等待偏长，可用设置项调整，
  本轮未改默认值。
- 全部改动**未 commit**。
