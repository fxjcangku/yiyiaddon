## 一、开发目标

建立 yiyiaddon 的模块展示体系，作为后续全部功能模块的统一接入入口。

本阶段只做四件事：

1. 模块展示系统；
2. 模块分类系统；
3. 模块注册系统；
4. 模块页面入口系统。

不做的事：不实现任何具体模块功能，不迁移旧项目模块，不实现自动化逻辑。

## 二、开源 UI 参考调研

开发前按需求先做了开源项目检索与设计分析，完整分析见
`02-开发报告/项目开发报告/2026-09-14-开源UI参考分析.md`。本节只摘录结论。

### 2.1 调研范围

检索方向：苹果系统风格、macOS 设置风格、iOS 控制中心风格、毛玻璃、半透明界面、
圆角卡片、模块列表、设置页面。筛选标准：开源、有明确许可证、有可查结构、与 Minecraft 可迁移。

### 2.2 参考项目

| 项目 | 技术栈 | 许可证 | 借鉴内容 |
| --- | --- | --- | --- |
| Atlas Client | Java / Fabric | MIT | 统一设计系统、分类到模块页面的三级信息架构 |
| LiquidBounce | Kotlin / Fabric | 待核对 | 模块自注册、UI 只读注册表、主题与 UI 分离 |
| glassmorphic_ui_kit | Flutter / Dart | MIT | 容器与卡片的分层、组件职责切分 |
| darwin-ui | React / Tailwind | MIT | 多层明度差营造毛玻璃层次 |
| glassmorphism 规范 | Markdown 规范 | MIT | 对比度、状态成组、空态与溢出处理要求 |
| GlassKit | CSS / Web Components | 待核对 | 派生式 token、状态必须成组定义 |
| Memos UI Kit | React / shadcn | 待核对 | 组件目录即样式的唯一事实来源 |
| ModernUI-MC | Java / Minecraft | LGPL-3.0 | 渲染层独立、背景模糊可开关 |
| React 系玻璃库（liquid-glass-react 等） | React / SVG | MIT | 模糊与折射的区分、高光描边做法 |

未参考实现、仅作反面对照：HUD420（保留全部权利，禁止参考代码）。

### 2.3 提炼出的原则

1. 单一事实来源：颜色只来自主题调色板，分类与模块只来自注册表。
2. 派生式 token：少量核心色派生全部交互色，换主题只改调色板。
3. 分层而非平铺：窗口 / 侧栏 / 内容 / 卡片 / 次级卡片五层明度差。
4. 组件化：底板、布局、卡片、徽章各司其职，页面只做组合。
5. 玻璃四件套：半透明填充 + 降采样模糊 + 1px 高光描边 + 大圆角，不做折射。
6. 状态成组：默认 / 悬停 / 按下 / 禁用同时定义，悬停用插值而非瞬变。
7. 层级导航：分类、模块列表、模块页面逐级进入，不在一页展开全部设置。
8. 可读性优先：文字取主题文字色，长文本截断，空列表给出空状态。
9. 动效克制：只做状态过渡。

本阶段**未复制任何开源项目源码**，借鉴内容限于信息架构、组件职责划分与设计原则。

## 三、UI 结构设计

左侧导航由原来的三项改为四项：

```
首页
模块
界面
设置
```

导航项顺序与路由根页面下标一一对应，由 `NAV_KEYS_ZH` / `NAV_KEYS_EN` / `NAV_ICONS` 三张常量表描述。
导航图标取自 Material Symbols：home(e88a)、extension(e87b)、tune(e429)、settings(e8b8)。

模块分支为三级下钻：

```
模块中心（分类卡片）
    └── 分类下的模块列表（模块卡片）
            └── 模块独立页面
```

下钻过程压入路由栈，内容区头部右侧出现返回按钮；按 ESC 与点击返回按钮都会退回上一级，
栈空时 ESC 才关闭整个界面。

## 四、页面结构

| 页面 | 职责 | 对应类 |
| --- | --- | --- |
| 首页 | 导航入口占位，概览内容待接入 | `HomePage` |
| 模块中心 | 展示全部功能分类卡片 | `ModuleCenterPage` |
| 模块列表 | 展示某分类下的模块卡片 | `ModuleListPage` |
| 模块页面 | 模块独立页面，未接入时用占位页 | `ModulePage` / `ModuleDetailPage` |
| 搜索 | 沿用既有搜索结果页 | `SearchResultsPage` |

卡片式页面共用一个基类 `CardPage`：负责两列网格几何、滚动偏移换算、命中判定与悬停强度插值；
子类只提供卡片高度、单张卡片绘制与点击行为。分类页与模块列表因此没有重复的布局代码。

模块列表页点击卡片的行为：

1. 读取 `ModuleEntry.page()`；
2. 工厂存在则调用 `ModulePage.createPage(entry)` 得到页面并压栈；
3. 工厂为空则压入 `ModuleDetailPage` 占位页。

卡片本身不展开任何设置，符合「点击模块必须进入独立页面」的要求。

## 五、模块数据结构

`ModuleEntry`（`com.yiyiaddon.module`）字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 模块 ID，全局唯一 |
| `name` | 模块英文名 |
| `displayName` | 模块中文名 |
| `categoryId` | 所属分类 ID |
| `description` | 模块描述 |
| `icon` | Material Symbols 图标码位 |
| `order` | 排序权重 |
| `version` | 版本信息 |
| `state` | 启用状态来源（`BooleanSupplier`） |
| `page` | 页面入口（`Supplier<ModulePage>`，可为空） |

实例通过内部 `Builder` 构造，注册点可读性优先。启用状态与页面入口是「取值来源」而不是取值本身，
因此模块中心只负责展示，不持有任何模块状态。

## 六、分类系统设计

`ModuleCategory` 为不可变记录：`id`、`displayName`、`description`、`icon`、`order`。

分类**不持有模块列表**。模块与分类的从属关系由 `ModuleRegistry` 单向维护，
避免同一份数据存在两个来源；分类卡片上的模块数量通过 `ModuleRegistry.countIn(categoryId)` 取得。

`CategoryRegistry` 按 `order` 升序返回全部分类，排序结果缓存，仅在注册新分类时失效。

---

## 七、注册系统设计

两个注册表均为静态表 + 计算结果缓存：

- `CategoryRegistry`：`register` / `byId` / `all` / `count` / `clear`。
- `ModuleRegistry`：`register` / `byId` / `all` / `byCategory` / `countIn` / `count` / `isEmpty` / `clear`。

缓存策略：

- `all()` 结果按「分类权重 → 模块权重 → ID」排序后 `List.copyOf` 缓存；
- `byCategory()` 结果按分类单独缓存；
- 任一次 `register` 都会整体失效，下一次读取时重建。

因此模块中心每次打开**不会重新扫描全部模块**，只读缓存。页面对象在打开界面时创建，
打开界面时即读到最新注册结果。

注册入口为 `AddonModules.bootstrap()`，在 `YiyiAddonClient.onInitializeClient()` 中调用一次，
内部保证幂等。当前注册内容：

- 6 个分类：自动化、辅助、工具、导航、附魔、星露谷（含描述、图标与权重）；
- 1 个**示例模块**：`auto_farm` / 自动农场，归属「自动化」。

示例模块只用于验证「模块列表 → 模块卡片 → 页面跳转」链路，
不含任何功能实现，也没有注册独立页面（点击进入占位页）。真实模块接入后可整段删除。

模块中心与模块列表页内不存在任何 `if (模块 == X)` 形式的判断。

## 九、未来扩展方式

新增一个功能模块只需两步：

1. 实现 `ModulePage`，返回自己的页面实例（可选，暂不实现则点击后进占位页）；
2. 在 `AddonModules` 中注册一条 `ModuleEntry`，填分类、名称、描述、图标、顺序、版本、状态来源与页面工厂。

模块中心、模块列表页、路由与卡片组件均不需要改动。

新增一个分类只需在 `AddonModules.registerCategories()` 中追加一条 `ModuleCategory`。

配色、圆角、间距仍由既有主题体系（`ClickGuiThemeColors` / `ClickGuiPalette`）统一提供，
本阶段未新增并行的主题系统；卡片外观全部封装在 `ui/component`，页面类不直接书写颜色值。
