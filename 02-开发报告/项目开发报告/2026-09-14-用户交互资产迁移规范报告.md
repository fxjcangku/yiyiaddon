日期：2026-09-14
类型：规范类报告（非阶段报告）
主题：旧项目用户交互资产完整基准 + 迁移兼容铁律

扫描范围：

| 项目 | 路径 | 说明 |
| --- | --- | --- |
| 旧项目 | `D:/mcaddon/26.1.2` | Meteor 客户端，业务包 `com.example.addon`，作为用户交互资产的唯一基准来源 |

## 零、本报告的核心结论（先看这条）

代码可以重构，架构可以升级，目录可以重排。**但旧项目的用户交互资产属于不可随意修改资产。**

本次扫描确认的事实：

1. 旧项目有 **11 条自定义指令**，前缀 `.`；新项目当前只有 4 条指令，其中仅 `.id` 一条对应旧项目。
2. 旧项目 `.id` 的子命令是**中文**（`物品` / `实体` / `方块`），新项目改成了英文（`item` / `block` / `entity`）。
3. 旧项目的指令回执走统一「卡片式」排版器（标题 + 字段 + 状态行，分隔符 `§8▸`），新项目改成了零散的单行文本。
4. 旧项目的模块播报前缀为 `§c§l[yiyiaddon]§r§f§l[模块名]§r`，新项目改成 `§8[§byiyiaddon§8] §r`。**前缀已由用户定稿**（第七章）：统一为 `§f§l[模块名]§r` + 正文，**不显示 `yiyiaddon`**，模块名段必须补回。
5. 旧项目的 5 个分类名带固定样式（`§c§lyiyiaddon §a§l工具` 等），新项目的 6 个分类名是另一套（`自动化` / `辅助` / `工具` / `导航` / `附魔` / `星露谷`）。
6. 旧项目 `ID识别` 与 `ID配置管理` 是**两个模块**，新项目合并成了一个 `ID识别与配置管理`，名称是新造的。
7. 用户 2026-09-14 定稿《用户交互消息显示规范》（第七章）：前缀用当前模块名（白色 + 加粗），**加粗作用于整条消息（前缀与正文均为加粗）**，状态颜色固定八种语义。该规范的八色与旧项目实际用色一致，**唯一冲突是前缀含 `yiyiaddon`，已裁决为不显示**。

以上差异**不是本报告要求立即回改的内容**（本阶段禁止修改业务代码），而是后续迁移必须遵守的基准与必须逐条核对的清单。

## 六、发现的问题

### 6.1 已被改写的用户交互资产（违反本次铁律的既成事实）

1. **`.id` 子命令主名由中文改为英文。** 旧项目子命令主名是 `物品` / `实体` / `方块`，新项目主名改成 `item` / `block` / `entity`。虽然保留了中文别名，但补全候选、`.help` 输出、后续所有文档都会以英文为主，与旧用户习惯相反。
2. **`.id` 裸指令行为从「显示帮助」变成「执行识别」。** 旧用户输入 `.id` 是查用法，新用户输入 `.id` 会直接触发识别动作（未启用时给出报错）。这是行为改变，不只是文案改变。
3. **`.id` 的 description 被改写。** 旧：`识别物品、实体或方块并保存ID（.id 物品 / .id 实体 / .id 方块）`；新：`识别物品、方块、实体并管理身份库`。
4. **识别成功提示被改写。** 旧：`§a§l✓ 已识别物品 §8▸ <显示名>` + 卡片字段；新：`§b物品识别：§f泥土`。
5. **识别失败提示被合并且丢失区分。** 旧项目区分 `玩家未加载` 与 `没有可识别物品：主手和副手都是空的`，新项目只有 `主手没有物品`。
6. **「已在 ID 配置中（稳定身份相同）」这一判定说明丢失。** 新项目只说 `未写入身份库（该身份已存在或写入失败）`，没有说明判定依据。
7. **回执排版器缺失。** 旧项目 `CommandMessageFormatter` 的卡片格式（标题 + `§8▸` 字段 + 状态行五级 `成功/处理中/警告/失败/信息`）在新项目中无对应实现，所有回执变成零散单行。
8. **模块播报前缀丢失模块名段。** 旧 `§c§l[yiyiaddon]§r§f§l[模块名]§r`，新 `§8[§byiyiaddon§8] §r`。**按第七章 7.1 的目标为 `§f§l[模块名]§r`**：`yiyiaddon` 段本就该去掉（用户已定稿禁止显示），但模块名段必须补回。
9. **模块开关措辞被改写。** `§a§l已开启` / `§c§l已关闭` → `已启用模块：X` / `已关闭模块：X`。
10. **资源链路两处细节被改写。** `§8 › ` → ` §8» `；`资源包…` → `资源包`；`星露谷资源准备失败` → `资源准备失败`。
11. **分类名体系被替换。** 旧 5 类带 `§c§lyiyiaddon ` 前缀与各自颜色，新 6 类为纯中文、顺序不同，且新增 `导航`/`附魔`、丢失 `绕过`。
12. **两个 ID 模块被合并为一个。** 旧 `ID识别` 与 `ID配置管理` 各自是独立模块（各自有独立设置与页面），新项目合并为 `ID识别与配置管理`。
13. **模块 description 被改写。** 旧：`识别手持物品或准星方块并加入ID配置。点击开启即识别。`；新：`识别物品、实体、方块，管理身份库与识别目标`。

## 七、用户交互消息显示规范（固定铁律）

本节为用户 2026-09-14 定稿的固定规范，已同步写入 `开发习惯.md` 第十七章（第 110-121 条）。**本节优先于本报告其它章节中与之冲突的表述**，特别是旧项目的前缀格式。

### 7.1 前缀显示规则

| 项 | 规定 |
| --- | --- |
| 前缀内容 | 统一使用**当前模块名称** |
| 前缀颜色 | 白色 `§f` |
| 字体 | **整条消息加粗 `§l`**（不限于模块名段，前缀与正文一律加粗） |
| 前缀格式 | `[模块名] 正文` |
| 示例 | `[自动农场] 收割完成`（`[自动农场]` 与 `收割完成` **均为加粗**；前者白色，后者取成功色绿色） |

**禁止显示**：`yiyiaddon`、旧项目插件前缀、内部项目名称。

实现口径：`§f§l[模块名] ` 之后直接接状态色即可保持加粗（`§` 颜色码不重置加粗），无需重复写 `§l`；确需在正文中途解除加粗时才用 `§r`，且必须重新指定颜色。

### 7.2 状态颜色规则（八种语义，固定不得改动）

| 状态 | 颜色 | 用色代码 | 适用范围 |
| --- | --- | --- | --- |
| 成功 | 绿色 | `§a` | 完成、成功、验证通过 |
| 失败 | 红色 | `§c` | 执行失败、错误、无法完成 |
| 异常 | 橙色 | `§6` | 异常情况、风险提醒、需要处理的问题 |
| 信息 | 蓝色 | `§b` | 普通状态、流程说明、信息提示 |
| 处理中 | 黄色 | `§e` | 等待、加载、执行中 |
| 调试 | 紫色 | `§d` | 调试信息、开发诊断 |
| 禁用 | 灰色 | `§7` | 未启用、不可用、无数据 |
| 重要 | 青色 | `§3` | 重要提醒、核心状态 |

**与旧项目用色的核对结果（本次扫描证据）**：该八色语义与旧项目实际用色一致，不构成冲突。

| 状态 | 旧项目实际用例（原文） | 用色 |
| --- | --- | --- |
| 成功 | `§a§l✓ 已识别物品 §8▸ <名>`、`§a资源检测完成` | `§a` |
| 失败 | `§c§l✗ 已删除标点 §8▸ <坐标>`、`§c星露谷资源准备失败：<reason>` | `§c` |
| 异常 | `§6未发现本地缓存，也没有可用的资源包下载地址，改用客户端已加载的服务器资源`、`§6⚠ 未观察到资源应用完成信号，按当前已加载资源继续解析` | `§6` |
| 信息 | `§b功能模块（共 N 个，启用 M 个）`、`§b物品识别：<名>` | `§b` |
| 处理中 | `§e正在下载当前服务器资源包…`、`§e正在解析资源…` | `§e` |
| 调试 | `§d§l乐源回服 §r§8[§f§l<step>§r§8/6] §r§f§l<message>` | `§d` |
| 禁用 | `§8未绑定`、`§7当前为只展示模式，未写入身份库` | `§7`/`§8` |
| 重要 | `§3§m═══════════════════════════════════` | `§3` |

补充约束：一条消息只用一个状态色；字段值用白色 `§f`，字段标签用灰色 `§7`，**两者同样保持加粗**（加粗沿整条消息延续）。

**加粗与旧项目的一致性核对**：旧项目状态文字本就是加粗（`§a§l已开启`、`§c§l已关闭`、`§a§l✓ 已识别物品`、`§e§l正在下载…`），故第 7.1 节「整条消息加粗」不是新增样式，而是与旧项目一致，无需另立例外。

### 7.3 与旧项目的唯一冲突点及处置

| 项 | 旧项目 | 本规范 | 处置 |

3. 用户交互层的差异，只能通过「旧文本优先」解决；如确认旧文本有错需要改，必须单独记录并说明理由，不得顺手改。

前缀与配色以本报告第七章（《开发习惯》第十七章）为准：前缀 `[模块名] 正文`，模块名白色 `§f`，**整条消息加粗 `§l`**（前缀与正文均加粗），**不含 `yiyiaddon`**；配色按八种状态固定语义执行。

### 8.2 迁移时逐条核对的方法

对每一个待迁移模块，按下面顺序执行，缺一项视为不合格：

1. **指令**：从本报告第一章查出该模块的指令名、别名、子命令、参数、帮助、错误、成功提示原文；实现后逐条比对，包括标点与 `§` 颜色代码。
2. **播报**：从本报告第二章查出该模块全部播报原文；实现后逐条比对。
3. **中文文本**：模块显示名、分类名、设置名、按钮文字、页面标题、说明文字，从本报告第三章逐条取原文。
4. **配置名**：设置项中文名、自定义 Setting 控件的按钮与计数文字、中文 JSON 写盘 key，从本报告第四章逐条取原文。
5. **排版**：指令回执必须走统一卡片格式（`§8▸` 分隔 + 五级状态），不得各模块自己拼字符串。
6. **前缀与加粗**：按第七章 7.1 输出 `§f§l[模块名]§r` + 正文，**前缀与正文整条加粗**。禁止出现 `yiyiaddon`；禁止丢失模块名段；禁止只加粗模块名段。
7. **配色**：按第七章 7.2 的八种状态固定语义用色（成功 `§a` / 失败 `§c` / 异常 `§6` / 信息 `§b` / 处理中 `§e` / 调试 `§d` / 禁用 `§7` / 重要 `§3`）。禁止自行换色、禁止一色多义。

### 待定稿 2：`ID识别` 与 `ID配置管理` 是否拆回两个模块
