### 2.3 模块系统

三层结构已经成型，且只有一个事实来源：

```
业务模块 feature/<模块>  （继承 core.module.Module）
        ↓ 声明元数据与能力
core.module.ModuleManager  （注册 / 开关 / 持久化 / 每刻派发 / 异常隔离 / 恢复与等待队列）
        ↓ 转换
core.module.ModuleEntries → module/ModuleRegistry（模块中心只读条目）
```

- 模块基类能力：元数据（ID、中英文名、分类、说明、图标、权重、版本）、生命周期（`onInitialize` / `onEnable` / `onDisable` / `onTick` / `selfCheck`）、事件（`subscribedEvents` / `onEvent`）、设置（`loadSettings` / `saveSettings`）、界面（`page`）、指令（`commands`）。
- 异常隔离：初始化 / 自检 / 启用 / 关闭 / 每刻 / 事件回调任一环节出错，都中文播报并自动关闭该模块，不影响其余模块；初始化失败者永久不可用。
- 状态恢复为三态：成功 / 条件未满足（进等待队列，不写回状态，进服事件与每 20 刻重试）/ 失败（写回关闭）。
- 注册入口唯一：`module/AddonModules.createModules()`；引导顺序为 分类 → 事件入口 → 模块 → 指令。

### 2.4 事件系统

- 唯一注册点：`core/event/EventDispatcher`；七个事件类型：每刻、进服、断线、收包、发包、界面打开、界面关闭。
- 收发包经 Mixin `ConnectionPacketMixin` 在网络线程入队（上限 4096，溢出计数丢弃），主线程每刻最多出队 512 条后派发；事件载荷只带包类名，不携带包对象。
- 订阅按 `module.<模块ID>` 所有者去重，重复启用覆盖、关闭时整批退订，结构上排除重复监听；监听异常按所有者归属到具体模块。

### 2.5 指令系统

- 前缀 `.`，聊天输入拦截用 Fabric 的 `ClientSendMessageEvents.ALLOW_CHAT`，不注入原版界面；未知指令名同样拦下并中文报错，不发往服务器。
- 已实现：`.help`（别名 h、帮助）、`.module`（m、模块）含 `list/on/off/toggle/status`、`.id`（identify、识别、身份）含 `item/block/entity/stat/mode`。
- 两级补全：指令名（含中文别名）→ 指令自报候选；唯一候选直接补全，多候选补公共前缀，无法推进时列候选（上限 30）；聊天框内 Tab 由 `ChatScreenCompletionMixin` 在 `.` 前缀时接管。

### 2.6 配置系统

两套配置严格分家（已写入规则第 91 条）：

| 配置文件 | 内容 | 归属 |
| --- | --- | --- |
| `config/yiyiaddon.json` | 界面外观、界面缩放、模糊参数、GUI 快捷键、Baritone 汉化开关 | `config/AddonConfig` |
| `config/module-state.json` | 模块启用状态、模块快捷键、模块设置 | `config/ModuleStateConfig` |

实测当前 `module-state.json` 内容：`identity` 模块 `启用=false`、`快捷键=90`（键盘 Z）、`设置={"识别模式":"CHAT_COPY","详细输出":false}`，字段与代码常量完全一致。写入走 `repository/JsonFileStore` 原子写，缺失/类型不符/损坏一律回退默认且不删原文件。此外 `config/identity/IdentityTargetConfig` 存身份目标选择。

### 2.7 UI 架构

- 屏幕：`ui/screen/ClickGuiScreen`（Skija 自绘）+ `ui/render/SkiaScreen` 基类，帧末经 `RenderTargetMixin` 直绘。

```
身份识别（已完成并接入模块）─┴─→ 资源内容探针（待做）
                                        ↓
                                  星露谷 / 任何资源驱动识别
容器/发包 ─→ 自动农场 / 自动箱子 / 挖掘 / 交易 / 附魔 / 星露谷 的物流与交互

```
