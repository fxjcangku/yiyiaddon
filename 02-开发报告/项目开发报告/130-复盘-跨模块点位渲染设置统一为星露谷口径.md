## 2. 为什么先抽共用件（第 169 条）

改造前星露谷把「显示 / 颜色 / 渲染模式」内嵌在自己的设置类里，其余五个模块各有一套写法
（自动挖矿是三个 ARGB 整数、村民交易是写死的 `ColorPresets` 预设、附魔是枚举里的固定 RGBA、
农场是散落的布尔 + `EspColor`、箱子是自带的 `EspStyle` + 三色）。六份同类逻辑意味着任何口径变更都要改六遍。

本轮新增三个共用件，六个模块只声明「我有哪几类渲染对象」：

| 文件 | 职责 |
|---|---|
| [EspRenderObject.java](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/ui/render/world/EspRenderObject.java) | 一类渲染对象的载体：`show` / `color`（`EspColor`，含彩虹）/ `mode`（`ShapeMode`）+ 出厂值 + 编解码（键前缀 `render.<对象名>.`，与星露谷历史键**完全一致**，老存档原样读回） |
| [RenderObjectScreen.java](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/ui/screen/RenderObjectScreen.java) | 「渲染设置 · 对象名」窗口：显示 / 颜色 / 彩虹 / 渲染模式，每行自带 ↺（星露谷原窗口 1:1 抽公用件） |
| [PointRenderSection.java](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/ui/console/PointRenderSection.java) | 点位页「显示与颜色」小节的唯一装配处：`title()` + `rows()`（每类对象一行：显示开关 + 「设置」+ ↺）+ `labelSizeRow()` |

**星露谷同步改为使用共用件**：`StardewSettings.RenderObject` 内嵌类删除，10 个渲染对象改用 `EspRenderObject`；
`StardewRenderObjectScreen` 整文件删除（由 `RenderObjectScreen` 取代）；`StardewRenderState.RenderOption`、
`StardewPointPage` 一并改为共用件。落盘键、默认值、调色板迁移与老键名兼容（`LEGACY_RENDER_NAME` /
`LEGACY_PALETTE`）**一字未改**，因此星露谷老存档与实机观感不变。

## 6. 明确保留 / 未做

- **农场点位1 / 点位2 两个字牌**不进渲染对象（它们不是箱子、也没有对应设置项），颜色 `§a/§e` 与字号 10 维持现状。

  （旧代码固定 `1f` 忽略色里的 alpha）。文字、色值、字号均未变。

| 加粗 | 统一前缀 `§l`；`MinecraftText` 的 `measure` 与 `draw` 都认这个码（切粗体字族并量准宽度），因此加粗后仍然居中 |

对外三个入口：`containerLabel`（容器：名字 + 维度 + 距离）、`nameLabel`（选点：只有名字）、

## 13. 维度认不出来一律显示「自定义维度」（用户 2026-09-19 第七条）

### 13.1 用户原话与影响面

- 「所有模块吗，如果识别不出来维度，有一些服务器是自定义的，你就显示自定义维度就好了。」

**答案：是，六个模块全部生效**，因为它们只把「名字」交给共用件 `PointLabelText`，维度由共用件自己拼。

### 13.2 改前的两个毛病

1. `WorldIdentity#dimensionDisplayName` 用 `contains("overworld")` 这类**模糊匹配**：自定义维度只要键里含这串字
   （如 `mypack:overworld_nether`）就会被误判成原版主世界。
2. 认不出时**直接把技术键甩到屏幕上**（`mypack:custom_dim`），字牌里就成了 `[mypack:custom_dim]种子箱[12m]`。

### 13.3 改法：只留一套规则

| 位置 | 改前 | 改后 |
|---|---|---|
| `WorldIdentity#dimensionDisplayName` | `contains` 模糊匹配，认不出回退原始键 | **委托** `WorldContextFormatter#dimensionDisplayName`（规则只此一份，第 169 条） |
| `PointLabelText#text` | 调 `WorldIdentity` 的旧逻辑 | 直接调 `WorldContextFormatter#dimensionDisplayName` |

规则链（`WorldContextFormatter` 既有实现，本次未改）：**原版三维度精确匹配**（`minecraft:overworld` /
`the_nether` / `the_end`，先脱掉历史遗留的 `ResourceKey[...]` 包装）→ 查语言文件 `dimension.*` /
`dimension_name.*` 且译文含中文 → 兜底 **「自定义维度」**。

### 13.4 连带影响（有意）

- 六个模块的**字牌**：自定义维度显示 `[自定义维度]名字[距离]`。
- 模块内**卡片 / 控制台 / 命令回执**里凡是走 `WorldIdentity` 的维度行（挖矿、自动箱子、附魔、身份、星露谷、
  首页等）一并跟着改口径：自定义维度不再显示技术键。
- 农场 / 村民模块原本就走 `WorldContextFormatter#dimensionSummary`，自定义维度显示
  「自定义维度（维度 ID：mypack:xxx）」—— 那是短行显示保留技术键的既有设计，本次未动。

### 13.5 验证

- `.\gradlew build --console=plain` → **BUILD SUCCESSFUL（EXIT=0）**。
- **未实机**：待进自定义维度服务器看字牌是否为 `[自定义维度]…`，原版三维度仍显示中文名。
