### 2.2 GEAR 模式完整流程（文档第 3 节）

```
装备箱（按 gearTargetItem 类型过滤，每批取用数量默认 4）
  → 读取 JSON 目标（GearEnchantSetting.currentProfile → TargetProfile）
  → 附魔台（装备 QUICK_MOVE 到 slot 0 + 青金石 slot 1 + 点击附魔）
  → 读实际附魔（DataComponents.ENCHANTMENTS 完整解析）
  → 评估评分（EnchantEvaluationService.evaluate）
       ├─ complete(100%) → 成品箱
       ├─ 可合并         → AnvilPlanner 规划铁砧合并
       └─ 凑不齐         → 砂轮磨掉全部 → 重新附魔重试
  → 铁砧「装备+装备」合并（互补 / 不互斥 / 不冗余）
  → XP 判断（附魔台固定 30 级 / 铁砧 AnvilMenu.getCost 实际费用）
  → XP 不足 → 挂机刷经验（KillAura）→ 达标 gearReturnState 返回
  → 铁砧继续 → JSON 最终验证（STRICT 100%）
  → 成品箱（卸货前重新验收 + 卸货成功确认）
```

**关键**：铁砧合并的是**装备 + 装备**（叠加附魔凑齐目标），不是「空白书 → 附魔书 → 装备」；装备模式**零依赖**附魔书生产流程。

**顶层可见性由 `同步模式分组()` 决定（`AutoEnchantBook.java:635-649`，实测）**：

```java
List<SettingGroup> ordered = new ArrayList<>();
ordered.add(sgBasic);                                              // 恒在
if (mode == TargetMode.CUSTOM) ordered.add(sgAdvanced);            // CUSTOM +1
if (mode == TargetMode.CUSTOM) ordered.add(sgCustom);              // CUSTOM +2
if (mode == TargetMode.BOOK)   ordered.add(sgVanilla);             // BOOK  +1
if (mode == TargetMode.GEAR)   ordered.add(sgGear);                // GEAR  +1
if (settings.groups.equals(ordered)) return;                       // 幂等保护
settings.groups.clear(); settings.groups.addAll(ordered);
```

→ 也就是说 **18 个分组里顶层只会同时出现 2~3 个**（`基础设置` + 当前模式的 1~2 个），其余 13 个是页内折叠子组（`addSelector(名字, 源组, 目标组, 可见条件)`，`:592-600` 把源组的每个 `BoolSetting` 收进一个 `EnchantmentSelectSetting`）。

> **幂等保护不可省**（原文注释保留）：顺序一致时直接 return，否则 `目标模式.onChanged` 在 `Modules.load / Settings.fromTag` 遍历 `settings.groups` 期间同步 clear+addAll 会抛 `ConcurrentModificationException`，**导致启动闪退**。新项目换成控制台页签后，同样要避免「遍历页签时重建页签列表」。

### 2.8 挂机刷经验的具体做法（实测 `AutoEnchantBook.java` 1120~1154、1989~2020）

```
tickWalkToFarm  → 到挂机点 → State.FARMING
tickFarming     → restoreHangoutView() 恢复挂机视角
                → equipSweepingSword()：找「横扫之刃」剑并切到手上
                → startKillAura()：KillAura ka = Modules.get().get(KillAura.class); if (ka != null && !ka.isActive()) ka.toggle();
                → 经验达到目标（GEAR：gearTargetXp；其余：30 + 3×(单轮抽取次数-1)）→ stopKillAura() → 回到 gearReturnState
```

两个移植注意点：
1. `equipSweepingSword()` 是**按 tooltip 文本包含「横扫之刃」**来找剑的（`TooltipFlag.NORMAL` 取 tooltip 逐行 `contains("横扫之刃")`）→ 依赖中文语言环境；移植时保持原判据（换成本项目术语表里的正式译名，逐字对齐）。
2. 剑不在快捷栏时用 `handleContainerInput(..., ContainerInput.SWAP, ...)` 换进当前槽；在快捷栏则直接 `setSelectedSlot`。
3. `startKillAura()` 只是 **toggle 对方模块的开关**，KillAura 自己的设置（范围、目标类型、切武器等）由玩家在它自己的面板里配 —— 所以复刻的 KillAura 必须**有独立的设置面板**，不能做成"内部写死的最小攻击"（这也是用户要求「一比一复刻」的原因）。
