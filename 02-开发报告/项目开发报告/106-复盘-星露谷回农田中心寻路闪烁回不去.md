## 2. 现象与机理

状态行永久停在「返回农田 ▸ 正在前往农田中心」，游戏里 Baritone 的路径线高频闪烁、角色原地不动，
约 12 秒后播报「无法继续寻路」。四层叠加，缺一层都不会发病：

1. **中心点被抬到空中**。回中心目标取 `Region.center()` = `(中点X, maxY()+1, 中点Z)`
   （`StardewRegionManager.java:108-111`）。这个 `+1` 沿用的是旧项目 START/END 点（记的是**地面层**）的口径；
   而本项目的区域是**点方块圈出来的**，在这些服务器上作物载体（甘蔗等空碰撞方块）与**玩家脚层同层**（y64），
   再 `+1` 就落到 y65 —— 该列 y64 是甘蔗，**脚下没有任何支撑面**。
2. **回中心用的是全模块最严的一套判定**：`navigationRadius()==0`（必须站进那一格）
   + `CENTER_REACH==0.85`（必须贴到格子中心 0.85 格内）。目标格站不住 → `GoalNear(半径 0)` 数学上无解，
   Baritone 算不出任何可落地路径。
3. **失败即重发**：`calcFailed` 时 `CustomGoalProcess.onLostControl()` 把 `state` 清成 `NONE`，
   于是 `FarmNav.pathing()`（`isPathing() || customGoalProcess.isActive()`）返回 false，
   `navigate()` 下一 **_tick_** 就重发同一目标 → 计算永远打不完。
   Baritone 在计算期间渲染的是 `bestPathSoFar`（`baritone/utils/PathRenderer.java:120-130`），
   这就是玩家看到的「路径线一直闪」。
4. **兜底变成循环**：80 刻无进展 → `cancelPath()` + `retryCount++`；3 次用尽 → 拉黑该目标 10 秒并播报
   「无法继续寻路」；10 秒后再派发，还是同一个站不住的中心点 → 无限循环。

## 4. 修复

| 文件 | 改动 |
| --- | --- |
| `feature/stardew/task/StardewTaskPlanner.java` | `regionCenter()` 选出最近区域后，把几何中心落到**站得住的格子**：新增 `standableCenter()` —— 中心列自上而下 → 四邻各自自上而下，最多向下 `CENTER_STAND_DROP=3` 格，落点 XZ 必须仍在该区域内；全部候选都站不住时回退几何中心，保留原有重试 / 拉黑 / 播报兜底 |
| `feature/stardew/navigation/ContainerApproachPlanner.java` | 把「人能不能站在这一格」抽成唯一一份 `public static boolean standable(BlockPos)`（脚下有真实支撑面 + 脚 / 头两格无碰撞 + 玩家碰撞箱不撞世界），`legalStand()` 复用它 —— 后勤外围站位与回中心落点同源，禁止各写一份 |

没有改区域 Y 语义（`Region.center()` 仍是纯几何）：区域 Y 还参与扫描范围与已有存档，
就地落地的改动面最小，也不会让老区域失效。

## 7. 遗留

- **同类风险点**：任何「只按几何算出来的落点」都可能站不住（不止回中心）。将来给别的模块加固定站立点类目标时，
  一律先过 `ContainerApproachPlanner.standable`。
- 区域 Y 语义（点方块得到作物载体层）与旧项目 START/END（地面层）不同源，属于本项目的分区种植口径，
  本次未改；若以后要让区域 Y 直接等于「可站层」，需要同时回归扫描范围与既有存档。
- 全部改动**未 commit**。
