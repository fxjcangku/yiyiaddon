## 3. 根因（第 167 条取证）

| 项 | 证据 |
| --- | --- |
| 潜影盒菜单不是 `ChestMenu` 子类 | `01-开发参考库/Minecraft原始源码/net/minecraft/world/inventory/ShulkerBoxMenu.java:9` `class ShulkerBoxMenu extends AbstractContainerMenu`；其容器槽 27 格 + `addStandardInventorySlots` 36 格 |
| 旧判据只认 `ChestMenu` | `EnchantContainer#chestMenuOpen` 旧实现：`mc.player.containerMenu instanceof ChestMenu` |
| 槽位遍历同样只对箱子成立 | 状态机 6 处 `(ChestMenu) mc.player.containerMenu` 强转 + `handler.getRowCount() * 9`（`getRowCount()` 只有 `ChestMenu` 有） |
| 点位绑定明确允许潜影盒 | [EnchantBindingService#isValidTarget](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/enchant/service/EnchantBindingService.java#L186-L187)：`getBlockEntity(pos) instanceof Container`，失败文案「必须设置为箱子、木桶或潜影盒容器」 |
| 自动挖矿/自动箱子不受影响 | 它们走 `ContainerAccess.openMenu()`（判 `containerId != 0`）+ `slot.container != 玩家背包`，本来就与菜单类型无关 |

**故障链**：潜影盒成品箱 → 界面其实已开（`ShulkerBoxMenu`）→ `chestMenuOpen()` 恒 false →
`tickGearStoreOutput` / `tickStoring` 停在 `!chestMenuOpen()` 分支 → `guiPhase==0` 每 tick 重发一次开箱包
（= 用户看到的「一直重复打开」）→ 永远进不到 `QUICK_MOVE` 那一相（=「成品放不进去」）。

## 4. 修复（最小改动，2 个文件）

| 位置 | 改动 |
| --- | --- |
| [chestMenuOpen](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/enchant/service/EnchantContainer.java#L233-L245) | 改为 `return ContainerAccess.openMenu() != null;`——平台层唯一实现（`containerId != 0` 即服务端已推来方块容器菜单），本类不再自带第二份判据（第 169 条） |
| [containerSlotCount](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/enchant/service/EnchantContainer.java#L247-L256) | 新增「容器本体槽位数 = `slots.size() - 36`」，取代 `getRowCount() * 9`；[containerSlotOf](file:///d:/mcaddon/yiyiaddon/src/main/java/com/yiyiaddon/feature/enchant/service/EnchantContainer.java#L104-L118) 改为复用它（同一来源） |
| 状态机 6 处 | `ChestMenu handler = (ChestMenu) mc.player.containerMenu;` → `AbstractContainerMenu handler = mc.player.containerMenu;`；`handler.getRowCount() * 9` → `container.containerSlotCount(handler)`。涉及 `tickStoring` / `tickRestocking` / `tickGearTakeGear` / `tickGearRestockLapis` / `tickGearTakeAnvil` / `tickGearStoreOutput`；`ChestMenu` 导入随之删除，新增 `AbstractContainerMenu` 导入 |

覆盖范围：**五个箱类点位全适用**（成品箱 / 书本箱 / 青金石箱 / 装备箱 / 铁砧箱）；箱子（27）/ 大箱子（54）/ 木桶（27）
的槽位数与改前数值完全一致（`rows*9 == slots.size()-36`），无行为回归。

## 8. 遗留与风险

- `chestMenuOpen()` 从「按菜单类」放宽到「任何非玩家背包的容器菜单」：理论上玩家在模块搬运相中手动开出
  其它容器界面时会被当成目标容器。该风险与改前同源（改前玩家手动开箱子同样会被误认），且模块在这几个相位
  统一静默容器界面（`SilentContainer` + `shouldSuppressScreen`），实操不可达；沿用自动挖矿 / 自动箱子的既有口径。
