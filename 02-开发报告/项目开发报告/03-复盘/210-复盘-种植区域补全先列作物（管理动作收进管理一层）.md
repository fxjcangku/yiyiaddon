# 210 · `.stardew 种植区域` 补全先列作物（管理动作收进「管理」一层）

- 日期：2026-09-22
- 触发（用户原话）：「还有这里的 .stardew 种植区域 为什么会出现 列表 取消那些 不应该是先提示种子吗
  太多用户看着很乱」（附 TAB 补全截图：`列表 / 删除 / 取消 / 混种 / 清空 / 菠萝 / 选择`）
- 规范同步：[36-规范-分区种植.md](../01-规范与UI规格/36-规范-分区种植.md) 第十节（指令全集与 TAB 补全）

## 一、现象与成因

`.stardew 种植区域 <TAB>` 一屏给 7~8 条候选：6 个固定管理字面量 + 已勾选作物（截图里是「菠萝」），
两种性质的东西混在一起 —— 玩家想圈地（主用途），却要先在管理词里找自己的作物。

成因就在补全实现里：第二层把 `REGION_ACTIONS`（选择 / 混种 / 取消 / 列表 / 删除 / 清空）与
`module.selectedCropCompletions()` 直接拼接：

```java
List<String> candidates = new ArrayList<>(REGION_ACTIONS);
if (module != null) candidates.addAll(module.selectedCropCompletions());
```

## 二、改动

1. **分层**：管理动作收进 `管理` 一层 —— `.stardew 种植区域 管理 列表 / 管理 删除 <序号> /
   管理 清空 / 管理 取消`；第二层只列 **已勾选作物 + `选择` / `混种` / `管理`**。
2. **旧写法保留可用**：`.stardew 种植区域 列表` 这类省略 `管理` 的写法照常执行
   （`region()` 里 `管理` 只是把参数指针后移一位），**只是不再出现在补全里**。
   理由：补全要干净，但已养成的习惯不该被一次性打断 —— 语法是兼容的，变的只是"推荐路径"。
3. **文案同步**：无参时的提示面板（`管理 列表` / `管理 删除 <序号>` …）、
   `删除` 缺参时的示例（`.stardew 种植区域 管理 删除 1`）、模块帮助页那一行、
   《36-规范-分区种植》第十节与 TAB 补全说明，全部改成新写法 —— 避免"补全教一套、文档说另一套"。
4. `删除` 的序号补全两条路都给：`管理 删除` 之后、以及旧写法 `删除` 之后。

## 三、验证

- `GetDiagnostics`：`StardewCommand.java` / `StardewFarmModule.java` 均 0 诊断。
- 待实机：进服后敲 `.stardew 种植区域 ` + TAB —— 应只看到已勾选作物与 `选择 / 混种 / 管理`；
  再敲 `.stardew 种植区域 管理 ` + TAB —— 应看到 `列表 / 删除 / 清空 / 取消`；
  旧写法 `.stardew 种植区域 列表` 仍应正常列出区域。

## 四、教训

1. **补全是"推荐路径"，也是收敛点**：把不同性质的字面量混在一屏，玩家要先分类再选。
   主用途（圈地）排前面、管理动作收一层，是零成本的顺序改法，不需要动语法。
2. **能不动语法就不动**：分层只放在补全与文案层，`管理` 在解析层只做"参数指针后移"，
   旧写法继续有效 —— 玩家不会因为一次 UI 优化而敲不出原来的命令。
3. **文档与补全必须一起改**：规范文档、模块帮助页、提示面板、补全四处是同一件事的四种呈现，
   改一处漏三处，下次玩家照着文档敲又会对不上（第 240 条同源逻辑只留一份的精神）。
