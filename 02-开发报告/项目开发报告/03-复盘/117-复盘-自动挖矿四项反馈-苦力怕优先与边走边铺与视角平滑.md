## 一、用户报的四项（原话要点）

1. 身边一只苦力怕 + 一只蜘蛛时，先去打蜘蛛，结果打蜘蛛的过程中苦力怕贴到身前要爆炸——要求优先处理苦力怕；
2. 填岩浆时会「罚站放」，要求边走边放（或给更好的方案并执行）；
3. 更正 116 号的口径：「静止隔墙挖」是**仅仅不隔墙挖**，不是不捡掉落物——「物品掉到墙后的原因就是隔墙挖，修好隔墙挖就好」；
4. 视角跟随仍有轻微抖动不流畅（走路时），要求继续优化。

## 二、逐项取证与改动

### 2.1 苦力怕优先（战斗目标分级 + 抢占锁定）

**取证**：`MiningCombat#scanThreat` 只按**距离**取最近怪（原 `:356-366`），而 `lockedTarget` 口径是「锁住就不换，直到它被了结」（2026-09-18 定）。于是先锁蜘蛛就会一直打蜘蛛，苦力怕（3 格点燃引信、1.5 秒炸）在旁边无人处理。

| 文件:行 | 改动 |
| --- | --- |
| `feature/mining/fsm/MiningCombat.java:391-406` | 新增 `threatPriority(LivingEntity)`：`0` 引信点燃的苦力怕 → `1` 苦力怕 → `2` 其它怪（判据 `getSwellDir() > 0`，与 `tickCreeper` 同源） |
| `feature/mining/fsm/MiningCombat.java:338-380` | `scanThreat` 改为「先比危险等级、同级再比距离」 |
| `feature/mining/fsm/MiningCombat.java:453-470` | `tickCombat` 新增**抢占**：扫描到的目标等级高于已锁目标时换锁（清 `chaseTicks`、`lastPathKind` 让寻路立刻按新目标重发），并播报「优先处理 xxx ▸ 暂停当前目标」 |

同级或更低等级**不抢占**，「锁住就不换」的原口径保留（否则会来回换目标、两个都打不死）。

### 2.2 垫脚实现「边走边放」（不再停 Baritone）

**取证**：`MiningStateMachine#tickMining` 触发垫脚时先 `baritone.stop()`（原 `:1413`），于是整轮站着铺；`finishBridging` 再 `startMining` 把人拉回来。用户的「罚站」即由此而来。

| 文件:行 | 改动 |
| --- | --- |
| `feature/mining/fsm/MiningStateMachine.java:1412-1428` | 触发分支**删掉 `module.getBaritone().stop()`**：人沿路径继续走，每刻填够得着的岩浆格 |
| `feature/mining/fsm/MiningStateMachine.java:1926-1949` | `finishBridging` 删掉「重启 mine」两行（本轮从没停过 Baritone，重发等于白重启），javadoc 同步 |
| `feature/mining/fsm/MiningStateMachine.java:991-996` | Stage 1 起 mine 的「垫脚期间不下发 mine」避让删除（该避让的存在前提是 Baritone 被我方停着；现在必须让它照常重启，否则 mine 退出后没人重新下发、人站着不动） |
| `feature/mining/fsm/MiningStateMachine.java:1096-1105` | mine 看门狗豁免从「连锁 **或** 垫脚」收窄为「连锁」：垫脚期间不再是我方主动停 Baritone，mine 真退出就该照常重启 |
| `feature/mining/fsm/MiningStateMachine.java:504-532` | 注释与常量说明同步（`BRIDGE_MAX_PLACES_PER_ROUND` / `BRIDGE_ROUND_COOLDOWN_TICKS` 的旧理由作废重写） |

保留不变：每刻最多 4 块（`BRIDGE_PLACES_PER_TICK`）、一轮 16 块、两轮间隔 2 秒、连锁进行中与秒破激活时不触发垫脚（三者都要写主手）。播报文案维持原样（「垫脚过岩浆 ▸ 开始铺设通路」/「✓ 垫脚完成 ▸ 继续挖矿」）。

### 2.4 视角跟随的轻微抖动（转向平滑）

**取证**：66 号复盘第 7 节已预留这一步——随机偏移清零后，男中音仍是**每刻直接跳到**「下一个路径节点」方向，节点切换（转弯 / 上下坡 / 绕障碍）就是一次阶跃。用 `javap` 核对 Baritone jar 的 `LookBehavior` 字节码确认：`smoothLook = true` 时写入的是**最近 `smoothLookTicks` 刻目标角度的滑动平均**（双端队列 + `stream().average()`），否则直接写瞬时目标角；`Settings.smoothLook`（默认 false）与 `Settings.smoothLookTicks`（默认 5）均存在。

| 文件:行 | 改动 |
| --- | --- |
| `feature/mining/navigation/MiningPathing.java:81-82` | 新增 `originalSmoothLook` 原值字段 |
| `feature/mining/navigation/MiningPathing.java:356-395` | `applyViewFollow`：跟随开启时 `smoothLook = true`（关闭时还原原值，不覆盖玩家/男中音的设置）；javadoc 写明原理与代价（转向滞后约 5 刻 ≈ 0.25 秒） |
| `feature/mining/navigation/MiningPathing.java:405-417` | `restoreViewSettings` 一并还原 `smoothLook`（模块关闭不留副作用） |

战斗期间视角走 SERVER 静默分支（`setCombatViewHold`），与平滑无关；挖矿对准不受影响（服务端只校验距离与 sequence，不看客户端朝向）。

## 四、影响面

- 只动自动挖矿模块（战斗拦截 / 垫脚推进 / 视角下发）与其用户可见文案；无新增设置项、无新增指令、无落盘结构变更。
- 垫脚不再停 Baritone 后，主手会与 Baritone 的自动选工具、秒破的换工具在同一刻交替（放置同刻切回并还原），最坏情况是服务端某 1 刻按方块速度计破坏进度;因此保留「连锁进行中 / 秒破激活时不触发垫脚」的避让与两轮间隔。
- 视角平滑会带来约 0.25 秒转向滞后；若觉得不跟手，可关掉「寻路视角跟随」或调 Baritone 的 `smoothLookTicks`。
