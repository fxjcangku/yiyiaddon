## 一、问题：口径只学了「动作」，学不到「手持什么」

各服口径不止左键 / 右键两种，实际有四种形态：

| 服形态 | 动作 | 手持 | 改前的行为 |
| --- | --- | --- | --- |
| jmy（巨型作物） | 左键破坏 | 不限（空手也行） | 对：破坏分支走 `ensureDigTool`，拿什么都能挖 |
| 老服（金番茄） | 右键 | 原版金锄头 | 对：靠 `specialHarvestTool()` 写死的那件 |
| 某服 | 左键破坏 | 必须手持某件专用道具 | **错**：破坏分支从不换到那件，服务端驳回 |
| 某服 | 右键 | 自定义道具（不是原版金锄头） | **错**：观测门槛写死「必须手持原版金锄头」→ 永远学不到；执行只找金锄头 → 提示缺工具 |

硬编码点：`StardewFarmExecutor#specialHarvestTool()`（写死 `Items.GOLDEN_HOE`）、
`MultiPlayerGameModeSpecialHarvestMixin` 的右键观测门槛。

## 二、口径模型：动作 + 手持

- 新记录 [StardewSpecialHarvestRecipe](../../../src/main/java/com/yiyiaddon/feature/stardew/profile/StardewSpecialHarvestRecipe.java)：
  `动作` = 左键破坏 / 右键，`手持` = 不限 / 原版物品（只记本体 ID）/ 自定义道具（记身份键）。
- **工具怎么认**：带自定义名 / 显示名 / 模型的道具（资源包里同基底的自定义镰刀、锄头）按
  `ItemIdentifier.coreKeyOf` 的身份键比 —— 只按本体认会拿错那一把（第 167、194 条）。
- **学习**：Mixin 把「玩家当时的动作 + 主手那件」一起上报，空手 = 不限；
  比对口径改成「动作 + 手持」都比（否则玩家换了工具重收一次不会被记录）。
  观测门槛不再要求金锄头：真正的滤网是既有证据链「那一格确实被收掉」（方块 / 展示实体身份变了）。
- **执行**：
  - 手持 = 不限：左键走 `ensureDigTool`（有工具就挑最快的、带效率附魔的优先；没有就空手挖），
    右键用当前手，不换手；
  - 手持 = 指定：先从背包 0~35 + 副手按口径找那件并换到手；**破坏期间锁住不换手**
    （新增 `specialToolHold`，`ensureDigTool` 读到它就直接返回、不挑工具 —— 服务端认「拿的就是那件」）；
  - **找不到那件**：只播一条提示 + 跳过这一格，不停机、不拿别的工具硬试，
    拿到后下一轮扫描自动继续（用户要求「不影响收割其他的菜」）。
- **默认值**：没学过也没预置 = 老口径（金锄头右键）；永不自动试探左键（不可逆）。
- **存档 v1 → v2**：一条口径从「动作」扩成「动作 + 手持」；v1 旧档按旧语义补齐
  （右键 = 原版金锄头、破坏 = 不限），行为与升级前逐字一致。

## 三、预置本服的三种巨型变种

服包 `jmy.seasonmc.xyz_25565.zip`（指纹 `b2e4560efd20`）里地里能长出来的变种模型只有 4 个：
`gigantic_cabbage` / `gigantic_pineapple` / `gigantic_tomato`（巨型三件）+ `stage_golden` / `golden_tomato`（金番茄，本服只有番茄有金色阶段）。

新类 [StardewSpecialHarvestPresets](../../../src/main/java/com/yiyiaddon/feature/stardew/profile/StardewSpecialHarvestPresets.java)
按**服务器键**（`jmy.seasonmc.xyz:25565`）预置 3 种巨型 = 左键破坏 + 工具不限（学习者实测口径，
工具身份类口径不写进预置）。预置只做兜底：学习档案优先，换服 / 换包互不影响。

> 服包里 `*_silver_star` / `*_golden_star`（各 11 种作物）是**产物品质**图标，不是地里变种；
> `fertilizers/variation_1~3` 是变异肥料 —— 都不需要特殊收割动作。

## 五、按服务器的「记忆」（用户 2026-09-22 追加确认）

用户确认设计意图：「按服务器学是对的 是要让脚本有 记忆 下次去到新的服要适配」。落地形态：

1. **记忆的键** = 服务器 + 资源指纹 + 作物 → 文件落在
   `StardewFarm/special-harvest/<服务器>/<指纹>.json`，读时复核文件里的服务器与指纹：
   换服 / 换包天然空白，不需要额外「忘记」逻辑。
2. **换服 / 换包**：`configure()` 检测到服务器或指纹变化即 `specialHarvestRules.clear()` + 重读档案，
   运行期去重集（已学过 / 未知口径 / 缺工具 / 砸不掉）由 `reset()`（停机 / 换世界必经）清空。
3. **新服适配 = 玩家示范一次**：新服默认只按最保守的老口径（金锄头右键）动手，绝不自动试左键
   （不可逆）；玩家手动收一棵后写进该服档案并播报。
4. **同服只需示范一次**（本轮追加）：新学到的口径同时写进本服「通用口径」键 `"*"`，
   本服其它还没学过的变种先按它收 —— 不必为每种作物各示范一次。
   通用口径**只在第一次学到时写入**（`putIfAbsent`，先到者为谁）：同服确实存在形态各异的变种时，
   后学到的只更新自己的专属记录，不会顺手把通用口径改成左键（左键不可逆，这个风险不留）。
   查找顺序：作物专属记录 → 本服通用口径 → 本服预置 → 老口径默认。
5. **工具匹配不看附魔**（用户 2026-09-22 追加：「跟效率有什么关系？效率只是挖的快而已
   工具对得上就行」）：工具身份键改用 {@code ItemIdentifier.coreKeyWithoutEnchantmentsOf}
   —— 与 {@code coreKeyOf} 共用同一份身份判据，只把附魔那一维置空；以后给那件工具附魔 / 改附魔等级，
   模块照样认得是同一把。附魔只影响挖得快不快（挑工具时由 `effectiveDigSpeed` 负责），
   不参与「是不是同一件工具」的判断。

## 七、教训

1. 「口径」在真实服上至少是二维的（动作 × 手持），只学一维时看似正确的写死值，换服必错。
2. 学习门槛要架在**结果证据**上，不要架在「手持什么」这种表层特征上：
   本轮把「必须手持金锄头」的门槛删掉后，自定义工具的服才可能学到；防误学仍由「那一格确实被收掉」兜住。
3. 记忆的粒度要跟「服务端说了算的东西」对齐：动作 / 工具按服务器隔离，
   同服内的通用性用「通用口径 + 专属覆盖」表达，而不是把口径写死在代码里。

## 八、后续候选：新服「自动适配」（用户 2026-09-22 提出，先记着）

用户追问「为什么要我自己挖？」—— 即希望去新服时模块自己适配，而不必等他手动示范一次。
本轮**不做**（用户指示：修好现在的 bug 再谈），先把方案与代价记在这里：

- 触发条件：口径未知（本服无专属记录、无通用口径、无预置）。
- 顺序（风险从低到高）：① 右键（先金锄头 → 背包里其它锄 / 镰类 → 空手）→ ② 左键破坏（工具不限）。
- 判据仍然是硬的：那一格**真的被收掉**（方块 / 展示实体身份变了）才算数，立即落盘并升级为本服通用口径。
- 兜底：各步只试有限次；都不行 → 退避 + 提示（与现在一致）。
- 开关：设置项「新服自动适配特殊变种收法」（计划默认开、可关）；关掉即回到现在的「玩家示范一次」模式。
- 代价（必须写进设置项说明）：新服第一次遇到变种时模块会自己动手闯一步 ——
  最坏情况是把那一棵成熟变种提前收掉 / 砸掉（产物照掉），甚至碰到别的玩家种的东西；
  所以默认顺序是「先右键（不破坏方块）、后左键」。
- 实现落点（届时）：`StardewTaskPlanner` 的 SPECIAL 分支 + `StardewFarmExecutor` 的特殊收割分发
  加一个「未知口径试探」子状态机，证据链复用 `tickSpecialObservation` 的 cellSnapshot 比对。
