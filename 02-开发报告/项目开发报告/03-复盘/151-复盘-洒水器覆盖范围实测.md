# 151-复盘-洒水器覆盖范围实测（数湿盆反推真实范围）

日期：2026-09-21
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件

用户在自己的星露谷服（jmy.seasonmc.xyz）实机质疑：

> 洒水器的范围是真实的？我觉得没对齐资源包

并给出方案：

> 我加这个「覆盖范围实测」吗？做法是绑定洒水器（或 `.stardew` 一条命令）时扫周围盆的干湿、
> 把结论写进点位文件，没测出来之前仍用现在的等级猜测兜底

## 二、取证

### 1. 现状：范围是硬猜的

`StardewRenderState.radiusOfLevel(level)` 是**写死的等级表**（1 → 1、3 → 2、4 → 3，其余 1），
形状一律正方形，注释自认「仅供观察」。资源包（`customcrops` 系）里**没有**任何范围字段，
`blockstates` / 模型 / 语言文件都不带「这台盖几格」，所以这条数据不可能从资源包读出来——
用户看到的「没对齐」不是解析 bug，是猜的本来就不准。

### 2. 本服可用什么反推

磁盘上的点位档（`run-26.1.2/StardewFarm/points/jmy.seasonmc.xyz_25565.json`）：

```
sprinkler 4797,85,-5597   customcrops:sprinkler_1  世界载体 = minecraft:air（展示实体渲染）
sprinkler 4797,85,-5603   customcrops:sprinkler_2  世界载体 = minecraft:air
seedbox   4793,85,-5600 / output 4807,85,-5600 / water 4800,84,-5600
```

而种植盆（`minecraft:note_block`，识别为 `dry_pot` / `wet_pot`）在 **y=84**，作物在 y=85——
即本服洒水器是**摆在盆上**的，盆层 = 洒水器层 - 1。

`CropRecognizer.recognizePotDetailed` → `PotState.DRY / WET` 早已存在（扫描器、浇水判定都在用），
**围着洒水器数一圈湿盆**就是真实范围的直接证据，不需要资源包、也不需要服务端配合。

### 3. 为什么只认湿盆

干燥盆可能只是「刚收完还没浇水 / 刚换过土」，把它当「没被覆盖」会把范围算小。
因此只把**湿润**的盆记为覆盖证据，干燥盆只统计一个数字供播报参照，绝不参与范围推导。

## 三、改动

### 1. 新增 `SprinklerCoverage`（唯一的实测入口）

[SprinklerCoverage](../../../yiyiaddon/src/main/java/com/yiyiaddon/feature/stardew/point/SprinklerCoverage.java)：

- `capture(origin)`：扫以洒水器为中心的 9×9 窗口（`SCAN_RADIUS = 4`），每列先看**下一格**、
  再看**洒水器那一格**（覆盖「摆在盆上」与「摆在地上」两种服）；
- **一盆湿的都没有就返回 `null`**：那是「没测到」，绝不能写成「实测 1×1」，调用方继续用等级估算；
- 只存**相对偏移**（`dx,dz` 打包成 long），不存方块坐标——点位换维度 / 挪位置后结论依然成立；
- 隔离域与人工绑定同源：存 `serverKey` + `资源指纹`，`appliesNow()` 不一致自动失效；
- 派生量全部现算、不落盘（`dxMin/dxMax/dzMin/dzMax`、`width/depth`、`truncated()`、`covered()`），
  外接矩形按定义**恒包含洒水器自己那一格**（洒水器常就摆在一个盆上，那格可能是干的）；
- 按 `BlockState` 记忆化盆型解析：9×9×2 = 162 格若每格都去读一次资源包 `blockstates`（无缓存），
  绑定瞬间会明显卡顿，记忆化后实际只解析两三种方块状态。

### 2. 点位档新增「实测范围」（`StardewPoint` / `StardewPointManager`）

```
"实测范围": { "服务器": "jmy.seasonmc.xyz:25565", "资源指纹": "b2e4560efd20",
              "范围": ["-1,-1", "0,-1", ...], "矩形内干盆": 0 }
```

`StardewPoint` 增加 `sprinklerCoverage` 字段 + `withCoverage()` + `measuredCoverage()`
（后者统一做隔离域校验，渲染与统计一律走它，不直接读字段）。单格格式写坏只跳过那一格，
不让一个坏值废掉整份实测；老档没有这个字段时读成 `null`（继续等级估算），绝不把老档当实测。

### 3. 绑定即实测 + `.stardew 实测范围 [清除]`

- `StardewPointActions.addSprinklerFromCrosshair`：绑定成功后立刻实测一次（玩家此刻就在旁边，
  代价最小），成功就把结论一并写进点位；失败不影响绑定，播报如实写「未测出（仍按等级估算）」。
- 新指令 `.stardew 实测范围`：对当前维度全部已绑定洒水器逐台重测并落盘，每台一行
  「实测 5×5 · 湿盆 9 格（等级估算 3×3）」——这一行就是「到底对齐没对齐」的答案。
- `.stardew 实测范围 清除`：清掉实测结论退回等级估算（实测被污染时的退路，不用删点位重绑）。
  该分支**不做资源闸门**：它是退路，资源没就绪也必须敲得动。

### 4. 渲染与统计：实测优先，等级兜底

- `SprinklerEspRenderer`：`renderCoverage` 改为接收 `Function<BlockPos, AABB>`；几何统一收进
  `coverageBox(pos, radius)` 与 `coverageBox(pos, dxMin, dxMax, dzMin, dzMax)` 两个重载
  （等级估算与「附近洒水器预览」原本各写一份 AABB 算式，迟早会出现「预览 5×5、已绑定 3×3」）。
- `StardewRenderState.sprinklerCoverageBox`：有实测就画**实测外接矩形**（可以不对称、不居中，
  那正是真实范围的样子），没有才回退 `sprinklerRadiusAt` → `radiusOfLevel`。
- `StardewFarmModule.regionSprinklerInfo`：实测的洒水器只算 `covered(dx,dz)` 真正被浇到的格，
  **不拿外接矩形虚报面积**；没实测的仍按等级方形算。
- `StardewSprinklerListScreen` 悬停补一行「覆盖 实测 5×5（湿盆 9 格）/ 未实测（按等级估算）」。

## 五、口径与边界

- **实测不参与任何决策**：范围只用于渲染与覆盖率展示，补水 / 维护 / 收割判定一律照旧走点位与资源包身份。
- **不自动重测**：只在「绑定」与「显式敲指令」两个时刻测。洒水器可能某天没工作、盆全干，
  自动重测会把「今天的状态」写成结论；换服 / 换资源指纹后旧结论自动失效，需要重新测一次。
- **顶到扫描边界会标出来**（`truncated()`）：9×9 已经比等级表上限（7×7）多一圈，
  真有大范围洒水器时播报里会写「顶到扫描边界，实际可能更大」，不会被当成精确结论。
