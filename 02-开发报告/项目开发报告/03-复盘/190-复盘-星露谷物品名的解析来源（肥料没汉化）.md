# 复盘：星露谷物品名的解析来源（肥料没汉化 → 包语言表 + 实测学名双源）

- 日期：2026-09-22
- 触发：用户实机截图「星露谷服务器解析的肥料没汉化」——「选择肥料」界面里一排技术名
  （`soil_retain_2`、`speed_grow_3`、`quality_3`、`yield_increase_3`…），并追加要求
  「我要做到每个星露谷物语解压资源包精准识别并翻译 包括种子那些」
- 结论：工具类（肥料 / 药剂 / 水壶 / 洒水器 / 种植盆 / 温室玻璃）的显示名原先只有**一条**来源
  ——「客户端已加载的语言表」（{@code Language.getInstance()}）。它有两个先天缺口：
  1. 只包含「游戏当前语言 + **已被客户端应用**的那份资源」，服务器资源包被「暴力绕过」跳过、
     或玩家还没接受推送时，这里什么都查不到；
  2. 只按当前语言取一份，服务器把物品名写进别处（例如原版命名空间的语言文件、或插件自己的命名空间）
     也拿不到。
  于是名字全丢，退回技术名。与此同时，**实测学名**（服务器自己下发、玩家在游戏里看到的名字）
  早就被记录下来了，却只接给了作物，工具类没接 —— 两处一起造成「肥料没汉化」

## 一、取证（本次全部来自真实资源包，不靠推测）

| 检查项 | 结果 |
| --- | --- |
| 出问题的服务器 | `play.moexd.com:25565`（第一次截图）与 `jmy.seasonmc.xyz:25565`（第二次截图，客户端日志 22:16 进服、22:17 资源检测完成） |
| 该服务器的资源包长什么样 | `run-26.1.2/yiyiaddon_resourcepacks/play.moexd.com_25565.zip`（6167 条目）：**物品与模型路径被整体混淆** —— 命名空间是 `1m`/`663v`/`9z` 这类随机串，文件名叫 `..json`，模型指向 `z1wusi:8jsr/x9u/.`；`assets/customcrops/` 下只有 23 张贴图 + 1 个 font json，**没有任何 items / models**；2085 个 `assets/*/items/*.json` 里**没有一个**引用 customcrops |
| 中文名在哪 | `assets/minecraft/lang/zh_cn.json`（58 KB）里有 **105 条** `item.customcrops.*`：`quality_1`=基础肥料、`soil_retain_2`=优质保湿土壤、`speed_grow_3`=超级生长激素、`yield_increase_3`=高级增产剂、`variation_1`=初级魔法药剂、`tomato_seeds`=… —— **语言键是按逻辑名写的，与被打乱的模型路径无关** |
| jmy 的包呢 | `jmy.seasonmc.xyz_25565.zip`（2730 条目）：**没有** `assets/minecraft/lang/zh_cn.json`，全包只有 5 条 customcrops（3 个作物模型 + 2 张贴图）—— 这台服**没有任何可读的名字来源**（与文档里「jmy 的包用 `minecraft:paper` 阈值表派发全部种子与工具」的记载一致） |
| 学名库里已有什么 | moexd：`quality_1`=品质肥料 Lv.1、`yield_increase_1..3`=丰收肥料 Lv.1..3、`watering_can_2`、`dry_pot`、`greenhouse_glass`…；jmy：只有 18 条（作物 + 水壶 + 洒水器 + 盆 + 玻璃），**没有肥料与药剂** —— 学名靠「在背包 / 容器 / 田地里实见物品」学习，玩家没露过面的物品学不到 |
| 为什么这些名字没用上 | `StardewResourceIndex#resolveDisplayName` 的行序是「绑定身份 → 扫描名（按模型路径查 Language）→ 文档化兜底 → 逻辑名」，**学名只接给了作物**（`cropName` 里那一行 `StardewCropNameStore.nameOf(stem)`），工具类走不到它；而扫描名在「模型路径被混淆 + 客户端没应用该包」时必然为空 |
| 种子受影响吗 | 受影响同一根链路：种子名走 `ScannedModel#displayName`，语言键查不到就只剩 `<作物>种子` |

## 二、改动

### ① 新增 `StardewPackLang`：直接把资源包的语言文件读成表（`feature/stardew/profile/`）

1. 来源与优先级（前者先占）：**当前生效资源包**（`ResourcePackAccess#packsByPriority()`，高优先级在前）
   → **本模组下载落盘的服务器资源包 ZIP**（`ResourcePackCache#cachedZip`，只补前者没给出的键）。
   第二个来源是给「包没被客户端应用但我们已经下载了」这种情况兜底。
2. 语言优先级 `zh_cn` → `en_us`；命名空间探测 `minecraft` / `customcrops` / `default`
   （实测服务器最爱把物品名覆盖进原版的 `zh_cn`）。
3. 只保留三类键：`item.` / `block.` / `plugin.customcrops.`（后者是服务端插件写的规则文案，
   作物 × 盆型分组要读；其余上万条与模组无关，丢弃省内存）。
4. 缓存按「生效包列表 + 缓存 ZIP 的大小/时间戳」签名，签名变了才重读；读取全程吞异常，
   拿不到名字只是退技术名，绝不让索引构建失败。
5. 对外两个入口：`get(键)`（规则文案）、`itemName(命名空间, 逻辑名)`（物品名，
   **整条路径扁平化与末段名都试**）。

### ② `StardewResourceScanner#resolveLocalizedName`：包语言表优先，再查客户端语言表

- 顺序改为「包语言表 → `Language`」；两处都补上**末段名**形态的查找。
  原先只把整条路径扁平化（`crops/tomato/tomato_seeds` → `item.customcrops.crops.tomato.tomato_seeds`），
  而服务器语言键普遍只认末段（`item.customcrops.tomato_seeds`）—— 漏掉末段就白白丢名字。

### ③ `StardewResourceIndex#resolveDisplayName`：接入学名，并拒绝技术名冒充名字

新行序：**绑定身份 → 学名 / 包语言表（带汉字的优先）→ 扫描名 → 文档化兜底 → 逻辑名**。

1. 学名（`StardewCropNameStore`）现在对**全部七类**生效，不再只有作物。键的形态逐个试：
   聚合键（`dry_pot_-1`）→ 去掉归一序号（`dry_pot`）→ 原始末段名。
2. 「带汉字的优先」：学名与包语言表都是服务器真相，但只写了 `en_us` 的包语言表是英文名，
   那种情况下该用玩家在游戏里看到的名字 —— 两者都拿到时挑含汉字的那份（`Character.UnicodeScript.HAN`）。
3. 新增 `packedName`：**按逻辑名**查包语言表（`item.customcrops.quality_1`）。
   光靠扫描阶段按模型路径查不够 —— 模型被混淆、物品定义不在 `items/` 下的服务器，
   聚合槽可能是「真实身份」单独建出来的，压根没有扫描名。
4. 新增 `meaningful`：与逻辑名 / 末段名相同、或形如 `item.<ns>.<名>` 语言键原文的候选名一律**丢弃**。
   这是「技术名冒充名字」的判据 —— 绑定身份里存的就是 `quality_1` 这类技术名，
   不挡掉就等于没汉化。

### ④ 盆型维度声明也改走包语言表

`installCropPotGroups` 原先读 `Language` 的 `plugin.customcrops.crops.<作物>.not_met_requirement.message`
（判断「只能种在下界 / 末地」）。改为「包语言表 → `Language`」，包没被应用时也能拿到服务器自己的规则。

### ⑤ 肥料 / 药剂补「官方译名」兜底档（第二轮，用户 2026-09-22 复测「还是没汉化」后追加）

第一轮改完仍在 `jmy.seasonmc.xyz` 上失效 —— 取证发现这台服的包**连 {@code item.customcrops.*}
语言键都没有**（`assets/minecraft/lang/zh_cn.json` 不存在，全包 2730 条目里只有 5 条 customcrops：
3 个作物模型 + 2 张贴图），学名库里也只有 18 条（作物 / 水壶 / 洒水器 / 盆 / 玻璃，**没有肥料与药剂**
——玩家没在背包 / 容器里露过面就学不到）。三档全空 → 无档可退 → 只剩技术名。

处置：把 CustomCrops 本体 4 族肥料 × 3 阶 + 药剂 3 阶的**官方译名**补进 `documentedName` 这一档
（与既有的盆 / 水壶 / 洒水器 / 玻璃同级，仍是最低优先级）。数据来源不是记忆，而是**五台不同服务器的
资源包语言文件逐字一致**的 15 条 `item.customcrops.*`：

| 家族 | 1 | 2 | 3 |
| --- | --- | --- | --- |
| `quality_` | 基础肥料 | 优质肥料 | 高级肥料 |
| `soil_retain_` | 基础保湿土壤 | 优质保湿土壤 | 高级保湿土壤 |
| `speed_grow_` | 生长激素 | 高级生长激素 | 超级生长激素 |
| `yield_increase_` | 基础增产剂 | 优质增产剂 | 高级增产剂 |
| `variation_`（药剂） | 初级魔法药剂 | 中级魔法药剂 | 高级魔法药剂 |

取自 `202.189.10.38_52599` / `long.kkwmc.cn_25565` / `mcwf.top_25565` / `play.moexd.com_25565` /
`tingwanmc.top_25565` 五份 `assets/minecraft/lang/zh_cn.json`，五份完全相同。台账里的
「不写死数量语义」原则在此处的边界是：**写的是名称表（官方译名），不是按数量生成语义**；
家族前缀与阶数都由资源包自身的模型键给出（`soil_retain_2`），认不出的前缀（服务器自建肥料）
一律返回 {@code null}，绝不编名字。

## 三、验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew.bat compileJava` | **EXIT=0** |
| 实机验证 | **已通过**（用户 2026-09-22 截图：`选择肥料` 显示「优质保湿土壤 / 超级生长激素 / 高级生长激素 / 高级肥料 / 基础保湿土壤 / 优质肥料 / 高级增产剂 / 优质增产剂…」；`选择魔法药剂` 显示「初级 / 中级 / 高级魔法药剂」） |

复测要点：
1. 进一个星露谷服务器（`play.moexd.com`）→ 打开「选择肥料 / 魔法药剂 / 水壶 / 洒水器 / 种植盆 /
   温室玻璃」：条目应是中文名，不再是 `soil_retain_2` 这类技术名；
2. 打开作物选择器：种子列应为中文（如「番茄种子」），作物名为中文；
3. 日志里应出现一行 `[资源包语言] 已读取 N 条（生效资源包 + 服务器缓存 ZIP）`——N>0 说明表读到了；
4. 只写 `en_us` 的包（英文语言文件）应仍优先显示游戏内中文名（学名），而不是英文名。

## 四、能力边界：哪些拿得到中文名、哪些拿不到（回答用户 2026-09-22「现在是不是所有有星露谷资源的都能准确识别了」）

名称解析顺序（先到先用）：**绑定身份 → 学名（实测）→ 资源包语言表（任意命名空间，`zh_cn` 退 `en_us`）
→ 扫描名（按模型路径）→ 官方译名兜底 → 技术名**。

| 情况 | 结果 |
| --- | --- |
| CustomCrops 官方标准物品（4 族肥料 × 3 阶、药剂 × 3 阶、盆、水壶、洒水器、温室玻璃） | **任何服务器都能出中文名**（最后一档是官方译名表，不依赖资源包） |
| 服务器带语言文件的物品（`item.customcrops.*` 写在 `minecraft` / `customcrops` / `default` 命名空间） | **出中文名**，读的是包内语言文件（不依赖客户端是否应用了该包），高优先级包先占 |
| 服务器把物品改名（如 moexd 的「品质肥料 Lv.1」） | 出**游戏内实际名字**（学名优先，且「带汉字的优先」避免只写 `en_us` 的包把中文压成英文） |
| 服务器资源**没有任何语言文件** + 官方译名表覆盖不到的**自建**物品 | **拿不到中文名**，显示逻辑名（技术名）。出路：玩家在背包 / 容器 / 田里让它露一次面（学名自动学会），或在「身份绑定」里手工绑一次 |
| 被整体混淆、且派发关系也读不到的包 | **列不出来**（不是名字问题，是识别不到该物品）——这类包连模型都拿不到，本模组无法凭空列出 |

一句话：**标准物品 100% 中文，服务器自建物品要靠「包里有语言键」或「游戏里见过一次」**，
两者都没有时保留技术名而不是编一个名字（宁缺毋滥）。
