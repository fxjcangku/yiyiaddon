## 二、26.2 侧 cherry-pick：冲突只有两类，判据只有一条

`git cherry-pick 81f1f9a` 在 worktree `D:\mcv\wt-262` 上报 8 个冲突文件。动手前先把 26.2 线的在途现场
入库（`c780b41`），否则 cherry-pick 直接拒绝执行（工作区改动会被覆盖）。

冲突**全部**落在两类上，没有一处是业务逻辑分歧：

| 类别 | 文件 | 处理 |
| --- | --- | --- |
| 26.2 官方 API 换名 | `StardewRegionListScreen` / `StardewSprinklerListScreen` / `StardewPointPage` / `ModuleKeybindManager` / `SkiaBlurRenderer` / `GuiRendererMixin` | 采 master 的业务逻辑，形式换成本线 API |
| 注释里提到的旧类名 | `ItemIconCache`（3 处） / `SkiaScreen`（2 处） | 保留本线注释（提到的是本线真实存在的类） |
| 删/改冲突 | `RenderTargetMixin.java`（本线已删、master 改过） | `git rm`，本线由 `MinecraftFramePresentMixin` 取代，且 `yiyiaddon.mixins.json` 只登记后者 |

本线 API 与 26.1.2 的对应关系（本次又确认了一遍）：

```
Minecraft#getMainRenderTarget   → GameRenderer#mainRenderTarget
Minecraft#setScreen             → Minecraft#gui.setScreen
Minecraft#screen                → Minecraft#gui.screen()
GuiRenderer#render              → 去掉雾缓冲参数 GpuBufferSlice
RenderTargetMixin               → MinecraftFramePresentMixin（注入点迁移，mixin 配置同步）
```

**踩到的坑**：解决冲突时按 API 表换了 `client.gui.setScreen(...)`，但**漏了同一处方法体里的
`client.screen` 读值**（`canTrigger` 与 `trigger` 各一处），`compileJava` 直接报「找不到符号 变量
screen」。教训：26.2 的界面入口改名是「读」和「写」两个方法，换的时候必须两个一起换，
`Minecraft#gui` 这层的 `screen()` 是方法不是字段。

## 六、下一次可以少踩的地方

1. 两线同步前**先看在途现场有没有改动**，有就先入库再 cherry-pick，省得被拒一次；
2. 26.2 的 API 换名要**成对检查读写两侧**（`screen` 字段 vs `gui.screen()`），编译过一遍再 continue；
3. `RenderTargetMixin` 这类「改/删」冲突别手工改内容 —— 认 `yiyiaddon.mixins.json` 里登记的是谁，
   另一个直接 `git rm`；
4. 覆盖上传后**必须回读线上摘要**，本地 `build/release/` 的包只是「最近一次构建」的结果。
