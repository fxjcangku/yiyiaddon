# 160-复盘-洒水器范围自学（读物品说明的「工作范围」）

日期：2026-09-21
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件

用户实机截了三种洒水器的物品说明（本服「季明月种植」包），说明里明明白白写着范围：

```
初级洒水器  储水总量 3   工作范围 5 * 5    单次加水 5
中级洒水器  储水总量 5   工作范围 9 * 9    单次加水 5
高级洒水器  储水总量 9   工作范围 13 * 13  单次加水 5
```

随后用户提出「我现在进别的服务器都能正确识别材质包了，你可以帮我加强一下算法」，并选定方向：
**洒水器范围改成读物品说明**。

159 那轮只是把等级表从「原版攻略的 1/1/2/3」改成「照这份说明反推的 5/9/13」—— 仍然是**写死的**。
换个服务器改了配置就又错了。这一轮把范围变成**从实物上自学**。

## 二、方案

### 新类 `StardewSprinklerRangeStore`（profile 包）

- **数据来源**：`DataComponents.LORE` 与渲染出来的 tooltip（与
  `StardewInventoryService#readWaterCapacity` 同一口径：部分服务器的数值是动态替换的，只有 tooltip 里才是最终文本）。
- **解析**：只认含「范围」的行，用 `(\d{1,2})\s*[*×xX＊乘]\s*(\d{1,2})` 取一对数字；
  单边限 3~31（更小说明这行没写范围，更大说明读错了行）。**读不出就什么都不写**。
- **隔离域**：`StardewFarm/sprinkler-ranges/<服务器>/<指纹>.json`，原子写；换服 / 换包各读各的。
- **只学不猜**：`ensureLoaded()` 在会话键未就绪（主菜单 / 断线）时返回 false 并清内存 ——
  绝不拿上一台服务器的范围给这一台画框。
- **对外**：`observe(key, stack)` / `rangeOf(key)`（偏移 `{dxMin,dxMax,dzMin,dzMax}`）/ `sideText(key)`（`5×5`）/ `learned()` / `reset()`。

### 自学时机（两条路，互补）

1. **识别那一刻顺手学**：`StardewPointActions#sprinklerOfDisplay` 认出展示实体是洒水器后立刻
   `learnRange(definition, stack)` —— 预览扫描 / 绑定 / 错位检查都会走到，零额外扫描。
   顺手抽出了 `sprinklerOfStack(ItemStack)`（世界展示实体与背包共用同一条判据链）。
2. **常驻节流扫一遍**：`observeSprinklerRanges()` 每 40 刻（2 秒）扫玩家背包 + 副手 + 附近 16 格的
   物品展示实体，认出是洒水器就学。**按用户「摆台 / 绑定常发生在停机状态」的实际情况，
   订阅挂在模块构造函数里（独立 owner `module.stardew.range-observe`），不挂在 `onEnable` 的 tick 上**
   ——否则模块没开就永远学不到。已学到的身份直接跳过，稳态下这一拍几乎零开销。

### 三个来源的可信度（定版口径只写一处）

`StardewRenderState#coverageRange(identity, measured)`：

1. **点位实测**（`SprinklerCoverage`，世界里数湿盆）—— 最贴近实际，会被「整片地都湿着」干扰；
2. **物品说明**（`StardewSprinklerRangeStore`）—— 服务器自己声明，精确、跨服；
3. **等级表**（`radiusOfLevel`）—— 前两者都没有时兜底。

消费点全部改走这一份口径：

- `StardewRenderState#sprinklerCoverageBox`（已绑定覆盖框）；
- `StardewRenderState#renderNearbyPreview` + 预览字牌（未绑定的台，多写一个来源：
  `初级洒水器 · 5×5（物品说明）`）；
- `StardewFarmModule#regionSprinklerInfo`（分区覆盖率：实测只算湿格，物品说明只给方形，整块算）；
- `StardewPointActions#coverageText(coverage, key, level)`（绑定播报与 `.stardew 实测范围` 卡片的对照来源）；
- `StardewSprinklerListScreen#coverageHint`（列表 hover：「未实测（按物品说明 5×5）」）；
- `.stardew 诊断` 新增一行「洒水器范围 ▸ N 种（物品说明自学）：初级洒水器 5×5、…」——
  换服最想知道的就是「这台服务器的范围学到了没」。

`onResourceInvalidated` 里与学名同源地 `StardewSprinklerRangeStore.reset()`。

## 四、第一轮实机：诊断「未学到」的三种成因（2026-09-21 03:39）

用户重启后回诊断仍是「未学到」。查日志发现真因不在自学链：

```
[03:39:42] 诊断 资源 ▸ 未检测 · 指纹 无
[03:39:42] 诊断 索引 ▸ 作物 0 · 盆 0 · 肥料 0 · 药剂 0 · 水壶 0 · 洒水器 0 · 温室玻璃 0
[03:39:42] 诊断 洒水器范围 ▸ 未学到
[03:39:42] 诊断 展示物 ▸ 4797, 85, -5603 customcrops:item/sprinklers/sprinkler_2(无)、…（4 台都在眼前）
```

**这一会话根本没跑资源检测**（`资源 ▸ 未检测 · 指纹 无`），索引是空的 → 洒水器身份判据无从匹配 →
`observe()` 一次都不会被调用（所以连「自学未命中」的日志都没有）。同一会话再往前（03:35）资源是
`就绪 · 指纹 b2e4560efd20`，那是上一轮跑过检测的状态；重启客户端后需要重跑。

处置（不是加功能，是让「未学到」这句诊断不再含糊）：

1. `StardewQuerySupport#sprinklerRangeLine` 拆成三种说法 ——
   `资源未就绪（索引里没有洒水器）· 先跑一次资源检测` /
   `未学到（本会话还没认出过洒水器实物）· 走近一台站两秒` /
   `未学到（已认出 customcrops:sprinkler_1，但物品说明里没有「工作范围 A * B」）`。
   三者处置完全不同，含糊成一句就会像这次一样白折腾一轮。
2. `StardewSprinklerRangeStore` 增 `observedKeys()`（本会话认出过实物的身份）作为上面第二条判据；
   另加「自学命中 / 自学未命中」各一行日志（每身份每会话一条，不刷屏）；
   未命中**不放弃**——背包 / 箱子里的那一份可能带说明，下次见到还会再试。
3. `observeSprinklerRanges` 增扫**打开的容器槽位**（前 128 格）：玩家的洒水器多半存在箱子里，
   而真机证据显示**展示实体上的物品栈是精简副本**（取证日志里洒水器展示物的名字是空的，
   稻草人展示物却有名字），说明文字很可能只挂在完整物品上。

## 六、口径校正：说明写的是「能力上限」，不是实际覆盖（2026-09-21 04:10）

学到三种范围后，我把画框口径改成「物品说明 > 实测」，结果四个框变成 5×5 / 9×9 / 13×13 ——
用户当场否掉：**「这也太大了吧？根本浇不到那么多水」**（截图：13×13 的框铺出整块田）。

结论：说明里的「工作范围 13 * 13」是这台洒水器的**能力上限**（最多能带多大一片田），
不是它当前实际浇到的范围；这一层语义原始文本里没有，只能靠实机反馈定。实测给的
`5×5 · 湿盆 24 格` 才是「实际浇到」。

**定版口径（最终，两次翻转后定下来）：**

```
物品说明（服务器声明的真实覆盖） > 实测（下限） > 等级表
```

- `StardewRenderState#coverageRange`：说明第一、实测第二；
- `StardewFarmModule#regionSprinklerInfo`：说明整块算、实测只算湿格；
- 播报 / 列表 / 卡片一律标明**画框用的是哪个来源**，并把实测标成下限：
  `实测 5×5 · 湿盆 24 格（下限）· 画框按物品说明 13×13`、
  `未测出 · 画框按物品说明 9×9`、`未测出 · 画框按等级估算 5×5`；
- 未绑定的台（范围预览）字牌写 `初级洒水器 · 5×5（物品说明）`。

**为什么最后是说明优先（用户亲手试验，2026-09-21 04:2x）：** 在 13×13 的边角放一个新盆、
等清晨洒水，**远处那盆确实湿了** → 说明里的「工作范围 13 * 13」是真实覆盖；实测的
`5×5 · 湿盆 24 格` 只是「盆群只有 5×5 大」造成的下限 —— **实测只能在盆已经铺到的地方证明浇到了，
永远测不出盆群之外的能力**。

**两次翻转的教训（写进这里以免再犯）：**
1. 学到的数字要连同**语义**一起确认：同一个「范围」可能是能力、可能是当前生效范围；
2. 但语义**不能靠"看起来太大"猜** —— 我第一次据用户的主观判断改了口径，一轮之后又被试验推翻。
   正确做法：把它当**待验证的声明**，让用户做一次**最小试验**（摆个盆看湿不湿）再定；
3. 口径定错时，代码里每一处文案跟着错，所以「来源」必须写在播报里 —— 这次正是文案里的来源
   标注让口径能被快速归因和纠正。

**验收（用户实机 2026-09-21 04:2x）：** 四个框按物品说明显示 5×5 / 9×9 / 13×13，
用户确认「完成了！！现在是真实的」——**本口径与范围自学功能均通过**。
