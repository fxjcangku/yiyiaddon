# 118-复盘-自动挖矿发包连吃与自动回血

日期：2026-09-19
项目：yiyiaddon（新项目，Fabric 26.1.2 客户端模组）
旧项目对应物：`D:/mcaddon/26.1.2` 自动挖矿（`mining/service/ContainerHelper#autoEat`、`mining/fsm/MinerFSM#tickEating`）——本次是在其之上按用户要求新增能力，非移植项

## 一、用户需求（原话与三问口径）

原话：「可以帮我自动挖矿加一个发包功能吗 自动回血」。

三问确认（AskUserQuestion，用户 2026-09-19 答复）：

| 问 | 用户选择 |
| --- | --- |
| 回血方式 | **发包秒吃**（直发用食包，不等原版进食动画） |
| 吃什么 | **所有食物都发包秒吃**（不看食物白名单） |
| 落在哪里 | **不做设置项，默认开启，吃任何食物** |

因此本次不新增任何设置项，也不新增模块，能力直接落在自动挖矿内部。

## 二、先取证：原版 26.1.2 用食链路（决定「发包能做到什么」）

全部依据取自 `26.1.2/01-开发参考库/Minecraft原始源码/`：

| 事实 | 证据 |
| --- | --- |
| 单件食物的用食时长由服务端按物品组件结算，原版食物 = 32 刻（1.6 秒） | `Consumable#consumeTicks()`（`consumeSeconds * 20`，默认 1.6）→ `Consumable#startConsuming` 返回 `user.startUsingItem(hand)`；`LivingEntity#updateUsingItem` 每刻自减、归零才 `completeUsingItem()` 结算 |
| 服务端对「已在使用物品」期间重复送达的 UseItem 包**直接忽略** | `LivingEntity#startUsingItem` 的 `!this.isUsingItem()` 卫语句；`ServerPlayerGameMode#useItem` 在 `isUsingItem()` 时无副作用分支 |
| 客户端会**主动**发 RELEASE 包打断进食，如果右键没按下 | `Minecraft` 主循环：`if (player.isUsingItem() && !options.keyUse.isDown()) gameMode.releaseUsingItem(player)`；`MultiPlayerGameMode#releaseUsingItem` 会发 `ServerboundPlayerActionPacket(RELEASE_USE_ITEM)`，服务端收到即 `stopUsingItem`（这一件白吃） |
| 吃什么由原版判：饱食度未满，或该食物 `canAlwaysEat`（金苹果类） | `Consumable#canConsume → Player#canEat(canAlwaysEat) = invulnerable \|\| canAlwaysEat \|\| foodData.needsFood()` |
| 「回血」靠自然再生，条件是饱食度 ≥ 18；饱和度 > 0 时 10 刻回 1 点 | `FoodData#tick`（饱和度 > 0 且饱食度 20 且受伤 → 10 刻回 1 点；否则饱食度 ≥ 18 且受伤 → 80 刻回 1 点） |

结论（已在代码注释中写明）：**发包不能让原版服务端加速单件食物的结算**；「秒吃」的收益只能来自
①不等按键 ②两件之间零间隔 ③饱食度与饱和度顶满后自然再生条件即刻成立。
只有服务端自定义了用食时长为 0 的物品（按包结算）时，逐包续发才是真秒吃 —— 对应代码里的续包分支。

### 3.3 复用而非新造

- 进食仍然走既有的 `EATING` 状态：停 Baritone（进食期间换槽会让服务端 `stopUsingItem`，这一件白吃）、
  逐件连吃、2 分钟超时保护、退场还原被顶掉的快捷栏物品、补给的取货白名单 —— 全部沿用，未新增第二条进食链路。
- 续包走 `core/net/ClientPacketSender`（既有直发通道），起手仍走原版 `gameMode.useItem`，
  因此仍受「发包防踢」的放置限速保护（每秒 8 包，进食约 0.6 包/秒，远低于阈值）。

## 四、能力边界与已知取舍

1. **单件食物仍是 1.6 秒**：这是服务端结算口径，发包改不了（取证见第二节）。连吃省下的是件与件之间的间隔与按键等待。
2. **战斗中（`COMBAT`）不吃**：战斗态每刻由 `MiningCombat#ensureWeapon` 换武器槽，换槽会打断进食；打完架回到 `MINING` 会立刻触发回血分支，因此不影响「战后回血」，但战斗过程中不会边打边吃。
3. **血量未满但饱食度已满时不触发**：原版普通食物此时吃不下（`canEat` 为假），血由已有的自然再生继续补。
4. **「任何食物」包含腐肉等低价值食物**：用户明确要求「所有食物都发包秒吃」；金苹果类恒排最后，不会被当口粮提前吃掉。
5. **自动丢弃不再丢食物**：背包会多留食物格（用户要求吃遍背包所有食物，二者必须一致）。
