## 二、取证

### 1. 同一台机器、同一个崩溃签名

```

j  com.yiyiaddon.ui.render.ItemIconCache.readRegion([II)[B+589

```

`EXCEPTION_ACCESS_VIOLATION writing address 0x00000245064d17f0`，问题帧 `C [nvoglv64.dll+0xb774d3]`。
环境：i5-13600KF / 31G / Win11、RTX 4060 Ti、NVIDIA **591.86**、133 个模组（含 `voxy 0.2.18-beta`）、
PCL + `LwjglUnsafeAgent`、Java 27、`-Xmx6451m`。两次报告的栈、问题帧、机器完全一致。

### 2. 仍是那版旧 jar，用户还没换包

`dumpPresentedFrame` / `probeBlock` 在**当前源码与全部构建产物里都不存在**（复盘 149 已开包核验），
而这份 hs_err 的栈上还是这两个未混淆的方法名 —— 说明 23:40 那次运行用的仍是「带整屏回读探针的旧调试包」，
与 23:28 构建、供其替换的新包无关。mod 列表里只写 `yiyiaddon 1.0-beta1`，不含 jar 文件名，故需向用户索取。

### 3. 现场时序（为什么偏在这一刻炸）

- 23:40:41 `ContainerScreen`（容器槽 23 个物品）—— 正是图标回读的活跃窗口；
- 23:40:42~43 Voxy 拆掉再重建渲染管线（`Shutting down render pipeline` → `Creating new world engine`）；
- 23:40:45 崩。

即：**界面回读 + 别的模组正在释放/重建 GL 资源**同时发生。这台机的驱动早被 Sodium 标记
`NVIDIA_THREADED_OPTIMIZATIONS_BROKEN`，游戏还强制 `GL_DEBUG_OUTPUT_SYNCHRONOUS` 去关驱动的
线程化提交 —— 它本来就跑在降级通道上。

### 4. 写地址落在 JVM 已预留但未提交的堆区 → 驱动把目的地算到了我们缓冲区之外

`-Xmx6451m`，堆自约 `0x2440…` 起（RBX 等指向的 Java 对象在 `0x24422…`、线程对象在 `0x24505dc…`），
而故障写地址 `0x245064d17f0` 正落在该区间的**未提交部分**：热点的 `Register to memory mapping`
也把它标为 `unknown value`。这与「PBO 仍绑着时，驱动把 `pixels` 指针当成该缓冲的字节偏移量」的机制吻合 ——
写目的地不再是我们的 `rowBytes × height` 分配，而是一个算术上凑出来的野地址，踩空页即原生崩。

## 三、改动

全仓共两处回读，两处都按同一口径加固（`glGetTexImage` 与 `glReadPixels` 同样吃 `GL_PACK_*` 与
PBO 绑定，因此是同一类越界）。

### 1. `ui/render/ItemIconCache.readRegion`（图标行抽帧与 backdrop 备份共用）

1. **进 `glReadPixels` 前复核 PBO 绑定**：再取一次 `GL_PIXEL_PACK_BUFFER_BINDING`，非 0 就返回 null，
   宁可本帧不回读，也不带着「指针会被当成偏移量」的前提进那次原生调用。
2. **目标缓冲区留冗余**：分配由 `rowBytes × height` 改为 `rowBytes × height + rowBytes + 64`，
   万一驱动在行距/对齐上仍多写一点，落点还在我们自己的分配里，不至于踩未映射页把进程带走。
   实际拷贝仍只取前 `rowBytes × height` 字节，行为不变。
3. 前一轮的第三道防线保留：`SkiaGlBackend.mainFramebufferId()` 回落 `0`（窗口默认帧缓冲）时直接返回 null。
4. `readRegion` 的 javadoc 同步补上「三道防线」与第二次取证（第 212 条：文档与代码一致）。

### 2. `ui/render/PlayerFaceCache.readPixels`（首页头像读皮肤贴图）

原来只有「保存/还原纹理绑定」，打包状态与 PBO 一个都没管 —— 与 `readRegion` 加固前同样的隐患。
现改为同口径：保存并还原 `GL_PIXEL_PACK_BUFFER_BINDING` 与 `PACK_ROW_LENGTH` / `PACK_ALIGNMENT` /
`PACK_SKIP_PIXELS` / `PACK_SKIP_ROWS`，回读前清零并复核 PBO 为 0，目标缓冲区同样留一行 + 64 字节冗余。
静态导入由逐个 GL11 常量改为与邻居（`SkiaGlState`、`ItemIconCache`）一致的 `GL45.*`。

## 五、影响面与待办

- 正常路径行为不变：回读的区域、格式、行序全同，只是多一次状态读取与几十字节冗余分配。
- `return null` 的两条分支都会让调用方走既有保守路径（本帧不画格子 / 不覆盖 backdrop），画面可能少一帧
  图标刷新，不会留下残留。
- **给用户的两条硬要求**：① 删掉 mods 里旧的 `yiyiaddon-*.jar`（含 PCL 版本隔离目录），只留当前
  `yiyiaddon-1.0-beta1-personal+26.1.2.jar`（SHA256 `078E197AAEEB855CC7D779F37A5146B0C5EF7CCDEE82FBB7EBC2F2F4BA81B2B1`）；
  ② 升级显卡驱动 —— 591.86 已被 Sodium 判为降级通道，这类原生越界是驱动内部行为，
  我们只能做地址空间兜底，不能根治。
- 若换包后仍复现，索取新的 `hs_err_pid*.log`：先看栈上是否还出现本 mod 帧，若只有 `nvoglv64.dll`
  而没有我们的帧，则属驱动/别家模组问题。
