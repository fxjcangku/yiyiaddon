# 205 · 产物箱满改成「直接停机」（撤掉 20 秒自动复查）

- 日期：2026-09-22
- 触发（用户原话）：「然后还有卸货箱子满了没有直接停机 现在是等20秒 我要的是直接停机」
- 前序：[195](195-复盘-背包满了还在收菜与产物箱满了不提示.md)（满仓停手）、
  [199](199-复盘-破坏速度属性不是挖不动的判据（巨型菠萝两道客户端闸撤销）.md) 所在的满仓链路

## 一、旧行为：满了之后每 20 秒自己又跑一趟

`outputBoxFullUntil = now + 20s`（`OUTPUT_BOX_FULL_RETRY_MS`）是个**时间窗口**：
- 卸货验证发现放不进去 → 置窗口 + 播「产物箱没有空间，已暂停收菜（每 20 秒自动试一次）」；
- 停机期间 `tryOutputBoxRecovery()` 每到点就**真的再跑去开一次箱**，失败再续一个窗口。

观感就是用户说的：没有「直接停机」，而是「停 20 秒 → 又跑去开箱 → 再停 20 秒」。
窗口当初是为了解决「标志永久卡死」（玩家清完箱子没人去复位），代价是这份来回。

## 二、新行为：满了就停住不动

- 状态量从「窗口时间戳」改成布尔 `outputBoxFull`（常量 `OUTPUT_BOX_FULL_RETRY_MS` 一并删除，
  不留死代码）；卸货放不进去 → 立刻置位 → 整机停机（收菜 / 拾取 / 卸货 / 浇水 / 播种 / 维护都不动）。
- `tryOutputBoxRecovery()`（到点自动开箱）**整个删掉**，停机期间不再有任何定时开箱。
- 复原点（三个，都不靠轮询）：
  1. **玩家自己打开过一次容器**（`StardewCoordinator#onPlayerOpenedContainer`，
     由 `StardewFarmModule#onOpenScreen` 在「容器界面 + 我方没在用静默容器」时调）——
     玩家清箱 / 看一眼就是最自然的信号，下一轮真去卸一趟：成功即完全恢复，仍满则立刻再次停机；
  2. **背包里已无可卸成品 / 产物箱点位不可用**（`outputBoxFullBlocksHarvest` 里自动失效）——
     这时「箱子满」挡不住任何事，避免玩家清完背包反而永久停机；
  3. **模块停机或重开**（`reset()` 里清）—— 轮询取消后，重启不清就等于卡死（漏斗自动清箱的玩法
     没有别的复原点），代价是重启后白跑一趟箱子。此处与「背包已满故意不清」的旧注释分开写清。
- 文案同步：`产物箱没有空间，已停机｜清空产物箱后打开一次箱子（或重开模块）即复查`。

## 三、验证

- `.\gradlew build --console=plain -q` → **EXIT=0**；全仓库已无 `outputBoxFullUntil` /
  `OUTPUT_BOX_FULL_RETRY_MS` / `tryOutputBoxRecovery` 残留。
- **未实机**：复测看点 —— 卸货失败后应立刻显示「已停机」并**停着不动**（不再每 20 秒跑一趟箱子）；
  清空箱子后开一次箱子，应回一行「产物箱重新检查」并去卸货。

## 四、教训

1. 「带时限的自动重试」在玩家眼里就是「没停机还在动」：**停机**与**自动恢复**要分开表达 ——
   停机就是停住，恢复靠一个明确事件（这里选「玩家自己开箱」）而不是定时器。
2. 撤掉轮询时必须同时补上复原点，否则会把「标志卡死」换回来；本轮把复原点写在同一段注释里，
   便于以后有人再想加回轮询时先看清代价。
