## 2. 第一条：坚守者排除出自动战斗

| --- | --- |

## 3. 第二条：玩家手动指令检测（改的是检测机制，不是阈值）

**原来为什么漏**：玩家的手动传送只有一条线索——`manualTeleportDetected()` 的位置跳变，
而它 `state == MINING` 才判定（卸货 / 补给 / 修补 / 前往野外都是模块自己发传送指令的地方，
判了会误伤自己）。玩家在打怪、进食、卸货途中敲 `/spawn` 就整段漏掉；即便在挖矿态，
我方的传送宽限窗（`ownTeleportPendingTicks`，最长 600 刻）也可能把玩家那一跳当成「我方落地」消费掉。
两条加起来就是用户看到的：人到了 spawn、脚本在他落地的地方继续开挖。

**新线索**：从客户端发包出口拿指令原文。复用**已有的**发包观测点（`ConnectionPacketMixin` 已在
`Connection#send` 上入队，没有新增 Mixin），在 `EventDispatcher` 主线程出队处抽出：

- 新增事件 `ClientEventType.CLIENT_COMMAND`，载荷 = 指令原文（不含前导斜杠）；
- 覆盖两个包：`ServerboundChatCommandPacket`（**无参数**指令，`/home`、`/spawn`）与
  `ServerboundChatCommandSignedPacket`（**带参数**指令，`/res tp 矿区`）——
  `ClientPacketListener#sendCommand`（`:2654-2668`）按参数有无二选一，只认前者会漏掉一大半；
- 纯客户端指令（`.wk` 之类）在聊天栏就被客户端指令系统拦下、不产生这两个包，因此不会误报。

**区分「自己发的」**：`ServerCommandRunner` 发指令前记下原文 + tick（`markOwnCommand`），
模块处理器用 `isOwnCommand` 比对**原文 + 5 刻窗口**排除自家指令。
只按时间窗口不行——玩家完全可能在我们发指令的同一秒敲 `/spawn`，那正是这个 bug 的形态。

**只记录、不当场动作**：指令是否真的挪动了位置由位置跳变确认（`/msg`、`/ping` 这类不改位置的
指令不该打断挖矿）。窗口 100 刻（5 秒），过期自动失效。

**判定范围与阈值分层**：

| 线索 | 状态范围 | 阈值 |
| --- | --- | --- |
| 常规跳变（无指令线索） | 只 `MINING`（照旧） | 32 格 |
| 玩家指令窗口内 | 所有状态（死亡流程除外） | **8 格** |

8 格的依据：这条线索的前提已经是「玩家刚敲了一条服务器指令」，剩下的只是确认它有没有挪动位置，
而服务器瞬移可能只挪几格（`/home` 就在附近、`/tpa` 到身边的人）；存活状态下单刻位移达不到 8 格
（自由落体极限约 3.9 格/刻、鞘翅约 1.5 格/刻），因此不会误判。

**已经在 GO_WILD 时的特殊处理**：玩家这一传会把「前往野外」流程顶掉，此时 `transitionTo(GO_WILD)`
是同态空操作，本态随后会把玩家自己那一跳当成「我方传送生效」直接进 `MINING`——又是「在 spawn 附近挖」。
所以命中时若 `state == GO_WILD` 就改走 `restartGoWild()`（`stateTick` 归零 → 下一句阶段 1 重发
`前往挖矿指令`，重试计数与冷却清零）。处理完立刻关掉指令窗口，避免我们随后自己那一跳又被算成玩家的。

**播报**：玩家指令来的那条带原文，便于事后核对是哪条指令把模块踢出矿区：

```
§e⚠ 检测到手动指令 §8/spawn §8▸ 重新前往野外挖矿
§e⚠ 检测到传送 §8▸ 重新前往野外挖矿          （无指令线索的旧口径，一字未改）
```

处置动作与 2026-09-18 的既定裁定一致（第 72 号报告：任何来源的传送都复位到 GO_WILD 重走一遍传送流程），
**不是**停机——用户那次裁定明确否掉了直接关模块。

> **同日修正（见 86 号报告，以下描述已过期，保留作记录）**：用户澄清「我的意思是让他不要挖……
> 我检测到我输入什么什么指令，不仅仅是 home、spawn，检测到了都默认暂停」。
> 于是**玩家敲指令**这条线索的处置改成「一敲就暂停挖矿（关模块）」，
> 不再走 GO_WILD 重新前往野外；`manualTeleportDetected()` 里我为这条线索加的东西
> （指令窗口、8 格阈值、`onPlayerCommand`、`restartGoWild`）已整段删除，
> `manualTeleportDetected()` 恢复成只兜「没有指令线索的传送」。

## 4. 第三条：预警范围 32 → 15×15

`WardenWarningGuard`：

| 项 | 原 | 现 |
| --- | --- | --- |
| 范围 | 半径 32 格（球形） | 边长 15 的立方体（水平 ±7、垂直 ±7），用户口径「玩家自身附近 15x15」 |
| 判定 | `distSqr(pos, player) > 32²` | 每轴 `abs(差值) <= 7` |
| 覆盖区块 | 5×5 = 25 个（25 刻一轮） | 3×3 = 9 个（**9 刻一轮**，更快） |
| 实体兜底 | 无 | 范围内若已有坚守者实体 → 同样报警（`Alarm.PRESENT`） |

垂直方向与水平取同一边长：坚守者是贴着自己脚下召唤的
（`SculkShriekerBlockEntity.WARDEN_SPAWN_RANGE_Y = 6`，见 `:46`），垂直不需要更大。

新增实体兜底的理由：方块扫描有覆盖盲区（玩家刚进区块那一轮还没扫完、或尖啸体在范围外把人叫来了），
这种时候还在原地挖就是等死。实体查找走区块段索引，成本与范围无关，每刻查也划算。

警报类型因此分成两种（`Alarm.SUMMONING` / `Alarm.PRESENT`），播报说实话、不把「已经在场」说成「准备出现」：

```
§6⚠ 附近有坚守者准备复活 §8▸ 立刻传送逃离
§6⚠ 附近已有坚守者 §8▸ 立刻传送逃离
```

```

```

## 7. 待实机验证项

1. 打怪场景下把坚守者拉进附近：模块不进 `COMBAT`、不去打它（其他怪照常自动击杀）。
2. 挖矿态敲 `/spawn`、`/home`：播报「检测到手动指令 §8/xxx」并重新前往野外挖矿，不在落点继续挖。
3. 打怪 / 进食 / 卸货途中敲同样指令：同样被抓住（这是本轮修的漏检）。
4. 挖矿态敲 `/msg`、`/ping` 之类不改位置的指令：挖矿不被打断。
5. 尖啸体在 15×15 外尖叫：不报警（31 格那批不再触发）；范围随玩家走动实时跟随。
6. 远古城市里尖啸体一响：播报「附近有坚守者准备复活」+ 立刻传送，且此时坚守者尚未出现。
7. 模块自己发的前往挖矿 / 卸货 / 补给 / 挂机 / 死亡返回指令：不会被判成手动干预（不出现自触发循环）。
