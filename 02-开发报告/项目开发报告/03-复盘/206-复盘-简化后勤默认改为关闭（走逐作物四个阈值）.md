# 206 · 「简化后勤」默认改为关闭（走逐作物那四个阈值）

- 日期：2026-09-22
- 触发（用户原话）：「还有卸货补货那些种子单独设置那个简单精简模式能不能默认关闭」
- 前序：[1.0-beta2 台账第 9 / 19 条](../../../07-bug记录/1.0-beta2.md)（同一天的后勤 / 口径改动）

## 一、改了什么

| | 旧 | 新 |
| --- | --- | --- |
| 字段默认值 | `logisticsSimple = true` | `logisticsSimple = false` |
| 后勤页首次打开 | 收起四个阈值，固定用默认值 | 逐作物展开四个阈值 |
| 「行内恢复默认」按钮 | 落回 true | 落回 false |
| 说明文案 / 帮助面板 | 「默认勾选简化后勤」 | 「默认不勾选…没单独调过的作物用的就是那组默认值（2 / 8 / 8 / 0）」 |

## 二、关键事实：关掉 ≠ 改数值

`CropLogistics.DEFAULT = (2, 8, 8, 0)`（种子少于 2 补、补到 8；成品攒 8 卸、不留底）
**就是「简化后勤」那组数值**。所以默认关闭之后，没单独调过阈值的作物行为与之前完全一致，
区别只是界面按作物展开、你想给某个作物单独调的时候立刻生效 —— 不会因为这次改默认值把谁的农田改坏。

## 三、老档迁移（不然等于没改）

旧版把默认值 `true` 写进了每一份存档，光改字段默认值对老档无效。按本类已有的
`paletteRevision → migratePalette()` 惯例加了一个版本键：

- 存档写出 `logisticsRevision = 2`；
- 读档时 `logisticsRevision < 2`（或该键缺失）→ 把 `logisticsSimple` 置 false。

因为「关掉不改数值」（第二节），这次迁移对没调过阈值的人零行为变化；手动调过阈值的作物从此按他调的值走
（这正是「逐作物设置」的语义）。想回到简化档，后勤页勾上即可。

## 四、验证

- `.\gradlew build --console=plain -q` → **EXIT=0**。
- **未实机**：复测看点 —— 进「后勤」页应默认逐作物展开四个阈值（不再是「后勤全自动」那一行），
  且换台服 / 换个作物看到的数值应与之前一致（2 / 8 / 8 / 0）。

## 五、教训

「默认值」不是实现细节，是产品决定：这次改动本身很小，真正花时间的是**确认它不改变现有行为**
（把逐作物默认值与简化那组逐项对齐）以及**老档怎么办**（存档里存着旧默认，改字段默认值等于没改）。
以后凡是调整 boolean 开关的默认值，都要同时回答这两个问题。
