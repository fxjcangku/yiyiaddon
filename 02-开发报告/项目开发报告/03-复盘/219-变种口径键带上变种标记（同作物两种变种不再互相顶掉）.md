# 219 · 变种口径键带上变种标记（同一作物的两种变种不再互相顶掉）

- 日期：2026-09-22
- 触发（用户提问）：「黄金番茄是用右键收割的，不用指定工具 这个你写上去了嘛 是不是以后每个服都能学习变异作物」
- 前置：[194 / 204](../01-规范与UI规格/)（口径学习机制本体）、第 24 条（挑工具与预置三件）

## 一、问题

本服 jmy 同时有**两种番茄变种**，收法还不一样：

| 变种 | 实测收法 |
| --- | --- |
| 巨型番茄 | 左键破坏（工具不限，效率斧更快） |
| 黄金番茄 | 右键采收（不需要任何工具） |

而口径的存档键是**作物键**（`tomato`）—— 一份记录只能有一个动作，于是：

- 学了巨型番茄的「左键」→ 黄金番茄会被左键去砸（收不动）；
- 学了黄金番茄的「右键」→ 巨型番茄只会被右键点（更收不动）。

**识别链其实分得清这两种变种**（身份里有 `gigantic` / `golden` 标记），
漏的是**键里没带上它** —— 信息在手上，却没进键。

## 二、改动

1. **口径键扩成 `作物#变种标记`**：`tomato#golden` 与 `tomato` 各记各的。
2. **`CropRuntimeStateResolver#variantTag(identity, stage)`**：从身份路径与阶段名里取标记
   （`gigantic` 判定必须排在 `giant` 前，否则被前缀先命中）；两种身份形态都认 ——
   阶段化 `tomato_stage_golden`、独立变异体 `pineapple_gigantic_pineapple`。
3. **学习与取用同源**：`observePlayerSpecialHarvest` 落盘用 `specialRuleKey(cropKey, tag)`，
   `specialHarvestRecipe(recognition)` 取表用同一个函数；两边都从同一个识别结果取标记。
4. **查表顺序向后兼容**（这是重点，旧档案不能废）：
   `作物#标记` → `作物`（旧档 / 只学了一种变种）→ 本服通用 `*` → 预置（先 `#标记`、再 `作物`）→ 老口径。
5. **预置补一条**：`jmy: tomato#golden → 右键 + 工具不限`；巨型三件仍按 `cropKey` 预置
   （`tomato` 那条正好是巨型番茄的兜底）。

## 三、为什么不干脆"按变种分别学、学不到就不收"

那会让没学过的变种直接停摆。回退链保留了「本服通用口径」与「作物键旧记录」两层兜底：
**能精确就精确、精确不了就退而求其次**，而不是把功能关掉。

## 四、验证

- `GetDiagnostics`（全工作区）：0 诊断。
- 待实机：jmy 服同时放一株巨型番茄与一株黄金番茄 →
  - 模块对巨型走左键破坏、对黄金走右键；
  - 日志 `特殊变种口径已学会 … 口径键=tomato#golden`（学黄金时）与 `… 口径键=tomato#gigantic`（学巨型时）各自独立，不再互相覆盖。

## 五、教训

1. **"能区分"与"用上这个区分"是两件事**：识别层早就能分清变种，但键设计没带上它，
   于是能力白放在那里。凡是把对象当字典键的地方，都要问一句：**这个键足够唯一吗？**
   （同一作物多形态、同一物品多附魔、同一方块多状态 —— 都是这类坑。）
2. **扩键必须配回退链**：改键格式等于改存档语义，旧档、旧预置、旧通用口径都要有退路，
   否则升级即失效（本条的查表顺序就是为了这个）。
