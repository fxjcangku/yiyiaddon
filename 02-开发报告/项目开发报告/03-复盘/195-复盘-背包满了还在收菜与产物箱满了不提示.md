# 复盘：背包塞满后还在收菜、产物箱满了既不提示也不停手

- 日期：2026-09-22
- 触发：用户实机（故意把背包塞满做压力测试）——
  「我还发现一个bug 背包已经满了还在 收菜没有赶紧去卸货 我估计弄满测试的 卸货箱子满了也没提示停机」
- 日志证据（`run-26.1.2/logs/2026-09-21-7.log.gz`，22:54:15）：
  `[星露谷农场] 产物箱没有可用空间 ▸ 已结束本次卸货，其他任务继续`
  —— 箱子满只留了一条普通状态行，模块随后照常继续跑。

## 一、两个独立成因

### ① 插队卸货的资格写错了

`StardewTaskPlanner#tryStartUnloadForProtection()` 原先的判据是：

```
背包空格 ≤ 6  &&  某作物「自己的成品数 ≥ 该作物的卸货阈值(unloadTrigger，默认 8)」
```

阈值是**按作物**配的（「这种作物的成品攒到 X 个才去卸」）。可背包被**别的东西**塞满时
（实机：36 格金锭），任何一种已选作物的成品数都到不了阈值 → 资格永远不成立 → 插队卸货永不触发，
模块继续一格一格收，收下来的成品只能掉在地上（被别的玩家捡走或 5 分钟后消失）。

**阈值语义错位的根源**：`unloadTrigger` 回答的是「攒多少去卸划算」，而「背包快满」是
「还有没有地方放」——两件事，前者不能当后者的判据。

### ② 箱子满只更新状态卡，不停手也不显眼

`StardewTaskVerifier#markLogisticsBlocked()` 在「箱子没有空间」时走的是 `status.state(...)`
（普通状态行）+ 该作物 60 秒退避。玩家看到的是「已结束本次卸货，其他任务继续」，
于是继续收 → 背包真的满了 → ①的插队又不成立 → 静默地一直掉东西。

## 二、处置

### ① 背包一个空格都不剩时，资格判据换成「还有没有可卸的成品」

```java
int freeSlots = playerFreeSlots();
if (freeSlots > PLAYER_LOW_FREE_SLOTS) return false;
boolean bagFull = freeSlots <= 0;
for (CropDefinition crop : targetCrops()) {
    boolean need = bagFull
        ? owner.inventory.countProduce(crop) > owner.logisticsOf(crop.cropKey()).unloadKeep()
        : owner.snapshot(crop).unloadNeeded();   // 没满则照旧按该作物自己的阈值
    ...
}
```

阈值只决定「平时攒多少去卸」，**背包满时只问「有没有超出保留量的成品」**，不再看阈值。

### ② 满背包 + 卸不出去 = 停收停拣，并且报出来

`StardewTaskPlanner#bagFullBlocksHarvest()`（`playerFreeSlots() <= 0` 时为真）：

- 拦的位置：`resolveTask` 的 `MATURE` / `SPECIAL`（收割与收获学习都会产出物品）与
  `decide()` 里的 `COLLECT`（拾取本身就是往背包里装）。浇水 / 播种 / 清枯苗不拦——
  它们不占新格，停了只会让田荒。
- 报的内容按「到底卡在哪一步」分档，让玩家一眼知道该动什么：

| 情形 | 文案 |
| --- | --- |
| 没有可卸成品 | 背包里没有已选作物的成品可卸，占满的是别的东西 |
| 没绑产物箱 | 还没绑定产物箱，成品卸不出去 |
| 箱不在当前维度 | 产物箱不在当前维度，成品卸不出去 |
| 箱子没空间 | 产物箱没有空间，成品卸不出去 |

统一播报为 `critical`（状态栏弹窗 + 聊天）：「背包已满，已暂停收菜 / 拾取 ▸ <原因>｜
出路：清空产物箱或背包腾出空格，腾出空间后自动继续」。
去重到「一次阻塞只报一条」：背包重新有空格时 `forgetBagFullHalt()` 复位，下次再撑满会重新报。

### ③ 产物箱没空间改按 critical 播报

`OUTPUT_FULL` 从 `status.state` 提到 `status.critical`（文案补上出路），
因为它必然需要玩家动手（清箱子），不是「任务状态」那种可以静音的信息。

## 三、口径一致性（对《开发习惯》第 246 / 247 条）

- 第 246 条「状态判据只写一处、计数必须是实处理数」：卸货资格在同一条 `if` 里分档
  （满 / 未满），不再让两处各写一套；「能不能卸」与「要不要停」都用
  `countProduce(crop) > unloadKeep()` 这一条同源判据。
- 第 247 条「有前置条件的动作在触发那一刻校验」：停手不是硬停机，而是「每次决定派发收割 / 拾取时
  现算」——玩家清了箱子、背包有了空格，同一 tick 就能恢复，不需要重开模块。

## 四、验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew.bat compileJava` | **EXIT=0** |
| 满背包 + 有可卸成品 | 走插队卸货（`UNLOAD`） |
| 满背包 + 箱子满 | 先 `OUTPUT_FULL` critical，再 `BAG_FULL_HALT` critical，收割 / 拾取停手 |
| 背包腾出空间 | 提示复位，收割 / 拾取立即恢复（无需重开模块） |
