# 158-复盘-区域换作物同步勾选与菜单界面按 G 唤出

日期：2026-09-21
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件

用户实机反馈两件事（2026-09-21）：

1. **种植区域页换作物后，作物选择器没有同步勾选**：
   「种植区域页面换种子成功了 但是选择器里面没有同步更新还要自己去添加 有点麻烦 能不能换种子的同时
   同步切换选择器的 我换了红包变成大蒜还要重新选择器添加麻烦」。
2. **菜单界面按 G 唤不出面板**：「我发现菜单页面 按 g 无法唤出我的 ui 能不能游戏主页面也按 g 可以换出来」。

## 二、根因

### 1. 区域绑的品种与「目标作物」是两处数据，换作物只写了其中一处

- 区域档：`StardewRegionManager.rebind` 只改 `Region.cropKey/cropName` 并写
  `StardewFarm/regions/<服务器>.json`（`StardewRegionManager.java:343-359`）。
- 目标勾选：`StardewSettings.selectedCropKeys` 内存镜像 + `StardewSelectionStore` 按 ServerKey 落盘
  `StardewFarm/selection/<服务器>.json`（`StardewSelectionBinding.Selection.persist`）。
- `StardewFarmModule.changeRegionCrop`（`StardewFarmModule.java:1103-1126`）走的是选中回调
  （`StardewRegionListScreen.openCropPicker` 传的单选 `pickHandler`），而选择器单选分支**故意不写选择集合**
  （`StardewTargetSelectScreen.setSelected` 第 422-427 行提前返回，那是给「点一下即交回调用方」用的）。

于是换完作物，勾选集还是旧的 ⇒ 启动提醒报「区域 N（XX）绑的作物不在目标作物里，这块地会被跳过」
（`StardewStartupCheck.java:275-288`），任务规划同样跳过该区域（`StardewTaskPlanner.java:158`），
玩家还得回选择器手动再勾一次。

### 2. 按 G 的条件是「必须没有任何界面」

`ModuleKeybindManager.tick` 第 92 行原为 `down && !previous && client.screen == null && !isCapturing()`。
主菜单（`TitleScreen`）、暂停界面（`PauseScreen`）的 `screen` 都非 null，所以一律被拦。

## 三、改动

### 1. `StardewSelectionBinding.Selection#select(String key)`（新增）

把一个键并入本类选择并立刻 `persist()`；`isValidKey` 不通过（不属于本类别 / 索引里没有）或已在集合里时
不做任何事，返回是否真的新勾上。

首版**只增不减**（其它区域、其它用途仍在用的旧勾选一律保留），理由见下面第五节——用户当天就要求
改成「真实替换」，见修订。

### 2. `StardewFarmModule.changeRegionCrop` 换成功后同步勾选

```java
boolean newlySelected = selections().crop().select(cropKey);
```

放在 `rebind` 成功之后、`configureCoordinator` 之前；播报的副标题随之改成
「已同步勾选到目标作物」（本来就在勾选里时仍是原来的「范围不变，只换了品种」）。
旧品种的处理见第五节修订。

### 3. `ModuleKeybindManager` 放行菜单类界面

```java
private static boolean canTrigger(Minecraft client) {
    Screen screen = client.screen;
    return screen == null || screen instanceof TitleScreen || screen instanceof PauseScreen;
}
```

`trigger` 里打开面板时把当前界面当父级（`new ClickGuiScreen(client.screen)`）——
`SkiaScreen.closing()` 是 `setScreen(this.parent)`，所以从主菜单 / 暂停界面进去，ESC / G 关闭后
**原路回到那个菜单**；游戏里（`screen == null`）父级仍是 `null`，与既有行为一字不差。

**其余界面一律不放行**：箱子、聊天、设置、我们自己的页面都可能是「正在输入 / 正在操作」的地方，
抢键会把玩家正在干的事顶掉。

## 五、修订：换品种改成「真实替换」（同日）

用户实机验证后反馈：红包换下去之后，启动提醒一直报「背包无红包种子」——因为只增不减把红包留在
目标作物里了（选择器里红包确实还勾着，只是他以为换区域品种就等于不种它了）。要求改成真实替换。

- 新增 `StardewSelectionBinding.Selection#deselect(String key)`：从选择里去掉并立刻 `persist()`，
  本来就不在集合里时不做任何事。类注释写明**只有能自证「这个键已经没有任何地方在用」的调用方才许调**
  ——选择集合是玩家的意图记录，光凭「我觉得他不种了」不许替玩家删。
- `changeRegionCrop` 里：新品种照旧 `select`；旧品种**在「全服再没有任何区域绑它」时**才 `deselect`。
  判据是新增的 `cropKeyInUse(cropKey)`：遍历 `regionManager.all()`（**跨维度**，因为目标作物勾选
  是按服务器存的、不分维度），混种区不绑品种不算。
- 播报副标题由 `replaceNote(...)` 拼：勾了新就写「已同步勾选到目标作物」，退了旧就追加
  「XX已无区域在用、同步取消勾选」，两者都没发生仍是「范围不变，只换了品种」。

**为什么保留「还有别的区域在用就不退」这一条**：跨维度的另一块地可能还在种它；
不分维度是因为勾选本身不分维度，退了它会让那块地也被跳过。

**注意**：本修订只作用于「以后发生的换品种」。已经被留在集合里的旧作物（本次的红包）
仍需在选择器里手动取消一次。
