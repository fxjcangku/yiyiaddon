# 149-复盘-用户闪退取证：图标回读的 GL 打包状态加固

日期：2026-09-20
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件

用户转来其用户的闪退报告包 `d:\mcaddon\错误报告-2026-9-20_23.21.38.zip`，问「是不是我的 jar 问题」。
包内：`hs_err_pid15936.log`、`latest.log`、`PCL 启动器日志.txt`、`启动脚本.bat`、`游戏崩溃前的输出.txt`、
`26.1.2-Fabric 0.19.5.json`（版本元数据）。**没有 Fabric 的 crash-report** —— 因为这不是 Java 异常，
是 JVM 原生崩溃。

## 二、取证结论

### 1. 崩溃点在本 mod 的 GL 回读路径（不是别的模组、也不是驱动先动的手）

`hs_err_pid15936.log` 渲染线程栈（Java 帧）：

```
j  org.lwjgl.opengl.GL11.glReadPixels(...)
j  com.yiyiaddon.ui.render.ItemIconCache.readRegion([II)[B+589
j  com.yiyiaddon.ui.render.ItemIconCache.probeBlock(Ljava/lang/String;I)V+39
J  com.yiyiaddon.ui.render.ItemIconCache.dumpPresentedFrame()V
J  com.mojang.blaze3d.pipeline.RenderTarget.blitToScreen()V
```

`EXCEPTION_ACCESS_VIOLATION (0xc0000005) writing address 0x000001e37c95f000`，问题帧
`C [nvoglv64.dll+0xb774de]` —— NVIDIA 驱动在替我们 `glReadPixels` 写像素时写越界。
环境：RTX 4060 Ti、NVIDIA 591.86、Iris 1.11.4 + Sodium 0.9.1 + Voxy 0.2.18、共 133 个模组、
PCL 启动器 + `LwjglUnsafeAgent`、LWJGL 3.4.1-snapshot、Java 25。

### 2. 那版 jar 不是当前仓库的代码（是旧的调试版）

- `dumpPresentedFrame` / `probeBlock` **当前源码中不存在**，全仓 grep 只命中该 hs_err。
- 仓库内 5 个 jar 逐个开包核验（personal 26.1.2 / release 26.1.2 / release 26.2 / personal 26.2 /
  归档混淆包）：**都不含这两个方法**。
- `git log --all -S dumpPresentedFrame` 无任何提交 → 那版 jar 是从「当时工作区里的调试探针」编出来的
  （为排查方块图标加的整屏回读探针，挂在 `RenderTarget.blitToScreen`，每帧呈现时回读），且未混淆
  （栈里是 `com.yiyiaddon.ui.render.ItemIconCache` 明文类名）。
- 当前 [RenderTargetMixin](../../../yiyiaddon/src/main/java/com/yiyiaddon/mixin/client/RenderTargetMixin.java)
  只做 `renderSkijaFrame` / `flushBackdrop`，没有这条回读。

**处置**：用户侧换成当前发布包，那条「每帧回读整屏」的路径随之消失。

### 3. 当前代码里同一处的真实隐患：GL 打包状态没隔离

`glReadPixels` 往目标缓冲区写多少、按什么行距写，由**上下文级**的 PBO 绑定与 `GL_PACK_*` 决定；
而 LWJGL 的容量校验只按 `width × height × 4` 算。别处（Skija 自身读回、截图类模组、
Iris / Sodium / Voxy）留下非 0 的 `PACK_ROW_LENGTH` 或仍绑着 PBO 时，驱动会按错误行距往
`rowBytes × height` 的 ByteBuffer **外**写 —— 与这次的故障现象完全吻合。
原来的 `readRegion` 保存/还原了纹理、采样器、FBO、视口、裁剪、sRGB，**唯独没管打包状态**。

## 三、改动

只动一个文件、一个方法：`ui/render/ItemIconCache.readRegion`。

1. 新增保存并还原的打包状态：`GL_PIXEL_PACK_BUFFER_BINDING`、`GL_PACK_ROW_LENGTH`、
   `GL_PACK_ALIGNMENT`、`GL_PACK_SKIP_PIXELS`、`GL_PACK_SKIP_ROWS`、`GL_PACK_IMAGE_HEIGHT`、
   `GL_PACK_SKIP_IMAGES`、`GL_PACK_SWAP_BYTES`、`GL_PACK_LSB_FIRST`。
2. 回读前清零：解绑 PBO、行距 0、对齐 1、跳过量 0、交换关闭 —— 无论外面留了什么脏状态，
   本次回读都是紧致 `width × 4` 行距。
3. `finally` 里逐个还原（先参数、最后还 PBO 绑定，保证还完之后 `pixels` 的语义回到外面那套）。
4. 主帧缓冲名字取不到时（`SkiaGlBackend.mainFramebufferId()` 回落值 `0` = 窗口默认帧缓冲）
   **直接返回 null**，宁可不回读：那个缓冲区内容不受我们控制，返回 null 会走「本帧不画格子」的
   保守路径（调用方已有该分支），比冒险读窗口后缓冲稳。

## 四、验证

- `.\gradlew build --console=plain -q` → **EXIT=0**。
- **未实机**：本次改动直接影响图标采集，需在开发客户端开界面（控制台列表 / 目标选择器）确认图标
  照常显示、无闪块、无崩溃。

## 五、影响面

- 正常路径行为不变：读的还是同一个区域、同一份格式，只是把打包状态摁回默认值再还原。
- 新增 9 个状态量的存取，每帧最多几十次 GL 调用，可忽略。
- 若用户侧仍复现同类原生崩溃，则说明还有别的越界来源，需要让他提供新 hs_err（本复盘的四段证据
  采集流程可复用）。
