# 214 · 自检错位改用世界红框（未启动也要看得见）

- 日期：2026-09-22
- 触发（用户原话）：「这个报错显示坐标没用 应该显示红色的 ESP 全包那种 不然农田大了 不好找」
  （自检未通过时的回执：`分区错位：区域 2（番茄）实际 卷心菜 · X4799 Y84 Z-5604 ▸ 清掉那几格里的作物…`）
- 相关：[36-规范-分区种植.md](../01-规范与UI规格/36-规范-分区种植.md)（错位处置那一节：错位格用红框标出）

## 一、现象与成因

红框机制**本来就有**（运行期错位格会画红框，`StardewRenderState` 读 `coordinator.regionMismatchCells()`），
但**自检那条路走不到它**：

1. 自检在 `startupRegionMismatchProblem()` 里扫出错位格，只把它们拼成一行聊天栏文案，**没有留给高亮**；
2. 自检不通过 → 模块被立刻 `setEnabledSilently(false)`；
3. `onDisable()` → `coordinator.reset()` → `mismatchCells.clear()`（运行期高亮清空）；
4. `WorldOverlay.unregister(MODULE_ID)`（连那层渲染也摘了）。

于是玩家只剩一行坐标。农田一大，那一格在哪全靠数格子 —— 而这条报错恰恰是"让你去清某几格"的，
指不到位置等于没给结论。

## 二、改动

| 位置 | 改动 |
| --- | --- |
| `StardewCoordinator` | 新增 `startupMismatchCells`（**不随停机清空**）；`startupRegionMismatchProblem()` 算出错位格时登记进去，没算出则清；`regionMismatchCells()` 返回运行期 ∪ 自检两份；新增 `hasStartupMismatch()` / `clearStartupMismatch()` / `pruneStartupMismatch()` |
| `StardewRenderState` | 抽出 `drawMismatchBoxes()`；新增公开入口 `renderMismatchOnly()`：**只画错位红框**，并每 20 帧复核一次 |
| `StardewFarmModule` | 新增渲染层 `stardew-startup-mismatch` 与 `syncStartupMismatchOverlay()`：`未启动 && 有自检错位` 时挂层，否则摘层；在 `onEnable` 末尾、`onDisable` 末尾、自检通过路径各同步一次 |
| 文案 | 「清掉那几格里的作物」→「**已用红框在世界里标出**，清掉那几格里的作物，或把该区域删掉重划」 |

### 两个关键取舍

- **为什么单独一份集合、而不是复用运行期那份**：运行期那份的正确语义是「当前决策轮的错位快照」，
  停机就该清；自检这份的语义是「玩家欠我一次清理」，停机后仍成立。两者生命周期不同，混在一起必然二选一错。
- **复核为什么借渲染这一路**：模块被禁止启动后没有任何 tick（`tick()` 早退），而玩家会立刻去清那几格，
  清完红框必须自己灭 —— 否则「框还在 = 没清干净」的误导比没有框更糟。渲染回调每帧都在跑，
  集合通常只有个位数格子，每 20 帧读一次方块 + 识别，开销可忽略。

## 三、验证

- `.\gradlew.bat compileJava --console=plain -q` → **EXIT=0**。
- 待实机：
  1. 故意在「番茄区」种一株卷心菜 → 开关模块 → 自检拦住并**在世界里看到那格红框**；
  2. 把那一格挖掉 → 红框 **约 0.3 秒内自动消失**（不需要重开模块）；
  3. 再开模块 → 自检通过、红框层随之摘掉，运行期高亮接管。

## 四、教训

1. **"我把结论写出来了"不等于"玩家能找到目标"**：凡是要求玩家去某个坐标做动作的报错，
   都必须同时给出**世界里可见的定位手段**（ESP 框 / 高亮）。一行 `X Y Z` 在农田里等于没有。
2. **同一份数据若有两套生命周期，就不要共用**：运行期快照 vs 欠账提醒，前者随时清、后者要留到条件满足。
   把它们塞进一个集合，早退路径（停机 / reset）就会顺手抹掉本来该留的那份。
3. **没有 tick 的地方要另找驱动**：模块被关掉后唯一的常驻回调就是渲染，这次借它做轻量复核；
   下次遇到"停机后还要维持某个效果"，先看渲染 / 事件总线有没有现成入口，别急着加轮询线程。
