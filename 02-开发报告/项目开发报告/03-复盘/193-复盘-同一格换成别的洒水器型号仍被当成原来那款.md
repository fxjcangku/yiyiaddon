# 复盘：同一格换成别的洒水器型号仍被当成原来那款（贴图实体型号核对）

- 日期：2026-09-22
- 触发：用户实机反馈「我刚刚放的是优质洒水器，假如我放一个高级洒水器也能识别，不能识别原来的物品」
- 结论：与复盘 192 同一根链路的**第二个漏判**。贴图形态（`item_display`）洒水器的**型号信息只在
  展示实体的物品上**（`item_model` 组件 / `custom_model_data`），方块格永远是空气。而绑定校验
  当时只比了两项：那一格的 BlockState（空气=空气）、以及「这一格有没有挂着展示实体」——
  把优质换成高级之后**两项都没变**，于是继续按优质洒水器维护（定位、覆盖范围、水位判断全部按错的型号走）。

## 一、改动

### ① `SprinklerWorldBinding`：型号核对（读得出才比）

- `displayCarrier(pos)`：把「找这一格的展示实体」抽成内部方法，`displayCarrierAt` 复用它
  （搜索范围保持 `inflate(1.0)` + `blockPosition()` 相等，与准星取坐标同一口径）。
- `displayIdentityAt(pos)`：这一格展示实体**此刻挂的是哪一款**，读法与本模组的展示实体识别同一入口
  `StardewCropDisplayProbe.modelOf`（`item_model` 组件优先，缺失时按「基础物品 + `custom_model_data`」
  查资源包派发表）→ 得到 `customcrops:sprinkler_2` 这类身份。
- `displayTierMismatch(pos, expectedKey)`：不一致时返回**当前挂着的型号**，一致 / 读不出来返回 `null`。
  **读不出来一律不比** —— 那是「还不知道」，不是「不一致」，不能凭读不出来拦住正常维护。
- `sameTier / normalizeTier`：只比「末段型号名」并忽略物品形态后缀。同一台洒水器在本项目里有三种写法
  （模型身份 `customcrops:sprinkler_2`、学名里的物品键 `sprinkler_2_item`、带子目录的
  `customcrops:item/sprinkler_2`），照字面比会把同一款判成不同款，反而拦住正常维护。
- `matches(pos)`：展示实体形态下现在是「**实体在 + 型号对**」两条都成立才算绑定有效。

### ② `StardewPointManager#validationFailure`：型号不符要说人话

```
这一格的洒水器型号与绑定不一致（绑定的是 优质洒水器，现在挂的是 高级洒水器）
```

（名字经 `describeSprinkler` 从索引取显示名，索引里没有就照身份原文报出，绝不编名字。）
型号不符属于**确定结论**，因此它也走 192 建好的那条链路：从维护对象与 ESP 里剔除、
第一次发现时提示一次、并拦启动（自检的「配置问题」）。

### ③ `StardewPointActions#bindSprinkler`：绑定时当场核对型号

绑定点位之前多一道 `displayTierMismatch(pos, definition.key())`：展示实体挂的是另一款时**直接拒绝**，
提示「这一格挂的是「高级洒水器」，不是要绑的「优质洒水器」：请对准实物确认型号，或改用
`.stardew 添加洒水器 <类型>` 明确指定」。

这一条同时把复盘 154「洒水器贴图形态可任意绑定品质」的尾巴收掉了：以前只要玩家选定一种型号
（认不出实物时按唯一已选类型兜底），就能把任何一格绑成任何型号；现在贴图形态能读出型号就必须对得上。

### ④ 播报口径改为通用

`announceSprinklerMissing` 的标题从「洒水器不在了」改为「**洒水器点位已失效，已跳过维护**」，
原因行照实（实体没了 / 型号不一致），出路写两条：删掉后按现场重新绑定，或关掉「洒水器维护」。

## 二、验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew.bat compileJava` | **EXIT=0** |
| 实机验证 | **已通过**（用户 2026-09-22「ok了 修复了」） |

复测要点：
1. 已绑「优质洒水器」的点位上换成「高级洒水器」→ 维护跳过、ESP 方框消失、聊天出现一次
   「洒水器点位已失效，已跳过维护 ▸ … 这一格的洒水器型号与绑定不一致（绑定的是 优质洒水器，
   现在挂的是 高级洒水器）」；自检也会拦住启动；
2. 把原来那款换回去 → 一切恢复正常（不需要重绑）；
3. 对着「高级洒水器」执行 `.stardew 添加洒水器` → 当场拒绝并说明型号不符（不再能绑错）；
4. 型号读不出来的服务器（模型认不出）→ 行为与旧版一致，不因「读不出」而拦维护。
