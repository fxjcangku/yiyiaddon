# 复盘：服务器资源包处理模式默认改回「原版处理」

- 日期：2026-09-22
- 触发：用户指令「服务器核心资源包下载 默认就是原版，不是自动白嫖」
- 结论：服务器检测模块的「资源包处理模式」出厂值从 `AUTO_DOWNLOAD`（自动白嫖）改为 `VANILLA`（原版处理）。
  这是**指令覆盖**，不是缺陷修复：2026-09-18 的指令是「服务器核心的资源包下载 默认打开白嫖模式」，
  2026-09-22 被新指令推翻

## 一、现象与取证

| 检查项 | 结果 |
| --- | --- |
| 出厂值在哪 | `feature/tactical/config/ServerDetectorSettings#resourcePackMode`，原为 `ResourcePackMode.AUTO_DOWNLOAD` |
| 三种模式 | `BYPASS`（暴力绕过：回 ACCEPTED + SUCCESSFULLY_LOADED，跳过下载进服）、`AUTO_DOWNLOAD`（自动白嫖：放行原版 + 旁路把包存一份到 `yiyiaddon_resourcepacks`）、`VANILLA`（原版处理：不接管） |
| 谁在消费 | `ServerDetectorModule#handleResourcePackPush`（经 `ResourcePackGate` 由 `ResourcePackPushMixin` 询问）：BYPASS 发响应包并取消原版处理；AUTO_DOWNLOAD 放行原版并旁路下载；VANILLA 直接不接管、交回原版 |
| 改默认会不会影响星露谷 | 不会。推送元数据在 `ResourcePackPushMixin` 里**先无条件登记**给 `ResourceExtractionService`，之后才问闸门 —— 「检测 / 提取当前服务器资源包」与模式无关；`AUTO_DOWNLOAD` 只是额外多存一份到 `yiyiaddon_resourcepacks` |
| 旧存档怎么办 | 不动。`load` 只在配置里确有该键时生效，已存盘的玩家仍按存档值（想要「自动白嫖」的老用户不受影响） |

## 二、改动（`feature/tactical/config/ServerDetectorSettings`，一行 + 注释）

1. `resourcePackMode` 默认值 `AUTO_DOWNLOAD` → `VANILLA`。
2. javadoc 记下两条指令的先后（2026-09-18 白嫖 → 2026-09-22 原版），并写明「已存盘配置以存档值为准」，
   避免下一个人看到注释与代码不一致时改反。
3. **不动**枚举三值本身、不动 `handleResourcePackPush` 的三分支、不动控制台页行（`资源包劫持` 页的
   模式切换与「后三项只在自动白嫖下出现」的可见性条件照旧）。

**修复后的表现**：全新配置进服务器时不再接管资源包推送（走原版弹窗 / 原版加载），
`yiyiaddon_resourcepacks` 里不会再自动多出文件；想留档的玩家在控制台「资源包劫持」页切「自动白嫖」。

## 三、验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew.bat compileJava` | **EXIT=0** |
| 实机验证 | **已通过**（用户 2026-09-22「可以了 已修复」）：出厂模式为「原版处理」 |

复测要点：
1. 控制台「资源包劫持」页：出厂模式显示「原版处理」；
2. 进一个推送资源包的服务器：走原版流程，`config/yiyiaddon_resourcepacks` 不新增文件；
3. 切成「自动白嫖」后重进：包被下载留档（旧行为仍在，只是不再是默认）；
4. 星露谷「服务器资源 → 检测 / 提取当前服务器资源包」不受影响（任一模态下都能提取）。

## 四、双版本线

改动在 `master`（26.1.2 主线）落地，只涉及 `ServerDetectorSettings` 一个文件、纯默认值与注释、
与 MC 版本无关，按第 231 条待「同步仓库」时 cherry-pick 到 `port/26.2`。
