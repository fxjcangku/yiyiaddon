日期：2026-09-21

## 一、需求（用户原话）

「帮我把自动登入改成正版服可以开启，但是区别是检测是正版服不用输入密码的流程。」

## 二、旧口径与取证

| 事实 | 位置 |
| --- | --- |
| 旧口径：正版验证服（加密连接）检测到即关闭模块 | `AutoLoginModule#closeForUnsupportedEnvironment` 原 `:949-954`（判据 `isAuthenticatedServer()`） |

| 认证完成后的统一收尾（指令 / 路线 / ACTIVE） | `proceedAfterAuth()` `:778-795`，自带 `authFlowCompleted = true` |
| 使用说明旧文案「仅支持离线验证服务器」 | `AutoLoginTexts.java:275`（HELP_NOTICE） |

## 三、改动（口径变化，非缺陷修复）

1. **`beginPostLoadFlow()` 首插正版分支**：检测到加密连接 → 播报「已识别正版验证服务器，跳过登录流程。」→ 直接 `proceedAfterAuth()`。正版服的会话在握手阶段已由 Mojang 验证完毕，没有注册 / 登录 / GUI 密码流程；进服指令、回服路线、断线重连照常工作。
2. **`closeForUnsupportedEnvironment()` 去掉正版判据**：只剩单人世界关闭（单人世界确实没有登录概念），播报改为「单人世界无需自动登录，模块已自动关闭。」
3. **`isAuthenticatedServer()` 保留不动**（判据本身仍正确：`isEncrypted()`），仅补 javadoc 说明新用途。
4. **注释与使用说明同步**：类头「只允许在离线验证服务器使用」段改写为新口径；`HELP_NOTICE` 第一条改为「单人世界会自动关闭；正版验证服务器可开启，将自动跳过登录流程」。

### 流程对比

| 场景 | 旧行为 | 新行为 |
| --- | --- | --- |
| 正版服开启模块 / 进正版服 | 播报后自动关闭模块 | 允许开启；跳过认证 → 指令 / 路线 / ACTIVE |
| 正版服断线 | 模块已关，无重连 | 走模块自己的重连（重连回来同样跳过登录） |
| 离线验证服 | 完整认证流程（不变） | 完整认证流程（不变） |
| 单人世界 | 自动关闭（不变） | 自动关闭（不变） |
