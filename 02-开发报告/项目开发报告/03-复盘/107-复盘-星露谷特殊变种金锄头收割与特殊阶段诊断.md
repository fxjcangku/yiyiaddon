## 1. 先搞清楚「现状是什么」

识别层本来就已经覆盖它，不需要新增识别：

| 环节 | 现状 | 依据 |
| --- | --- | --- |
| 身份 → 作物键 / 阶段 | `customcrops:tomato_stage_golden` → `cropKey=tomato`、`stage=stage_golden` | `CropRuntimeStateResolver.stageCropKey/stageName`（按 `_stage_` 切分） |
| 阶段 → 状态 | `isSpecialStage` 命中 `golden` → `CropState.SPECIAL`（特殊变种） | `CropRuntimeStateResolver:309-312、379-384` |
| 产物身份 | `golden_tomato` / `tomato_golden_star` 已建号 | `StardewResourceIndex:497-500`、`StardewCropResourceSignature:220-240` |

缺的是**动作**：`StardewTaskPlanner.resolveTask` 的 `SPECIAL` 分支只播报一次
「发现特殊作物 ▸ 收割动作尚未确认，已安全跳过」然后 `yield null`；
`StardewServerProfile.specialCrops` 与 `StardewHarvestRule.specialHarvest` 这两个字段
**在旧项目与新项目里都只有声明、没有任何消费者**（`Grep specialCrops|特殊收割` 仅命中定义与聚合处）。
旧项目 `26.1.2 StardewCoordinator:1203-1207` 行为完全一致 —— 也就是说这不是移植偏差，
而是**旧项目从未落地的能力**，本次按用户实机口径补齐。

## 2. 动作口径（用户实机给出，不再自行假设）

| 项 | 口径 |
| --- | --- |
| 触发条件 | 该格识别为 `SPECIAL`（金色 / 巨大 / 变种，共用同一个动作） |

## 3. 实现（四处代码 + 两处文案，全部复用既有机制）

| 文件 | 改动 |
| --- | --- |
| `StardewTaskPlanner.java` | `SPECIAL` 分支改为：**有金锄头 → 派 `HARVEST`**；没有 → `skipSpecialWithoutTool()` 提示一次并跳过这一格（`yield null`），删掉旧的 `notifySpecialCalibration`（同源逻辑不留两份） |
| `StardewFarmExecutor.java` | 新增 `specialHarvestTool() = Items.GOLDEN_HOE`、`hasSpecialHarvestTool()`（`inventory.findSlotItem` 双源查背包 + 副手）；`doHarvest()` 命中 `isSpecialTarget()` 时走 `doSpecialHarvest()`：复用现成 `holdItem()` 取手（快捷栏直选 / 背包换主手 / 在副手直接用），右键后由 `restoreHandNow()` 复位 |
| `StardewTaskVerifier.java` | `HARVEST` 验证增加特殊变种判据：**这一格不再是特殊阶段 且 盆还在**（`crop.state() != SPECIAL && potStillPresent`）。不套普通成熟规则 —— 特殊阶段不在成熟阶段表里，拿 `afterHarvestStage` 比对会把成功判成失败，进而对收干净的格子反复右键 |
| `StardewQuerySupport.java` | `.stardew 诊断` 新增一行「特殊阶段」：按 `index.crops()` × `index.stagesOf()` 列出**本服资源包里真实存在**的金色 / 巨大 / 变种阶段，判据复用 `CropRuntimeStateResolver.isSpecialStage`（同源，不另立一套）；没有就如实报「无」 |
| `StardewFarmModule.java` | 帮助页两处文案同步：注意事项（金锄头收割 / 没工具只提示不停机）、诊断指令说明（会列特殊阶段） |

## 4. 行为定义（按用户要求）

- **有金锄头**：走普通 `HARVEST` 流程 → 播报「正在收获 · 番茄」→ 持金锄头右键 → 收完变植株 → 不刷屏。
- **没有金锄头**：**只提示一次，不停机**。提示文案「发现特殊作物 ▸ 背包里没有金锄头，已跳过这一格
  （放一把金锄头就会自动收）」，走 `status.state`（普通状态提示，非 `critical`），这一格跳过、
  其余任务照常推进；放回金锄头后**下一轮扫描自动恢复自动收割**，不需要重开模块。
- **绝不空手乱点**：没有工具时不回退成空手右键（空手点特殊阶段收不掉，只会白跑一趟）。

## 5. 只读诊断的样子

在 `.stardew 诊断` 输出里，紧跟「阶段模型」之后多一行，例如：

```
特殊阶段 ▸ tomato(番茄) stage_golden/stage_variation、pineapple(菠萝) giant
```

- 数据全部来自当前服务器资源包扫描结果（`stagesByCrop`），不编造阶段名；
- 判据与识别层共用一个 `isSpecialStage`，不会出现「诊断说有、识别层认不出」的分叉；
- 资源包里一个特殊阶段都没有时输出「无（本服资源包里没有金色 / 巨大 / 变种阶段）」。

## 7. 遗留与风险

- **巨大作物**（`giant/gigantic`）若是多格结构，可能需要逐格或按主体收；本次统一按「手持金锄头右键
  这一格」处理（用户口径「其他特殊都是右键一起做了」）。真机遇到多格巨大作物时再按实况调整。
- 没有金锄头时，那一格会一直保持 `SPECIAL`：每轮扫描都会重新命中 `SPECIAL` 分支（播报已去重，
  不会刷屏），不影响其它任务，也不会被「自动清理错位」误挖（该判据只在区域绑定的作物与格子作物
  不同名时成立）。
- 特殊变种的「回退到哪个具体阶段」没有写进任何规则：由下一轮扫描如实识别为 `GROWING`，
  这样不会因为猜错回退阶段而污染普通收获规则。
- 全部改动**未 commit**。
