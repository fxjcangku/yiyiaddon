## 1. 取证：到底哪一份数据被覆盖了

| 对象 | 隔离情况 | 证据 |
| --- | --- | --- |
| 三点点位 | **本来就隔离**（每服一份文件） | `run/config/yiyiaddon/mining/points/` 下 `server_520mc.cc_25565.json` 与 `server_rubiksmp.net_25565.json` 坐标完全不同 |
| 模块设置 | **不隔离**（全服共用一份） | `run/config/module-state.json` 的 `"mining"` 只有一块 `设置`，`wildCommand=rtp`、`unloadCommand/supplyCommand/afkCommand=res tp ZZB`，与服务器无关 |

结论：被覆盖的是**设置项**。旧项目对应物为**无** —— 旧项目三点位同样按服务器存
（`WKCommand` 的 `config/yiyiaddon/wk/<服务器>.json`，文件里**只有坐标**），设置项走框架的全局 Setting，
从来不分服。因此这是**用户明确要求的新增能力**（按第 163/165/171 条先问后做）。

## 2. 用户拍板的两条口径（本轮实现依据）

| 问题 | 选择 |
| --- | --- |
| 隔离范围 | **只自动挖矿**（其它模块维持全局共用） |
| 隔离粒度 | **自动挖矿的全部设置项**（一个服务器 / 存档一套完整配置；新服的初始值 = 现有全局配置） |
| 与手动记录的关系 | **两个都要**：设置自动按服务器隔离 + 控制台手动「保存 / 复原」记录 |
| 按钮形态 | **两个按钮**（`保存本服记录` / `复原本服记录`，无记录时「复原」为禁用态） |

## 3. 改动一：设置按服务器 / 单人存档隔离

### 3.1 框架层（新增一个可选钩子，默认不改变任何既有模块）

- `Module#settingsScope()`：返回非 `null` 时该模块的设置按该键分区；**默认 `null` = 不隔离**，
  未覆写的模块行为与旧档完全一致。两条硬要求写进 javadoc：键必须稳定可作 JSON 键；
  **未进入世界必须返回 `null`**（主菜单没有服务器身份，造键会写到并不存在的世界上）。
- `ModuleStateConfig`：模块记录内新增桶 `服务器设置` → `<隔离键>` → 设置对象；
  `settingsOf(id, scope)` 的回落口径是**该键没有记录时取全局模板**，于是：
  - 从旧版本升级上来：模板里就是玩家原有的那套配置，**不丢配置**；
  - 新服务器 / 新存档：初始值 = 玩家最近一次用的那套（模板每次保存都会同步更新）。
- `ModuleManager`：
  - `saveSettings` 读 / 写都按 `module.settingsScope()`；写入时**同时更新全局模板与本服桶**；
  - 新增 `reloadScopedSettings(module)`：按当前隔离键重读设置（读盘动作留在运行时，模块只判「变没变」）。

### 3.2 自动挖矿侧

- `settingsScope()`：进世界后返回 `WorldIdentity.fileSafeServer()`（多人 `host:port`，单人存档目录名），
  未进世界返回 `null`。
- `refreshSettingsIfScopeChanged()`：挂在 `reloadStore()` 的**第一步**。该入口覆盖三条必经路径
  ——启动自检、模块启用、打开配置页；设置先于点位读，因为自检读的就是设置（目标矿 + 三条指令）。
- `loadSettings` 记下 `loadedSettingsScope`，换服判据用它比对，避免每刻重读。

### 3.3 落盘结构（升级后）

```json
{
  "模块": {
    "mining": {
      "启用": false,
      "设置": { "...": "全局模板 = 新服务器 / 新存档的初始值" },
      "服务器设置": {
        "server_520mc.cc_25565": { "...": "这台服务器自己的一套" },
        "singleplayer_新的世界 (1)": { "...": "这个单人存档自己的一套" }
      }
    }
  }
}
```

只声明了隔离键的模块会出现 `服务器设置` 桶；其余模块（ID 三件套、自动箱子、星露谷、附魔、村民交易…）
文件结构与行为一字未变。

## 4. 改动二：控制台「配置记录」按钮

- 位置：控制台底部「刷新 / 关闭」那一行的**下方**（用户原话「在控制台的按钮的下面加一个按钮」）：
  一条状态行 + 一行两个按钮。
  - 状态行：`本服记录：未进入世界` / `本服记录：未保存` / `✓ 本服记录：09-17 23:55`；
  - `§b保存本服记录`：把**全部**设置写成当前服务器 / 当前存档的快照；
  - `§e复原本服记录`：把快照灌回设置并落盘；**没有记录时为禁用态**（`Button#disabledWhen`），
    正常点不到。
- 存储：`feature/mining/repository/MiningConfigRecordStore`（新建，模块内 `repository/`），
  文件 `config/yiyiaddon/mining/records/<服务器键>.json`，结构 `{ "保存时间": <毫秒>, "设置": {...} }`；
  「设置」直接复用 `MiningSettings#save` 的键，保证整份可原样回灌（不漏项）。
- 与自动隔离的分工：自动隔离管「切服自动换成那一套」，记录管「改乱了回滚」；
  复原只写回当前服务器的设置桶，快照文件不动，两者互不覆盖。
- 回执（走模块统一出口，受「状态播报」开关与 5 秒折叠约束）：
  - 保存成功 `§a✓ 已保存本服记录 §8▸ MM-dd HH:mm`；
  - 复原成功 `§a✓ 已复原本服记录 §8▸ MM-dd HH:mm`；
  - 主菜单点保存 `§e⚠ 未进入世界 §8▸ 本服记录只能在进入服务器或单人存档后保存`；
  - 无记录时点复原 `§e⚠ 本服还没有记录 §8▸ 先点「保存本服记录」`。
- 复原后若模块正在运行，重新下发男中音那 23 项调优（原启用路径里的那段调用抽成
  `applyBaritoneSettings()`，两处共用；入参顺序与旧 `onActivate :727-751` 一字未改）。

   在 B 服改成 B 的值 → 回 A 服 → **A 的值仍在**（本轮核心验收项）。

   把某项改乱 → 点「复原本服记录」→ 该项回到保存时的值（并有一条聊天回执）。

5. 升级前已有的配置仍能在首次进入的服务器上看到（回落模板），不需要重新填。

## 7. 遗留与风险

- 本轮及之前数轮改动**均未 commit**。
- **未做运行时验证**：`settingsScope()` 依赖 `mc.level`/`mc.player` 就绪，进世界第一刻的时序
  （进服即自动启用模块时 `reloadStore` 的调用时机）未实机确认。
- 「全局模板 = 最近一次保存的那套」是**有意口径**（新服继承最近配置）。若玩家希望「新服一律默认值」，
  需改成模板冻结，属口径变更，需用户拍板。
- 未做「其它模块也按服务器隔离」：按用户选择只做自动挖矿；框架钩子已通用，
  将来要给自动箱子 / 星露谷等模块开隔离，只需各模块覆写 `settingsScope()` 并在自己的进世界入口
  调 `ModuleManager.reloadScopedSettings`（不必再动框架）。
- 主菜单（未进世界）里改的设置只进全局模板，不会写进任何服务器桶（有意设计，已在 javadoc 说明）。
