## 取证与实现

此前 `gradle/proguard-rules.pro` 只执行名称混淆，ProGuard 本身未在此流水线中提供字符串加密与流程变换。新链路为：原始 JAR → ASM 加固类文件 → ProGuard 名称混淆 → 合并原始资源 → 最终包审计 → 独立备份。

| 文件 | 职责 |
| --- | --- |
| `gradle/hardening.gradle` | 单独编译构建工具，组织加固、行为测试和最终审计任务 |
| `gradle/hardening/src/com/yiyiaddon/build/ConstantEncryption.java` | 为常量生成随机密钥材料、随机 nonce 与认证密文 |
| 同目录 `FlowObfuscation.java` | 基本块物理重排及加密分派键跳转 |
| 同目录 `HardeningTool.java` | 选择安全变换范围、加密字面量和拼接配方、重算栈帧、输出统计 |
| 同目录 `HardeningFixture.java`、`HardeningSelfTest.java` | 随机布局行为回归与边界输入对照 |
| 同目录 `ProtectionAudit.java` | 针对最终改名产物验证类、常量解密、分派键和篡改拒绝 |
| `src/main/java/com/yiyiaddon/utils/ReleaseProtection.java` | 仅使用 JDK 的运行时解密入口 |
| `gradle/obfuscation.gradle` | 接入前置加固与后置审计，保存映射和统计 |
| `.gitignore` | 精确排除构建工具源码包名 `build` 被通用 `build/` 规则误忽略的问题 |

运行时采用 AES-256-GCM，12 字节 nonce 与 128 位认证标签；动态常量站点名参与密钥派生和附加认证数据。字符串保留 UTF-16 码元，覆盖 NUL 和非配对代理项，解密结果 intern 以保持 Java 字面量引用身份。ConstantDynamic 在首次解析时解密并由 JVM 缓存，避免每次 tick 重复解密。

控制流采用基本块随机排列，将跳转改写为加密整数常量驱动的 LOOKUPSWITCH，并为异常分支设置抛出路径。它不是覆盖全部代码的虚拟机保护，也不是完整状态机平坦化。名称继续由 ProGuard 混淆，清理调试信息。

解密算法和密钥材料必须随 JAR 分发，研究者可以执行辅助方法恢复明文；AES 算法强度不能直接等同于客户端逆向保护强度。自身审计就能恢复全部受保护常量，证明这一边界。

## 构建与自动验收

1. `./gradlew build --console=plain -q`：EXIT=0，记录 `build/obfuscation/final-build.log`。
2. `./gradlew buildRelease --console=plain`：EXIT=0，记录 `build/obfuscation/final-release.log`；最后复验摘要与下述反编译、启动测试使用的产物完全相同。
3. 行为测试：8 组随机布局、64,448 项输入对照通过，覆盖 Unicode、字符串引用身份、循环、switch、lambda、异常、数组、浮点边界和带条件的对象分配。
4. 最终包在 `-Xverify:all` 下加载 1,143 个类并检查成员；13,594 个字符串与原始常量集合对应；26,587 个整数逐项匹配实际跳转表；密文篡改触发认证拒绝。
5. 六类 Gson DTO 实际 JSON 往返通过；入口与 Mixin 类存在；原始资源字节保持一致；加密前后检查临时埋点标志。
6. ZIP 解压读取确认 1,685 个条目，源码、映射和构建工具类为 0；中文声明存在。实际抽取三个 class 用于 CFR 验收。

这些验证不能覆盖全部游戏运行路径，尚未进行完整游戏内功能与长时间性能验收。

## 实际反编译测试

工具放在 `build/obfuscation/tools/`，测试未借助缺失依赖来制造失败。

| 测试 | 输入与结果 |
| --- | --- |
| Vineflower 1.12.0 | 最终完整 JAR，补齐 compileClasspath 外部依赖，EXIT=0，输出 760 个 Java 文件 |
| CFR 0.152 | 从最终 JAR 抽取 Easing、IdentityService、ReleaseProtection 的改名 class；补齐依赖及最终包，启用 `--antiobf true`；三项均 EXIT=0 |

Vineflower 参数保存在 `build/obfuscation/vineflower.args`，日志与源码输出分别为 `vineflower-with-dependencies.log`、`vineflower-with-dependencies/`。出现一个重复处理方法警告，不能把它说成整个反编译失败。

CFR 输出在 `build/obfuscation/cfr-with-dependencies/`，抽取类在 `cfr-samples/`。Easing、IdentityService 输出可见动态常量伪表达式，部分方法出现 `Unable to fully structure code` 与 GOTO 伪代码，不能直接当原源码重新编译。解密辅助类本身能够被阅读，密文、种子和调用结构也能观察。

较早一次未补依赖的 CFR 全包尝试在生成部分文件后主动停止，不作为全包失败证据；本报告只对最终完成的三类 CFR 抽样给出结论。Vineflower 完整包成功输出说明反编译器仍然可以分析大量结构，不能声称“无法反编译”。目前证据支持提高直接静态阅读和直接重编译的成本，不支持无法动态提取或阻止 AI 辅助分析。

## 独立客户端启动验收

使用 `build/obfuscation/client-smoke/` 独立游戏目录，正式模式 Fabric KnotClient，安装当前摘要的发布包与 Fabric API；未复制用户账号、存档或服务器配置。启动参数保存在该目录 `launch.args`。

最终日志 `protected-stdout.log` 显示：08:16:54 加载 55 个模组，包含 yiyiaddon 1.0-beta1 及嵌套依赖；08:16:57 输出 `yiyiaddon initialised (baritone localisation: on)`；窗口标题为 Minecraft 26.1.2 且进程响应正常；08:18:25 通过关闭窗口正常停止。没有新增崩溃报告，也未发现 VerifyError、BootstrapMethodError 或 Mixin 应用失败。

测试使用离线占位令牌，日志有 Mojang/Realms 认证失败，不能把它归因为加固错误。此前首次启动未放置 mods 导致只加载基础模组，该次不算模组启动验收；此处结论来自安装发布包后的第二次启动。

验收口径：实际混淆包启动已验证；游戏内完整功能未实机验收。未声称进入世界、人工观察全部页面、连接服务器或完成模块全流程。

## 使用说明与资料

以后发布执行 `./gradlew buildRelease --console=plain`，仅分发 `build/release/` 下的混淆 JAR。普通 `build` 是开发包。工具变换失败、字节码验证失败、常量审计失败或映射备份冲突会使发布构建失败。新随机加固可能产生不同摘要，必须使用本次对应映射并重新验收。

免费组件依据：[ASM 官方版本信息](https://asm.ow2.io/versions.html)、[JDK 25 Cipher API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/javax/crypto/Cipher.html)、[Vineflower 使用文档](https://vineflower.org/usage/)、[ProGuard 配置说明](https://www.guardsquare.com/manual/configuration/usage)。当前使用说明已同步到 `05-混淆文件备份/README.md`。

## 下一阶段开发规划

### 一、下一阶段目标

完成目标比赛环境中的核心模块功能与性能验收。

### 二、执行原因

字符串首次解密、额外分派和类体积增加有成本；启动与纯函数夹具不能覆盖实际世界、服务器和全部 UI 路径。

### 三、前置条件检查

当前构建、自动审计、解压、反编译及独立启动通过；需准备合法可用的测试场景和实际操作清单。

### 四、任务拆分

1. 目标：验证页面、配置持久化与常用模块；涉及目录：独立客户端；影响范围：测试数据；预计修改内容：记录实际行为，只有发现证据明确的问题再定点修正构建兼容规则。
2. 目标：比较启动、首次打开页面及 tick 开销；涉及目录：测试记录；影响范围：性能验收；预计修改内容：补充基线与混淆包测量结果，不预先承诺无性能损耗。

### 五、验收标准

对应摘要的包在实际比赛环境正常加载、主要功能行为一致、配置读写无损、性能可接受；结果区分自动验证与人工游戏内验收。

### 六、禁止事项

禁止公开内部映射、把原始 JAR 当发布包、把反编译警告当绝对安全证明、擅自修改业务逻辑或上传源码。
