# 复盘：挖不动的格子没有退避，且按物品类型认「金锄」（巨型菠萝空砸两分钟）

- 日期：2026-09-22
- 触发：用户实机 ——「巨型菠萝也不挖 看日志」（196 续二之后的第三次实机复现）
- 取证：本地开发客户端 `run-26.1.2/logs/2026-09-21-7.log.gz`（23:34:56~23:38:08 会话）

## 一、现象与日志

同一格 `BlockPos{4796,85,-5601}`（`minecraft:chorus_plant`，巨型作物的承载体）从 23:36:05 一直砸到
23:38 启动前，每十几秒一整轮、每轮四次发包，方块纹丝不动：

```
[23:36:05] 破坏 开始挖掘 目标=4796,85,-5601 chorus_plant · 该格无实体 选中物品=1 minecraft:golden_hoe
           硬度=0.4 物品破坏速度=0.0 正确工具=true 原始每刻进度=0.0 → 实际用 1.0E-4 客户端估算 7000 tick
           → 按住 40 tick 发包=true
[23:36:08] 破坏 重试挖掘 … 第 2 轮 按住 80 tick  选中物品=1 minecraft:golden_hoe  每刻进度=0.083333336
[23:36:13] 破坏 重试挖掘 … 第 3 轮 按住 120 tick 每刻进度=0.083333336
[23:36:23] 破坏 开始挖掘 …（下一轮，回到 0.0 估算、按住 40 tick）
[23:37:14] 这一格服务端没放行｜4796, 85, …｜已按学到的口径按住挖了 4 轮仍是原样
[23:37:14] 破坏 开始挖掘 …（又一次，从头再来）
```

同一会话里另一格 `4799,85,-5602`（同类方块）却在 23:39:09 三轮内挖掉了 —— 说明破坏链路本身没问题，
问题出在「这一格用哪件东西挖」。

## 二、成因一：按物品本体认工具，认不出「金锄基底的自定义道具」

`breakAt` 原先靠 `holdItemOnce(Items.GOLDEN_HOE)` 换手，而它判断「手上已经是它了」用的是
`ItemStack#is` —— **只比物品本体**。资源包里存在与金锄同基底（`minecraft:golden_hoe`）的自定义道具，
它的 `tool` 组件采掘速度是 0（正确的工具判定仍为 true，所以日志里 `正确工具=true` 但
`物品破坏速度=0.0`）：

- 手里正是那把时：客户端算出每刻 `1.0E-4`、需 7000 tick → `holdTicksFor` 退回固定 40 tick → 服务端
  按真实进度判定必然驳回；
- 手里是原版金锄那一次：每刻 `0.083333336`、需 8 tick —— 同一格同一天的日志在两种读数之间反复跳，
  196 续二把它当成「客户端估算整条不可信」，其实其中一半是**拿错了东西**（第 167 条：说得出是哪一件）。

## 三、成因二：挖不动之后没有退避，每轮决策重新派发同一格

`reportBreakRejected` 只负责「按坐标报一次」，**没有任何退避**。于是：

- 每次扫完农田（十来秒一轮）决策层又是这一格 → 4 轮发包 + 4 轮按住 → 再放弃 → 再来；
- 玩家看到的是「模块赖在这一格空砸了两分钟」，聊天栏只有一条结论，与眼前的动作对不上。

## 四、处置

1. **选工具改为按实测挑**（`StardewFarmExecutor#ensureDigTool`，替换 `holdItemOnce`）：
   - 手上那件算得出可用进度（`required ≤ BREAK_MAX_REQUIRED_TICKS`）→ 什么都不动（工具不限）；
   - 否则先找一把真挖得动的**金锄**（`0~35`，按 `ItemStack#getDestroySpeed(state) > 0` 挑最快的；
     快捷栏直接切、背包里的换到选中槽）；
   - 再退一步挑「换到这一格进度最高」的一件（空手也算 —— 本服口径「工具不限」，空手每刻 0.025、
     约 27 刻也能挖掉），只扫快捷栏且逐个试算 —— 试算用引擎自己的 `BlockState#getDestroyProgress`
     （临时改本地选中槽、不发携带物包，算完立刻还原），因此不在模块里复刻 hardness / 正确工具那套公式；
   - 整包都是挖不动的道具时保持原样，仍按原口径试（估算离谱 ≠ 这一格挖不动，196 已验证过
     「40 tick 那一轮真的挖掉了」）。逐轮重试（`tickBreakDig`）里也同样先过一遍 `ensureDigTool`。
2. **挖不动的格子加退避**（`StardewCoordinator#BREAK_REJECT_BACKOFF_MS = 60_000L`）：
   `reportBreakRejected` 顺手登记「这一格 60 秒内不再派发破坏动作」，到期自动解除（不留永久黑名单）；
   决策层按 `isBreakRejected(那一格)` 跳过它，与「满是满仓」两条闸并列。换服 / 换包 / 换维度时清空
   （坐标在不同维度是别的方块）。
3. 播报补一句出路：`这一格服务端没放行｜…｜已按住挖了 4 轮仍是原样｜出路：手动收一棵给我看；
   这一格 60 秒内不再重试`。
4. 删掉已无用的 `holdItemOnce`（它正是「按物品本体认工具」那一步），`holdTicksFor` 的
   `BREAK_MAX_REQUIRED_TICKS` 兜底注释改回「估算离谱时按多久」，不再宣称「不开会话」（那条闸从未落地）。
