# 124-复盘-食物白名单管不住嘴（白名单只有金苹果却吃了腐肉）

日期：2026-09-19
项目：yiyiaddon（Fabric 26.1.2 客户端模组）
用户原话：「我选了白名单是金苹果然后没放在快捷栏 刚刚然后杀了一个僵尸掉了两个腐肉 然后就吃腐肉了？
我的丢弃物品白名单没有选腐肉呀 怎么会吃腐肉？我白名单食物只有金苹果」
裁定：**严格白名单：只吃也只留白名单食物**；「保留白名单」与「食物白名单」**职责分开**。

---

## 一、根因（三处判据各自绕开白名单）

118 号做「发包连吃 + 自动回血」时，把进食口径从「白名单内食物」放宽成了「任何带 `FOOD` 组件的物品」，
而放宽只做了两处、漏了一处，且三处口径互不一致：

| # | 位置 | 当时的判据 | 后果 |
| --- | --- | --- | --- |
| 1 | `MiningContainer#shouldKeep`（`:286`） | `stack.has(DataComponents.FOOD)` → 保留**任何**食物 | 僵尸掉的腐肉**没被当垃圾丢掉**，留在背包里 |
| 2 | `MiningContainer#isEdible / findBestFoodSlot`（`:967/:975`） | 只判「有 FOOD 组件 + 原版允许吃」，**完全不看白名单** | 挑口粮时把腐肉挑出来吃了 |
| 3 | `MiningStateMachine#hasFoodToEat`（`:3109`） | 同 2 | 与 `countFoodStacks`（一直按白名单统计）口径打架 |

再叠加评分规则（`foodScore`，`:1014`）：

```java
return food.canAlwaysEat() ? 0 : 1000 + food.nutrition() * 10 + Math.round(food.saturation());
```

金苹果类恒为 **0 分**、排在所有普通食物**之后**（原设计意图：金苹果留着救急，平时不当口粮）。
腐肉营养 4 → 1041 分，金苹果 0 分。**所以就算金苹果就在背包里，也会先吃腐肉** —— 这正是用户看到的现象。

补充：`foodWhitelist` 当时的注释写的是「从食物箱**只拿**选中的食物」，即它只被当**补给取货清单**用，
这就是它管不住嘴的根源。

## 二、修复（吃 / 留 / 统计 / 取货四处统一走 foodWhitelist）

新增单一判据 `MiningContainer#isWhitelistedFood(ItemStack)` = 「在白名单内 **且** 带 FOOD 组件」，
所有涉及「食物」的地方改调它：

| 位置 | 改动 |
| --- | --- |
| `MiningContainer#isEdible` | 增加 `if (!isWhitelistedFood(stack)) return false;`（`findBestFoodSlot` 随之自动收口） |
| `MiningContainer#shouldKeep` | `stack.has(FOOD)` + 单独一行白名单 → 合并为 `isWhitelistedFood(stack)`：**白名单外的食物照垃圾丢掉**；`keepWhitelist`（保留白名单）作为职责独立的额外免丢名单原样保留 |
| `MiningContainer#findTemporaryHotbarSlot` | 腾快捷栏时「不顶食物」收窄为「不顶白名单食物」 |
| `MiningContainer#describeEatingFood` | 播报口中的食物名改用 `isWhitelistedFood`（否则手上非白名单食物会被误报成正在吃它） |
| `MiningContainer#restoreEatDisplacedItem` | 换回被顶格的条件「该格还是食物或空着」收窄为「还是白名单食物或空着」 |
| `MiningStateMachine#hasFoodToEat` | 加白名单判据（白名单 + FOOD 组件），与 `countFoodStacks`、`withdrawFood` 完全同源 |

文档同步：`MiningContainer` 与 `MiningStateMachine` 的类注释、`packetEat` / `foodScore` / `shouldKeep`
的 javadoc、`MiningSettings#foodWhitelist` 的注释、控制台「食物白名单」行说明全部改写为新语义。

## 三、语义（用户裁定后）

- **食物白名单**＝自动挖矿的食物总口径：**只吃、只留、只统计、只从箱子拿**这里面的食物；
  白名单外的食物（腐肉、怪物掉的熟肉…）一律当垃圾丢弃。
- **保留白名单**＝职责独立的额外免丢名单（非食物物品用它保留）。想吃/想留某样食物 → 加进食物白名单。
- 评分规则不变：白名单里同时有金苹果与普通食物时，**先吃普通食物**，金苹果留作饱食度满时的救急口粮。

## 四、构建与验证

- `.\gradlew.bat build --console=plain` → **BUILD SUCCESSFUL**（EXIT=0）。
- 开发客户端已重启。实机验收项：
  1. 食物白名单只留金苹果 → 打僵尸掉腐肉，**不吃也不留**（腐肉会在跑路中被丢出背包）；
  2. 白名单加回普通食物（如熟牛排）→ 饿了先吃牛排，金苹果留到最后；
  3. 饱食度 < 15 且背包只有白名单外食物 → 正确转补给（不再误判「有吃的」而死循环进食）；
  4. 控制台「食物白名单」行说明文字已更新为新口径。
