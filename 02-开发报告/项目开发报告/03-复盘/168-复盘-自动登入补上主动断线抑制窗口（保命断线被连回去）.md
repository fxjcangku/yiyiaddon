# 168 - 复盘：自动登入补上主动断线抑制窗口（保命断线被连回去）

日期：2026-09-21
分支：`master`（26.1.2 主线；本改动与 MC 版本无关，26.2 侧 cherry-pick 即可）
验证：`.\gradlew build --console=plain -q` → EXIT=0；**未实机**（判据为纯新增分支，无 API 变更）

## 一、问题

用户问「自动登入里的重新连接与独立的自动重连模块冲不冲突」，排查共存机制时发现缺口：

- 两个模块本身**不冲突**：`AutoReconnectModule#autoLoginTakesOver()` 已让路，`ReconnectEngine` 同源共用（第 169 条）。
- 但管理员检测的保命断线（`AdminDisconnect#disconnect`）靠 `ReconnectSuppression` 抑制窗口通知「这次别连回去」，全树**只有 `AutoReconnectModule#handleDisconnect` 查了它**（`:363`）；`AutoLoginModule#handleDisconnect` 没查。

后果：自动登入模块开着且其「自动重连」设置开着时（此时恰是自动登入接管重连的场景），管理员检测主动断线逃生后，自动登入会按设置把人立刻连回去——保命动作等于白按。

## 二、取证

| 事实 | 位置 |
| --- | --- |
| 抑制窗口的设置方（断线前开窗） | `feature/admindetect/service/AdminDisconnect.java:48` |
| 抑制窗口的读方全树仅一处 | `feature/reconnect/AutoReconnectModule.java:363` |
| 自动登入断线处理无该判据 | `feature/autologin/AutoLoginModule.java` 原 `:799-847`（`handleDisconnect`） |
| 独立模块的判据写法（对齐口径） | `AutoReconnectModule.java:362-367`：查 `suppressed()` → 播报 → 置 IDLE → return |

## 三、修复（最小改动，一处分支）

`AutoLoginModule#handleDisconnect` 在「已调度」守卫之后、乐源路线 `beginRecovery()` 之前插入抑制分支：

- **不调度重连、不走乐源异常恢复**（恢复同样会把人连回登录服）。
- **会话清场照常做**（与正常断线路径同一串字段重置）：断线清场是任何断线都要做的，漏了会留过期会话状态，下次进服误判。
- **乐源路线 `stop()`**（中途断线时先松开兜底快捷键再清状态，与正常运行期停表同一实现）；子服路线 `reset()`。
- 播报「本次断开是主动断线（管理员检测），不自动重连。」（口径对齐独立模块的 `MSG_SUPPRESSED` 文案），状态回 `IDLE`。

不动的部分：判据顺序与独立模块一致（「已调度」守卫在前）；「未搬的旧行为」清单第 93 条（旧流星框架接管播报）不涉及。

## 五、遗留

- 未实机验证：建议实测路径——自动登入开 + 其自动重连开，进服后让管理员检测触发「立即断线」，确认断开后无重连倒计时、聊天出一条抑制播报。
- 边缘口径（与独立模块同样存在，未改）：若断线时已有一轮重连倒计时在跑（`RECONNECT_WAIT` 且已调度），两模块的守卫都直接 return、不再查抑制——但主动断线前提是「有连接」，此时通常不在倒计时态，实际不可达，仅登记。
