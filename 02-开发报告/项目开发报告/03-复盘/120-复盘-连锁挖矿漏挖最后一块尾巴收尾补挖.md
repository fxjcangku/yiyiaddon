# 120-复盘-连锁挖矿漏挖最后一块（尾巴收尾补挖）

日期：2026-09-19
项目：yiyiaddon（新项目，Fabric 26.1.2 客户端模组）
旧项目对应物：无（连锁挖矿是本项目 2026-09-17 起自建能力，旧项目没有；本次是它的缺陷修复）
用户原话：「还有个 bug 你看物品 经常漏挖 剩下一个 然后走掉 跑去挖别的 然后又跑回来在挖一次这个 真的很浪费时间」

---

## 一、取证：漏的那一块是怎么被丢下的

沿「谁把方块交回给 Baritone」查了三处，全部落在 `feature/mining/vein/MiningVeinMiner.java`：

| # | 位置 | 行为 |
| --- | --- | --- |
| 1 | `scanVein`（原 `:539-555`） | 脉扫描按三类**不入队**：够不到（超交互距离）、隔着方块看不见、达队列上限。三类都只计数、不入队，注释写着「交给 Baritone 走过去挖」 |
| 2 | 派发循环（原 `:319-325`） | 队列里的块如果「还是矿但已经够不到」→ `skippedCount++` 后**直接出队丢掉** |
| 3 | 派发循环（原 `:326-330`） | 被秒破判「挖不动」拉黑的块 → 同样直接出队丢掉（这一条保留：放行原版给它挖） |

三条的共同结果：**尾巴块回到 Baritone 的全局目标池**（`resumeBaritone()` → `startMining(module.getMiningTargets())`）。
Baritone 的 mine 按自己的**路径成本**排序挑目标，不按直线距离，于是这几个尾巴常被排在别的矿后面 ——
玩家看到的就是「剩一个 → 跑去挖别的 → 又跑回来挖这个」。这不是随机现象，是这三条分支的必然结果。

既有缓解手段只有 `sweepNearbyOres`（近矿清扫：半径 3 格 + 要视线 + 每 20 刻采样一次、空扫后冷却 40 刻）——
它治的是「3 格内的近矿」，**够不到 4~8 格的尾巴它扫不到**，所以用户的症状仍在。

## 二、修复：队列排空后自己把尾巴补完（挖干净才还 Baritone）

改在 `feature/mining/vein/MiningVeinMiner.java`，不新增设置项、不新增第二条寻路：

| 位置 | 改动 |
| --- | --- |
| `:147/:157-164/:218-228` | 新增「本脉尾巴」状态与常量：`leftovers`（尾巴坐标集，上限 64）、`leftoverTarget/StartPos/Ticks/NoSightTicks/GiveUps/HandedOver`；`LEFTOVER_CHASE_TIMEOUT_TICKS=200`（单块 10 秒）、`LEFTOVER_NO_SIGHT_GRACE_TICKS=40`（到位 2 秒仍看不见）、`LEFTOVER_STUCK_TICKS=60`（原地 3 秒不动）、`LEFTOVER_MAX_GIVE_UPS=3` |
| `:756/:763/:769` | `scanVein` 的三类「不入队」分支各加一次 `rememberLeftover(neighbor)`（**超出连锁搜索距离的不记**：那是用户设置，仍按设置交给 Baritone） |
| `:340` | 派发时「走远了够不到」由「丢弃 + 记账」改成 `rememberLeftover(next)`（不再是丢下不管） |
| `:315` | `tick` 的「队列空 + 控制器空闲」分支插入 `if (chaseLeftovers(player)) return;`，排在近矿清扫之前 |
| `:504-580` | 新增 `chaseLeftovers`：① 到位且看得见 → 入队（下一刻用秒破挖）+ 停 Baritone；② 正在追 → 累计刻数并检查三条放弃判据（追太久 / 到位仍看不见 / 原地卡住）；③ 换目标 → 停 Baritone 后走 `MiningPathing#pathToOre`（`GoalTwoBlocks`，与种子模式同一入口）走过去 |
| `:576-607` | `giveUpLeftover` / `finishChase`：放弃与收尾都清干净追补状态；`finishChase` 把剩余块记进 `leftoverHandedOver` |
| `:392-412` | `reset()`：离开挖矿态 / 关模块时显式 `stop()` 掉追补用的单目标寻路（否则它会留在世界里没人收），并清空尾巴状态 |
| `:846-862` | `resumeBaritone()` 播报口径改为 `skippedCount + leftoverHandedOver`（「另有 N 块挖不动或够不到，已交回 Baritone 补挖」），数值与实际行为对齐 |
| `:49-61` | 类注释「只挖够得着的方块」一节改写为「只挖够得着的方块 + 尾巴收尾补挖」 |

兜底与旧行为一致：单块追 10 秒 / 原地 3 秒不动 / 连续放弃 3 块，就把剩余整批交回 Baritone 全局池，
不会卡在追补里；追补期间 `isActive()` 为真，状态机的「挖不动自愈」与漏捡补偿照旧避让。

## 三、明确不做的事

1. **不追「超出连锁搜索距离」的尾巴**：`veinRange`（默认 4）是用户设置，越界块仍按设置交给 Baritone。
   如果实机发现漏掉的块正好在搜索距离之外，说一声，把它们也纳入收尾补挖（改 `scanVein` 的
   `beyondRangeCount` 分支加一行 `rememberLeftover` 即可）。
2. **不动秒破「挖不动拉黑 600 刻」那条路径**：那类方块交给原版按原速挖，拉黑本身是防「永远挖不烂」的既有设计。

## 四、构建与验证

- `.\gradlew.bat build --console=plain` → **EXIT=0**（2026-09-19，本机）。
- **未实机**。实机验收项：
  1. 挖一条脉（末块够不到 / 隔着方块）时，人应当**自己走过去**把那块挖掉，而不是跑掉再回来；
  2. 聊天栏「连锁完成 ▸ 本次连锁破坏 N 块」里的 N 应包含这些补挖的尾巴；
  3. 遇到确实走不到的尾巴（岩浆湖对面 / 封死），3 秒不动或 10 秒超时后放弃并照常回去挖矿，不卡住；
  4. 战斗中 / 离开挖矿态时追补立即中断（`reset()` 收掉单目标寻路）。
