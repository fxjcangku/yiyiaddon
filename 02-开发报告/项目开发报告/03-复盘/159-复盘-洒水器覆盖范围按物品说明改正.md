# 159-复盘-洒水器覆盖范围按物品说明改正（5×5 / 9×9 / 13×13）

日期：2026-09-21
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件

用户实机截了三种洒水器的物品说明（本服「季明月种植」包）：

| 物品 | 储水总量 | 工作范围 | 单次加水 |
| --- | --- | --- | --- |
| 初级洒水器 | 3 | **5 * 5** | 5 |
| 中级洒水器 | 5 | **9 * 9** | 5 |
| 高级洒水器 | 9 | **13 * 13** | 5 |

并指出「给你看水量 你改正一下 范围」——即 `radiusOfLevel` 的等级估算表是错的。

## 二、根因：估算表抄的是原版攻略，不是本服 customcrops 配置

改动前 `StardewRenderState.radiusOfLevel`：等级 1/2/3/4 → 半径 1/1/2/3（3×3 / 3×3 / 5×5 / 7×7），
注释写明口径来自《星露谷物语》**原版攻略**的洒水器表。

本服真实数据是 **边长 = 4n+1**（5 / 9 / 13），即半径 = 2n。两处后果：

1. **覆盖框画小了**：初级按 3×3 画、实际 5×5，中级按 5×5 画、实际 9×9，高级按 7×7 画、实际 13×13。
2. **实测永远「顶到扫描边界」**：`SprinklerCoverage.SCAN_RADIUS` 取 4（9×9 窗口），
   是照「估算上限半径 3」定的；可高级洒水器半径是 6，湿盆必然铺满窗口，
   `truncated()` 每次都命中——实机四台全报「顶到扫描边界，实际可能更大」，等于这份实测没有结论价值。

## 三、改动

### 1. `StardewRenderState.radiusOfLevel`：改成实测口径

```java
public static int radiusOfLevel(int level) {
    return switch (Math.max(1, Math.min(4, level))) {
        case 1 -> 2;   // 初级 5×5
        case 2 -> 4;   // 中级 9×9
        case 3 -> 6;   // 高级 13×13
        default -> 8;  // 四级（本服资源包无此档）按同一边长等差外推 17×17
    };
}
```

- 等级越界一律夹到端点：一个脏数据不会画出一个荒唐的大框；
- 等级未知（0 / 负数）取最小一档（初级 5×5）；
- `sprinklerRadiusAt` 的「认不出身份」分支从写死 `1` 改成 `radiusOfLevel(1)`，
  口径只有这一处。

### 2. `SprinklerCoverage.SCAN_RADIUS`：4 → 7（15×15 窗口）

窗口必须能整个装下最大的 13×13，再往外留整整一圈余量，`truncated()` 才只在
「湿盆真的超出了任何已知洒水器」时报警。扫描格数 225 格（原来 81 格），
实测只在绑定时与玩家敲命令时各跑一次，可忽略；每格仍走 `BlockState` 记忆化解析。

## 四、验证

- `.\gradlew.bat build --console=plain -q`：EXIT=0。
- **是否实机：未实机**（已重启 dev 客户端待测）。预期：未实测的洒水器覆盖框变成
  5×5 / 9×9 / 13×13；`.stardew 实测范围` 重测后不再报「顶到扫描边界」。
- **旧实测结论必须重测**：点位文件里现存的范围是在 9×9 窗口下测出来的（7×7 / 5×7 且顶边界），
  渲染「实测优先」，不重测就仍按旧结论画。跑一次 `.stardew 实测范围` 覆盖即可，
  或 `.stardew 实测范围 清除` 退回等级估算。
