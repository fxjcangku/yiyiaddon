# 复盘：物品选择器两旁露出放大图标（隐藏格子改按「面板可盖面积」排版）

- 日期：2026-09-22
- 触发：用户实机截图（个人版 `yiyiaddon-1.0-beta1-personal+26.1.2.jar`）「没看见两旁出现了大图标？
  物品选择器里面的」——面板左右两侧各露出放大的方块贴图图标
- 结论：不是贴图缓存错，是 `ItemIconCache` 的**隐藏格子排布与面板尺寸脱钩**：格子固定一排 12 格
  （428 逻辑像素）居中铺开，而面板宽度随「界面大小」（默认 75%）与 GUI 缩放变化，窄的时候只有
  约 277 逻辑像素 —— 一排铺不下，两侧各两格直接露在面板外

## 一、现象与取证

| 检查项 | 结果 |
| --- | --- |
| 是哪条链路 | `ItemIconCache`「借位渲染 + 截取」：抽帧阶段把待加载物品画进屏幕中央的隐藏格子（上黑底 / 下白底两行，相减反解 alpha），Skija 阶段回读入库，帧末面板把它盖住 |
| 格子几何 | `slotX = round(guiWidth/2 − 428/2) + i×36`，总宽 `BATCH(12) × (32+4) − 4 = 428` 逻辑像素，与窗口/面板无关 |
| 面板几何 | `PanelFrame#update`：`scale = fit × 2 / guiScale × uiScale`，面板逻辑宽度 = `740 × scale` |
| 为什么现在才露 | `07bbe43` 把「界面大小」默认从 100% 改成 75%（用户要求），面板随之缩到 3/4 → 1440p + GUI 缩放 4 下面板 ≈ 277 逻辑像素 < 428 |
| 露出的具体量 | 1440p/缩放 4：`(428 − 277) / 2 ≈ 75` 逻辑像素，即每侧两整格放大图标；1080p/缩放 3：`(428 − 370)/2 ≈ 29` 逻辑像素，每侧小半格 |
| 有没有掩盖机制 | 曾有「抽帧回读格子区域 → 帧末写回」的掩盖动作，`03e8c4f` 期间已判定它是另一串怪象（正中横带 / 白糊 / 纯黑块 / 更亮的带子）的来源，产出入口被改成空实现，注释里留的假设正是「面板在任意 GUI Scale 下都比格子宽」—— 这个假设在 75% 下不成立 |

结论：**格子必须被面板盖住，而「盖得住」是面板尺寸的函数，不能写死一排 12 格。**

## 二、改动

### 1. 布局：`ItemIconCache` 新增 `Grid` + `fit(cover, slots, client)`

- 格子改成「上下两个色块（黑底 / 白底）+ 每块内 `cols × rowsPerBlock` 网格」，行优先铺开；
- 列数由可盖宽度定：`cols = min(slots, ⌊(availW + SLOT_GAP) / CELL⌋)`；
- 行数由可盖高度定：`maxRows = ⌊((availH − ROW_GAP) / 2 + SLOT_GAP) / CELL⌋`；
- 整片格子仍以屏幕中心居中，两块之间固定留 `ROW_GAP`，因此**缝隙正中仍是屏幕正中**（准星永远落在
  缝隙里，不会被截进任何一格）；
- 装不下就少截几张（`capacity` 封顶），连一格都排不下就整帧不截、请求原样留在队里等下帧。

### 2. 可盖面积从界面来：`SkiaScreen#coverRegion()` + `PanelFrame#opaqueScreenRect()`

- `PanelFrame#opaqueScreenRect(width, height, rise)` 返回面板玻璃**完全不透明的内接矩形**：
  四条边各内缩一个圆角（`CARD_RADIUS`）再加 4 设计像素余量 —— 圆角处玻璃是缺的，不内缩就会在
  四角露角；
- `SkiaScreen#coverRegion()` 默认 `null`（退回整屏可用，避免出现「图标彻底加载不出来」）；
  画面板的三个界面各自覆写：`PanelScreen`（带开合上浮位移）、`ModuleScreen`、`ClickGuiScreen`
  （后两者无位移，传 0）；
- `renderPending(graphics, cover)` 多接一个参数，`capturePending` 用同帧的 `frameGrid` 回读对应格子。

### 3. 删掉已死的「画面备份写回」产出入口

`saveBackdrop` / `saveBackdropLegacy` / `backdropBox`（以及 `BACKDROP_PAD`）一并删除：格子现在永远在
玻璃里，没有需要糊回去的东西。`paintBackdrop` / `flushBackdrop` / `finishBackdropFrame` 保留为保底接口
（外部调用点 `SkiaGlBackend#beginScreenFrame`、`SkiaScreen`、`RenderTargetMixin` 不动；备份恒为 null 时
全是空操作），段头注释写明「将来真遇到盖不住的界面，正确做法是给更准的 coverRegion，而不是把回读写回来」。

## 三、验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew.bat compileJava` | **EXIT=0** |
| `.\gradlew.bat buildPersonal` | **EXIT=0**，产出 `build/libs/yiyiaddon-1.0-beta1-personal+26.1.2.jar` |
| 排版实测（笔算，1440p / GUI 缩放 4 / 界面大小 75%） | 面板 277×187 逻辑像素 → 可盖 258×168 → `cols=7, maxRows=2` → 7×2 网格，块宽 248、总高 152，**左右各留 5、上下各留 8 逻辑像素** |
| 旧口径回归（1080p / GUI 缩放 3 / 界面大小 100%） | 面板 493 逻辑像素宽 → `cols=12, rowsPerBlock=1`，格子 428×80 与原实现**逐像素同落点**（`left = round(guiW/2 − 214)`、`blockTop = round(guiH/2 − 40)`），即大屏高缩放下行为完全不变 |
| 实机验证 | **已通过**（用户 2026-09-22「修好了上一个bug」）：物品选择器打开后，面板两侧与四角均无放大图标外露 |

复测要点（已跑过的第 1 条通过，其余仍可顺手核对）：
1. 物品选择器（自动取物 / 村民交易 / 保留白名单等任一处）打开并滚动，两侧与四角都干净；
2. 「界面大小」在 75% / 100% / 125% 之间切换后重新打开，两侧仍干净；
3. 图标照旧能加载出来（滚动一屏后每行都带贴图），不出现「一直空着」的行 —— 这是「少截几张」那条
   兜底路径是否被误触发的判据。
