# 110 - 复盘：发包秒破运行期间压掉 ESP 的「瞄准方块高亮」白框

- 日期：2026-09-19
- 触发：用户反馈「发包秒破跟我 esp 的白色选择框有冲突，能不能发包秒破开启不要显示这个白框」
  （澄清：指 **ESP 全局设置页里的「瞄准方块高亮」**，他自己把颜色设成了白色）
- 涉及文件：`ui/render/world/EspGlobalSettings.java`、`ui/render/world/BlockOutlineRenderer.java`、
  `feature/packetbreak/PacketInstantBreakModule.java`
- 验证：`./gradlew build --console=plain -q` → **EXIT=0**；**未实机**

---

## 1. 冲突成因

ESP 全局设置里的「瞄准方块高亮」（`BlockOutlineRenderer`，常驻注册、不属于任何业务模块）
给**准星指向的方块**画一圈整格描边，默认白色。而秒破开挖前会把视角转向目标方块
（`settings.rotate`，默认开）—— 准星于是随挖掘目标一路扫过去，白框一直闪、挖东西时一直出现，
与玩家自己的 ESP 视觉互相打架。

**这完全不是新问题**：2026-09-18 用户对自动挖矿提过一模一样的要求
（原文记在 `EspGlobalSettings#autoMinerRunning()` 注释里：「esp 那个白色显示的方块功能跟自动挖矿
冲突了，挖的时候都会出现，能不能自动挖矿启动的时候不显示」），当时的处理是自动挖矿运行期间不画。
秒破没接上这条，于是同一个毛病又出现一次。

## 2. 实现（沿用同一套机制，不另立开关）

| 文件 | 改动 |
| --- | --- |
| `EspGlobalSettings` | 新增运行期标志 `instantBreakRunning`（不落盘，与 `autoMinerRunning` 并列）+ `instantBreakRunning()` / `setInstantBreakRunning()`；再抽一条**统一判据** `aimOutlineSuppressed()`＝`autoMinerRunning || instantBreakRunning`，注释登记两次用户口径 |
| `BlockOutlineRenderer` | 渲染前把「只判自动挖矿」换成判 `aimOutlineSuppressed()` —— 判定只留一处，以后再有同类模块直接加进这条判据即可 |
| `PacketInstantBreakModule` | `onEnable` 写 `setInstantBreakRunning(true)`、`onDisable` 写 `false`（与 `AutoMinerModule` 逐行同款写法）；类注释新增「与『瞄准方块高亮』的关系」一段 |

行为边界：**只在秒破运行期间压掉**，关掉秒破立刻恢复；玩家自己的「瞄准方块高亮」开关与颜色设置
一字未动（他要白框、要别的颜色都照旧，只是挖东西时不被秒破搅得乱闪）。

## 3. 验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew build --console=plain -q` | **EXIT=0** |
| 实机 | **未实机** |

复测清单：

1. 开秒破 → 挖掘时那个白色整格框应不再出现（秒破自己的红/绿进度框不受影响，仍在）；
2. 关掉秒破 → 准星指方块时白框立刻恢复（说明只压运行期间，没有动用户设置）；
3. 自动挖矿行为不变（它原本就会压掉这个白框）。

## 4. 遗留

- 秒破的「挖掘时转向」（`rotate`）本身没改：它仍会转视角，只是那个白框不再跟着闪。
  若以后也不想要视角被转，那是另一条需求与另一个开关。
- 全部改动**未 commit**。
