# 216 · 产物箱满改成直接关闭模块（撤掉「停机等恢复」那一套）

- 日期：2026-09-22
- 触发（用户原话，两轮）：
  1. 「产物箱塞满 → 应立刻 critical 停机；清空 + 开一次箱子 → 恢复 是会恢复 但是没用啊 箱子都满了」
  2. 「是不是听不懂人话 我说了 直接停机了 **关闭模块**懂？我刚刚打开箱子然后又进去状态机
     那这样 用户想清空箱子 都没办法」
- 相关：[205](205-复盘-产物箱满改成直接停机（撤掉20秒自动复查）.md)（第一版：撤 20 秒轮询）、
  [213](213-复盘-产物箱还满时开箱不复位（复位判据落到箱内空位）.md)（第二版：复位要箱内真有空位）

## 一、三轮演进，错在同一处

| 版本 | 实现 | 玩家的感受 |
| --- | --- | --- |
| 初版 | 满箱 → 退避 60 秒，到点自动再跑一趟开箱 | 「停了但还在来回跑」 |
| 205（第一版） | 满箱 → **模块内**一个停手状态，复原点=玩家开箱 | 「停了，但模块还开着」 |
| 213（第二版） | 复原点补上「箱内真有空位」 | 白跑没了，但**模块仍然开着** |
| 216（本次） | 满箱 → **关模块**（`forceStop`） | 世界静止，安心清箱 |

三轮都在打磨"停手状态"的细节，而用户要的从来不是停手状态 —— 是**把这台机器关掉**。
他说「直接停机」时，我理解成"停止任务"，他指的是"关闭模块"；这是**同一个词在两边含义不同**。

## 二、为什么会漏掉这层语义

- 代码里「停机」本来就有两种：`forceStop`（关模块）与决策层的 silent 停手状态；
- 我按"不打断玩家、能自动恢复"的思路选了后者 —— 这是**替玩家省事**的取向；
- 但产物箱满的场景里，"自动恢复"恰恰是负担：玩家必须**本人跑去开箱清箱**，而模块开着就会
  继续跑动、并且在玩家开箱时用静默容器抢走界面（`SilentContainer`），
  于是"能自动恢复"变成了"我连箱子都清不了"（实机原话）。
- 结论：**"减少打扰"的设计在"玩家必须亲自操作"的场景里会变成"抢戏"**。

## 三、改动

- 卸货放不进去（`failure == null`）→ `coordinator.stopForOutputBoxFull()` → 模块 `forceStop`：
  撤寻路 / 容器 / 目标 → `critical` 播报 → 关模块。与「水壶不见了」「玩家死亡」同一条路径。
- 播报：「产物箱没有空间，**已关闭模块**｜已结束本次卸货｜清空产物箱后重新开启模块即可（模块关闭期间不会跑动）」。
- **删掉的整条自动恢复机制**（不留死代码）：`outputBoxFull` / `outputBoxFullAnnounced` 字段、
  `outputBoxMayRetryUnload()`、`outputBoxFullBlocksHarvest()`、`onPlayerOpenedContainer()`、
  `containerSideHasRoom()`；`storageFullHalts()` 只剩「背包满」一条；
  `FULL_HALT` 的两条文案去掉产物箱字样。

## 四、为什么背包满仍然是「停手」而不是关模块

两者看起来同类，处理不同，判据是**恢复的代价**：

- **背包满**：玩家随手丢掉 / 收好一件东西就恢复，期间模块停手即可，自动继续最省事；
- **产物箱满**：必须离开农田、走到箱子、打开、清空 —— 期间任何跑动都是干扰，
  所以关掉模块、把控制权完整交还给玩家。

**同一类状态（"满了"）不该套用同一种处置**；决定处置的是"玩家要为此付出多大操作代价"。

## 五、验证

- `GetDiagnostics`：`StardewFarmModule` / `StardewTaskPlanner` / `StardewCoordinator` / `StardewTaskVerifier`
  / `StardewContainerLogistics` 均 0 诊断。
- 待实机：塞满产物箱 → 模块应立刻播报「已关闭模块」并真的关掉（开关变灰、人不再动）→
  清空箱子 → 重新开启模块 → 正常卸货。

## 六、教训

1. **需求里的"停机"必须先问清是哪种**：停手（模块内状态）还是关掉（`forceStop`）。
   分辨方法：如果玩家必须**离开现场**去做某件事，那他要的多半是"关掉"，而不是"原地等着"。
2. **"自动恢复"不是无条件的优点**：只有恢复条件由程序自己满足时它才是优点；
   若恢复条件要玩家亲自操作，那自动恢复只会让程序与玩家抢同一个舞台。
3. **同一个词在代码里已有两种实现时，先对齐词义再写代码**：这次三轮返工都源于没先分辨
   "停手 vs 关模块"，而这两种实现在本模块里早就并存（`forceStop` 与 silent 停手）。
