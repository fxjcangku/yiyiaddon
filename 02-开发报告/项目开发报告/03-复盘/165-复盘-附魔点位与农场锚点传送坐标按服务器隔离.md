## 3. 改动一：自动附魔点位改每服一份文件

- 落盘位置：`config/yiyiaddon/enchant/points/` 下 `WorldIdentity.fileSafeServer() + ".json"`，
  与挖矿 `mining/points/` 同一命名口径；文件内的键名（`posBook` 等 9 个 + `hangoutYaw` /
  `hangoutPitch` / `posAnvilFacing` / `pointServer` / `pointDimension`）**逐字未改**，旧版本仍可读。
- 内存里记 `loadedServer`；`save()` 增加兜底：内存快照不属于当前服务器就拒绝写盘（宁可少写一次，
  也不把 A 服的点位写进 B 服文件）。
- **旧档迁移**（`migrateLegacyFile`）：目标文件不存在、旧 `points.json` 里至少有一个点位、
  且旧点位归属当前服务器（`pointServer` 为空时按当前服务器认领并补齐服务器 / 维度）→ 复制过来，玩家不必重设；
  属于别的服务器的旧档**原样保留**，等切回那台服务器时自然认领（只复制不移动，与挖矿 / 村民交易同一做法）。
- **读 / 写两条装载路径**（这是本轮唯一的性能取舍）：
  - 读路径（`get` / `has` / `size` / `matchesCurrentContext` …）只做「没读盘过就读一次」，
    **不比对服务器键** —— 点位渲染 `EnchantPointRenderer` 每帧都要取点位，逐帧算服务器键等于给渲染热路径加字符串开销；
    换服后的读数据由四条入口的 `reload()` 保证最新（模块启用 / 启动自检 / 打开控制台 / `.fumo` 指令）。
  - 写路径（`bind` / `unbind` / `clearAll` / 挂机视角 / 铁砧朝向 / `bindContext`）先比对服务器键再写，
    避免拿上一台服务器的快照整份落盘。
- `EnchantBindingService.bind / remove / clear` 在动判定之前先调 `store.ensureCurrentServer()`：
  「已设置」覆盖保护、清空范围、归属世界判定读的都是内存快照，不先装载会拿着上一台服务器的点位下结论。
- 说明正文同步（第 212 条）：「首次配置」第 1 行的「先执行 `.fumo 清空`」改为「点位按服务器和维度分别记录，
  换服 / 换维度直接设点，不必先清空」；「换服、换维度与指令」整节改写为
  「每个服务器 / 存档各存一套点位，互不覆盖 / 换服直接设点 / 同服换维度仍不生效 / 回原世界可直接用」。
  改动已登记进 `EnchantPage` 的「用户交互资产例外清单」（新增第 3 条例外）。

## 4. 改动二 / 三：自动农场锚点、传送坐标按服务器隔离

两项都走框架既有钩子（第 81 条为自动挖矿建的 `Module#settingsScope()`），**不新建存储类、不改落盘键名**：

- `settingsScope()`：进世界后返回 `WorldIdentity.fileSafeServer()`，未进世界返回 `null`（主菜单没有服务器身份）。
- `refreshScopedSettings()`：作用域变了才 `ModuleManager.reloadScopedSettings(this)`，没变直接返回。
- 调用点（与挖矿一致的四条路径）：
  - 自动农场：`selfCheck()` / `onEnable()` / `AutoFarmPage.createPage` / `openConsole` / `FarmCommand.execute`；
  - 传送：`onEnable()` / `TeleportPage.createPage` / `openConsole` / **新增 `JOIN_SERVER` 事件**
    （传送没有「退出世界自动关模块」的行为，同一会话内退 A 服进 B 服不会再走 `onEnable`，
    靠 `JOIN_SERVER` 补这次重读；农场的 DISCONNECT 会自关模块，下次启用必走 `onEnable`，无需补）。
- 升级不丢数据：`ModuleStateConfig.settingsOf(id, scope)` 命中不了本服桶时回落**全局模板**，
  老档的锚点与坐标就是模板里的那一套；新服务器 / 新存档的初始值 = 玩家最近一次用的那套。

## 5. 影响面（用户可见）

- 附魔：换服不再提示「请清空后重设」；同一服务器内换维度仍按旧口径不生效（未变）。
- 自动农场：六个锚点与作物勾选、收割 / 补种模式、范围等**全部设置项**随服务器分开存。
- 传送：`坐标 X/Y/Z` 与阈值随服务器分开存；**三个功能键（TP地面键 / TP穿墙键 / TP坐标键）也随之按服务器分开**——
  这是「一个服务器一套完整配置」的必然结果（与自动挖矿一致）。若用户要求「只隔离坐标、按键仍全局共用」，
  需单独改造（不在本轮）。
