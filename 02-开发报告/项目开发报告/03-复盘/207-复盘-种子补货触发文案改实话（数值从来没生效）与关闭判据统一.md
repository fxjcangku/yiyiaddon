# 207 · 「种子补货触发」文案改实话（数值从来没生效）+ 关闭判据统一

- 日期：2026-09-22
- 触发（用户原话）：「文案改实话」——上一轮我核对了四个后勤阈值的真实行为，发现第一条的界面说明是假的
- 前序：[206](206-复盘-简化后勤默认改为关闭（走逐作物四个阈值）.md)（同一批后勤改动）

## 一、查出来的事实

界面写「背包里这种作物的种子**少于 N** 时，才去种子箱取种子补货」，但运行期的补货触发写死在
`StardewTaskPlanner#hasRestockDemand` 里：

```java
if (crop == null || countSeed(crop) > 0 || ...) return false;   // 背包里还有 1 颗种子就不补
```

即真实门槛是「**这种作物的种子一颗都不剩 + 恰好有空盆要种**」，`N` 从头到尾不参与任何比较
（全仓库只有 `restockTrigger > 0 / <= 0` 这两种用法）。移植时把旧项目的参数说明一起搬过来了，
数值语义却没跟着落地 —— 文案写了个从来没生效的数字。

附带查到一处口径不一致：关闭补货的判据，计划器看的是「补货**目标** ≤ 0」，
而「是否需要种子箱」的 `anyCropNeedsRestock` / `canAutoRestock` / 启动自检看的是「补货**触发** ≤ 0」。

## 二、改动

| 位置 | 旧 | 新 |
| --- | --- | --- |
| 行标签 | 种子少于 | 种子补货 |
| 行尾注释 | 低于它才去补种 | 0 = 关掉补货 |
| tooltip | 「种子少于这个数时才去补」 | 「填 0 = 不自动补货（也就不需要给它绑种子箱，启动自检按这个判）；填任何正数 = 开启：种子一颗都不剩、又刚好有空盆要种时才去取，每次取到『种子补到』为止；数字填几都不影响行为」 |
| 简化后勤那行灰字 | 「种子少于2补到8，成品攒到8卸光」 | 「种子用光补到 8，成品攒到 8 卸光」（数值改为从 `CropLogistics.DEFAULT` 取，不再硬编码） |
| 简化后勤 tooltip | 「种子少于 N 才去补」 | 「种子用光了才去种子箱补，补到 N」 |
| 关闭判据 | 计划器看 `restockTarget <= 0` | 统一看 `restockTrigger <= 0`（与自检 / 种子箱需求同一口径） |

控件仍是数字框（本轮只改文案）；默认值仍是 2 —— 正数即开启，数值本身无意义。

## 三、验证

- `.\gradlew build --console=plain -q` → **EXIT=0**。
- 全仓库核对：`restockTrigger` 的用法只剩「0 = 关 / 正数 = 开」与界面显示，`restockTarget` 只用于
  「取到多少 / 回收多少」，两处语义不再交叉。
- **未实机**：复测看点 —— 后勤页第一行应显示「种子补货」+ 数字框，tooltip 不再出现「少于 N 才去补」。

## 四、教训

1. 移植来的参数说明必须回源码对一遍判据：本例中「数值」是纯装饰，只有 0 / 非 0 有意义，
   而说明把它写成了阈值 —— 玩家会照着调，然后发现怎么调都一样。
2. 同一个语义（这里是「补货是否启用」）在多个模块各写一份判据，迟早会分叉；
   这次统一到 `restockTrigger`，并在计划器那处注释里写明「必须与自检口径一致」，防止再分叉。
