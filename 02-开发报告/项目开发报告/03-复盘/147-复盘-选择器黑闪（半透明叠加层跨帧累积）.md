# 复盘：选择器横贯面板的光带 / 放大物品图标（隐藏格子备份被 ESP 叠加层提前消费）

日期：2026-09-20
项目：yiyiaddon（Fabric 26.1.2 / 26.2 双版本线）
涉及文件：`ui/render/SkiaScreen.java`、`ui/render/SkiaGlBackend.java`、`ui/render/ItemIconCache.java`、
`ui/render/world/WorldOverlay.java`（+ 前一阶段的 `ui/screen/PanelScreen.java`、`ui/render/SkiaBlurRenderer.java`）

---

> 「有个坏消息 还是不行 你看图 图一是我关闭了面板模糊 图二是开了面板模糊」

两张截图（同一位置、同一块内容）：

| 图 | 面板模糊 | 现象 |
| --- | --- | --- |
| 图一 | 关 | 一条**横贯面板的锐利横带**，内容是放大到 32 逻辑像素的原版物品图标（自定义资源包的蓝色贴图），两端还露着隐藏格子底色的黑方块 |
| 图二 | 开 | 同一位置变成一大块**白糊**（同一条带被面板玻璃模糊后的样子） |

「两端露黑方块」是关键：那正是 `ItemIconCache` 隐藏格子那一行（12 格 × 36 − 4，上行纯黑底 / 下行纯白底）。

## 二、机制（为什么会有隐藏格子）

26.1.2 的物品图标只能由原版 GUI 通道画进主 Framebuffer，而本项目界面是 Skija 即绘。于是
`ItemIconCache` 走「借位渲染 + 截取」：抽帧阶段在**屏幕正中**两行隐藏格子（黑底 / 白底 + 放大的物品图标），
帧末回读反解 alpha 入库，再用**上一帧画面备份**把格子盖回去（`saveBackdrop` → `paintBackdrop`）。

备份是**一次性**的：画回后立即销毁（`paintBackdrop` 里 `backdropImage = null`）。

## 三、根因（两条，先后都得修）

### 根因 A：半透明深色叠加层逐帧累积（前一阶段已修）

主 Framebuffer 上每帧叠一层全屏压暗 / 面板霜化 / 玻璃 frost·tint，下一帧又基于「已压暗的画面」再叠一次，
0.16 的压暗按 **0.84 = 1 − 0.16** 的比值逐帧累积收敛到纯黑。像素采样锁定：备份读取恒定明亮、
帧末逐帧递减 0.84。

处置：删掉 `PanelScreen` 的全屏压暗与 `GlassPanel.frost`、删掉 `SkiaBlurRenderer` 的 `FROST_DARKEN` /
`frostPaint` / `tintPaint` 与 `glassTint()`（见本目录 147 号前半段）。**这一步同时把原本被霜化层
（无模糊时 alpha 0.94，几乎不透明）遮住的另一条 bug 暴露了出来**——就是根因 B。

### 根因 B：画面备份被 ESP 叠加层提前消费（本轮真凶）

`paintBackdrop` 原先挂在 `SkiaGlBackend.begin()` 里——**谁取画布谁就顺手写回**。而主 Framebuffer 上
不止界面一条 Skija 路径：

```
一帧顺序（26.1.2）：
  抽帧阶段（extract）            → saveBackdrop 备份「上一帧画面」；记录黑/白底 + 物品绘制指令
  GameRenderer.renderLevel       → 世界
  GuiRenderer.render 的 HEAD     → WorldOverlay.renderOverlay() → BACKEND.begin(主帧缓冲)
                                   ★ 在这里就把一次性备份消费掉了（此刻 GUI 通道还没开始画）
  GUI 通道                       → 隐藏格子（黑/白底 + 放大图标）落地，盖在备份之上
  RenderTarget.blitToScreen HEAD → SkiaScreen#renderSkiaFrame → capturePending（截取，OK）
                                   → begin() 再想写回：备份早已为 null → 空操作 → 格子裸露
```

于是：格子**裸露在面板里**。面板内容区（未选中那一栏、空分组）是半透明的，直接看得见 → 图一；
面板玻璃（`SkiaBlurRenderer` 用 `glBlitFramebuffer` 直接读主帧缓冲的 GPU 当前内容）把这条带子采样进玻璃
→ 图二的白糊。

只有开 ESP（`WorldOverlay` 有 2D 元素待画）才会触发，所以表现为「有几率 / 一闪一闪」。

## 四、改动（两棵树一致）

| 文件 | 改动 |
| --- | --- |
| `ui/render/SkiaGlBackend.java` | **删掉 `begin()` 里的 `paintBackdrop` 写回**（任何人都能开画布=任何人都能偷备份）；补注释说明写回统一归界面帧末路径，避免以后又被人加回来 |
| `ui/render/SkiaScreen.java` | `capturePending()` 之后**无条件** `ItemIconCache#flushBackdrop()`（截完立刻写回，不依赖面板绘制路径是否走到）。该路径内部走共享后端 + `end()` 里 `flushAndSubmit`，写回**立即落地 GPU**，紧接着的面板玻璃才采样到干净画面 |
| `ui/render/ItemIconCache.java` | `flushBackdrop` / `paintBackdrop` 的 javadoc 改写成「无条件主路径」口径（原来写的是「面板绘制路径顺手写回」） |
| `ui/render/world/WorldOverlay.java` | `renderOverlay()` javadoc 明确「这里只能开普通画布，不许写回隐藏格子备份」并说明后果（防回归） |

## 六、经验（下次复现可继续修）

1. 「一次性资源 + 多个调用方」= 谁先取谁消费。`begin()` 这种人人都会调的入口里**不能**放一次性动作，
   否则任何一条旁路（ESP 叠加层、控制台、世界叠加）都可能先把它吃掉。
2. 隐藏格子的失败是**自 perpetuating** 的：备份来自「上一帧画面」，一旦某帧格子裸露，下一帧的备份就把
   这份裸露当干净画面存下来，于是残影被反复备份、画回、再被玻璃模糊 —— 越糊越久，看着像「一直有」。
   所以这类问题的收尾必须是**无条件**的，不能依赖「面板这一帧画不画」。
3. 定位手法依旧有效：拿「备份读取 vs 帧末读取」做像素对比，用递减比例反推 alpha 来源；
   判断「是格子底色还是叠加层」看**两端有没有黑方块**（格子行宽 = 10 格 × 36 − 4 的固定宽度）。
4. 临时埋点用完必须清零（本轮 `COVER_DIAG` / `dumpFrameIfNeeded` / `probeBlock` / `glassTint` 等已全部删除）。
