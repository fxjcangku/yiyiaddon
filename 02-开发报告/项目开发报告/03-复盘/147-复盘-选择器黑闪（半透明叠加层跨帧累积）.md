## 二、机制背景（必须理解，否则会再踩）

物品图标只能由原版 GUI 通道画进主 Framebuffer，而本项目界面是 Skija 即绘。`ItemIconCache` 的解法是
「借位渲染 + 截取」：抽帧阶段在**屏幕正中**两行隐藏格子（上行纯黑底、下行纯白底 + 放大到 32 逻辑像素的
物品图标），帧末回读两行反解 alpha 入库，再用**上一帧画面备份**把格子盖回去。

**关键事实（前面几轮一直没抓住的点）**：主 Framebuffer 里面板区域在下一帧开始时**保留着上一帧末的合成结果**
（不是干净的世界）。因此任何「每帧往面板区域叠一层半透明东西」都会跨帧累积，任何「不加底的面板」
都会把上一帧的面板透出来。

## 三、根因与处置（六条，全部保留在代码里）

### ① 全屏压暗 + 霜化 + 玻璃 tint 叠加累积 → 中心纯黑

主 Framebuffer 每帧被叠上一层全屏压暗（alpha 0.16），下一帧又基于「已压暗的画面」再叠一次，
按 **0.84 = 1 − 0.16** 的比值逐帧收敛到纯黑（像素采样实测：备份读取恒定明亮、帧末逐帧递减 0.84）。

处置：删掉 `PanelScreen` 的全屏压暗。**注意：这一层至今没有恢复**（它是黑块来源）；
`ModuleScreen` / `ClickGuiScreen` 各自那份压暗仍在（那两处不在本轮反馈范围内，若将来出现「越用越暗」
按同一判据处理：备份读取 vs 帧末读取的像素比值）。

### ② 画面备份必须「与面板绘制同后端、同表面」写回

备份写回原先挂在 `SkiaGlBackend.begin()` 里 —— 谁取画布谁先写回。主帧缓冲上不止界面一条 Skija 路径
（ESP 叠加层 `WorldOverlay#renderOverlay` 跑在 `GuiRenderer.render` 的 HEAD，那时 GUI 还没开始画），
它一取画布就把**一次性**备份用掉了；等帧末轮到面板时备份早已不在，格子裸露成那条横带。

中间试过把写回挪到「常驻共享后端」（`ItemIconCache#flushBackdrop`）——**实测无效**：
同一块 GL FBO、同一个共享 DirectContext，但不同的 `SkiaGlBackend` 实例／不同的 Skija 表面，
写回没落到呈现上。

最终形态：
- 主路径 `SkiaGlBackend#beginScreenFrame(int)`：`begin` + `paintBackdrop` + **立刻 `flushAndSubmit`**
  （玻璃紧随其后要用 `glBlitFramebuffer` 直接读 GPU 画面，写回必须先落地）；
- 三个屏幕（`PanelScreen` / `ModuleScreen` / `ClickGuiScreen`）统一走它；
- `begin()` 保持**不写回**（防旁路抢占）。

### ③ 备份改成幂等可重放 + 帧末释放

`paintBackdrop` 画完不销毁备份（同一帧谁来调都能再画一次）；释放交给：
「本帧没有格子」的 `renderPending` 早退分支、`finishBackdropFrame()`（换屏/关屏：先写回再释放）、
下一次 `saveBackdrop`、`clear()`。这样两条写回路径（主路径 + 兜底）互不吞噬，也不会跨帧留旧备份贴到画面上。

### ④ 覆盖范围不足 → 残留一条「小黑条」

备份矩形原先正好贴合格子，取整误差 + 放大图标的轻微溢出会在边缘留一条没被盖住的底色。

处置：`ItemIconCache#BACKDROP_PAD = 8f`（逻辑像素）四周外扩，读写用同一个矩形。

### ⑤ 玻璃采样到「上一帧的面板」→ 蓝雾 / 文字影

玻璃绘制在帧末，现场采样主帧缓冲拿到的就是**上一帧的面板自身**，把它再模糊一次盖回面板，
逐帧累积扩散成蓝灰雾（原先那层近乎不透明的霜化把它遮住了，霜化撤掉后显形）。

处置：玻璃背景改用**世界帧**——
- `SkiaScreen#extractRenderState`（抽帧阶段）登记本帧玻璃区域（`glassRegion()`，
  三个屏幕各自给出面板矩形，按 `GLASS_MARGIN = 48f` 外扩，容下模糊半径与动画位移）；
- `GuiRendererMixin` 在 `GuiRenderer#render` 的 HEAD（**世界已画完、界面还没上屏**，
  且顺序必须在 ESP 叠加层之前）调 `SkiaBlurRenderer#captureWorldFrame()` 截下该区域
  （GPU blit 到临时纹理 + Skija 收养，不回 CPU）；
- 帧末玻璃优先用这张图（`backgroundCapture`），取不到才退回现场采样；
- 没有新请求时**保留上一帧世界帧**（退回现场采样才是要避免的）。

### ⑥ 面板的「底」不能删 → 文字重影

删霜化层时连带删掉了面板底，面板区域透出上一帧面板 → 文字错位重影（就是《开发习惯》里 2026-09-16
「字糊了」那条的同一机制）。

处置：`PanelScreen` 恢复 `GlassPanel.frost(..., tc.window, panelBlur ? 0.62f : 0.94f, alpha)`
（与模块页、主界面同档；本节早先写的 0.80 是当时的备选值，最终没落到代码里，2026-09-21 晚核对后更正）。

同时恢复玻璃的**主题色蒙版** `glassTint()`（用设置里的玻璃色调 alpha × 主题窗面色）——
用户 2026-09-21「怎么感觉你把我的主题调浅色了」就是它被一起删掉造成的；它叠在不透明玻璃图像之上，
不参与跨帧累积，可以放心保留。**这一档当时给得太轻**（暗色主题只剩 14% 自身窗面色），
当晚按用户反馈重新分档，见第七节。

## 四、最终每帧顺序

```
抽帧 extract：saveBackdrop 备份「上一帧画面」(格子区域 + 8px) + 记录格子绘制指令
              + 登记本帧玻璃区域（glassRegion，外扩 48px）
世界渲染
GuiRenderer.render HEAD：captureWorldFrame 截下「世界帧」玻璃区域 → ESP 叠加层
GUI 通道：隐藏格子落地（黑底/白底 + 放大图标）
帧末 Mixin：capturePending 截取图标 → flushBackdrop（兜底，幂等）
   → drawFrame → beginScreenFrame：界面自己的后端写回备份 + flush
   → 面板绘制：玻璃（世界帧 + tint）→ 面板底 frost → 环境光/边框/内容
```

## 六、下次再复现时看这里

1. **判据**：看**两端有没有黑方块**（格子行宽 = 10 格 × 36 − 4 逻辑像素）区分「格子裸露」与「叠加层压暗」；
   叠加层类用「备份读取 vs 帧末读取」的像素比反推 alpha（0.84 ↔ 0.16）。
2. **面板必须有不透明/高不透明的底**（frost），否则上一帧面板一定透出来 → 文字重影。
3. **一次性资源不要放在人人都会调的入口**（`begin()` 这类）；要么限定入口，要么改成幂等。
4. **必须可见的绘制不要跨后端**：换一张 Skija 表面就可能「画了但没落到呈现上」。
5. 玻璃的背景只能取「界面还没上屏」的世界帧；现场采样等于把上一帧面板再糊一遍。

## 七、主题收口：只留浅色 / 深色，深色回到「深空灰」（2026-09-21 晚）

用户原话：「颜色帮我调浅了好多 我想深空灰」「浅色 深色 两个主题就行」「bug 已经修好了 你别改了
只是让你把星空灰颜色加深一下就行」——**渲染管线一行没动**，只改主题层的颜色与档位。

### 7.1 变浅的量化口径

面板区域这一帧的合成是三层叠加（都在帧内，不跨帧）：

| 层 | 贡献 | 暗色主题实际值 |
| --- | --- | --- |
| 玻璃图像 | 模糊后的世界帧（明亮场景约 `#909090`） | 占主导 |
| 主题色蒙版 `glassTint` | `blurTint` alpha ÷ 255 × 档位 × 主题窗面色 | `80/255 × 0.45 = 0.141` → 只剩 **14%** |
| 面板底 `GlassPanel.frost` | `0.62 × density(0.78) × panelBackgroundAlpha(0.46)` | `0.222` |

自身色占比 ≈ `1 − (1−0.141)(1−0.222) = 0.33`，也就是 67% 是"明亮世界的模糊图" →
实测截图里那块面板亮度接近 `#737373`（浅灰），用户说的「调浅了好多」正是它。

### 7.2 处置（三条，全部在主题层）

1. **两个主题**：`ClickGuiThemeManager` 只注册 `WhiteTheme`（浅色）+ `DeepGrayTheme`（深色，深空灰）；
   `DarkTheme` / `GrayTheme` / `AppleDarkTheme` 三个类删除。兜底固定为深空灰，配置里指向已下线 id 的
   会落到兜底并把 `uiTheme` 改写回 `deep_gray`（用户本机配置 `apple_dark` → `deep_gray` 已实证）。
2. **蒙版分档**：`SkiaBlurRenderer#glassTint` 里 `blurTint` 只当"档位"用 —— 暗色主题 × `TINT_SCALE_DARK = 2.2`
   （蒙版 `0.3137 × 2.2 = 0.69`），浅色主题维持 `0.45`。改后自身色占比 ≈ `0.76`，
   明亮场景下算得 `≈ #3A3A3A`、普通场景 `≈ #2E2E2E`，即深空灰。
   **不提高面板底 frost 的不透明度**（那属于黑块修复的受力区，别碰）。
3. **主题名**：`displayName` 统一中文（「浅色」/「深色」），主题预览网格只剩两张缩略图。

### 7.4 教训

1. **"变浅"要先量再改**：三层叠加各自能算出占比，别对着一个参数试。这次真正的元凶是
   `glassTint` 的档位（14%），不是主题调色板。
2. **调色板的深浅管不了玻璃面板**：面板可见色 = 自身色占比 × 主题色 + 其余 × 世界模糊图；
   明亮场景下面板色几乎由"占比"决定，改 `window` 的 RGB 是无效功。
3. **用户说"别改了"是在划边界**：指的是别回头重做已经验收的修复，不是"不许动颜色"；
   这类改动要落在主题/参数层，与受力区（跨帧、帧序）保持距离。
