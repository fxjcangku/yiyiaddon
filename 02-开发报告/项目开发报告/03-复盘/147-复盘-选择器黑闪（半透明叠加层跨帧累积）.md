# 复盘：选择器黑闪（半透明叠加层跨帧累积）

日期：2026-09-20
项目：yiyiaddon（Fabric 26.1.2 / 26.2 双版本线）

## 一、用户反馈

症状集中在「目标选择器」，多轮复现：

> 「选择器还是有黑色的背景一闪一闪的」
> 「只在选择器 就打开 就闪一下 特别是物品多的选择器」
> 「缩进去了 但是还能看见一点点」
> 「还是会闪 没上次的黑边宽了 往里缩点就看不见了」

## 二、复现路径

1. 打开任意目标选择器（物品 / 方块 / 实体分组）。
2. 观察屏幕正中：一块纯黑方块逐帧加深，边缘随修复逐步「缩进去」。
3. 物品越多的选择器越明显——图标抽帧管线每帧都在屏幕中央画隐藏格子，正中那块的叠加被反复重画，黑得最快。
4. 只有选择器出现，主界面 / 模块页不出现。

## 三、取证与根因

### 数字采样锁定

- 备份读取（`saveBackdrop` 读到的干净画面）恒定明亮；
- 帧末主 framebuffer 逐帧变暗，每帧递减比例 **0.84**；
- `0.84 = 1 − 0.16`，正好对应全屏压暗的 `alpha 0.16`——说明每帧都在把上一帧画面再压暗一次。

### 根因

`PanelScreen` 每帧在主 framebuffer 上叠加三层半透明深色，且叠加不重置：

1. 全屏压暗 `GlassPanel.fill(..., alpha * (dark ? 0.16f : 0.10f))`；
2. 面板霜化 `GlassPanel.frost(...)`；
3. 玻璃合成里的 `frostPaint` / `tintPaint`（`SkiaBlurRenderer`）。

每一帧都基于「已含上一帧压暗结果」的画面再画一遍，0.16 的压暗按 0.84 倍逐帧累积，收敛到纯黑。

## 四、改动

| 文件 | 改动 |
| --- | --- |
| `ui/screen/PanelScreen.java` | 删除全屏压暗 `GlassPanel.fill(...)` 与面板霜化 `GlassPanel.frost(...)`；保留阴影 / 环境光 / rim / 模糊磨砂 |
| `ui/render/SkiaBlurRenderer.java` | 删除 `FROST_DARKEN`、`frostPaint`、`tintPaint` 字段，`render()` / `renderRegions()` 中的 frost / tint 绘制，以及 `glassTint()` 死方法；只保留模糊图像 + 圆角折射边带 |
| `ui/render/SkiaGlBackend.java` | 回退调试期错误假设加的 `context.flushAndSubmit(surface)`（那次根因不是 flush 缺失），恢复为只 `paintBackdrop` |

## 五、验证

- 双线编译通过：26.1.2 `d:\mcaddon\yiyiaddon` 与 26.2 `D:\mcv\wt-262` 均 `BUILD SUCCESSFUL`。
- 用户确认：「没事了」。
- 临时埋点（PNG 导出、像素回读、二分注释、`COVER_DIAG` / `dumpFrameIfNeeded` / `glassTint` 等）全部清零，未重启客户端。

## 六、影响面与经验

### 影响面

- 视觉上少了全屏压暗与面板霜化两层深色，面板通透度略升；模糊磨砂（`panelBlur`）与圆角折射边带保留，玻璃质感不变。
- 本次改动同时落到 26.1.2 与 26.2 两条线。

### 经验（以后复现可继续修复）

1. 黑闪 / 逐帧加深类问题先怀疑「每帧在 framebuffer 上重复叠加的半透明层」——用像素采样看「每帧是否 × 固定比例递减」，递减比例能反推 alpha 来源（0.84 ↔ 0.16）。
2. 隐藏格子（抽帧 + 备份 + 写回）会放大这类问题：它让屏幕正中每帧都有一次额外绘制，叠加层在中间被反复重画，黑得最快。
3. 临时埋点定位到根因后必须全部删除，避免残留；本次已清零。
