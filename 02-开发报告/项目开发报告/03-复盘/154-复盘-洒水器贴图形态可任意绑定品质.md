# 154-复盘-洒水器贴图形态可任意绑定品质

日期：2026-09-21
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件

用户真机反馈（jmy.seasonmc.xyz）：

> 发现 bug 洒水器可以随便绑定任何品质的 这个服务器

即：写明任意一种洒水器（初级 / 优质 / 高级 / 顶级）都能绑到同一台实物上，绑定结果与地里摆的实物无关。

## 二、取证

### 1. 日志：两次绑定全是「写明即绑上」

同一轮的两次绑定（`run-26.1.2/logs/latest.log`）：

```
[01:53:34] 已设置洒水器点位 · 坐标 X4803 Y85 Z-5597 · 验证=人工确认世界载体 · 类型=高级洒水器 · 状态=已验证
[01:53:40] 已设置洒水器点位 · 坐标 X4803 Y85 Z-5603 · 验证=人工确认世界载体 · 类型=初级洒水器 · 状态=已验证
```

两次都没有任何「与实物不符」的拦阻，随后维护播报也直接按点位身份走
（`[01:54:54] 正在维护洒水器 ▸ 高级洒水器 · 4803, 85, -5597`）——**身份错则维护、等级、覆盖范围全部跟着错**。

### 2. 代码：贴图形态那一支等于没判

`StardewPointActions.sprinklerMismatch` 的旧实现：

```java
if (state.isAir()) {
    return SprinklerWorldBinding.displayCarrierAt(pos) ? null : "准星这一格是空气，没有洒水器实物；请对准洒水器";
}
```

本服的洒水器是**展示实体（`item_display`）渲染**，所在格是空气，方块状态三者完全一样，
于是唯一判据「这一格有没有挂着展示实体」对任意品质都成立 → **一律放行**。
非空气但语义「未确认」的隐形载体（`block/empty`）分支同样是 `return null`，缺口相同。

### 3. 实物品质本身是可辨识的

`StardewPointActions.matchSprinklerDisplay` 已经能读展示实体的外观身份，并且本服有真机取证
（同文件注释：jmy 的初级洒水器 = `minecraft:paper` + `custom_model_data 10635`，
旧实现只读 `ITEM_MODEL` 组件时「洒水器就在眼前却怎么都绑不上」，现已由
`StardewInventoryService.resolvedModelOf` 兜住）。**识别链是通的，只是绑定时没用它核对**。

## 三、根因

绑定核对把「实物是不是存在」当成了「实物是不是这一种」：贴图形态洒水器的品质信息
**只存在于展示实体**，而核对分支从头到尾没读实体。人工确认被误用成「绕过一切核对」，
而不是「在资源包认不出时兜底」。

## 四、改动

`StardewPointActions`（单文件）：

1. 新增 `displayMismatch(pos, definition)`：用 `matchSprinklerDisplay(pos)` 认实物，认得出就比品质，
   不一致时报「这一格上摆的是「X」，不是「Y」；请对准实物，或改用正确类型：`.stardew 添加洒水器 X`」。
2. `sprinklerMismatch` 的两支改为走它：
   - 空气载体（贴图形态，本服）：先判有没有实物载体，再核品质；
   - 非空气但方块语义**未确认**（隐形载体 `block/empty`）：方块这侧给不出身份，同样核品质；
   - 语义**已确认**的非空气分支不变（方块身份是权威，原来就会挡掉「不是洒水器」的方块）。

**边界（与既有口径一致）**：实物认不出（资源包没登记该模型序号名、同格多个实体互相矛盾
使 `matchSprinklerDisplay` 返回 null）一律放行——那条路正是人工确认存在的意义，
挡掉它会让非 ItemsAdder 布局的服务器整台绑不上。因此本次修复是「认得出就必须一致」，
而不是「一律禁止人工写明类型」。

## 五、验证

- `.\gradlew.bat build`：EXIT=0。
- **未实机**。用户重启客户端吃新包后的预期：
  1. 对准初级洒水器写明「高级洒水器」→ 应被拒，播报给出实物正确类型；
  2. 写明实物本身那种 → 正常绑定，`验证=人工确认世界载体` 不变。
- **历史错绑不会自动纠正**：已落盘的 4803,85,-5597（标「高级洒水器」）与 4803,85,-5603（标「初级洒水器」）
  身份可能存在错误，需重新绑定一次；`.stardew 实测范围` 测出的覆盖范围是物理事实，与身份无关，不受影响。

## 六、附：混淆版对星露谷资源的影响核实（回答用户同轮提问）

结论：**不影响**。逐条依据：

- 服务器资源包 → 走文件 / zip 读取（`ResourceExtractionService`），与自身类名无关；
- 资源指纹 → 资源包内容哈希，不是类名哈希；
- 学习结果与点位档 → `gameDirectory/StardewFarm/...`，字段名是**手写中文字符串常量**
  （Gson `JsonObject`，不依赖字段反射）；
- 内置参考规则 → `StardewReferenceRuleLibrary.RESOURCE = "/assets/yiyiaddon/stardew/reference-harvest-rules.json"`
  以 `/` 开头是**绝对 classpath 路径**，混淆改包名照样读得到（若写成相对路径才会失效）；
- 混淆规则（`gradle/proguard-rules.pro`）：`-dontshrink -dontoptimize`，
  已 keep Mixin 包名、Fabric 入口、枚举成员、Gson DTO 字段。

另外：混淆版与开发版读写的是**同一个**游戏目录下的 `StardewFarm/`，学习结果可直接互通。
