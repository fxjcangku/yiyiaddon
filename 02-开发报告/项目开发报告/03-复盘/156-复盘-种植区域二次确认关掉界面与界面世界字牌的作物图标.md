# 156-复盘-种植区域二次确认关掉界面与界面/世界字牌的作物图标

日期：2026-09-22
分支：master（业务唯一真源，按第 231 条；26.2 分支另行 cherry-pick）

---

## 一、事件（用户原话）

> 还有种植区域的地方 有bug 我点击删除 二次确认之后 就直接 关闭ui了 不应该到模块设置页面吗？
> 然后区域选择没有显示 农作物图标呀 可以在全面渲染图标吗 esp点位也可以加一个农作物吗？

附两张实机截图：①「种植区域」列表页（4 个区域，行尾「换作物 / 删除」，底部「清空全部区域 / 返回」）；
②世界里区域框 + 红字字牌「区域 1 · 大白菜 · 自定义维度」+ 青色洒水器框。

拆成三件事：二次确认后界面被整个关掉、区域列表/区域选择没有作物图标、ESP 点位字牌也要带作物图。

## 二、根因

### 1. 二次确认后关掉整个界面：确认窗用了「回游戏」的默认收尾

`ConfirmPanelScreen` 的默认构造器走 `exitToGame()`（确认完 `setScreen(null)` 回游戏），
只有 `inPlace(...)` / `noticeInPlace(...)` 才在关闭动画结束后回**上级窗口**（第 112 条那条口径）。

控制台那两处「清空全部点位 / 清空全部种植区域」在上一轮已改 `inPlace`，但**列表页那两处漏了**：

```java
// StardewRegionListScreen.confirmClearAll / StardewSprinklerListScreen.confirmClearAll
minecraft.setScreen(new ConfirmPanelScreen("清空全部种植区域", …, module::clearRegions, parent));
```

用户走的正是这条：控制台「农田」卡 →「管理」→ 种植区域列表 → 底部「清空全部区域」→ 确认 → 整个 UI 消失。

### 2. 图标：能画物品图标的链路只在 GUI 通道里，ESP 字牌用不了

- GUI 侧（列表行、按钮）能用的只有 `ItemIconCache`：它靠「隐藏格子借位渲染 + 主帧缓冲回读反解」
  取图，必须在 `SkiaScreen#extractRenderState` 期间驱动，且要等面板开合动画停稳
  （`canCaptureIcons()`）。
- ESP 字牌的绘制跑在**GUI 通道开始之前**（`WorldOverlay#renderOverlay` → `GuiRendererMixin` HEAD），
  那一刻没有 `GuiGraphicsExtractor`，上述链路根本无从驱动 —— 这是本条目必须换做法的原因，
  不是参数问题。
- 于是世界字牌的图标只能**直接读资源包 PNG**；而「作物/点位 → 贴图」这条解析在项目里此前
  只有 `StardewPreview` 的私有 `readModelTexture`（且不沿 parent 链）。

## 三、改动

### 1. 二次确认回到上级窗口（两处）

- `StardewRegionListScreen.confirmClearAll`、`StardewSprinklerListScreen.confirmClearAll`：
  `new ConfirmPanelScreen(...)` → `ConfirmPanelScreen.inPlace(...)`，收尾目标统一为控制台
  （`parent`，它 `init()` 会重建正文，数量当场变 0）。
- 洒水器那处顺带把 parent 从 `minecraft.screen` 改为外层字段 `parent`，与区域列表同一写法。
- 同类收尾还有一处：`StardewRegionListScreen`「换作物」失败时的「没换成」提示，原本走
  `notice(...)`（点掉回游戏），改为 `noticeInPlace(..., this)`（点掉回本列表）。同一屏里
  「删掉数据」和「提示失败」两种收尾不能一个回列表、一个回游戏。

### 2. 资源包贴图缓存（新）

`ui/render/TextureImageCache.java`：`Identifier` → Skija `Image` 常驻，按
`ResourcePackAccess.packsByPriority()`（高优先级在前）读 PNG，**用原版 `NativeImage` 解码**，
预乘后按 `ColorAlphaType.PREMUL` 建光栅图（第 7 条说明为什么不走 Skija 自带解码）；
失败记 `FAILED` 不再逐帧重试；`draw(canvas, id, x, y, size, alpha)` 等比居中并乘透明度，
采样用 `SamplingMode.DEFAULT`（最近邻，16×16 的原图放大才保持像素质感，与 `PlayerFaceCache` 同口径）。

### 3. 「模型键 → 贴图」解析

`StardewPreview.textureOf(itemModelId)`：`items/<id>.json` 的 `model.model` → 模型文件
`textures.layer0`（旧布局没有 items 定义时，模型键本身就是 `models/<path>.json` 的键）→
拼成 `textures/**.png` 并校验存在。模型链上的 `parent` 逐级找（上限 8 层防环），
`#layer0` 这类变量引用跳过不当作路径。

### 4. 「哪张图代表这种作物 / 这类点位」只写一次

- `CropDefinition.iconModel()`：**成熟产物优先、回退种子**。选择器的作物行原本内联了这段规则，
  本次改为调它（第 169 条：同源逻辑禁两份）；控制台列表行、圈地收口窗按钮、世界区域字牌全读这一份。
- `StardewPointType.iconItemId()` / `icon()`：种子箱＝小麦种子、成品箱＝小麦、补水点＝水桶、
  岩浆箱＝岩浆桶、龙息箱＝龙息、洒水器＝滴水石锥（**不是喷溅药水**，原因见下面第 6 条）。
  控制台点位卡与洒水器列表行读 `icon()`，世界字牌读 `iconItemId()` 再解析成贴图 ——
  卡片与字牌不可能各画一个样。

### 5. 把图标接到四处界面

| 落点 | 做法 |
| --- | --- |
| 种植区域列表行 | `CompactRow.icon(Supplier<ItemStack>)`（与模块行同尺寸档，16px） |
| 圈地收口窗「这块地种什么」按钮 | 新增 `Button.itemIcon(Supplier<ItemStack>)`：物品贴在文字左侧，宽度按「图标 + 间距」自适应，空栈不占位 |
| 世界区域字牌 | `EspRenderer.textWithIcon(...)`：图标按字号 1.6 倍画在名字左侧，底板包住「图标 + 文字」整块，整体居中于投影点 |
| 世界点位字牌 | `PointLabelText.containerLabel(..., iconTexture)`：`label(...)` 只留一份实现，无图标时走原路径 |

**性能口径**：`StardewPreview` / `textureOf` 要读资源包 JSON，因此
①界面侧一律「先取好 `ItemStack` 再喂给行 / 按钮」，不让每帧的 Supplier 里做资源解析；
②世界侧在 `StardewRenderState` 里按模型键缓存解析结论（空串 = 解析不出来）。

### 6. 图集 sprite 反查：本服 `layer0` 根本不是贴图路径（真机取证后的补丁）

**症状**：上面四处接好之后，界面侧的图标能出（走真实物品渲染），但**世界字牌仍然只有纯文字**。

**取证（直接读实机包 `jmy.seasonmc.xyz_25565.zip`）**：

```
assets/customcrops/models/item/crops/corn/corn.json
  {"parent":"minecraft:item/generated","textures":{"layer0":"ia:75"}}
assets/customcrops/models/item/crops/chinese_cabbage/chinese_cabbage.json
  {"parent":"minecraft:item/generated","textures":{"layer0":"ia:70"}}
```

`ia:75` 不是贴图路径，包内**根本没有** `assets/ia/`（0 条目）。它是 ItemsAdder 自建图集里的
**sprite 名**，真实贴图写在图集定义里（`ia_overlay_modern_atlas/assets/minecraft/atlases/items.json`）：

```json
{"type":"single","resource":"customcrops:item/crops/corn/corn","sprite":"ia:75"}
{"type":"single","resource":"customcrops:item/crops/chinese_cabbage/chinese_cabbage","sprite":"ia:70"}
```

该图集定义放在 overlay 目录，由 `pack.mcmeta` 的 `overlays.entries` 声明
（`{"directory":"ia_overlay_modern_atlas","formats":[75,9999]}`，本包 `pack_format=75`；
另有 `ia_overlay_legacy_atlas` 为 `formats:[1,69]`，客户端 format 落在哪一档就合并哪一份），
由原版合并后交给 `ResourceManager`。

**修法**：`StardewPreview` 增加「sprite 名 → 真实贴图 PNG」反查表。

- `textureOf` 先按原版语义把 `layer0` 当裸贴图路径找（标准资源包走这条，老行为不变），
  找不到再拿这一串去反查表里找 `resource`，再拼 `textures/**.png` 并校验存在。
- 建表：`minecraft:atlases/items.json` 先整表登记，再枚举 `minecraft:atlases/` 其余图集兜底
  （图集定义只挂在 `minecraft` 命名空间）；同一 sprite 名先到先占，于是生效资源包压过原版包。
  **只认 `type=single`**：`directory` 那种「sprite 名 = 资源名」的写法，裸路径分支本来就能直接命中，
  其余类型（`filter` / `paletted_permutations` / `unstitch`）一律跳过 —— 宁可少认，不猜结构。
- 惰性构建一次并缓存；**资源包没就绪时不缓存空表**（否则首个调用会把「空」记成结论）；
  `ResourceExtractionService.onReloadApplied()` 里与 `ItemModelDispatchIndex.invalidate()` 一起作废。
- 表里直接存**拼好的 PNG 路径**，命中后只做一次存在性校验；不能再走「贴图引用 → PNG」那道
  转换，否则会把 `textures/` 前缀拼第二次，路径直接作废（本条目自审时抓到并已修）。

**顺带修掉一个观感缺陷**：洒水器原本取 `minecraft:splash_potion`，它的模型 `layer0` 是
`minecraft:item/potion_overlay` —— 一张只给瓶身染色用的白色叠加图，字牌那条路径只取 `layer0`
且不染色，画出来是一团没有颜色的糊块。改用 `minecraft:pointed_dripstone`（全彩、且与
「补水点＝水桶」一眼分得开）。

**验证（离线核对，逐环对过实机包）**：`ia:70` → `customcrops:item/crops/chinese_cabbage/chinese_cabbage`
→ `assets/customcrops/textures/item/crops/chinese_cabbage/chinese_cabbage.png` **存在**；
`ia:75` → `.../corn/corn.png` **存在**；五个点位物品的 `models/item/*.json` 一律是
`layer0 = minecraft:item/<name>` 的直路径（`pointed_dripstone` 已核）。

### 7. 字牌图标仍不显示：Skija 自带解码器在本机解不开这批 PNG（真机日志实证）

**症状**：第 6 条打上、用户重启客户端后回报 —— **界面侧图标出来了（区域点位设置里有），
世界字牌仍然没有**。

**取证（`run-26.1.2/logs/latest.log`）**：

```
[02:47:47] [Render thread/WARN] (yiyiaddon/texture) 贴图解不开：customcrops:textures/item/crops/chinese_cabbage/chinese_cabbage.png
             （java.lang.IllegalArgumentException: Failed to Image::makeFromEncoded）
             ……同样的还有 pineapple / redpacket / hop（正好是四个区域的作物图）
```

四个失败的路径**全都是对的** —— 说明第 6 条的图集反查已经命中，卡在最后一步解码：
Skija 自带的 `Image.makeDeferredFromEncodedBytes`（`makeFromEncoded` 的替代品）在本机
对这批贴图一律失败。包里的图本身没问题（同目录 PNG 的 IHDR 逐个核过：16×16、8 位、
调色板 / 真彩、非隔行，都是标准 PNG）。

**修法**：不再用 Skija 的编解码，改用**原版解码器**：

```java
try (NativeImage pixels = NativeImage.read(NativeImage.Format.RGBA, in)) {
    byte[] rgba = new byte[width * height * 4];
    MemoryUtil.memByteBuffer(pixels.getPointer(), rgba.length).get(rgba);
    premultiply(rgba);
    new ImageInfo(width, height, ColorType.RGBA_8888, ColorAlphaType.PREMUL, ColorSpace.getSRGB())
}
```

三条理由：

1. 原版解码器就是客户端渲染这些贴图用的那一个 —— **能画出来就一定能解开**，这是「适配多种
   服务器」最硬的保证，也不再挑 PNG 的具体编码（调色板 / 真彩 / 隔行通吃）。
2. 建图口径与 `PlayerFaceCache` / `ItemIconCache` 逐字一致：`Format.RGBA` 是直通 alpha
   （内存里就是 R,G,B,A），**必须预乘后再按 `PREMUL` 建图**，否则透明区在本机被画成黑块
   （用户 2026-09-16「首页头像黑底」的同一条教训）。
3. `TextureImageCache` 的 `FAILED` 是「不再重试」语义，解码方式一旦错就是整会话无图 ——
   这一条必须一次做对。

**顺带**：`ResourceExtractionService.onReloadApplied()` 里把 `TextureImageCache.clear()` 也接上
（原来只有图集表作废）。同名贴图在两份资源包里内容可以完全不同，不丢就是「换服后字牌还挂着
上一台服的图」。

## 四、验证

- `.\gradlew.bat compileJava --console=plain -q`：EXIT=0（无告警）。
- `.\gradlew.bat build --console=plain -q`：EXIT=0。
- **实机（第一轮，2026-09-22 02:47，仅到第 6 条为止）**：用户回报「区域的 esp 没有种子图标，
  但是区域点位设置里面有」—— 即**界面侧四处图标已生效**，世界字牌因 Skija 解码失败而无图；
  日志给出了确切的失败点（见第 7 条）。第 7 条打好后重启客户端，待验：
  1. 种植区域列表 / 洒水器列表底部「清空…」→ 确认 → 停在控制台（正文数量变 0），不再回游戏；
  2. 种植区域列表每行左侧出现该地块作物的图标；圈地收口窗每个作物按钮左侧出现作物图；
  3. 世界里的区域字牌「区域 N · 作物 · 维度」前面多一张作物图；
  4. 种子箱 / 成品箱 / 补水点 / 岩浆箱 / 龙息箱 / 洒水器的字牌前面各多一张代表物品的图。
- 图标取不到时不画图标、字牌照画（不出现黑紫缺失模型，也不刷屏）。
- 已知边界：贴图解析走的是资源包里声明的模型链 + 图集定义，**两处都没有的作物只会显示纯文字**；
  `layer0` 是 `paletted_permutations` / `unstitch` 这类图集来源的贴图也拿不到（只认 `single`）；
  `TextureImageCache` 的 `FAILED` 是会话内「不再重试」，所以**资源包还没生效时渲染过的那张图
  要到重开客户端才会补上**（图集反查表本身在资源重载时会作废重算）。
  `StardewRenderState` 的按模型键缓存同理。
