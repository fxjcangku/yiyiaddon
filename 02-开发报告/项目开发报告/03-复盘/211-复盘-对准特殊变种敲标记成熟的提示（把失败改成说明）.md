# 211 · 对准特殊变种敲「标记成熟」的提示（把失败改成说明）

- 日期：2026-09-22
- 触发（用户实机）：准星对准地上的巨型菠萝敲 `.stardew 标记成熟`，回执是
  「标记成熟失败 ▸ 已识别为自定义作物，但缺少阶段信息（无法确定 stageKey）· 未保存」
- 相关：[194](194-复盘-特殊变种收割口径按服务器学习（巨型作物左键破坏）.md)（特殊变种口径学习）、
  [209](209-复盘-挖巨型作物不主动换手（挑工具不再「够挖就别动」）.md)（同一轮实测发现）

## 一、现象

作物好好的、模块也认得出它（同一格在准星诊断里报「作物 pineapple / 状态 特殊变种」），
玩家敲「标记成熟」却收到一条**失败**结论，看起来像"识别链坏了"。

## 二、成因

特殊变种（巨型 / 金色 / 变异）的身份里**没有 `_stage_` 段**（如 `pineapple_gigantic_pineapple`），
所以 `RuntimeResult.stageName()` 为 null、`hasStage()` 为 false —— 而 `标记成熟` 的准星路径在
`!crop.isCrop()` 之后、`!crop.hasStage()` 这条通用校验上把它拦下了，给出「缺少阶段信息」。

问题是：**特殊变种本来就没有普通成熟阶段**，它的收割动作与手持工具按本服口径（学习 / 预置）执行，
根本不需要人工标记成熟。玩家做了一件不该做的事，得到一条像故障的失败 —— 指令把"不适用"报成了"出错"。

## 三、改动

准星路径在「缺少阶段信息」之前先判特殊变种，改成说明式回执：

- 标题：`无需标记成熟`
- 当前状态：特殊变种（巨型 / 金色 / 变异作物）
- 说明：没有普通成熟阶段，收割动作与手持按本服务器学到的口径执行（本服已预置过的无需示范）
- 你要做的：什么都不用做，模块会自己按口径收割
- 状态：`未改动任何规则`（INFO 级，不是 FAILURE）

「缺少阶段信息」那条保留给**真正的异常**：认得是作物、又不是特殊变种、却读不出阶段。

## 四、验证

- `GetDiagnostics`：`StardewCommand.java` 0 诊断。
- 待实机：对准巨型菠萝敲 `.stardew 标记成熟` → 应弹「无需标记成熟」，不再出现「标记成熟失败」。

## 五、教训

1. **"不适用"不是"失败"**：玩家对着一株巨型作物敲标记成熟，正确的回应是"这个不需要标记"，
   而不是一句失败原因。指令的失败回执要留给**玩家做错了**的情况（写错参数、资源没就绪、
   阶段真读不出来），"这件事对本对象不成立"要用说明式回执 + INFO 状态。
2. **先判特例再走通用校验**：通用校验（必须有阶段）写在前面，特殊形态就会掉进通用错误分支。
   凡是"某类对象天然缺某个字段"的设计，都要在通用校验之前显式分流 —— 这与第 195 条
   「巨型变种不受盆型过滤」是同一类错误。
