# 213 · 产物箱还满时开箱不复位（复位判据落到「箱内空位」）

- 日期：2026-09-22
- 触发（用户原话）：「（开一次箱子）是会恢复 但是没用啊 箱子都满了 我回去收菜有什么意义 背包满了还不是直接停机？
  你直接停机就好了啊」
- 相关：[205](205-复盘-产物箱满改成直接停机（撤掉20秒自动复查）.md)（满箱停机那一版）、
  [195](195-复盘-背包满了还在收菜与产物箱满了不提示.md)（满了停手的第一版）

## 一、现象

满箱停机后，玩家点开箱子（只是看一眼、或先从里面拿点东西）→ 模块立刻"恢复"：下一轮就去卸货 /
继续收菜；可箱子还是满的 → 卸不进去 → 立刻再停一次。玩家看到的是"停了又动、动了又停"，
而这一切没有产生任何实际进展。

## 二、成因

第 205 条给满箱状态留了三个复原点，其中第一个写成「玩家自己打开过一次容器」——
**把"玩家开过箱子"当成了"箱子处理过了"**。这两件事完全不同：

| 玩家动作 | 箱子实际状态 | 老判据 | 应该 |
| --- | --- | --- | --- |
| 点开看一眼 | 还满 | 复位 → 白跑一趟 | 保持停机 |
| 拿点东西走 | 还满 | 复位 → 白跑一趟 | 保持停机 |
| 清空 / 腾出位置 | 有空间 | 复位 → 真能卸进去 ✓ | 复位 ✓ |

## 三、改动

1. 复位判据加上**箱内此刻真有空位**：打开容器界面时读**箱子那一侧**的槽位
   （玩家背包之外的 `Slot`），存在空槽、或存在没叠满的堆叠，才算"腾出位置了"。
2. 还是满时：**什么都不做** —— 不复位、不播报、不跑动（安静保持停机，符合用户「直接停机就好了」）。
3. `critical` 文案同步写明「箱子还满时打开它不会恢复」，把复原点讲清楚。

「没叠满的堆叠」这一条放宽了一点点（那一格可能是别的物品），代价只是白卸一趟 ——
真放不进去会被验证层立刻再次停机，不会来回折腾；换成只认空槽则会把"拿掉一半"的箱子挡在外面。

## 四、验证

- `GetDiagnostics`：`StardewFarmModule.java` / `StardewCoordinator.java` / `StardewTaskVerifier.java` 均 0 诊断。
- 待实机：
  1. 塞满产物箱 → 应立刻 `critical` 停机；
  2. **箱子还满时**打开一次箱子 → 不应有任何恢复动作（日志无 `OUTPUT_FULL_RECHECK`）；
  3. 清空箱子后再打开 → 应出现「产物箱重新检查 ▸ 箱子已有空位」，随后自动去卸货并继续收菜。

## 五、教训

1. **"玩家做过某个动作"与"客观条件成立"是两个判据，别混用**：开箱子只是玩家在操作，
   箱子有没有空位是客观事实。用前者当判据，就会在条件没变的情况下反复触发。
   凡是"以玩家动作为信号"的复原点，都要再补一句"信号所暗示的那个事实是否真的成立"。
2. **停机要停得干净**：既然承诺"直接停机"，那停机期间任何不产生进展的动作都不该发生 ——
   白跑一趟的代价不只是性能，而是让玩家以为模块在乱动（这一条与第 205 条「撤掉 20 秒复查」同源）。
