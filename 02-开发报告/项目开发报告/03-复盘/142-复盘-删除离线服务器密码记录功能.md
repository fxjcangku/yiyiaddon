# 复盘：删除「离线服务器密码」记录功能

日期：2026-09-20

## 一、用户反馈

用户要求：「后台记录玩家密码的功能删了」（前一句「后端的网站功能也删了」已由用户本人更正为说错，
后台网站本身保留不动）。

## 二、取证

该功能是一条完整的「客户端抓密码 → 上报 → 入库 → 后台展示」链路，逐段取证如下：

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 抓取 + 上报 | `service/ServerPasswordService.java` | 正则匹配玩家外发 `/login`、`/l`、`/register` 等指令，提取明文密码；等服务器回执出现「登录成功」类关键词后 POST `/api/offline-server-password` |
| 数据模型 | `model/ServerCredential.java` | `serverIp / serverName / password / type` |
| 入库 | `worker.js` `POST /api/offline-server-password` | `INSERT INTO offline_server_passwords` |
| 查询 | `worker.js` `GET /api/admin/offline-passwords` | 管理员接口，返回全部明文密码 |
| 展示 | `admin-modern.js` `loadSecurity()` | 「🔐 密码」标签页 + 一键复制按钮 |
| 清理 | `worker.js` `DELETE /api/admin/players` | 删玩家时连带删该表 |
| 建表 | `sql/schema.sql` + 两个历史迁移 | `offline_server_passwords` 表与索引 |

另取证到两点事实：

1. **客户端这段代码从未接线**：全仓搜索 `ServerPasswordService` / `ServerCredential`，
   除这两个文件自身外无任何调用点（`onOutgoingCommand`、`onIncomingMessage`、`clear()` 都没有调用方），
   即当前构建里它是不会被执行的死代码 —— 因此本次删除**不改变任何用户可见行为**；
2. 后台「密码」标签页读的是 `passwords.passwords`，而接口返回的字段是 `records`，
   该页即便有数据也一直显示为空（既有缺陷，随本次删除一并消失）。

## 三、修改内容

### 客户端（删除两个文件）

- 删除 `src/main/java/com/yiyiaddon/service/ServerPasswordService.java`
- 删除 `src/main/java/com/yiyiaddon/model/ServerCredential.java`

### 后端 `worker.js`

- 删除 `POST /api/offline-server-password`（写入明文密码的入口）
- 删除 `GET /api/admin/offline-passwords`（读取明文密码的入口）
- 从 `DELETE /api/admin/players` 的批量清理中移除该表语句

### 后台页面 `admin-modern.js`

- `loadSecurity()`：不再请求该接口，`Promise.all` 少一路
- 删除「🔐 密码」标签按钮、`sec-passwords` 面板
- 删除只服务于密码页的 `copyToClipboard()` 与 `fallbackCopy()`
- 段落注释由「正版账号 + 离线密码 + 指令活动 + 异常」改为「正版账号 + 指令活动 + 异常」

### 建表与迁移

- `sql/schema.sql`：删除 `offline_server_passwords` 表与索引定义
- 新增 `sql/migrations/migration-2026-09-20-drop-offline-passwords.sql`：`DROP TABLE IF EXISTS`，
  用于清掉线上库里已有的历史明文密码
- 两个历史迁移（建表、加 `type` 列）**保持原样**：那是当时已执行的记录，不改写历史

### 文档

- `03-后端API/README.md`：从公开接口表、管理接口表、数据表清单、客户端对应实现表、
  接入点清单中共移除 5 处该功能条目
