# 复盘：单人世界闸门（不可开启的模块）交由框架执行

日期：2026-09-20

## 一、用户反馈

> 「服务器核心单人游戏也可以开启……我的旧项目有很多模组都是单人无法开启的……帮我修复」
> 「旧项目什么模块不可以开启，新项目照搬」

即：旧项目里「单人世界不可开启」的那批模块，在新项目里必须同样开不起来；实测「服务器检测」在单人世界里仍是开启态。

## 二、旧项目的口径（照搬基准）

旧项目（`d:\mcaddon\26.1.2`）单人世界自动关闭的模块共 **6 个**，判据与文案逐字如下：

| 模块 | 旧位置 | 判据 | 文案 |
| --- | --- | --- | --- |
| 服务器检测 | `tactical/ServerDetector.java:205-213` | `mc.hasSingleplayerServer()` | `§c单人世界无需检测` |
| 飞行绕过 | `tactical/FlightBypass.java:227-234` | 同上 | `§c单人世界无需飞行绕过` |
| 发包防踢 | `tactical/AntiKickBypass.java:380-389` | 同上 | `§c单人世界无需防踢` |
| 发包秒破 | `tactical/packetbreak/PacketInstantBreak.java:364-371` | 同上 | `§c单人世界无需发包秒破` |
| 自动登录 | `autologin/AutoLoginModule.java:1631` | 单人 **或** 正版验证服 | `§c§l单人世界或正版验证服务器无需自动登录，模块已自动关闭。` |
| 星露谷农场 | `stardew/StardewFarmModule.java:594`（经 `resourceActionsAllowed()`） | 非多人服务器 | 自检缺项「当前环境不是多人服务器」 |

规范侧对应旧 `convention/YiyiaddonConvention.java:272-284` 第 5.4 节「单人世界自动禁用规范」。

## 三、为什么新项目里「拦不住」（根因）

新项目 6 个闸门**都在**，但只写在各自的 `onEnable()` 里，而 `onEnable` 只在「启用那一刻」跑：

- 旧项目四个战术模块**全部默认关闭**（`core/AddonTemplate.java:204-207` 只 `add` 不 `enable`），玩家只能在**世界里**点开启 → 闸门必命中；
- 本项目按用户 2026-09-18 决策把「服务器检测」「发包防踢」改为 `enabledByDefault() == true`
  （`ServerDetectorModule:188-197`、`AntiKickBypassModule:271-280`），它们**在装配期（主菜单）就恢复启用**——
  那时没有世界，`hasSingleplayerServer()` 恒为 `false`，闸门放行 → 模块就这样开着进了单人世界。

「在装配期就拦」也不可行：发包防踢的频道注册发生在**进服瞬间的配置阶段**，必须在进服前处于开启态。

## 四、改动（同源逻辑只留一份：闸门交给框架）

1. `core/module/Module`：新增 `environmentRefusal()`（默认 `null` = 允许），语义是「环境不允许运行的原因」，
   与 `selfCheck()`（配置没配好）分开；由框架在**启用时**与**进世界时**两个时机执行。
2. `core/module/ModuleManager`：
   - `JOIN_SERVER` 处理器里追加 `enforceEnvironmentGate()`：单人世界下把「声明环境不允许」且已开启的模块
     **环境暂停**（`stop()`；状态文件保持「启用」不动，因为这是环境暂停、不是玩家关闭），登记 `PENDING`
     ——换到多人服务器后由既有 `enablePending()` 自动开回来（对应旧帮助文案「多人世界自动启用」）；
   - `tryEnable()` 增加同一判据：拒绝时按 `BLOCKED` 返回（等待）并播报原因，玩家主动开启才有提示、后台重试静默；
   - 抽出 `stop()`（退订 + 改内存 + `onDisable`，不写盘），`forceDisable()` = `stop()` + 写盘。
3. 四个战术模块：删掉 `onEnable()` 里的单人分支，改为覆写 `environmentRefusal()`，
   **文案逐字照旧**（`§c单人世界无需检测 / 飞行绕过 / 防踢 / 发包秒破`），javadoc 的框架适配表与保留缺陷表同步更新。

未改动：自动登录（`closeForUnsupportedEnvironment()` 已在 `onEnable` / `onTick` / `onGameJoined` 三处执行，
无「主菜单绕过」缺口）；星露谷农场（自检缺项 + `PENDING` 机制已覆盖）；
界面上的「单人世界自动禁用，仅在多人服务器生效」提示文案（行为未变，无需改）。

## 五、验证

- `.\gradlew build --console=plain -q` → **EXIT=0**。
- **未实机**（第 19/46/193 条显式标注），需验证三条：
  ① 单人世界里「服务器检测 / 发包防踢」显示为关闭，手动点开启会得到「§c单人世界无需检测 / 防踢」；
  ② 进多人服务器后这两个模块自动开回来（旧文案「多人世界自动启用」）；
  ③ 多人服里手动关闭后不会被自动开回来（`PENDING` 只在环境暂停/自检受阻时登记）。

## 六、影响面

- 只有声明了 `environmentRefusal()` 的 4 个模块受影响；默认 `null` 的模块行为不变。
- 单人世界闸门现在是「内存停机 + 状态文件保留」，因此单人世界里的开关显示与状态文件可能短暂不一致
  （显示关闭、文件仍是启用）——这是刻意的：避免把玩家在多人世界的开启意图抹掉。
