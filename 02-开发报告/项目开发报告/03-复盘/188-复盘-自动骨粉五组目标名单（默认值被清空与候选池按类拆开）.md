# 复盘：自动骨粉五组目标名单（默认值被清空 + 候选池按类拆开）

- 日期：2026-09-22
- 触发：用户实机截图「自动骨粉 选择器 不是目标的物品而是都是73种」——控制台「目标方块」页五组
  （农作物 / 树苗 / 花卉 / 蘑菇·菌类 / 水下·下界）**全部**显示「未选择（共 73 项）」
- 结论：三件事，一件 bug、两件用户裁定的改法
  1. **bug**：设置载入把字段默认值清成了空名单（配置里没有名单键时无条件整表替换 → 读到空表 →
     11 / 9 / 8 / 4 / 6 项被抹掉）。当时的表现是模块开箱即无任何目标。
  2. **改法一**（用户拍板「按类拆开，每组只列自己那类」）：五组共用的候选池（73 项）改成每组只列本类。
  3. **改法二**（用户随后追加「默认自己选择 不要帮我全选」）：出厂五个名单**全空**，
     即默认不勾任何目标；旧那份 11 / 9 / 8 / 4 / 6 项不再当默认勾选，只留作每组的**候选范围**
     （分类依据）。这一条把 bug 1 的玩家可见表现抹平了 —— 出厂本就是空的，清空不再看得见。

## 一、现象与取证

| 检查项 | 结果 |
| --- | --- |
| 73 是什么 | 选择器候选池的条数 = 全方块里 `BonemealableBlock` 的个数，**不是任何一组的名单长度**（五组默认值合计 38 项） |
| 名单为什么是空的 | 载入路径 `ModuleManager#restoreStates` → `ModuleStateConfig#settingsOf("bonemeal", scope)` → `BonemealSettings#load(json)`：列表几行是 `replaceAll(名单, listOf(json, 键))`，而 `listOf` 对**缺键**返回空表 |
| 磁盘证据 | `run-26.1.2/config/module-state.json` 的 `"bonemeal"` 段只有 `{"启用": false}`，没有「设置」桶 → `settingsOf` 返回**空对象** → 每次载入都把默认名单清一遍 |
| 为什么之前没暴露 | 其它同类名单模块的默认值是空表（`PacketBreakSettings#targetBlocks`、`VisionSettings#blockTargets/entityTargets` 都注释着「空 = 不画 / 挖所有」），无条件替换看不出差别；只有自动骨粉的默认名单是非空的 |
| 正确口径在哪 | 同一个 `BonemealSettings` 里 `boolOf / intOf / enumOf` 全部带 fallback；`AutoLoginSettings#listOf(json, key, fallback)` 更是把「键不存在时回落原名单」写在注释里 —— 只有骨粉这几行漏了 |
| 候选池为什么五组一样 | 旧项目 5 个 `BlockListSetting` 共用同一个 `filter(block -> block instanceof BonemealableBlock)`，候选窗口因此五组都是同样那 73 项（本项目移植时照抄了这一层） |
| 有没有异常 | 日志无本模组异常；两件事都是纯口径问题，不抛错 |

## 二、改动

### ① 缺键不该整表替换（`feature/bonemeal/config/BonemealSettings`）

1. 新增 `replaceIfPresent(json, key, target)`：**只有配置里确有该键且是数组**时才 `replaceAll`，
   缺键 / 类型不符一律保持字段里的默认值（与 `boolOf` 等原语同口径）。
2. 五组名单的载入改走它；`replaceAll` / `listOf` 原样保留（`replaceIfPresent` 内部仍用它们）。
3. 在 `load` 与 `replaceIfPresent` 两处写清为什么不能直接写 `replaceAll(target, listOf(json, key))`。
4. **不动** `PacketBreak` / `Vision`：它们默认名单本就是空表，替换与不替换行为一致（若将来给它们加非空
   默认名单，必须一并改用同一口径）。

### ② 候选池按类拆开（`feature/bonemeal/ui/BonemealSelectors` + `config/TargetList`）

1. **分类数据搬家**：旧那份 11 / 9 / 8 / 4 / 6 项从 `BonemealSettings` 的字段默认值搬到
   `TargetList#members()` —— 它现在是「哪些方块属于这一类」的唯一定义（候选范围），
   不再是出厂勾选。五组另加一份分类表是没有必要的（第 169 条）。
2. **出厂名单全空**：`BonemealSettings` 五个名单字段改为 `new ArrayList<>()`。用户 2026-09-22
   「默认自己选择 不要帮我全选」—— 不给玩家预勾；「恢复默认」同样回到全空（一致口径）。
3. 候选从「全方块 ∩ 可催熟」改成「该组本类方块」：`candidates(group, selected)` 用
   `MiningRegistry.filter(blockEntries, 键在本类 ∪ 键在当前已选)` 现算。
4. **带上「已选里不属于本类的项」**：右栏「已选」是拿候选表逐条渲染的
   （`SelectorScreen#buildColumn`），候选表里没有的键既不显示也删不掉，而判定层还在按它催熟 ——
   那是玩家看得见却管不着的幽灵条目。带进候选表后既能显示也能取消勾选，且 `已选 ≤ 共` 恒成立。
5. **去掉「只列可催熟方块」这层过滤**：按类之后它已无意义，且有害 —— 成员名单里的 `海带` 不是
   `BonemealableBlock`，留着会让「已选 1 / 0 项」这种自相矛盾的数字出现。
   判定层本来就用 `isFertilizable` 再筛一遍，候选层不必重复。

**修复后的表现**：全新配置 / 没存过设置的存档打开「目标方块」页，五组都是
`未选择（共 11 项）`、`未选择（共 9 项）`、`未选择（共 8 项）`、`未选择（共 4 项）`、`未选择（共 6 项）`；
点开任一组的选择器，左栏只列本类方块（农作物那组 11 项、树苗 9 项……），勾哪个由玩家自己决定。
模块启用后按玩家实际勾选的名单催熟；一组都没勾时自检照旧拦下（与发包秒破 / 透视「空 = 不干活」同口径）。

## 三、验证

| 项 | 结果 |
| --- | --- |
| `.\gradlew.bat compileJava` | **EXIT=0** |
| 实机验证 | **已通过**（用户 2026-09-22「可以了 已修复」）：五组出厂不预勾、每组选择器只列本类 |

复测要点：
1. 打开「自动骨粉 → 目标方块」：五组分别是「未选择（共 11 / 9 / 8 / 4 / 6 项）」，一个都不预勾；
2. 点「农作物」的「选择」：左栏只列农作物（11 项，不再是 73 项），右栏为空，勾几项就有几项；
3. 勾过的组重进游戏后名单还在（键已落盘）；没动过的组保持空；
4. 模块启用后按勾选的名单催熟；一组都没勾时自检拦下并提示（这是预期行为，不再算「名单丢了」）。
