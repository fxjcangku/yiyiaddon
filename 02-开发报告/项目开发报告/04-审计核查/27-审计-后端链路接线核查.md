## 二、断掉的链路（客户端服务存在、入口从没被调用）

### 1. 遥测（崩溃 / 异常上报）从未启动

- `TelemetryService.java:45 start()` 是唯一安装入口（`start()` 内 `:49` 才 `BackgroundTasks.schedule(..., TelemetryService::sample)`）；
- 全库检索 `TelemetryService` 只命中它自己 3 处（`:24` 声明、`:41` 构造、`:49` 自调）→ **无任何外部调用点**；
- 后果：`/api/crash/report`（`TelemetryService.java:75`）、`/api/anomaly/report`（`:100`）从未产生流量，
  后台「崩溃」「异常」两页永远为空；
- 与契约冲突：`README.md:92`「客户端初始化：… `TelemetryService.start()`」。

### 2. 指令埋点从未挂载

- `CommandActivityService.java:27 onOutgoingCommand(String)` 是唯一入口，`report()`（`:46`）只被它调用；
- 全库检索 `onOutgoingCommand` / `CommandActivityService` 只有它自己文件内的 4 处 → **无调用点**；
- 后果：`/api/command-activity`（`CommandActivityService.java:57`）无流量，后台「指令记录」页永远为空；
- 与契约冲突：`README.md:95`「`ClientPacketListener.sendCommand(String)`：`CommandActivityService.onOutgoingCommand(...)`」
  —— 该注入点在 `mixin/` 包内也不存在（现有 mixin 均非此目标）。

### 3. 跨服聊天只接了「收」，没接「发 / 查 / 回」

- `ChatService` 现在只有 `start()/stop()` 被调用（`YiyiAddonClient.java:75/76`）；
- `onlinePlayers()`（`:55`）、`broadcast()`（`:68`）、`send()`（`:77`）、`reply()`（`:90`）**全库无调用点**；
- 后果：`/api/chat/online`（`:56`）、`/api/chat/send`（`:86`）、`/api/messages/reply`（`:98`）三条死；
- 附带文案错：`ChatService.java:145` 向玩家打印「（使用 `.回复 <内容>` 回复）」，
  但 `command/` 包内没有任何 `回复` 指令注册 —— 引导玩家使用一个不存在的指令。

### 4. 更新提示远程开关声明了但没人读

- `RemoteConfigService.java:24 UPDATE_NOTICE = "update_notice_enabled"`；
- 全库检索 `UPDATE_NOTICE` 只有这一处声明 → 从未被 `flags().enabled(...)` 读取；
- 后果：后台下发 `update_notice_enabled=false` 无效，更新提示照常。

## 四、面板与后端语义不匹配（点了没效果）

### 1. 「删除配置」删不掉

- 面板 `admin-modern.js:1700-1710 deleteConfig()`：`api('/api/admin/config',{method:'POST',body:{key,value:''}})`，
  注释写着「通过设置为空值来删除」；
- 后端 POST 分支是 UPSERT：`worker.js:914 INSERT … ON CONFLICT(key) DO UPDATE SET value = excluded.value`
  → **行仍在 `configs` 表里，只是 value 变成空串**；真正删除的 DELETE 分支（`worker.js:922-934`）没人调用。

### 2. 「保留天数」两个设置项后端不读

- 面板写入 `chat_retention_days` / `command_retention_days`（`admin-modern.js:1513/1514`，界面 `:1468/1469`）；
- `worker.js` 全文件检索 `retention` **0 命中** → 后端从不读取这两个值；
- 后端真正的清理接口 `/api/admin/clean-old-data`（`worker.js:1143-1158`）是 `DELETE FROM messages` /
  `DELETE FROM command_activities` **全表清空**，与「保留 N 天」无关。

### 3. 面板宣传的 8 个远程开关只有 2 个真的生效

面板说明（`admin-modern.js:1650-1657`）列出 8 项，客户端 `flags().enabled(...)` 全库读取点只有 3 处：

| 面板宣传的配置项 | 客户端是否读取 | 证据 |
| --- | --- | --- |
| `stats_report_enabled` | **生效** | `RegisterService.java:28`、`HeartbeatService.java:54` |
| `message_poll_enabled` | **生效** | `ChatService.java:42` |
| `update_notice_enabled` | 无效 | 常量仅 `RemoteConfigService.java:24` 声明，无读取 |
| `heartbeat_report_enabled` | 无效 | 全库无此字符串（心跳实际受 `stats_report_enabled` 控制） |
| `anomaly_report_enabled` | 无效 | 全库无此字符串 |
| `crash_report_enabled` | 无效 | 全库无此字符串（且遥测本身未启动） |
| `chat_retention_days` | 无效 | 后端不读（见上） |
| `command_retention_days` | 无效 | 后端不读（见上） |

### 4. `initWebSocket()` 是空壳

- `admin-modern.js:923` 调用它，函数体（`:936-941`）只有注释与 `console.log('轮询模式（每 5 秒刷新）')`；
- 真实刷新靠 `:926-930` 的 5 秒轮询兜底。不产生 404，但注释「WebSocket 实时推送（替代轮询）」与实现不符。

| 优先级 | 项 | 影响 | 建议做法 |
