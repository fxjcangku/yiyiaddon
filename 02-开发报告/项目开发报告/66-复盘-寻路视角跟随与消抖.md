## 1. 上一轮理解错了什么

64 号把「男中音寻路的那条线」当成了**渲染出来的路径线**，于是自绘了一个 ESP 层——
用户要的是**视角**：寻路时镜头跟着路径方向走（就像挖掘时男中音把镜头对准正在挖的方块那样）。
64 号那套已整类回退（见第 5 节）。

## 2. 取证：为什么走路时「看不到寻路视角」

唯一裁决点 `LookBehavior.Target.Mode#resolve`（`LookBehavior.java:336-356`），三个模式的含义写在
`Target.Mode` 的枚举注释里（CLIENT = 写本地可见视角；SERVER = 只写服务端朝向、本地还原；NONE = 都不写）：

| 场景 | 默认设置下的解析 | 本地视角 |
| --- | --- | --- |
| 走路（`blockInteract=false`） | `freeLook=true` → `antiCheatCompatibility ? SERVER : NONE` | **不动**（所以看不见寻路视角） |
| 挖矿 / 放置（`blockInteract=true`） | `freeLook=true` + `blockFreeLook=false` → **CLIENT** | 跟着正在挖的方块（这就是你要的「跟随视角挖掘」） |
| 任意场景，`freeLook=false` | 直接返回 **CLIENT** | **跟着路径走** ← 本轮要的 |

默认值（`api/Settings.java`）：`freeLook=true`（:759）、`blockFreeLook=false`（:764）、
`antiCheatCompatibility=true`（:798）、`smoothLook=false`（:774）、`smoothLookTicks=5`（:784）、
`randomLooking=0.01`（:419）、`randomLooking113=2`（:403）。

**「抖」的直接来源**（这是本轮能给出「不抖」的根据，不是猜的）：
`AbstractAimProcessor#peekRotation:223-224` 在每一刻把
`randomYawOffset`（= `(rand-0.5)*randomLooking113`）与 `randomPitchOffset` 加到目标角度上，
`tick():232-244` 每刻重掷。CLIENT 模式下这个偏移会经 `onPlayerUpdate PRE` 写进玩家实际角度
——`randomLooking113=2` 就是**每刻 ±1 度**的随机摆动，肉眼可见的抖。
（SERVER 模式下 POST 会把角度还原，所以以前看不见它。）

## 3. 改法

新增设置项 **「寻路视角跟随」**（`MiningSettings#pathViewFollow`，默认开，控制台「Baritone调优 ▸ Baritone 开关」首行）：

| 项 | 开（默认） | 关 |
| --- | --- | --- |
| `freeLook` | `false` → 走路也走 CLIENT：视角由男中音每刻写向路径下一节点 | 还原原值（走路视角不动） |
| `randomLooking` | `0.0`（去掉每刻 ±0.005 度的随机偏移） | 还原原值 |
| `randomLooking113` | `0.0`（去掉每刻 ±1 度的随机摆动 = 抖） | 还原原值 |

### 为什么这样就不抖（写入者唯一性）

- 打开后走路与挖矿都是 CLIENT，可见视角的**唯一写入者**是男中音自己（`LookBehavior.onPlayerUpdate`）。
  上一轮「剧烈抖动」是**两个写入者**（模块的 `MiningViewFollow` + 男中音）互相覆盖，那一类已删除，
  本次也没有再加回任何模块侧写角度。
- 鼠标输入不会制造第二个写入者：原版每刻先把鼠标转向应用到角度，随后实体 tick 里男中音再写目标角度
  覆盖它——结果每帧只呈现男中音那一个值，不存在交替。
- 唯一需要让位的地方是战斗：战斗走位由 `MiningCombat` 自己发纯走路目标 + 自己转头盯怪。
  所以进出 `COMBAT` 时调用 `setCombatViewHold(...)`，战斗期间把 `freeLook` 放回原值
  （男中音走路转 SERVER 静默），退出战斗再交回——两边各管一段，不会同时写。
  （`MiningCombat#turnTowards` 上方那条「战斗期间男中音的移动朝向是 SERVER 静默模式」的注释，
  说的就是这件事。）

### 还原

- `freeLook / randomLooking / randomLooking113` 三项的原值在**第一次写入前**抓一次，
  模块关闭时 `restoreViewSettings()` 原样还回去（视角涉及玩家手感，不能像其它 Baritone 调优项那样留在原地）。
- 界面上把开关关掉时同样立即还原（且模块没开着就不碰男中音，只落盘，等下次启用时统一下发）。

### 副作用（必须知道）

开着时**鼠标不能自由转视角**：每刻被男中音的目标角度覆盖（表现为「鼠标推不动 / 被拉回」）。
挂机场景无影响；想自己看风景，把「寻路视角跟随」关掉即可。

## 4. 分段视角归属总表

| 状态 | 可见视角写入者 | 依据 |
| --- | --- | --- |
| 走路 / 寻路（`GO_WILD`、物流寻路、水中脱困寻路级） | 男中音（CLIENT） | 本轮 `freeLook=false` |
| 挖矿 / 破坏 / 放置 | 男中音（CLIENT） | `blockInteract=true` 分支 |
| 战斗 `COMBAT` | `MiningCombat#turnTowards` | 本轮 `setCombatViewHold(true)` 把男中音转回 SERVER 静默 |
| 物流开箱（`UNLOADING` / `SUPPLY`） | 状态机 `faceBlock` | 先 `baritone.stop()` 再写，男中音已无目标 |
| 挂机修复对准（`REPAIR`） | 状态机 `smoothRotateTo` | 同上 |
| 水中脱困破坏级 | 状态机 `faceBlock` | 同上（代码注释原有说明） |

## 6. 待实机验证项

1. 开启状态下自动挖矿时，走路阶段镜头跟着路径方向转（不再是原来那样「镜头一动不动只平移」）。
2. 全程无抖动：走路、挖掘、上下坡、转弯都不出现高频抖动或来回摆。
3. 战斗时镜头盯着怪转（由模块转），战斗结束回到寻路视角。
4. 关掉「寻路视角跟随」后立刻恢复原行为（鼠标可以自由转视角）。
5. 关闭模块后男中音的行视角设置被还原（可以在 Baritone 设置页里核对 `freeLook` 回到 true）。
