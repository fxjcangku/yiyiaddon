## 四、开发习惯.md

已创建：`D:/mcaddon/yiyiaddon/开发习惯.md`

定位：这是所有 AI 智能体开始 yiyiaddon 开发工作之前必须第一步读取的长期规则文件。未读取之前不得扫描代码、修改代码或开发新功能。

核心规则归纳（共 28 条，分七类）：

**一、代码分类与目录**
1. 代码必须按职责工整分类，目录必须容易理解、容易查找。
2. 禁止把大量不同职责代码挤在一个 Java 文件中。
3. 一个 Java 文件应有明确职责。
4. 复杂功能按真实职责拆分：功能入口、流程控制、状态机、任务、服务、数据模型、Minecraft 适配、配置。
5. 不机械拆分：简单功能保持简单，复杂功能才拆分。
6. 禁止把不知道放哪里的代码塞进 `utils`、`helper`、`common`、`manager`。
7. 不知道放哪里时，先查调用关系和实际职责再决定目录。
8. 可使用 `client/core/platform/service/modules/integration/ui/mixin/dev` 等分类，但必须依真实代码建立。
9. 不要为目录漂亮创建大量空包，不要提前猜模块。
10. 正式代码只能位于 `src/main/java`、`src/main/resources`；参考库不参与编译。

**二、语言与用户可见内容**
11. 用户可见内容统一中文：界面、设置、按钮、提示、状态、错误、开发报告。
12. Java 类名、API、包名、Identifier 等技术名称允许英文，禁止翻译代码标识符。
13. 用户可见内容禁止 Emoji。

**三、开发报告**
14. 报告必须中文，禁止 Emoji。
15. 报告必须带日期。
16. 报告统一放 `02-开发报告/`。
17. 文件名格式 `YYYY-MM-DD-第X阶段-报告名称.md`。
18. 报告必须写明新项目与旧项目的关系。

**四、验证标准**
19. 不允许把「编译通过」当成功能已验证，必须区分：代码完成 / 编译通过 / 客户端启动验证 / 实际功能验证 / 待真实环境验证。

**五、旧代码迁移**
20. 禁止凭 AI 记忆猜功能，必须查真实源码。
21. 不依赖人工模块列表与旧开发报告，必须自行分析真实旧源码，分清真实业务、公共代码、第三方框架代码、Minecraft API、第三方依赖、数据和资源。

**六、Minecraft 26.1.2 API**
22. 必须参考 `01-开发参考库/` 中的真实 Mojang 26.1.2 源码，禁止凭旧版本经验猜 API。
23. 禁止使用 Yarn 旧名。
24. 参考库查不到不等于不存在，必须继续在源码中搜索确认。

**七、版权与工作前置**
25. 当前阶段不投入版权、许可证、NOTICE、第三方版权报告整理，不因这些工作中断开发。
26. 不主动重构现有版权文件，发布相关事项以后再单独处理。
27. 所有智能体开始工作前必须先读 `开发习惯.md`。
28. 开发前先按 `01-开发参考库/README.md` 的查询顺序铁律查证，禁止跳步猜测。
