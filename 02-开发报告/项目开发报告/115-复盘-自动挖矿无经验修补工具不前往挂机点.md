# 115-复盘-自动挖矿无经验修补工具不前往挂机点

日期：2026-09-19
项目：yiyiaddon（新项目，Fabric 26.1.2 客户端模组）
旧项目对应物：`D:/mcaddon/26.1.2` 自动挖矿状态机的耐久检测分支（旧 `MiningStateMachine` 耐久优先级与 `tickRepair`）

---

## 一、用户需求（原话口径）

> 拿一把没有经验修补的镐子启动，稿子快没耐久了会传送回修复点吗？本来就没有经验修补，
> 过去也没有意义。检测到没有经验修补，就不用回去挂机修复点了，提示用户 xx 品质稿子没有经验修补，
> 不回去修复点并停机；如果背包还有其余稿子可继续。

经四问确认（用户 2026-09-19 选项答复）：

| 项 | 口径 |
| --- | --- |
| 停机 | 背包还有别的镐子就继续挖矿；没有别的镐子才停机 |
| 替补镐子 | 不要求带经验修补，只要能挖就算「可继续」 |
| 提示取值 | 物品全名（物品悬停名，如「下界合金镐」，含自定义重命名） |
| 非镐工具 | 剑 / 铲 / 斧 / 锄无经验修补时同样只提示，不再连带挖矿停机 |

## 二、改动前的实况（取证）

- 触发点：`MiningStateMachine` 优先级 2，原 `if (findDamagedToolSlot() != -1)` 分支。
- 修复对象扫描（`findDamagedToolSlot`）取「副手优先 → 背包 0~35」中剩余耐久最低、且低于阈值（默认 100）的
  镐 / 铲 / 斧 / 锄 / 剑。
- 命中后若 `!hasMending(damaged)`：`Baritone.stop()` + 关闭整个自动挖矿模块 + 报错
  「✗ 镐子无经验修补附魔 ▸ 无法自动修复，请换有经验修补的工具」。
- 结论：**原本就不会传送回挂机点**（已拦住），但与用户期望的差距有三处：
  1. 拦住的方式是无条件整体停机，不看背包里还有没有别的镐子；
  2. 提示只有类别名「镐子」，没有物品品质 / 全名；
  3. 一把没有经验修补的剑耐久低了，也会把挖矿模块整体干掉。

## 三、本次改动（逐处）

### 1. 触发分流：可修复的走挂机点，修不了的只提示

`src/main/java/com/yiyiaddon/feature/mining/fsm/MiningStateMachine.java:1044-1052`

- 2a：`findDamagedToolSlot(true)`（只认带经验修补的受损工具）→ 播报低耐久音效 + `transitionTo(REPAIR)`，
  传送与挂机逻辑一字未动。
- 2b：`handleUnrepairableTool()` → 低于阈值但没有经验修补的工具，不传送、不换槽，只提示。

改动前「最低耐久的受损工具没有经验修补就整体停机」的口径不再存在；同时修掉了
「无经验修补的剑 / 铲 / 斧 / 锄连带挖矿停机」。

### 2. 新增 `handleUnrepairableTool()`

`src/main/java/com/yiyiaddon/feature/mining/fsm/MiningStateMachine.java:2873-2935`

- 用 `findDamagedToolSlot(false)` 取最低耐久受损工具；2a 已返回 -1 才走到这里，故命中的必定修不了。
- 按「物品登记 ID + `@` + 槽位」记账（`noMendingNotifiedKey`，字段见 `:264-271`，`reset()` 见 `:571`），
  同一件工具只提示一次；背包里已无受损工具时解除记账，工具被修好 / 换走后再出现照样提示。
- 提示文案（用户可见，中文、无 Emoji）：
  - 非镐工具：`§e⚠ <物品全名> 没有经验修补 §8▸ 不回去挂机点修复，继续挖矿`
  - 镐子且有替补：`§e⚠ <物品全名> 没有经验修补 §8▸ 不回去挂机点修复，改用背包内其余镐子继续挖矿`
  - 镐子且无替补：`§c✗ <物品全名> 没有经验修补 §8▸ 不回去挂机点修复，背包已无其余镐子，自动挖矿已停止`
    （`Baritone.stop()` + 关闭模块）
- 物品全名取 `ItemStack#getHoverName()`，与启动报告「目标矿物」同一取值口径。

### 3. 新增 `hasOtherPickaxe(int excludeSlot)`

`src/main/java/com/yiyiaddon/feature/mining/fsm/MiningStateMachine.java:2937-2953`

- 判据只看「是不是镐子」（`endsWith("_pickaxe")`，与 `isPickaxe` 同源），不要求耐久、不要求经验修补；
  排除受损镐子自身所在槽位（`-2` = 副手）。
- 停机条件由此收窄为：**受损的是镐子 且 背包（含副手）没有别的镐子**。

### 4. `findDamagedToolSlot` / `findDamagedTool` 增加「是否要求经验修补」

`src/main/java/com/yiyiaddon/feature/mining/fsm/MiningStateMachine.java:2937-3002`

- `findDamagedToolSlot(boolean requireMending)`：`true` 只认带经验修补的（触发修复与换槽），
  `false` 也包含无经验修补的（「修不了」的提示扫描）；扫描主体逐字未动。
- 调用点同步：`tickRepair` 换槽由 `findDamagedToolSlot()` 改为 `findDamagedToolSlot(true)`
  （`:2681`，避免把修不了的工具换到副手）；REPAIR 态状态播报的 `findDamagedTool()` 内部同样取 `true`（`:2997`）。

### 5. 耐久预警扫描同步口径

`src/main/java/com/yiyiaddon/feature/mining/fsm/MiningStateMachine.java:2119-2150`

- 「剩余耐久 XX ▸ 即将触发修复流程」的预警只针对带经验修补的工具：无经验修补的工具根本不会触发修复流程，
  旧的预警文案对它们是假的。修不了的提示由 `handleUnrepairableTool` 唯一负责（同源判据只留一份）。

## 四、影响面

- 只动自动挖矿模块的耐久判定分支与其用户可见文案；`REPAIR` 态本身的传送、换槽、杀戮光环、超时保护逻辑未改。
- 无新增设置项、无新增指令、无落盘结构变更、无新增用户可见入口。
- 附带修正一处旧偏差：无经验修补的剑 / 铲 / 斧 / 锄不再连带停掉挖矿。
