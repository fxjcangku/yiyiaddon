## 3. 落盘结构

### 3.1 设置按服务器隔离（`config/module-state.json`，第 91 条口径不变）

```json
{
  "模块": {
    "mining": {
      "启用": false,
      "设置": { "...": "全局模板：同时是新服务器 / 新存档的初始值" },
      "服务器设置": {
        "server_520mc.cc_25565": { "...": "这台服务器自己的一套" },
        "singleplayer_新的世界 (1)": { "...": "这个单人存档自己的一套" }
      }
    }
  }
}
```

读取回落口径：**该键没有独立记录时取全局模板** → 升级不丢配置、新服继承最近用过的一套。
未进世界（主菜单）时 `settingsScope()` 返回 `null`，读写都落在全局模板上（不会写到
`singleplayer_unknown` 这种伪键上）。

### 3.2 配置记录（`config/yiyiaddon/mining/records/<文件名安全键>.json`）

```json
{
  "服务器键": "520mc.cc:25565",
  "保存时间": 1758123456789,
  "设置": { "...": "MiningSettings 全字段" },
  "点位": { "mineral": {"x":..,"y":..,"z":..,"dimension":"..","yaw":..,"pitch":..}, "food": {...}, "afk": {...} }
}
```

- `服务器键` 是逻辑键原文（多人 `host:port`、单人 `singleplayer:<存档目录名>`），列表与播报靠它辨认；
- 记录列表**由目录枚举而来**，因此「没点过保存」的服务器不会出现在列表里（用户第 4 条要求）；
- 删除只删文件，不动设置与点位；读取写入的是**当前**服务器 / 存档的设置桶与点位文件，记录文件不动。

## 5. 行为口径（实现细节，便于实机核对）

1. **一键保存当前配置**：写「本服那条」记录；本服已有记录时先弹二次确认（旧快照不可恢复），首次保存直接存。
2. **读取**（卡片按钮）：设置 + 点位整份替换；
   - 同服 / 同存档 → 直接执行；
   - 别的服务器 / 存档 → 先弹提示「与当前服务器不一致，点位坐标在本服多半不适用」，确认后才执行；
   - 模块运行中 → 拒绝并播报「请先关闭自动挖矿」（与「运行中不能改点位」同一条口径）。
3. **替换**：用当前配置（设置 + 点位）覆盖点中的那条记录，二次确认。
4. **详情**：只读窗摊开记录内容 —— 目标矿、食物白名单、保留白名单、搭路方块、三个阈值、
   五条指令（前往挖矿 / 返回卸货 / 前往补给 / 前往修复 / 死亡返回）、三个点位坐标与维度。
5. **删除**：二次确认，只删记录文件。
6. **回执**（走模块统一出口，受「状态播报」开关与折叠约束）：
   - `§a✓ 已保存本服配置 §8▸ 设置 + N 个点位 §8· §7MM-dd HH:mm`
   - `§a✓ 已读取配置 §8▸ <识别名> §8· §7设置 + N 个点位 §8· §7保存于 MM-dd HH:mm`
   - `§a✓ 已用当前配置替换记录 §8▸ <识别名> §8· §7设置 + N 个点位`
   - `§a✓ 已删除记录 §8▸ <识别名>`
   - 异常：`§e⚠ 未进入世界 …` / `§e⚠ 模块运行中 …` / `§c✗ 配置保存失败 …`

## 8. 入口位置的两次更正（教训：不要把「控制台」当成「控制台窗口」）

用户的「控制台按钮」指**模块页上那个写着「打开控制台」的按钮**，不是控制台窗口底部的按钮行。两次返工都出在这个理解上：

| 版本 | 做法 | 用户反馈 | 结论 |
| --- | --- | --- | --- |
| v1 | 控制台**共享页脚**加「状态行 + 保存本服记录 / 复原本服记录」两行 | 「你弄去每个页面干嘛」 | 共享页脚 = 六个页签各一份，**否掉** |
| v2 | 控制台共享页脚改成**一个** `服务器记录复原` 按钮 | 「按钮在哪里 你瞎吗？」（截图是模块页） | 位置仍在控制台里，**否掉** |
| v3（当前） | **模块页**「打开控制台」正下方加 `服务器记录复原` 按钮；控制台页脚还原成只有「刷新 / 关闭」 | 待用户实机确认 | — |

## 9. 跨服读写都卡死（用户 2026-09-18 两轮裁定）

| 版本 | 跨服的行为 | 用户反馈 | 结论 |
| --- | --- | --- | --- |
| v1 | **读**：弹提示 → 确认后覆盖；**写（替换）**：不限本服，可推到任意一条 | 「我在别的服务器能读取 别的服务器？」 | 读方向太松，**否掉** |
| v2 | 读方向卡死；写方向仍不限本服 | 「还是能互相保存 根本没有识别服务器ip 拦截」 | 写方向也**否掉** |
| v3（当前） | **读 / 写都只认本服**：记录键与当前服务器 / 单人存档不一致时，「读取」与「替换」一律只弹提示、不动任何数据 | — | 采用 |

v2 的实机证据（客户端日志，00:24-00:25）：

```
00:24:21 [CHAT] ✓ 已用当前配置替换记录 ▸ long.kkwmc.cn:25565   （连点 3 次）
00:25:18 [CHAT] ✓ 已用当前配置替换记录 ▸ rubiksmp.net:25565
00:25:25 [CHAT] ✓ 已保存本服配置
```

即在 A 服点 B 记录的「替换」→ B 的记录被 A 的配置盖掉，记录互串。

落地位置四处（界面 + 逻辑层各两道）：

- 界面 `MiningRecordScreen#read` / `#confirmReplace`：`sameScopeAs` 不成立时弹
  `noticeInPlace("不能复原/替换：不是本服的记录", …)`，提示里写出「这条记录属于哪个服 / 当前是哪个服 /
  为什么不允许（跨服点位不适用 / 会把配置盖到别的服）」。
- 逻辑层 `AutoMinerModule#restoreRecord` / `#replaceRecord`：`!sameScopeAs(record)` 直接拒绝并播报
  `⚠ 不可复原 / 不可替换 ▸ 这条记录属于 X，与本服不一致`（不依赖界面调用路径）。
- 列表呈现：非本服那条的「读取 / 替换」压灰（`§7读取` / `§8替换`）；底部说明行写明
  「读取 / 替换 = 只认 ✓ 本服 的记录（IP / 存档一致）」。
- 播报带上服务器键：`✓ 已保存本服配置 ▸ rubiksmp.net:25565 · 设置 + 3 个点位 · 时间`
  （用户反馈「根本没有识别服务器ip」，单说「本服」看不出写到了哪一台）。

**删除仍不限本服**：它只删记录文件，不会把配置搬到别处；异服记录要清理时还得能删（若用户要求也一并卡死，改一处即可）。

## 10. 两个实机踩坑（都已解决，留作教训）

- **「详情」按钮看起来点不动**：客户端日志里是
  `NoClassDefFoundError: com/yiyiaddon/feature/mining/ui/console/MiningConfigDigest` ——
  点击真的执行了，是在 `showDetails` 里加载那次新加的类时失败（那个客户端进程的 classpath 上没有这个新类），
  于是没有任何界面反应。**新增类之后必须完整重启 dev 客户端**（本轮已重启；另附磁盘核验：
  `build/classes/java/main/.../MiningConfigDigest.class` 与 `build/libs/*.jar` 内均有该条目）。
- **聊天播报后面带 `(x2)`**：项目自带折叠规则（同内容 5 秒内只印一条 + 标次数），
  代码里每步只播一次，所以那是玩家连点两次的结果，不是重复触发。
