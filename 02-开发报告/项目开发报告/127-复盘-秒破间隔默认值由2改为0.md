# 127-复盘-秒破间隔默认值由 2 改为 0

日期：2026-09-19
项目：yiyiaddon（新项目，Fabric 26.1.2 客户端模组）
旧项目对应物：`IntSetting`「秒破间隔（tick）」默认 `2`（旧 `:445-452`，迁移记录见附录 B 第 28 项）
用户原话：「改成0默认」
落点：`feature/mining/config/MiningSettings.java`（+ 控制台文案 `ui/console/MiningBaritonePage.java`）

---

## 一、背景：这个「间隔」在流水线之后换了含义

118 号之后秒破控制器改成流水线（`nextStartTick` 与「等服务端确认方块变化」解耦），
`breakInterval` 的实际含义从「等确认」变成「**两块之间的最小间隔**」：

```java
nextStartTick = player.tickCount + Math.max(PIPELINE_MIN_GAP_TICKS, module.getBreakInterval());
//                                                        ↑ 常量 1，模块强制保留的 1 刻保险
```

所以 **0 与 1 完全等价**（都被 `max` 抬到 1），而旧项目的默认值 `2` 等于**每块白等 1 刻**：

| 每块服务端最少刻数 r | 间隔 2 | 间隔 0 | 损失 |
| --- | --- | --- | --- |
| 4（深板岩 + 好镐） | 6 刻/块 | 5 刻/块 | 约 17% |
| 2 | 4 刻/块 | 3 刻/块 | 约 25% |
| 1（效率 + 急迫） | 3 刻/块 | 2 刻/块 | 约 33% |

63 号复盘当时记过「默认值未改（用户裁定只做流水线）：想要最快，去控制台把「秒破间隔」设为 0」——
本次用户裁定直接把默认值改掉，不再要求手动设置。

## 二、改动

| 位置 | 改动 |
| --- | --- |
| `MiningSettings#breakInterval` | `2` → **`0`**；javadoc 补上「0 与 1 等价（模块强制留 1 刻保险）」与本次改默认值的理由 |
| `MiningBaritonePage`「秒破间隔（tick）」行说明 | 改为「默认 0 已是最快（0/1 等价，模块仍强制留 1 刻保险），设大一点可降低被服务端/反作弊盯上的概率」 |
| 「恢复默认」按钮 | 走 `DEFAULTS.breakInterval`，自动跟随新默认值，无需改动 |

**没动**：取值域仍是 `0~20`（`intBox(0, 20, ...)`），所以「调大降风险」这条老用法还在。

## 三、生效范围

查过存档 `run/config/yiyiaddon.json` —— **里面没有 `breakInterval` 这个键**，
`MiningSettings#load` 走 `intOf(json, "breakInterval", breakInterval)` 时会取字段默认值，
所以新默认值**当场生效**，不需要用户去控制台手动改。

（若某台存档里已经有这个键，则尊重存档值：那是用户显式设过的，不该被默认值覆盖。）

## 四、验收

`.\gradlew.bat build --console=plain` → BUILD SUCCESSFUL。实机：挖矿 / 连锁 / 找矿整体提速，
按每块服务端最少 4 刻计约 17~25%；长时间挂机若出现「方块被服务端回滚」（反作弊介入迹象），
把「秒破间隔」调到 2~4 即可（原有退路不变）。
