### 3.2 方块扫描：区块轮转 + `maybeHas` 预筛（关键性能决策）

**API 查证（第 159 / 207 条，工具 `01-开发参考库/工具/查JARAPI.js`，2026-09-18 实跑）**：

```
net.minecraft.world.level.chunk.LevelChunkSection
  public boolean maybeHas(java.util.function.Predicate<BlockState>);   ← 存在
  public boolean hasOnlyAir();                                        ← 存在
  public BlockState getBlockState(int,int,int);                       ← 存在
```

原版 `maybeHas` 的语义是「调色板（palette）里是否存在满足谓词的方块」——**不含目标方块的地段一次谓词就否掉，不用逐格查**。原版自己就用它做实体 AI 的 `BlockTags.WOOL` 预筛，因此稳定。

方案：

| 步 | 做法 |
| --- | --- |
| 1 | 每 tick 轮转处理 `CHUNKS_PER_TICK`（4）个区块，覆盖以玩家为中心、`范围` 半径内的全部区块；一轮走完（默认半径 64 → 9×9 = 81 区块 → 21 tick ≈ 1 秒；上限 128 → 17×17 = 289 区块 → 73 tick ≈ 3.6 秒） |
| 2 | 每个区块：`level.getChunkSource().getChunk(cx, cz, ChunkStatus.FULL, false)` 取区块（**不能用 `Level#getChunk`**，`WardenWarningGuard:178-181` 已踩过坑）；null 则跳过 |
| 3 | 遍历竖向 `LevelChunkSection`，只处理段中心与玩家竖直距离 ≤ `VERTICAL_REACH`（固定 64）的段；先 `hasOnlyAir()` 跳过空段，再 `maybeHas(state -> 目标集合.contains(state.getBlock()))` 预筛 |
| 4 | 只有**预筛命中**的段才逐格 `getBlockState` 枚举 16³；命中目标、且**水平距离 ≤ 范围、竖直偏移 ≤ 64** → 记入该区块的结果集 |
| 5 | 结果按区块键缓存（`Map<Long, List<BlockPos>>`）：重扫某区块时整体替换该区块条目，不整表清空 —— 玩家移动 / 重扫时不会出现「框整片闪一下」 |
| 6 | 区块卸载（`chunk == null`）→ 移除该键；目标名单变化 → 清空全部缓存并立即重扫一轮 |

对比「立方体游标 + 512 格/刻」方案（`ContainerScanner:78-114` / `WaterESPModule:214-276`）：半径 32 的立方体是 274,625 格，512 格/刻 = **536 刻 ≈ 27 秒一轮**，对「走动时要持续看到目标」的场景太慢。区块 + `maybeHas` 方案在同一半径下一轮只有约 25 区块 × 24 段 = 600 次预筛，**每 tick 4 个区块即可 7 tick 一轮**，且成本与「世界里有没有目标方块」正相关。

**范围口径：圆柱，不是球（用户 2026-09-18 追加：「默认范围远点 我要看见底下的方块」）。**

球口径会把脚下的目标一并筛掉（竖直距离吃掉半径），挖矿时「站在地表看不到下面 40 格的矿」；因此：

| 维度 | 口径 |
| --- | --- |
| 水平 | 玩家所在 XZ 平面上的实心圆，半径 = 设置的 `范围` |
| 竖直 | 固定 `VERTICAL_REACH = 64`（玩家 y ± 64，不给设置项，避免设置项膨胀）；地表往下 64 格足以覆盖常规矿层，往上 64 格覆盖悬空建筑与高空目标 |
| 代价 | 竖直范围独立后，同一水平半径下要多遍历若干段 —— 由 `maybeHas` 预筛与「只处理 ±64 内段」兜住，见 §3.5 |

### 3.3 实体扫描

- 遍历口径用既有 `level.entitiesForRendering()`（`EspTestModule:183`、`TargetScanner:86` 同源）；
- 白名单匹配：登记 ID（`BuiltInRegistries.ENTITY_TYPE.getKey(type).toString()`）与设置里的名单比对，**名单为空 = 该模式不画**（不默认全选，避免一开就满屏）；
- 距离裁剪用**水平距离**（`dx² + dz² ≤ 范围²`，与方块模式同口径的圆柱，竖直同样不裁）；照 `AdminThreatRenderer:70` 的写法但去掉竖直分量 —— 这样脚下的怪物 / 掉落物与头顶的目标都看得见，对应用户 2026-09-18 的「要看见底下的实体」；
- 垂直方向**不做裁剪**：`entitiesForRendering()` 本身只含已加载区块中的实体，数量有限（同一半径下通常几十个），无需再按 y 过滤；
- 排除自己：`entity == mc.player` 跳过（全局 `hideSelf` 只覆盖第一/第三人称的全模块行为，本模块仍显式跳过自己）。

### 3.4 渲染

| 项 | 实现 |
| --- | --- |
| 方块框 | `renderer.blockBox(x, y, z, sideArgb, lineArgb, mode, thickness)`（第 160 条：先填充色后描边色） |
| 实体框 | `renderer.box(entity.getBoundingBox(), sideArgb, lineArgb, mode, thickness)`（首选 `Lines`，避免填充糊住模型，`AdminThreatRenderer:74-75` 同口径） |
| 射线 | `renderer.tracer(center, color, thickness)` —— 起点为屏幕底部中心，与 `AdminThreatRenderer:78` 完全一致 |
| 样式（线框 / 面 / 两者） | `ShapeMode` + `SettingCycle(ShapeMode.labels())`，文案逐字 `线框 / 面 / 两者`（第 143 条） |
| 颜色 | `EspColor` + `SettingColorPicker` + 调色板 `ColorPickerScreen`（第 146 / 150 / 151 / 152 条），默认值取 `ColorPresets` 预设索引，**不写 RGB 字面量** |
| 透视 | 默认即透视（`occlusion` 默认 false → `setAlwaysOnTop`，第 149 条）；本模块**不新增遮挡开关**（用户未要求，第 163 条不擅自加） |
| 全局口径 | 线宽倍率 / 不透明度 / 最远距离 / 每帧图元预算全部由 `EspGlobalSettings` 统一乘，模块不另建第二套 |

### 3.5 性能预算（必须如实写清）

| 项 | 量 |
| --- | --- |
| 方块扫描（默认半径 64、竖直 ±64） | 每 tick 4 区块的段级预筛（`hasOnlyAir` + `maybeHas`），一轮 81 区块 / 21 tick ≈ 1 秒；**只有含目标方块的段才逐格枚举**，世界里没有目标方块时接近零成本 |
| 目标数防护 | 若目标方块是常见方块（如石头）导致命中数爆炸，结果集按水平距离保留最近 `MAX_TARGETS`（2048）个；概览页显示「已显示 M / 共 N」，超限不静默截断 |
| 实体遍历 | 每帧一次 `entitiesForRendering()` + 白名单过滤 + 水平距离平方比较；无遮挡射线时无额外成本，实体数量天然有界 |
| 每帧图元 | 上限受 `EspGlobalSettings.primitiveBudget()` 兜底；本模块在渲染前按距离截断，不把无上限集合丢给渲染层（第 149 条性能口径） |
| 已知代价 | 线宽是屏幕像素常量、填充面之间不做深度排序（第 147 条的三条代价照旧，本模块不改路线） |

## 9. 下一阶段开发规划

### 一、下一阶段目标

按本节拍板结论落盘阶段16「透视」模块（方块 + 实体两模式、一个控制台），编译与静态审计通过后交实机验收。

### 二、执行原因

本模块是用户点名的新增功能，全部依赖（世界渲染基建、控制台构件、选择器、颜色体系、全局总闸）在本项目都已存在且被 8 个模块验证过用法，属于「低新增基建、高复用」的一批；先做它也因为它反过来能验证基建的通用性（尤其 §3.2 的区块 `maybeHas` 扫描路线）。

### 三、前置条件检查

- 已完成：世界渲染基建（`ui/render/world/` 全套）、控制台构件（`ui/console/`）、选择器（`SelectorScreen`）、颜色体系（`ColorPresets` / `EspColor` / `ColorPickerScreen`）、ESP 全局总闸（`EspGlobalSettings`）；

- 需先确认（实现前逐条落实）：D-16-01 ~ D-16-10 的拍板结论；实体候选表复用方式（D-16-06）；图标字形验真（D-16-03）。
