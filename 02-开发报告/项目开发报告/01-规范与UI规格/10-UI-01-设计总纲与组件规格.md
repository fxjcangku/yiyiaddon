## 四、设计语言

### 4.1 视觉基调

深色玻璃拟态：世界画面经原版模糊后透出，面板以近黑色半透明底板叠加，卡片靠**明度差 + 高光内描边**分层，不使用彩色渐变。

模糊开关受 `AddonConfig.panelBlur` 控制；开启时 `panelBackgroundAlpha` 把面板透明度乘 `0.46` 以透出模糊背景。

### 4.2 圆角与高度层级

| 层级 | 圆角 | 说明 |
| --- | --- | --- |
| 窗口 | 22 | 最外层面板 |
| 模块 / 卡片 | 16 | 主卡片 |
| 子模块 / 区块 | 12 | 折叠区、次级表面 |
| 行 / 控件 | 6 ~ 8 | 按钮、输入框 |
| 徽标 / 标签 | 4 ~ 6 | 状态、键位 |

高度层级固定：窗口底 → 内容面 → 卡片 → 次级表面，逐层提亮。禁止用描边颜色区分层级（描边只用于 1px 细边与玻璃高光）。

### 4.3 字号

| 用途 | 字号 | 字体 |
| --- | --- | --- |
| 主文字 / 数值 | 11 ~ 12 | `harmony` |
| 控件内文字 | 10 ~ 11 | `harmony` |
| 区块标题 | 12 ~ 13 加粗 | `harmony_bold` |
| 次要与说明 | 10 | `harmony` |
| 图标 | 按尺寸 | `icon` / `material_symbols` |

所有文字走 `FontRenderer`，不得直接构造字体对象。

### 4.4 三态交互

每个可交互元素必须有三态，取值来自 `ClickGuiThemeColors`：

| 态 | 取色 | 附加表现 |
| --- | --- | --- |
| 常态 | 基础色槽 | — |
| 悬停 | `surfaceHover` / `hoverBackground` | 底色提亮，`HOVER_SETTLE = 0.16s` 平滑过渡 |
| 按下 | 在悬停基础上加深 | `PressState` 缩放到 `0.97`，回弹用 `easeOutBack` |

危险操作（删除、清空、重置）悬停用 `dangerHoverBackground` / `dangerHoverText`。

### 4.5 动效

| 场景 | 实现 |
| --- | --- |
| 按压回弹 | `PressState`（按下 0.09s，回弹 0.26s，深度 0.03） |
| 折叠展开 | `Spring` + `Easing` |
| 滚动 | `ScrollTracker` 平滑跟随，滚轮步长 16 |
| 页面切换 | `PageRouter` 栈式导航，无横向位移 |

禁止为每个控件自造动画参数；一律复用 `ui/anim` 下的现成实现。

### 5.2 待补齐（4 项缺口）

| # | 组件 | 规格 |
| --- | --- | --- |
| 1 | **物品图标渲染** `ItemIconCache` | 离屏 FBO 渲染原版物品 → `Image.adoptGLTextureFrom` → 按 `(物品ID, 尺寸)` 缓存 → `canvas.drawImageRect` 贴图。支持 16 / 32 / 64 三档；资源缺失时显示占位符（不得渲染黑紫）。**其余 3 项均可先做，此项为带图标选择器的前置。** |
| 2 | **列表行** `ListRow` | 行高 ≥ 32；结构 `[前缀标签] [名称] [技术ID] [状态] [右侧操作按钮组]`；支持行内 1~2 个操作按钮；配合分页（每页条数由业务定，ID 清单为 20）；悬停高亮用 `surfaceHover` |
| 3 | **双栏多选选择器页** `SelectorPage` | 顶部搜索框（初始聚焦）；左右两栏等宽，中间竖分隔线；左栏「可添加」按语义分组，右栏「已选择」；每行右侧 `+` / `-`，点击即生效并重建列表；两栏空态各有占位文案。业务差异（图标列、状态列、副列）通过列定义注入 |
| 4 | **二次确认窗口**（原计划 `ConfirmOverlay` 遮罩层） | **已改为独立窗口 `ui/screen/ConfirmPanelScreen`**：旧项目的确认窗本身就是独立窗口，遮罩层方案作废（见铁律第 131 / 136 条）。多行正文逐行原样渲染；两个等宽按钮（确认 / 取消），确认按钮 danger 变体；关闭后回游戏。文案照旧项目《UI 资产模板》第 4.3 节 |

### 5.3 控件统一要求

1. 控件只负责取值与绘制，不承载业务判断。
2. 每个控件必须实现 `getWidth()` / `getHeight()` / `draw()` / `update()`，需要交互的实现 `onClick()` / `onDrag()`。
3. 带动画或按压的要正确实现 `isAnimating()`，避免无谓重绘。
4. 数值控件参数按第 124 条：范围必须覆盖全部合法取值，整数步进 1，比例取最小可感知增量，单位写进格式串。

## 六、页面结构规范

### 6.1 导航链路

```
主界面（左侧导航：首页 / 模块 / 界面 / 设置）
  ↓ 「模块」页
模块中心（分类卡片网格，每行 3 个）
  ↓ 点分类
模块列表（模块卡片网格，每行 2 个，含状态与键位）
  ↓ 点模块
模块配置页（独立屏 ModuleScreen）
```

- 分类页面内导航走 `PageRouter.open / back`（界面内下钻），不脱离主界面。
- 模块配置页走 `ModuleScreen`（独立窗口），因为它需要更大的内容区与独立返回键。
- 需要脱离主界面看一次的临时信息（如识别结果），也走 `ModuleScreen` 形态。

### 6.2 模块配置页固定结构

```
[返回键 28×28]              [模块标题 + 状态条 ModuleStatusBar，高 46]
────────────────────────────────────────────────
核心行区（CompactRow，行高 36，区块间距 14）
  · 状态行 / 关键指标 / 主操作按钮
────────────────────────────────────────────────
底部键值区（KeyValueRow，行高 48）
  · 汇总数据、路径、目标数量等只读信息
────────────────────────────────────────────────
折叠区（CollapsibleSection，头部 36）
  · 高级设置、说明章节
```

顺序要求：**先状态与主操作，再只读数据，最后高级设置**。危险操作按钮必须单独用分隔线与其余按钮隔开。

### 6.3 模块页内容由模块职责决定

页面内容写在模块包内的 `ui/` 目录，与业务同包；`com.yiyiaddon.ui` 只放跨模块共用的界面基础设施。

| 模块 | 页面需承载 |
| --- | --- |
| ID识别 | 识别模式选择、当前模式、识别按钮（物品 / 准星方块）、方块语义调试 |
| ID配置管理 | 识别按钮组、刷新、汇总、搜索、类型筛选、方块状态筛选、分页清单、逐条删除、更多管理入口、数据清理入口、打开目录 |
| 其它模块 | 按各自职责确定，不预先规定模板 |

### 6.4 ID 三件套页面关系

```
ID识别（模块页）
    └─ 识别结果屏 ×3（物品 / 方块 / 实体）——独立窗口，看一眼即走
          └─ 按钮：复制 / 保存 / 另存快照 / 添加到 ID 配置

ID配置管理（模块页）
    ├─ 清单区（搜索 + 筛选 + 分页 + 逐条删除）
    └─ 「更多管理」→ ID 更多管理
                         ├─ 手动添加物品 ID → 添加物品（表单屏）
                         ├─ 打开物品 ID 目录   → AutoChest/items/
                         ├─ 打开实体 ID 目录   → AutoChest/entities/
                         ├─ 打开方块目录       → AutoChest/blocks/
                         ├─ 打开 ID 总目录     → AutoChest/
                         └─ 数据清理 → ID 数据清理（6 项清空 + 最高危险项）
```

打开目录统一实现：独立守护线程 + AWT `Desktop.open`，失败回落 `explorer.exe /select,`；目录不存在时先创建；失败经主线程报错。

## 七、按钮文案与点击作用

**逐字照《旧项目 UI 资产模板》执行**，本报告不重复抄录清单，只声明三条执行要求：

1. 文案含 `§` 颜色码一并照搬，不得增删颜色码。
2. 按钮的**点击作用**必须与旧项目一致，不得因为新架构换一种做法。

旧项目不存在的新界面按钮，按第十七章规范新写，并在报告中登记为「新增」。

## 九、禁止事项

1. 禁止引入任何旧框架代码、图标资源或设置系统。
2. 禁止新增或修改主题调色板与主题名。
