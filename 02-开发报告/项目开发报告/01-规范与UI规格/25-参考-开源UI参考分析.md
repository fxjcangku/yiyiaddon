# 25 · 参考 · 开源 UI 参考分析

> 口径与阅读顺序见 `00-AI阅读指引.md` 与 `01-总纲-迁移口径与复刻原则.md`。本文件为复刻依据，用户可见文本一律以本文件所载旧项目原文为准。


## 一、调研目的

在开发 yiyiaddon 模块中心 UI 之前，检索并分析 GitHub 等平台上的开源现代化 UI 项目，
为「模块中心 + 分类列表 + 模块卡片 + 模块页面」这套界面寻找可借鉴的设计理念、组件结构与交互方式。

参考方向：苹果系统风格、macOS 设置风格、iOS 控制中心风格、毛玻璃、半透明界面、
圆角卡片、模块列表、设置页面。

## 二、检索方式与筛选标准

使用关键词组合检索（macOS settings style UI library、glassmorphism component library、
Minecraft Fabric modern clickgui、open source design system tokens 等），
筛选标准按需求优先级排序：

1. 开源且有明确许可证声明；
2. 有完整源码与目录结构可查；
3. 与「macOS 设置 / iOS 控制中心 / 毛玻璃卡片 / 模块分类」任一方向直接相关；
4. 与 Minecraft 客户端 UI 有可迁移性。

**合规边界：全部项目只参考设计理念、组件结构、交互方式与视觉参数，不复制任何源码。**
yiyiaddon 使用 Skija（Skia）直接绘制，不存在可直接复用的 Web/Flutter/Swift 组件。

## 四、逐项分析

### 1. ModernUI-MC

- **GitHub**：github.com/BloCamLimb/ModernUI-MC
- **技术**：Java，Minecraft Mod（Forge / NeoForge / Fabric 多加载器），基于 ModernUI 桌面框架，LGPL-3.0。
- **UI 特点**：把桌面级文本排版引擎（TrueType/OpenType、Unicode 16、双向文本、SDF 渲染）移植进
  Minecraft；提供 GUI 组件与背景高斯模糊、平滑滚动、文本框撤销重做。
- **可参考部分**：
  - 「文本排版与字形渲染独立于游戏原版字体系统」的分层思路 —— yiyiaddon 已有 FontRenderer 与
    Material Symbols 图标字体，属于同一路线的简化版。
  - 「屏幕背景高斯模糊」作为可开关能力，与本项目 `AddonConfig.panelBlur` + SkiaBlurRenderer 一致，
    说明该做法在 Minecraft 环境里是被验证过的。
  - 以 JAR 形式自带框架、不要求使用者配置，与本项目「自包含客户端 Mod」的发布形态相同。
- **不适合直接使用部分**：LGPL-3.0 且是完整 mod 框架，引入即产生许可证传染与依赖冲突；
  其文本引擎规模远超当前需求，替换成本高于收益。
- **迁移到 Minecraft UI 的方式**：只借鉴「渲染层独立、背景模糊可开关、组件自包含」三条结构原则，
  不引入其代码与依赖。当前 yiyiaddon 的 Skija 直绘 + FontRenderer 已经覆盖所需能力。

### 2. Atlas Client

- **地址**：modrinth.com/mod/atlasclient
- **技术**：Java，Fabric 客户端 Mod，MIT，支持 Minecraft 26.1.2。
- **UI 特点**：宣称「全菜单与 HUD 共用一套统一设计系统」，可调项包括强调色、菜单/卡片不透明度、
  模糊强度、圆角大小、卡片辉光、动画、字体、主题预设；模块按分类组织并配可拖拽 HUD 编辑器。
- **可参考部分**：
  - **统一设计系统**：颜色、透明度、圆角、模糊、动画全部走同一组可调参数，而不是每个页面各写一套。
    这正是 yiyiaddon `ClickGuiThemePalette`（9 个核心色 → 派生全部色槽）在做的事，方向一致。
  - **模块分类 + 模块卡片 + 模块独立配置**的三级结构，与本任务的模块中心层级完全对应。
  - 「主题预设 + 用户可调参数」双层模型：预设给默认值，参数给自由度。
- **不适合直接使用部分**：MIT 但为完整客户端项目，包含战斗、社交、皮肤、后端等大量与 yiyiaddon
  无关的子系统；其 UI 为原版 GUI 体系绘制，与 yiyiaddon 的 Skija 直绘管线不通用。
- **迁移到 Minecraft UI 的方式**：采纳其**信息架构**（分类 → 模块列表 → 模块页面）与
  **可调外观参数清单**；绘制仍用 yiyiaddon 自己的 Skija 组件层。

### 3. GlassKit

- **GitHub**：github.com/JUNGHERZ/GlassKit（npm：@jungherz-de/glasskit）
- **技术**：CSS + Web Components，无构建步骤，token 驱动。
- **许可证说明**：本次检索到的是其 CHANGELOG 与 npm 页面，未直接读到 LICENSE 原文，
  **使用前需自行核对**；此处仅参考设计模式。
- **UI 特点**：所有颜色、边框、阴影、焦点环由 CSS 自定义属性派生；文档中专门讨论了
  「焦点环必须跟随主色，而不是写死琥珀色」这类 token 派生问题。
- **可参考部分**：
  - **派生式 token**：只声明少量主色，其余颜色（悬停、边框、焦点、阴影）由主色混合派生。
    yiyiaddon 的 `ClickGuiThemeColors.of(theme)` 已经是这个模型，本次继续沿用，不新增并行体系。
  - **单一主色换肤**：改名只需改两个变量。对应到本项目就是「换主题只改调色板 9 个色」。
  - **状态必须成组定义**：默认 / 悬停 / 按下 / 焦点 / 禁用，不能只定义默认态。
- **不适合直接使用部分**：Web 技术栈，CSS 变量、`color-mix()`、`::slotted()` 等机制在 Skija 中不存在。
- **迁移到 Minecraft UI 的方式**：把「token 派生」落到 `ClickGuiThemeColors`，
  把「状态成组定义」落到卡片组件的 hover 参数（本任务中 CategoryCard / ModuleCard 均带 hover 强度入参）。

### 4. darwin-ui

- **地址**：npmjs.com/package/@pikoloo/darwin-ui
- **技术**：React + Tailwind + shadcn 风格，MIT。
- **UI 特点**：macOS 风格深色主题组件库，以毛玻璃质感为核心视觉；
  自带完整深色主题而非仅提供中性色。
- **可参考部分**：
  - 深色模式下「窗口底色 / 侧栏 / 卡片 / 次级卡片」四层明度差，是营造毛玻璃层次的关键。
  - 卡片与背景之间保持固定明度差，而不是靠边框区分。
- **不适合直接使用部分**：React 组件，无法用于 Java；其 Tailwind 类名体系对本项目无意义。
- **迁移到 Minecraft UI 的方式**：映射到 `ClickGuiThemePalette` 的
  window / sidebar / content / module / subModule 五层底色；
  本任务新增的卡片统一取 `tc.module`，悬停叠加 `tc.hoverBackground`，保持与既有 SettingModule 一致的层次。

### 5. glassmorphic_ui_kit

- **地址**：pub.dev/packages/glassmorphic_ui_kit（GitHub 同源），MIT。
- **技术**：Flutter，基于 Skia 渲染引擎。
- **UI 特点**：组件命名与职责划分清晰 ——
  `GlassContainer`（基础玻璃容器）、`GlassCard`（毛玻璃卡片）、`GlassButton`、
  `GlassNavigationBar`、`GlassNavigationRail`、`GlassTabBar`、`GlassDialog`、`GlassBottomSheet`。
  可调项为 blur 强度、opacity、圆角、渐变叠加。
- **可参考部分**：
  - **基础容器 + 具体卡片分层**：先有 `GlassContainer`，再由 `GlassCard` 等具体组件组合它。
    本任务的 `GlassPanel`（底板）与 `CategoryCard` / `ModuleCard`（内容卡片）即采用同一分工。
  - **组件参数显式化**：blur、opacity、radius、gradient 是入参而不是写死。
  - 同为 Skia 渲染，其「模糊 + 半透明 + 描边」三件套在技术上是可平移的。
- **不适合直接使用部分**：Dart/Flutter 代码不可用；其渐变与动画系统依赖 Flutter 的合成管线。
- **迁移到 Minecraft UI 的方式**：照搬组件职责切分（容器 / 卡片 / 徽章 / 导航），
  绘制实现用 Skija 的 `drawRRect` + `Paint`（本项目已有同款封装）。

### 6. liquid-glass-react

- **GitHub**：github.com/aberhamm/liquid-glass-react，LICENSE 为 MIT（已读到原文）。
- **技术**：React / TypeScript，SVG displacement map 模拟折射。
- **UI 特点**：苹果 Liquid Glass 的「折射」质感 —— 元素边缘对背后内容产生位移与色散，
  而不是简单模糊；文档明确指出原生 `UIGlassEffect` 才具备真正的折射，Web 只能逼近。
- **可参考部分**：
  - **分清「模糊」与「折射」**：真正的液态玻璃依赖对背景的采样与位移，
    Web/Canvas 方案只能做模糊 + 高光描边。这条结论直接决定了本项目不追求折射。
  - **高光描边**：顶部 1px 白色低透明度描边 + 底部阴影是玻璃卡片廉价而有效的替代。
- **不适合直接使用部分**：SVG 滤镜与 DOM 位移机制在 Minecraft 中不存在；
  其折射效果在低分辨率游戏画面上收益极低、开销极高。
- **迁移到 Minecraft UI 的方式**：采用「模糊 + tint + 1px 高光描边 + 圆角」四件套，
  放弃折射；复用项目已有的 `SkiaBlurRenderer`。

### 7. react-glass-ui

- **地址**：npmjs.com/package/react-glass-ui，MIT。
- **技术**：React + SVG Filter。
- **UI 特点**：把玻璃质感拆成折射、模糊、色散三层，各自可独立调节。
- **可参考部分**：**分层可调**的思路 —— 把「毛玻璃」拆成若干正交参数，
  而不是一个整体开关。对应本项目即：模糊开关、模糊强度、底色透明度三者独立
  （`AddonConfig.panelBlur` / `blurStrength` / `blurTint`，已在界面设置页体现）。
- **不适合直接使用部分**：实现依赖 SVG 滤镜，与 Skija 无关。
- **迁移到 Minecraft UI 的方式**：保持现有三个独立参数，不合并成一个「玻璃效果」开关。

### 8. glassmorphism 设计规范（awesome-design-skills）

- **GitHub**：github.com/bergside/awesome-design-skills，`skills/glassmorphism/SKILL.md`，MIT。
- **技术**：Markdown 设计规范（面向设计系统编写）。
- **UI 特点**：给出玻璃风格的可执行约束 —— 语义 token 优先、视觉层次必须保持、
  交互状态必须显式、避免低对比度文字、避免无意义装饰动效、避免混用多种视觉隐喻。
- **可参考部分**：
  - **「避免低对比度文字」**：毛玻璃叠加半透明背景后文字对比度最容易失守。
    本项目所有卡片文字必须取 `tc.primaryText` / `tc.secondaryText`，不允许自造灰度。
  - **「避免无意义装饰动效」**：动效只用于状态过渡（悬停、展开、滚动），不做常驻闪烁。
  - **「保持视觉层次」**：同一屏内卡片不宜出现三套以上的明度。
  - **空状态、长文本、溢出必须有明确处理** —— 本任务在卡片描述上做了省略号截断，
    在分类无模块时给出空状态文案。
- **不适合直接使用部分**：面向 Web 设计团队，包含字体授权、WCAG 工具链等内容，与 Minecraft 无关。
- **迁移到 Minecraft UI 的方式**：作为代码评审清单使用（见第七节）。

### 9. RNFrostedSidebar

- **技术**：Objective-C / iOS。
- **许可证**：本次检索未确认，**不得参考其代码**。
- **UI 特点**：控制中心式侧边栏，先截屏再对截图做三次盒式模糊模拟高斯模糊，
  配合弹簧动画与点击波纹。
- **可参考部分**：工程取巧点 —— **模糊不必对实时画面做**，可以降采样后再模糊。
  本项目 `SkiaBlurRenderer` 已是「降采样 → 模糊 → 回填」的链路。
- **不适合直接使用部分**：iOS 专属 API（Accelerate / UIView 动画），且许可证未确认。
- **迁移到 Minecraft UI 的方式**：仅确认现有降采样策略的方向正确，不引入任何实现。

### 10. Memos UI Kit

- **GitHub**：github.com/usememos/memos。
- **许可证**：本次检索未确认。
- **技术**：React + shadcn/ui 风格。
- **可参考部分**：
  - **组件目录即样式的唯一事实来源**：所有外观决策集中在 UI Kit 目录内，业务层只通过
    `variant` / `size` 等 props 使用，禁止在业务代码里写颜色与尺寸。
    对应本任务：分类卡片、模块卡片、状态徽章的外观全部封在 `ui/component`，
    页面类只负责布局、数据与跳转，不直接写颜色值。
  - **重复出现的外观需求应提升为 variant，而不是复制样式**。
- **不适合直接使用部分**：React 生态与 Tailwind 类名体系。
- **迁移到 Minecraft UI 的方式**：把它作为组件层的纪律约束，而不是代码来源。

### 12. LiquidBounce

- **GitHub**：github.com/CCBlueX/LiquidBounce
- **技术**：Kotlin / Fabric。
- **许可证**：本次检索结果未给出许可证名称，使用前必须自行核对；

## 五、提炼出的设计原则

结合上述项目，确定 yiyiaddon UI 系统的九条原则：

1. **单一事实来源**：颜色只来自主题调色板；分类与模块只来自注册表；页面代码不写死任何清单。
2. **派生式 token**：少量核心色派生出全部交互色，换主题只改调色板。
3. **分层而非平铺**：窗口 / 侧栏 / 内容 / 卡片 / 次级卡片五层，靠明度差区分而不是靠边框。
4. **组件化**：底板（GlassPanel）、布局（CardLayout）、卡片（CategoryCard / ModuleCard）、
   徽章（StatusBadge）各司其职，页面只做组合。
5. **玻璃四件套**：半透明填充 + 降采样模糊 + 1px 高光描边 + 大圆角；不做折射。
6. **状态成组**：默认 / 悬停 / 按下 / 禁用必须同时定义，悬停用插值动画而非瞬变。
7. **层级导航**：分类 → 模块列表 → 模块页面，逐级进入，不在一页里展开全部设置。
8. **可读性优先**：文字一律取主题文字色，禁止低对比度自造灰；长文本截断、空列表给出空状态。
9. **动效克制**：只做状态过渡，不做常驻装饰动画。
