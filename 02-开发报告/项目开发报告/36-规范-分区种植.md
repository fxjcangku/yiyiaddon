## 二、目标（一句话）

把现在「整片农田只有一个目标作物」的口径，换成「**按矩形分区，每区绑一种作物，各收各的、互不干扰**」。

- 现状：整片田只能同时维护一组已勾选作物，混种会互相打架（`StardewTaskPlanner.mismatchedCrops()` 直接停机报错）。
- 目标：一块田切三个矩形区域，区域 1 只种番茄、区域 2 只种冬季作物、区域 3 只种另一种；播种、浇水、收割、施肥、洒水器维护全部**按区域各走各的**。
- 区域**取代**「农田起止点」成为范围来源；起止点数据**保留不删**（分区关闭时仍然照旧使用）。

## 五、数据模型与落盘

### 5.1 文件位置

照 `StardewPointManager` 的现成做法（`Minecraft.getInstance().gameDirectory` 下）：

```
run/StardewFarm/regions/<服务器标识>.json
```

- 服务器标识取自 `StardewContext.serverKey()`，文件名同样做非法字符替换（`[\\/:*?"<>|]` → `_`）。
- 写入用现有工具 `com.yiyiaddon.repository.JsonFileStore.writeAtomic(...)`（原子写，失败保留旧档）。
- 文件损坏时**读取返回空**，禁止覆盖写回。

### 5.2 结构（中文键，与 `points/*.json` 风格一致）

```json
{
  "服务器": "example.com:25565",
  "资源指纹": "1a2b3c",
  "区域": [
    {
      "序号": 1,
      "作物": "四季豆",
      "作物键": "customcrops:green_bean",
      "维度": "minecraft:overworld",
      "x1": 19860, "y1": 64, "z1": -1630,
      "x2": 19870, "y2": 64, "z2": -1620
    }
  ]
}
```

字段口径：

| 字段 | 说明 |
| --- | --- |
| `服务器` | 文件级；`load` 时必须与请求的服务器标识一致，否则整档不读 |
| `资源指纹` | 文件级；仅作记录（`ResourceExtractionService.fingerprint()`），**不作为拒绝读档的判据** |
| `序号` | 文件内自增，删除后**不重排**（保证用户看到的号不乱跳）；列表展示用它在存档内的顺序 |
| `作物` / `作物键` | 中文名（回执与界面用）与稳定逻辑键（判失效、判种子用） |
| `x1/y1/z1` `x2/y2/z2` | 两个角；读取时统一归一化成 `min/max`，不假设用户先点哪个角 |
| `维度` | 建区时所在维度；跨维度不参与（与现有 `StardewPoint.inCurrentDimension()` 同一口径） |

### 5.3 内存模型

新建区域管理器（建议 `feature/stardew/region/StardewRegionManager.java`），照 `StardewPointManager` 的公开方法形态：

- `record StardewRegion(int index, String cropKey, String cropName, String dimension, int x1,y1,z1,x2,z2)`，附 `minX()/maxX()/minZ()/maxZ()/contains(BlockPos)/intersectArea(StardewRegion)/cellCount()` 等纯计算访问器。
- `load(serverKey)` / `save(serverKey)`：与 points 完全同构（相同服务器跳过、原子写、损坏不覆盖）。
- `add(...)` / `removeByIndex(int)` / `clearAll()` / `list()` / `regionsInDimension()` / `regionAt(BlockPos)` / `intersectionWith(...)`。
- 改绑：`rebind(int index, String cropKey, String cropName)`（是否允许见 12.1）。

### 5.4 不落盘的东西

- 半成品（只点了一个角）、光标预览、当前选区模式状态：**只存内存**，切服 / 退出世界 / 关闭模块即丢弃。

## 六、选区模式（交互逐条）

### 6.1 进入

- 敲 `.stardew 种植区域 <作物>` 进入选区模式。
- `<作物>` 必须是选择器里**已勾选**的作物；否则拒绝，并提示到选择器里先勾上。
- TAB 补全**只列出已勾选的作物**（与现有 `.stardew 种植` 的补全口径一致，别给全量列表）。

### 6.2 选点

| 步骤 | 操作 | 反馈 |
| --- | --- | --- |
| 1 | **空手左键**点方块 | 记下第一个角，画一个小框；此后光标指向处实时预览「第一个角 ↔ 光标」形成的矩形边框 |
| 2 | **空手右键**点方块 | 记下对角，校验通过即生成区域并绑定该作物；回执含坐标范围、格子数、该区洒水器覆盖情况 |
| 退出 | `.stardew 种植区域 取消` | 丢弃半成品，回执「已取消」 |

- 不指定选点工具时，**只有空手**算选点；指定了工具后，**空手或手持该工具**都算。
- 模式内所有左键 / 右键一律拦下：不挖、不放、不浇水、不开箱、不交互。**只在模式内接管**；模式外一切照旧。
- 两个角都在**当前维度**内判定；切维度 / 切服 / 退出世界 / 关闭模块 → 直接丢弃半成品。

### 6.3 选点工具（设置项）

- 设置项「选点工具」，默认「空手」。
- 提供「一键设定」：把**当前主手物品**记为该工具（照现有「一键设定」类按钮的做法），并提供清除回「空手」。
- 设定时的提示必须明确写：**以后手持它不会挖方块**（逐字文案见第十二节）。

## 七、规则细则

| 规则 | 处置 |
| --- | --- |
| 两角同格 | 拒绝，提示两角不能在同一格 |
| 单边 > 64 | 拒绝，提示上限 64 |
| 越出农田矩形 | 裁到农田内，回执写明裁掉了哪几条边；裁完为空 → 拒绝 |
| 与已有区域重叠 | 拒绝，报出撞了哪个区域（区域号 + 作物）与重叠格数 |
| 未分区格子 | 不管（不种、不收、不浇、不画），列表只统计「未分区 N 格」 |
| 区内异种作物 | 停机报错，报出坐标 / 区域号 / 该区绑定作物 / 实际作物 |
| 改绑作物 | 见 12.1（默认口径：区内有旧作物即严格报错并拒绝改绑） |
| 作物被取消勾选 | 区域保留，本轮失效跳过，重勾自动恢复 |
| 缺对应种子 | 跳过该区，提示「区域 X（作物）缺种子」，同一条只报一次；不停机，绝不用别的种子顶替 |
| 保株再生作物 | 收割后不播种，回退「再生中」，继续浇水等下一茬（走现有 `REGROW` 链路） |
| 季节校验 | 不做 |
| 删除区域 | 从列表移除，地块回到「未分区」＝不再管；不做清理、不回溯、不回填 |
| 自动划分 | 不做 |

> 关于「删除」的落盘口径：因为 D11 已定「未分区 = 不管」，删除后该地块自动进入不管状态，**当前分析不存在「删了还被管」的路径，因此不需要额外的排除标记**。实现时若发现确实存在这样的路径（例如某处仍按农田起止点整片接管），再补落盘排除标记并在报告中登记。

## 九、界面与设置

### 9.1 区域列表页

- 入口：控制台「点位」页的「农田」卡片，照**洒水器卡片**那套做法加一个 `§e管理` 按钮 → 打开区域列表页。
- 新窗口照抄 `feature/stardew/ui/StardewSprinklerListScreen.java` 的结构与配色，新建 `StardewRegionListScreen`。
- 每行文字（逐字）：

```
区域 1 · 番茄 · X19860~19870 Z-1630~-1620 · 121 格 · 洒水器 2 台 覆盖 100%
```

- 行尾两个动作 `[换作物][删除]`（`SettingSegmented` 动作型：文案纯文本，不带颜色码）；底部「清空全部区域」与「返回」。
- **「换作物」**（2026-09-15 用户追加）：打开项目现成的作物选择器（`StardewTargetSelectScreen` 单选模式，标题「选择作物」）——点一下立即生效并重建本页；只改绑定品种，**范围 / 序号 / 维度一律不动**（实机反馈：换个品种不该逼玩家删了重圈）。换完区域名同步更新（列表行、世界里的区域字牌、错位播报都读同一份 `Region.cropName()`）。
- 「换作物」的**先验地**（口径 A，见 12.1）：区域内还有生长中 / 成熟 / 特殊变种的作物时**拒绝改绑**，报出是哪一株、在哪一格（聊天 + 屏幕中间面板）；空盆、死株、识别不出的格不算占地。**不支持把作物区改成混种区**（用户拍板：选择器只换作物）。
- 页面里同时显示一行统计：`未分区 N 格`。
- 悬停提示一律**纯文本**（不要颜色码，`CompactRow` 已统一 strip，照洒水器列表页的写法）。
- 空列表时给一行说明文字（不要空白页）。

### 9.2 无模块也可查看

- `.stardew 预览范围` 已实现（预览层只在「开着预览且模块未启动」时挂载）。

- 预览层**只画玩家附近 32 格内**（`StardewRenderState.PREVIEW_RADIUS`，与附近洒水器扫描同口径）：走后 / 传送走不再有农场的框与字牌留在画面上；模块自己的那层不裁剪（作业中要看得到整片地）。

## 十三、现有事实（免得新窗口重复取证）

以下均为**已实机验证的现状**，直接当作前提，不要重新取证、不要改动：

1. **洒水器识别**：三种洒水器的方块状态完全相同（都是隐形载体），只有挂在同一格的 `Display.ItemDisplay` 实体的 `DataComponents.ITEM_MODEL`（`customcrops:sprinkler_1/2/3`）能区分；验证文案 **「贴图实体已验证」**。识别逻辑在 `StardewPointActions.matchSprinklerDisplay(BlockPos)`。
2. **洒水器水量**：客户端读不到洒水器实时水量。唯一可靠信号是**手持水壶的水量差分**——每点一下掉 1 点，灌满后再点**不扣水**；容量藏在实体物品 LORE「储水量: N」（初级 4 / 优质 4 / 高级 6），全程不变。
3. **服务端行为**：同一 tick 内多个交互包会被丢弃（10 连发只生效 9 包）。
4. **保株再生作物**：`StardewCropLifecycle.REGROW` / `StardewServerProfile.regrows(cropKey)` / `StardewDocumentedRules.regrows` 已支持，收割后回退「再生中」，不播种。
5. **关键常量**：`DEFAULT_VERIFY_TICKS = 8`、`REFILL_MAX_PACKETS = 32`、`MAX_BATCH_ACTIONS = 8`、`MAX_RETRY = 3`。
6. **范围预览**：`.stardew 预览范围` 已实现（`StardewFarmModule.toggleRangePreview()` + 预览层 `stardew-preview`）。
7. **批量右击**：默认 4、上限 8；只做右键（收割 / 浇水 / 播种 / 施肥），清理枯苗永远单目标。
8. **各区域洒水器覆盖率**只用区域矩形与洒水器半径做几何计算（`StardewRenderState.radiusOfLevel`：等级 1~4 → 半径 1 / 1 / 2 / 3，未知取 1，**绝不可写成「半径 = 等级」**），**不查水量、不联网、不参与任何决策**。
