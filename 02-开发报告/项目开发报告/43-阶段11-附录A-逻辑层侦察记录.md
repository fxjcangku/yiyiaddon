### 4.1 `setState`（2030-2048）副作用

- 无条件：`state = newState; guiTick = 0; guiPhase = 0;`（**不重置 `gearAnvilPhase`**）
- `newState == WALK_TO_FARM` → `hangoutViewRestored = false`
- `newState == ENCHANTING && !发包附魔提示已播` → `notify("§7发包附魔中（不打开界面）...")` + 置锁
- `isWorkState(newState) && !cn().equals(lastNotifiedState)` → `notify("§7正在" + cn + "...")`
- `IDLE / GEAR_IDLE` → 清 `lastNotifiedState`

`isWorkState`（2052-2058）**仅 11 个**：`FARMING, STORING, RESTOCKING, GEAR_TAKE_GEAR, GEAR_ENCHANTING, GEAR_RESTOCK_LAPIS, GEAR_GRINDING, GEAR_ANVIL, GEAR_TAKE_ANVIL, GEAR_PLACE_ANVIL, GEAR_STORE_OUTPUT`（**`GEAR_WALK_ANVIL_POS` 不在其中**）。
`是容器操作状态`（2118-2122）**8 个**：上面去 `FARMING/STORING/RESTOCKING` 加 `GEAR_PLACE_ANVIL`。

### 4.2 界面抑制（`onOpenScreen` 987-1014 / `shouldSuppressScreen` 1021-1034）

- `InventoryScreen` 打开：若 `containerMenu != inventoryMenu` → `closeContainer()`；**无条件**重置 `guiPhase=0; guiTick=0; gearAnvilPhase=0`
- 被取消（`setCancelled(true)`）的屏 = 模块自己发包打开的容器屏，且只在这些状态：`ENCHANTING, GRINDING, STORING, RESTOCKING, GEAR_TAKE_GEAR, GEAR_ENCHANTING, GEAR_RESTOCK_LAPIS, GEAR_GRINDING, GEAR_ANVIL, GEAR_TAKE_ANVIL, GEAR_STORE_OUTPUT`
- 永不取消：`InventoryScreen` / `CreativeModeInventoryScreen`（创造背包替换会致配方书 NPE 闪退）、非容器屏、非 active
- 取消时：`GEAR_ANVIL` → `gearAnvilPhase = 0`；`RESTOCKING` **不重置** `guiPhase`（`guiPhase>=10` 表示青金石）；其余 `guiPhase = 0`；最后 `guiTick = GUI操作延迟`

## 十一、移植风险与难点（施工时逐条对照）

1. **`gearAnvilPlan.next()` 的位置（3034）**：每 tick 消费一步，移动即改变合并步数 → 原样保留。
2. **`GearCraftReport` 被主流程调用 10 处**（902 `begin` / 904 `disable` / 955 `flush` / 2112 `recordSkip` / 2521 `recordEnchant` / 2552 `recordAnvil` / 2750 `recordGrind` / 3092 `recordTooExpensive` / 3214 `recordComplete` / 3215 `flush`）。用户已裁定「产出报告延后」→ **这 10 处调用点必须有归宿**（保留空壳 / 删调用 / 完整搬）。**已在批次1 交付时提请用户拍板，不得自行决定。**
3. **`settings.groups` 直接增删**（571-583 `remove` ×13；646-648 `clear/addAll`）：Meteor Settings 内部集合 API。新项目控制台是「页签集合」，需自建等价模型，并**必须保留 `同步模式分组()` 的幂等保护语义**（顺序一致直接 return）——否则 `目标模式.onChanged` 在 `loadSettings` 遍历页签期间重建集合会 `ConcurrentModificationException` 启动闪退。
4. **`onChanged` 内同步重建界面**（114-117：`同步模式分组(); 刷新模式界面();`）→ 新项目走挖矿 `MiningTargetControls.afterModeSwitch` 的「整页重建」做法。
5. **`ESP标点` / `返回挂机视角` 是 `.visible(() -> false)`**（164、167）：永久不可见但真实存在且会落盘 → 保持同语义（控制台不出现，值照旧读写）。
6. **动态生成的 33 个原版附魔 BoolSetting 无字段引用**，`name` 字符串即落盘键（`EnchantmentSelectSetting.apply` 用 `name` 写回）→ **改名=丢配置**，一个字都不能改。
7. **`mergeBooksStep` 的 36 槽双层循环 + 三连点击**：移植时保持「每 tick 只发一次点击」的节奏。
8. **容器槽位映射**：`containerSlotOf(handler, invSlot)`（1815-1827）把玩家背包槽换算成菜单槽，**全流程共用这一处**，不得就地硬编码。
9. **`GUI_OPEN_PENDING=20` / `GUI_OPEN_TIMEOUT=40`**：菜单打开超时回落逻辑（`guiPhase=0`）必须原样保留，否则卡死。
10. **`是容器操作状态` / `isWorkState` 的两套集合**：判据互不相同（8 vs 11），不得合并简化。
