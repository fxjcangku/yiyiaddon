## 一、取证：男中音自带平滑为什么还是抖

上一版（117 号改动）在「寻路视角跟随」开启时改开男中音自带 `smoothLook`，期望它的
「最近 N 刻目标角度滑动平均」把转弯阶跃抹成渐变。对照
`baritone-26.1.2-source\behavior\LookBehavior.java:106-122` 的实写，它有三个病根：

| 病根 | 源码证据 | 观感 |
| --- | --- | --- |
| **±180° 环绕不处理** | `POST: smoothYawBuffer.addLast(target.rotation.getYaw())` 后直接 `stream().average()` —— 目标角度以原始度数进队列再取平均 | 视角跨「-179 → 179」中线时，平均出 (-179+179)/2 = 0 之类反方向角度，镜头瞬间抽风，这是最刺眼的一档抖 |
| **俯仰不平滑** | 平均写回只在 `isFallFlying()` 时才碰 pitch，平地走路/上下坡的俯仰阶跃原样落进视角 | 上下坡、瞄上瞄下一格一格跳 |
| **每刻 Δ/N 等差步** | 窗口平均对阶跃输入的响应是「每刻前进 Δ/N」的等距离散步 | 角速度不连续，转弯是顿挫不是弧线 |

三类都在「走路的时候」集中爆发：寻路节点一切换，目标角度就是一次阶跃。

## 二、方案：模块接管可见视角，自研平滑器

男中音每刻把「精确目标角度」直接写进玩家视角（`LookBehavior` PRE 阶段，同时保证
服务端朝向与射线检测分毫不差）。模块把自己注册成男中音事件总线上的监听器
（`CopyOnWriteArrayList` 按注册序派发，男中音所有行为在先、模块在末），于是：

- **PRE 阶段**（晚于男中音写入）读走它刚写下的本刻目标角度；
- **POST 阶段**（晚于男中音的复原/窗口平均）用自己的平滑器写回可见视角——本刻渲染
  拿到的最终值就是模块的写出，服务端与射线检测用的还是男中音的原值。

平滑器三件套（与上表三病根一一对应）：

| 措施 | 实现 | 效果 |
| --- | --- | --- |
| ±180 环绕归一 | `wrapDegrees()` 把 yaw 差值归一进 [-180,180) 再参与一切计算 | 跨中线取最短转角，抽风根治 |
| 指数趋近 | `viewYaw += wrapDegrees(desired - viewYaw) * 0.35f` 每刻消掉剩余差值的固定比例 | 角速度随剩余角度单调连续，转弯是「快起慢收」的丝滑弧线 |
| 静止贴合 | 目标连续 4 刻没动、或差值已 < 0.4° 时直接贴合目标 | 截断指数趋近的无穷尾巴：转弯收尾干脆，挖矿准星/开箱朝向最终分毫不差 |

配套改动：

- 男中音自带 `smoothLook` 一律置 false（模块运行期间由自研平滑接管，关闭/战斗时还原原值）；
- `randomLooking / randomLooking113` 继续归零（沿用 117 号，随机偏移会直接写进可见视角）；
- **闸门**：仅当「跟随开 + 未被战斗接管 + 男中音确有寻路/挖矿/物流寻路进程」时动手——
  战斗盯怪、挂机修复对准、水流脱困、连锁接管这些自己写精确视角的流程不受平滑器干扰；
- 滑翔（fall flying）不接管（男中音对滑翔走强制 CLIENT + 俯仰平滑，交给它自己的逻辑）；
- 开关切换 / 关闭模块时平滑器初值从玩家当前视角重新起跳，杜绝「从旧角度猛拉」的跳变。
