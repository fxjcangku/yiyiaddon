这个模组做什么

模块中心里选功能，独立页面里做配置，控制台里看设置和运行状态。三件事是当前版本的重点：

重点 一句话
星露谷农场 跟当前服务器的资源与玩法自适应，种什么、用什么工具、什么时候收，都按那台服的真实数据来
自动挖矿 从进矿、战斗、满载卸货到回城卖矿，串成一条能一直跑的流程
ID 联动自动箱子 ID 识别定下目标物品，自动箱子按这份目标清单取货，逐物品定量

星露谷农场

服务器自适应：换一台星露谷玩法服务器，不用重新学一遍。

进服后点一次「检测 / 提取当前服务器资源」，模组会读取这台服务器自己的资源包，把真实存在的作物、种植盆、种子与工具取出来给自己用——不写死在某台服的数据上：

自适应点 实际效果
服务器资源识别 作物、种植盆、种子、工具按该服资源包列出来供你选，改版或换服重测即可
旧布局资源包兼容 老服沿用的旧资源布局同样能识别（基础物品 + 派发表两套口径）
洒水器覆盖范围 从实物与物品说明自学覆盖范围，不靠固定尺寸猜
成熟与季节 按可确认的状态与已有规则判定成熟，结合该服季节与种子信息安排播种
服务器数据隔离 农田点位、绑定箱、配额按服务器各存一份，换服自动读那一份

一台功能齐全的农场，分成六个页签

概览 当前任务与库存　 /　 种植 作物与工具　 /　 运行 作业参数
后勤 数量与补给　 /　 点位 农田与设施　 /　 日志 状态回看

能力 你可以怎样使用
分区与混种 圈定单作物区域，或在混种区按已选作物与目标数量安排种植
作物配额 每种作物单独设目标，按个数或组数管理，不必所有作物同一个数
日常照料 浇水、施肥、药剂使用、洒水器维护，并处理枯死作物
补给与仓储 绑定种子箱、成品箱、补水点，管理补货、卸货与多余种子回收
范围与状态 查看种植范围、洒水器覆盖、配额与当前任务，日志可回看
第一次使用：从资源准备到开始种植
  1. 进入对应服务器，在模块页点击「检测 / 提取当前服务器资源包」。
  2. 打开控制台，在「种植」页选择目标作物及实际使用的工具。
  3. 在「点位」页的「农田」卡片圈地，确定单作物区或混种区。
  4. 按需求绑定种子箱、成品箱、补水点与洒水器。
  5. 在「后勤」页设置各作物目标数量，检查运行参数后开启模块。

使用前提： 依赖对应服务器的资源与玩法配置，不承诺兼容所有自定义农业服务器。缺少可靠成熟信息时需要人工确认规则；特殊作物需要对应工具。建议先从小块农田验证。

自动挖矿

不只是挖，是把一整套班次跑完。

选好目标矿物与后勤点位后，由随包提供的 Baritone 负责寻路，模组按背包、饥饿、耐久与敌情切换任务：

环节 功能说明
采掘目标 配置目标矿物与采掘参数，寻路进入矿区，连锁挖空矿脉并补挖残余
战斗与保命 遇敌优先处理战斗，苦力怕贴身先了断，坚守者预警时脱离
满载卸货 达到设定条件后走卸货流程，再返回采掘
食物补给 按饥饿与血量阈值进食、回血，口粮直补副手
工具维护 按耐久阈值换镐；满足经验修补条件时进入修复流程
边挖边走 需要时自行搭路、垫脚，水中脱困与卡住自愈都有人管
自用模式 挖够组数或背包满就静默回城卖矿，卖完回子服继续，形成循环
配置记录 设置与点位存成一份记录，按服务器查看、覆盖与复用

典型流程

前往采掘区域 → 寻路挖矿 → 检查背包 / 食物 / 耐久 / 敌情 → 卸货或卖矿 → 回矿继续

第一次使用：三个点位与一个必查设置
  1. 准备工具、食物，以及修复流程需要的装备与场地。
  2. 在控制台「点位」页绑定矿物箱、食物箱、挂机修复点；自用模式再配好回城与子服入口。
  3. 配置服务器实际可用的传送指令与等待时间。
  4. 选目标矿物，检查满载、食物与耐久阈值。
  5. 检查「保留白名单」再启动。非保留物品会被自动丢弃。

传送与回城流程依赖服务器支持对应指令；普通无经验修补工具不能靠经验修复。运行时先停止模块再改点位。

ID 联动自动箱子

ID 识别告诉它「要什么」，自动箱子替你「去拿」。

ID 识别负责认物品、把目标记进 ID 配置；自动箱子直接读这份目标列表，逐物品设置取货数量——不用在两个模块里各填一遍：

联动点 说明
目标来自 ID 取物目标取自 ID 目标列表，识别到的物品可直接进清单
逐物品定量 每个目标单独设数量，也可以取空清单物品或全部合法物品
三种工作方式 玩家自行走位时随走位触发 / 自动寻路扫描 / 只处理已保存点位
边界可配 容器类型、多人保护、重试与临时冷却分别配置
状态可见 概览、点位、运行模式、容器、保护、取物与渲染共七个页签

方向 代表功能 使用场景

安装准备

环境 当前版本要求
游戏 Minecraft Java 版 26.x（当前支持 26.1.2 与 26.2；26.3 及以后暂不支持）
加载器 Fabric Loader 0.19.5 或更新兼容版本
基础依赖 与游戏版本对应的 Fabric API：26.1.2 用 0.155.2+26.1.2，26.2 用 0.161.0+26.2
Java 25
系统 当前包包含 Windows x64 / ARM64 原生组件；其他系统暂未提供适配包

四步装好：

  1. 在启动器里建一个对应游戏版本（26.1.2 或 26.2）的 Fabric 实例，Java 选 25。
  2. 到 Releases 下载与游戏版本对应的包（文件名末尾带 MC 版本，如 yiyiaddon-1.0-beta2-26.1.2.zip）。
  3. 把包解压，取出里面的 JAR，连同对应版本的 Fabric API 一起放进该实例的 mods 文件夹——别直接把 ZIP 丢进去。
  4. 启动游戏。升级已有实例前，先备份存档与配置。

Baritone 已随包提供，不用另装。装错版本会起不来：26.1.2 的包不能丢进 26.2 实例。

这个模组的前身

yiyiaddon 的前身是 Meteor Client 的附属插件——功能、算法、状态机、配置项与文案都在那套体系里长出来的。现在整体重写为独立的 Fabric 客户端模组：不再依赖 Meteor 或任何第三方客户端框架，代码与运行方式都是自有的，只把操作界面重新做了一遍。

因此老用户的习惯基本可以照搬：模块位置、开关与指令前缀的用法一脉相承，配置项按原有口径迁移；界面换成了模块中心 + 独立页面 + 中文控制台。

1. 更新日志

  • 修复：背包满了仍收菜 / 浇水 / 往返、还去拿种子 —— 现在先卸货，实在腾不出空间才整机停机。
  • 修复：产物箱放不下成品时只是停手、模块仍在跑动 / 接管箱子界面 —— 现在直接关闭模块，世界恢复静止；清空产物箱后重新开启模块即可。
  • 修复：背包满时误报「当前农田已处理完成」—— 现在说明满仓停手，并报出熟菜 / 生长 / 空盆数。
  • 修复：背包满时提示「已暂停收菜」却还在砸枯苗 / 杂物 —— 现在一起停。
  • 修复：洒水器被挖或换成别的型号后仍照旧维护、标记不消 —— 现在跳过维护并提示清理 / 重新绑定。
  • 修复：没选物品也能开自动浇灌 / 施肥 / 药剂 / 洒水器维护 —— 现在缺什么当场提示并拒绝开启。
  • 修复：界面缩放调小后打开选择器、两侧露出放大图标 —— 已修。
  • 修复：肥料、药剂等显示技术名（如 soil_retain_2）—— 现在按服务器资源包显示中文名。
  • 修复：后勤页「种子补货」说明与真实行为不符 —— 它其实是补货开关（填 0 关、正数开），仅改文案。
  • 修复：正式版被提示下载下一版测试包 —— 现在正式版只提示正式版更新。
  • 修复：对准巨型 / 金色变种敲「标记成熟」时提示识别失败 —— 现在说明该类作物无需人工标记，收割口径按服务器自动学习。
  • 修复：关掉界面再打开总是回到首页 —— 现在回到上次关闭时停留的页面（在模块页里关掉的，打开时直接回到那一页）。
  • 修复：作物成熟阶段学习时连刷「收获学习未确认」—— 现在优先按最高阶段试探，一次即可确认，且同一作物只提示一次。
  • 修复：启动自检报「分区错位」时只有一行坐标、田里找不到 —— 现在那些格子会在世界里用红框标出，清掉后红框自动消失。
  • 修复：删除种植区域后该范围内的洒水器仍被维护、点位与 ESP 框仍保留 —— 现在删区时把这些洒水器点位一并删除，回执里写明删了几个。
  • 修复：一块地还没种完就先跑去别的地块（本区缺种子时先去取种、本区的掉落物优先拾取）—— 现在先把当前这块地做完再换下一块。
  • 修复：删掉某种作物的最后一块种植区域后，「目标选择器」里它仍显示已选 —— 现在会自动取消勾选（还有混种区或别的区域在用它则不动）。
  • 修复：部分服务器上枯死作物 / 杂物反复重试却始终不掉 —— 现在一律按服务端进度挖到底，并先用背包里最快的工具（含效率附魔）。
  • 修复：巨型 / 金色变种作物在部分服务器上「有破坏反馈却始终不掉落」—— 现在会优先换上背包里最快的工具（含效率附魔）按服务端进度挖到底，挖不动的格会提示并跳过，不再反复空砸。
  • 修复：地上的巨型 / 变异作物（如巨型菠萝）认不出、不收 —— 现在按服务器资源包里的变种外观识别，分区与作物配额照常生效。
  • 变更：特殊变种收割改为按服务器学习 —— 收一次记住动作与工具，同服通用、换服互不影响；同一作物的不同变种（如巨型番茄与黄金番茄）分别记录，缺专用工具只提示并跳过该格。
  • 变更：按 G 键可以关闭整个界面（原来只能开）—— 开与关是同一个键，任何界面下都可用。
  • 变更：简化后勤默认关闭 —— 后勤页默认逐作物显示四个阈值，数值与行为不变。
  • 变更：选择器默认展开第一个分组。
  • 变更：自动骨粉目标方块改为手动勾选，每组只列本类。
  • 变更：服务器资源包处理模式默认「原版处理」，要留档可在资源包劫持页切「自动白嫖」。
  • 变更：.stardew 种植区域 的补全先列作物，「列表 / 删除 / 清空 / 取消」收进「管理」一层（旧写法仍可用）。
