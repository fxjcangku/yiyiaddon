**发布说明怎么写（规范 + 可照抄模板）**

发布页正文只有两种形态：**首个测试版**、**后续版本**。先看两种都适用的硬约束：

1. **开头一行点明阶段**：首个测试版写「**首个测试版** —— <一句定位>」；后续版本写「**v<版本>** —— <这次的一句话>」。玩家第一眼就该知道这是什么阶段的东西。
2. **正文不超过六块**（定位 / 下载表 / 环境 / 更新日志 / 提醒 / 反馈），块与块之间空一行，**不许堆成一段**。
3. **下载表每行一个游戏版本**：ZIP 名 + 配套 Fabric API 版本。文件名按 `yiyiaddon-<版本>-<MC 版本>.zip` 从 `build/release/` 照抄，不要手打（打错了别人按名字找不着）。
4. **页面上不出现内部字样**：混淆、反编译、映射、加固、ProGuard 一律不写。也不写「重新上传 / 之前下载过的请重新下载」—— 那是台账的事，记在 `05-混淆文件备份/README.md`；**只有真有旧附件被人下载过才需要提醒重下**（下载次数看 `gh release view <标签> --json assets`）。
5. **依赖版本以文件为准**：Loader / Java / Fabric API 的写法必须与 `gradle.properties`、`build.gradle` 一致，别凭记忆写。
6. **语气**：短句、陈述；不堆营销词（最强 / 颠覆 / 独家），不承诺没实机验收过的能力。
7. **改完必须回读**：`gh release edit <标签> --repo fxjcangku/yiyiaddon --notes-file "06-发布页面\版本说明草稿.md"`，再 `gh release view <标签> --json body` 核一遍渲染出来的样子。

**一、首个测试版模板**（现行样本就是 `版本说明草稿.md`，可直接照抄改版本号）

```markdown
**首个测试版** —— 独立开发的 Minecraft Fabric 客户端模组。

| 游戏版本 | 下载 | 配套 Fabric API |
| :--- | :--- | :--- |
| 26.1.2 | `yiyiaddon-1.0-beta1-26.1.2.zip` | `0.155.2+26.1.2` |
| 26.2 | `yiyiaddon-1.0-beta1-26.2.zip` | `0.161.0+26.2` |

Fabric Loader `0.19.5`+ / Java `25`。解压后放进 `mods`，别直接丢 ZIP；装错版本无法启动。

建议先用独立实例并备份存档；**26.3 及以后暂不支持**；问题到 [Issues](https://github.com/fxjcangku/yiyiaddon/issues) 反馈。
```

首测**不介绍功能、不写更新日志**：功能等仓库首页讲，更新日志等下一版真能列举时再写。

**二、后续版本模板**（`<>` 处替换成实际内容）

```markdown
**v1.0-beta2** —— 修好了进世界就崩的问题。

| 游戏版本 | 下载 | 配套 Fabric API |
| :--- | :--- | :--- |
| 26.1.2 | `yiyiaddon-1.0-beta2-26.1.2.zip` | `0.155.2+26.1.2` |
| 26.2 | `yiyiaddon-1.0-beta2-26.2.zip` | `0.161.0+26.2` |

**修复**：<什么操作会出问题 → 现在怎样>。

**新增**：<多了什么，玩家能看见的效果>。

**变更**：<行为或配置改了什么，老用户要跟着改什么>。

提醒：<不支持的游戏版本 / 备份存档 / 服务器服规>；问题到 [Issues](https://github.com/fxjcangku/yiyiaddon/issues) 反馈，附模组版本、复现步骤与日志。
```

**更新日志怎么写**：

- 三段顺序固定 **修复 / 新增 / 变更**；哪段没有就**不写那段**，也不要写「无」。
- 每条一句话，写**玩家能看见的效果**，不写内部实现（不写类名、Mixin、混淆、映射）。
- 修崩溃写成「<什么操作> 会崩 → 现在正常」，方便别人对号入座确认自己碰到的是不是这个。
- 只在**递增了版本号**时才可能出现「请更新到新版本」；同标签换附件不改版本号，已装老版本的玩家收不到更新提示，正文就别写「请更新」。

新版采用方块农场与矿洞场景、点阵标题、苔绿与木石配色，动效为代码控制的轻微光点、薄雾层与矿石高光。旧 SVG 封面保留作历史草稿，现行首页不引用。首页只使用 Markdown 与基础 HTML；预览页的物品栏风格侧栏、主题按钮和页面外框用于本地查看，不会作为 GitHub 页面控件发布。GitHub 的导航、按钮和页面布局由平台控制，不能通过 README 更改。

本地预览根据首页正文生成；后续修改 README 后需要重新生成预览，不能只改预览文件。远程 Release 已回读核对预发布状态和附件摘要；本地外框不等同 GitHub 实际皮肤。
