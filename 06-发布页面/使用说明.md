**发布说明怎么写（规范 + 可照抄模板）**

发布页正文只有两种形态：**首个测试版**、**后续版本**。先看两种都适用的硬约束：

1. **开头一行点明阶段**：首个测试版写「**首个测试版** —— <一句定位，含主打功能>」；后续版本写「**v<版本>** —— <这次的一句话>」。玩家第一眼就该知道这是什么阶段的东西。
2. **正文按编号分块，标题一律 `## <序号>. <块名>`**：块名固定，块内顺序固定。**首个测试版**顺序为 **下载 / 运行环境 / 更新日志 / 使用提醒 / 反馈渠道**；**后续版本（beta2 起）更新日志开头**，顺序为 **更新日志 / 下载 / 运行环境 / 使用提醒 / 反馈渠道**。某一块没有就整块不写，**剩下的编号顺延**（不许留空号）。
3. **块与块之间空一行**，每块只讲一件事，**不许堆成一段**；块内信息用标签式短行承载（`**加载器**：…`／`**安装方式**：…`），整篇不超过五块。
4. **下载表每行一个游戏版本**：ZIP 名 + 配套 Fabric API 版本。文件名按 `yiyiaddon-<版本>-<MC 版本>.zip` 从 `build/release/` 照抄，不要手打（打错了别人按名字找不着）。
5. **页面上不出现内部字样**：混淆、反编译、映射、加固、ProGuard 一律不写。也不写「重新上传 / 之前下载过的请重新下载」—— 那是台账的事，记在 `05-混淆文件备份/README.md`；**只有真有旧附件被人下载过才需要提醒重下**（下载次数看 `gh release view <标签> --json assets`）。
6. **依赖版本以文件为准**：Loader / Java / Fabric API 的写法必须与 `gradle.properties`、`build.gradle` 一致，别凭记忆写。
7. **措辞高级但不浮夸**：准确、克制、书面，短句陈述；同一件事只说一遍。**禁止**营销词（最强 / 颠覆 / 独家 / 史诗）、Emoji、感叹号堆情绪、空泛承诺（第 240 条）。
8. **改完必须回读**：`gh release edit <标签> --repo fxjcangku/yiyiaddon --notes-file "06-发布页面\版本说明草稿.md"`，再 `gh release view <标签> --json body` 核一遍渲染出来的样子；同时确认渲染后编号连续、无空块。铁律见 `开发习惯.md` 第四十章（第 238—241 条）。
